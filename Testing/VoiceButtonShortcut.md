# 语音键自定义触发快捷键测试手册

## 适用版本与分支

- 分支：`codex/voice-trigger-shortcut`
- 基线：`bd1734a9f06d8f9a96da057e4b527686c3248c76`
- 功能范围：实体小米遥控器的语音键继续负责收音，同时可把默认 Fn 改为任意单键、单独左右修饰键或组合快捷键。
- 本手册不验证连续宏、鼠标动作、媒体键或手机与网页版语音键的自定义触发。

## 测试前准备

1. 准备一只已配对并可正常收音的小米蓝牙遥控器 2 Pro（RC003-MS）。其他型号必须单独记录型号和结果，不能代替 RC003 基线。
2. 在 macOS“隐私与安全性”中允许无线麦使用蓝牙、输入监控和辅助功能。
3. 确认 `MiRemoteV 2ch` 或 `BlackHole 2ch` 可用，并在目标语音输入工具中选为麦克风。
4. 准备千问输入法，并把“左 Control”设为按住说话的语音输入控制键。
5. 准备一个普通文本输入框，以及一个不包含未保存内容的测试窗口。
6. 记录测试版本、macOS 版本、遥控器型号、目标 APP、输入法版本和开始时间。

## 用例 1：默认 Fn 回归

1. 打开“按键映射”，启用自定义按键功能。
2. 点击遥控器示意图旁的语音键卡片，进入“语音键触发快捷键”。
3. 点击“恢复 Fn”。
4. 按住语音键说一句话后松开。

预期结果：页面显示“默认 Fn”；原有 Fn 按下、遥控器收音、松开停止和文字上屏行为不变。

失败判定：Fn 未触发、没有音频、松开后语音工具仍处于录音状态，或普通遥控器按键行为变化。

## 用例 2：千问左 Control 按住说话

1. 在语音键编辑区切换到“标准键盘”。
2. 在“单独修饰键”中选择“左 Control”。
3. 聚焦普通文本输入框，按住遥控器语音键并说一句完整的话。
4. 松开遥控器语音键，等待文字提交。
5. 再次按住并完成第二句，确认第一次成功不是偶发现象。

预期结果：遥控器按下时千问开始语音输入；整个按住期间左 Control 保持按下；松开后立即释放，遥控器音频完整进入千问，两次都能正常结束并上屏。

失败判定：只能点击不能保持、第一次失败第二次才成功、文字缺少开头或结尾、松开后仍录音，或 Control 保持在按下状态。

## 用例 3：普通单键与组合快捷键

1. 分别选择一个普通单键、一个 Control/Option/Shift 组合和一个 Command 组合。
2. 在无重要数据的测试 APP 中按住语音键 1 秒后松开。
3. 对每个选择重复两次。

预期结果：按下顺序为修饰键后主键，松开顺序为主键后修饰键；同一次按住只产生一组按下与释放，不因 HID 报告或音频流重复触发。

失败判定：事件顺序错误、按键重复、松开丢失、设置切换后仍发送旧快捷键，或触发未选择的系统动作。

## 用例 4：冲突警告

1. 依次选择 `Command-Q`、`Control-Command-Q`、`Command-Space`、`Command-C` 和无修饰字母键。
2. 只检查页面提示，不在重要窗口中实际执行危险组合。
3. 重新选择“左 Control”。

预期结果：退出/锁屏/强制退出组合显示红色危险警告；常见系统占用、Command 菜单命令和无修饰普通键显示对应橙色警告；左 Control 不显示误报；警告不阻止用户保存。

失败判定：危险组合无提示、提示与风险类型不符、警告阻塞保存，或安全的左 Control 被标成危险。

## 用例 5：异常释放

分别在按住语音键期间执行以下状态，每次之后都用实体键盘输入并检查 Control、Option、Shift、Command 是否仍被系统视为按下：

1. 遥控器断开或取下电池。
2. 关闭自定义按键功能。
3. 把语音触发快捷键恢复为 Fn。
4. 撤销输入监控或辅助功能权限。
5. 正常退出无线麦。
6. 强制结束无线麦进程后重新打开。

预期结果：正常断连、设置变化、权限撤销和正常退出都会补发释放事件；重新打开后无残留修饰键。强制结束进程受 macOS 进程终止边界影响，必须记录是否由系统自动清理合成按键状态。

失败判定：后续点击、滚动或输入持续表现为组合键，或必须再按一次实体修饰键才能恢复。

## 用例 6：设置持久化与回退

1. 保存左 Control 后退出并重新打开无线麦。
2. 导出配置，恢复 Fn，再导入配置。
3. 关闭自定义按键功能后重启，再重新开启。
4. 导入不包含 `voiceTriggerShortcut` 的旧版配置。

预期结果：重启和新配置导入保留左 Control；关闭映射时暂时恢复默认 Fn，但不丢失已保存快捷键；重新开启后恢复；旧配置安全回退为默认 Fn；自定义快捷键与“语音键模拟 Fn 点按”不会同时启用。

失败判定：配置丢失、旧配置导入失败、关闭映射后仍发送自定义键，或 Fn 点按和自定义按住同时执行。

## 稳定功能回归

- [ ] RC003 普通路径仍支持 `STREAM_START → AUDIO → STREAM_STOP`，无需主动 `MIC_OPEN`。
- [ ] 默认 Fn 按住路径与现有正式版等价。
- [ ] Typeless“语音键模拟 Fn 点按”在未设置自定义快捷键时行为不变。
- [ ] 普通按键单击、双击、长按、自定义快捷键和电源键保护不变。
- [ ] 两只遥控器同时连接时不会重复发送语音快捷键或互相遗留按下状态。
- [ ] 语音会话开始、音频路由、结尾排空和本地使用统计不变。
- [ ] `800 × 650` 的中文浅色、中文深色和英文浅色页面可通过纵向滚动访问完整编辑区，字号不低于 12pt，窗口几何不变。

## 日志收集

1. 从菜单栏打开日志目录，收集 `~/Library/Logs/RemoteMic/runtime.log`。
2. 记录失败发生的准确时间、遥控器型号、所选快捷键、目标 APP 和按下/松开/断连顺序。
3. 重点检查 `VOICE SHORTCUT`、`HID EDGE`、`ATVV STREAM` 和权限状态；日志中的“事件已发送”不等于目标 APP 已执行，必须同时描述屏幕最终结果。
4. 不附带语音正文、密码、Token、私人输入内容或设备唯一标识。

## 自动化、代理实测与用户实测边界

- 自动化覆盖：左 Control 持续按下与释放、重复按下去重、组合键按下/释放顺序、中途失败回滚、冲突分类、配置持久化/导入导出、HID 正常松开与断连补偿，以及主应用编译。
- 代理已完成：项目自检 48 项通过；Debug 和 App Bundle 构建通过；`800 × 650` 中文浅色、中文深色、英文浅色以及危险冲突警告页面已从生产 `SettingsView` 渲染并人工检查。
- 当前环境限制：本机只有 Command Line Tools，没有完整 Xcode；`swift test` 无法加载仓库既有的 `Testing` 模块，因此新增 Swift Testing 用例已写入但尚未在本机执行。
- 用户或真实桌面必须完成：RC003 实体 HID 语音边沿、千问左 Control、真实虚拟麦克风、断连/权限撤销、不同前后台状态、双遥控器以及文字首尾完整性。
- 未完成上述真机测试前，只能说明源码、自检、构建和离屏界面验证通过，不能说明功能已经完成真机验收，也不得把本地 ad-hoc App 当作可分发测试包。
