# 本地卡拉 OK 模式测试手册

## 适用版本或分支

- 分支：`codex/local-karaoke-mode`
- 功能状态：候选实现，尚未完成 RC001 / RC003 真机验收
- 适用设备：已与 macOS 配对、能在 SayAll 中完成普通语音的 RC001-MS 或 RC003-MS

## 测试前准备

1. 使用与本分支同一提交编译的 Developer ID 签名 App，确认“系统设置 → 隐私与安全性 → 蓝牙”已允许 SayAll；验证实体按键绑定时还需允许“输入监控”和“辅助功能”。
2. 先连接有线耳机或蓝牙耳机并设为 macOS 默认声音输出。第一次测试不要直接使用扬声器，避免麦克风与扬声器形成强烈回授啸叫。
3. 在“连接与语音”确认目标遥控器为已连接状态，并先完成一次普通“按住语音键 → 说话 → 松开”的基线。
4. 如需验证稳定语音回归，准备 `MiRemoteV 2ch` 或 `BlackHole 2ch`，并准备豆包、微信输入法、Typeless 或 QuickTime Player 中至少一个真实目标。
5. 打开“关于 → 打开日志目录”，保留本轮开始时间。日志不得包含音频正文，测试期间不要用其他版本覆盖当前 App。

## 用例 1：页面开关与默认关闭

1. 完全退出并重新启动 App，进入“连接与语音”。
2. 找到“本地卡拉 OK”，确认按钮显示“开启返听”。
3. 点击“开启返听”，观察页面状态；再点击“关闭返听”。

预期结果：每次启动均默认关闭，不沿用上次开启状态；已连接且没有其他语音会话时可以开启。关闭后最终显示“已关闭”，普通语音仍输出到所选虚拟麦克风。

失败判定：重启后自动开麦；未连接也显示开启成功；关闭后仍有本地声音、蓝牙流或后台麦克风状态；普通虚拟麦克风配置被修改。

## 用例 2：默认无绑定与自定义按键手势

1. 对目标遥控器执行“恢复默认”，完全退出并重新启动 App；快速双击语音键，确认卡拉 OK 状态不变化。
2. 进入“按键”，选择一个普通实体键，例如菜单键；打开“双击”，选择“系统与媒体 → 切换本地卡拉 OK”。
3. 双击已绑定的菜单键，确认模式开启；再次双击同一个键，确认模式关闭。
4. 分别把“切换本地卡拉 OK”改绑到另一个键的单击和长按，验证对应手势各能开启和关闭，未绑定手势保持原动作。
5. 重新启动 App，确认卡拉 OK 仍默认关闭，但用户配置的按键动作仍保留。

预期结果：任何默认映射都不包含卡拉 OK，语音键双击只执行普通语音流程。只有用户明确选择的普通按键及手势会切换模式；单击、双击、长按和不同遥控器 Profile 分别持久化且互不覆盖。绑定动作不重复执行，关闭后不会残留声音。

失败判定：首次启动或恢复默认后仍有实体键切换模式；语音键双击仍被硬编码；选择一个手势却改动其他手势或其他遥控器；绑定重启后丢失；一次手势连续切换多次；关闭后麦克风或本地播放器继续工作。

## 用例 3：主动持续音频与 RC001 / RC003 降级边界

1. 开启模式后不要继续按语音键，观察 2 秒并检查日志。
2. 如果持续收到声音，保持说话至少 60 秒，确认音频不中断；再使用已绑定的普通按键或页面按钮关闭。
3. 如果页面在约 1.5 秒后显示“当前遥控器没有提供持续音频”，按住语音键说话 10 秒，再松开。

预期结果：只有实际收到非空 PCM 后才能显示持续本地播放。当前固件若只返回 `STREAM_START` 而没有音频，App 会发送关闭、停止等待并降级为“按住语音键返听”；按住期间能听到，松开后停止。控制状态本身不能算成功。

失败判定：没有 PCM 却显示持续拾音成功；空流无限保留；降级后按住也无声；松开后仍继续；一次会话超过固件租期后不停止也不恢复且无明确状态。

## 用例 4：本机声音输出与虚拟麦克风隔离

1. 把耳机设为 macOS 默认声音输出，把 SayAll 语音输出设为 `MiRemoteV 2ch` 或 `BlackHole 2ch`。
2. 开启卡拉 OK 并说话，同时在 QuickTime 新建音频录制中观察虚拟麦克风电平。
3. 播放一首本地音乐，确认人声与音乐可同时从耳机听到。
4. 关闭模式，再执行一次普通语音输入。

预期结果：卡拉 OK 人声只进入默认物理输出，与系统音乐混音；不进入虚拟麦克风、不触发 Fn、不产生转写或本地历史。关闭后普通语音重新只走既有虚拟麦克风路径。

失败判定：选择了虚拟设备作为本地播放目标；卡拉 OK 同时触发目标语音工具；音频被保存或转写；关闭后普通语音无声、重复或改走扬声器。

## 用例 5：耳机、扬声器与输出变化

1. 使用耳机完成用例 4。
2. 降低系统音量后切到内置扬声器，短时间测试，出现啸叫立即关闭模式。
3. 模式开启期间拔出 USB 耳机或断开蓝牙耳机；确认 App 能恢复到新的物理默认输出，或明确关闭模式并显示输出不可用。
4. 构造只有虚拟输出可用的环境。

预期结果：始终排除虚拟输出；物理输出变化不会让声音误入 MiRemoteV / BlackHole。没有物理输出时拒绝开启或自动安全关闭。

失败判定：高音量啸叫后无法快速关闭；设备变化导致崩溃、无穷重连或虚拟输出泄漏；页面仍显示活动但没有有效物理输出。

## 用例 6：蓝牙断连、重连和多遥控器

1. 模式开启且正在返听时关闭蓝牙或让目标遥控器断开。
2. 恢复蓝牙并等待同一遥控器重连。
3. 在两只遥控器环境中，用 A 开启模式，再操作 B 的语音键。

预期结果：断连立即结束当前本地流并显示等待；不会切换到另一只遥控器偷接麦克风。重连后，已确认支持主动 PCM 的设备可恢复尝试；已降级设备仍要求按住。B 不会接管 A 的卡拉 OK 会话。

失败判定：断连后继续播放或保留录音状态；自动切换到 B；重连产生重复播放、两个并发流或虚拟麦克风回归。

## 用例 7：前台、后台、锁屏与睡眠

1. 在 SayAll 前台开启并返听，然后切换到其他 App，重复按住说话和使用已绑定的普通按键关闭。
2. 再次开启，锁定用户会话；解锁后检查状态。
3. 分别测试屏幕睡眠和整机睡眠，再唤醒。
4. 开启后直接退出 App。

预期结果：普通前后台切换不影响音频和已绑定的按键动作；锁屏、屏幕睡眠、系统睡眠或退出 App 会关闭模式、蓝牙麦克风请求和本地播放器，唤醒后不会自动恢复持续收音。

失败判定：后台按键动作失效；锁屏或睡眠期间仍收音/播放；唤醒或重新启动后未经用户操作自动开启。

## 用例 8：系统权限状态

1. 保持蓝牙权限允许，完成开启和关闭。
2. 撤销辅助功能和输入监控权限，再验证页面开关及按住返听。
3. 撤销蓝牙权限后重新启动 App。

预期结果：卡拉 OK 音频本身不依赖辅助功能或输入监控，不应因此错误阻断；原有 Fn 和自定义按键仍遵守各自权限门。蓝牙权限缺失时模式不可开启，并显示连接不可用。

失败判定：为了本地返听强制索取辅助功能；权限撤销绕过了原有 Fn/HID 安全门；没有蓝牙权限仍显示正在拾音。

## 稳定功能回归

- 模式关闭、缺失和使用后再关闭三种状态下，各完成一次 RC003 普通 `STREAM_START → AUDIO → STREAM_STOP`，确认虚拟麦克风、Fn 按住和 Fn 点按模式与正式版一致。
- 验证手机、Apple Watch、网页版语音继续只走虚拟麦克风，不进入本地卡拉 OK。
- 验证测试音、音频设备刷新、睡眠释放与恢复、双遥控器 Profile、普通按键单击/双击/长按没有变化。
- 在 `800 × 650` 窗口检查“连接与语音”：标题、状态、按钮和安全说明可通过现有纵向滚动访问，窗口尺寸不被改变，中英文、浅色和深色均无小于 12pt 的中文文字或横向裁切。

## 日志收集与判读

1. 记录测试开始和结束的本地时间，通过“关于 → 打开日志目录”复制对应日志。
2. 开关应出现 `KARAOKE MODE enabled` / `disabled`。
3. 主动持续尝试应出现 `KARAOKE HOST_OPEN requested`；只有收到 PCM 才会出现 `audio_confirmed`。
4. 当前固件没有 PCM 时应出现 `fallback reason=audio_timeout` 或 `no_audio_before_stop`，随后是 `MIC_CLOSE` / `STREAM STOP`，不能把单独的 `STREAM START` 当成功。
5. 真正返听时 `ATVV AUDIO routed` 的 `route=local_karaoke`、`accepted=true`、样本和批次数必须增长；停止后待播放缓冲最终归零。

## 自动化、代理实测与用户实测边界

- 自动化覆盖：所有默认按键均未绑定卡拉 OK、任意按键手势绑定与持久化、内部动作不重复执行、旧语音键双击识别不存在、物理输出选择、虚拟输出排除、默认关闭、系统暂停关闭，以及模式关闭时稳定虚拟音频代码路径仍存在。
- 代理可完成：Swift 测试、自检脚本、Debug/Release 编译、签名校验、静态页面与离屏截图检查；没有真实 PCM 和声学环境时不能证明延迟、音质、啸叫或固件持续取流。
- 用户或真实桌面必须完成：RC001 / RC003 自定义按键的单击/双击/长按、真实声音输出、耳机/扬声器、第三方语音工具隔离、前后台、权限、锁屏睡眠、断连重连和多遥控器。
- 在真机持续收到主动 `MIC_OPEN` 的 PCM 前，只能把该能力描述为“尝试”；当前固件降级为按住返听属于预期边界，不等于免按键持续卡拉 OK 已通过。
