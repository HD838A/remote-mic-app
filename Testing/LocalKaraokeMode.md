# 本地卡拉 OK 模式测试手册

## 适用版本或分支

- 分支：`codex/local-karaoke-mode`
- 功能状态：已按 RC003 真实按住说话能力改为本地音频路由，尚未完成 RC001 / RC003 完整声学真机验收
- 适用设备：已与 macOS 配对、能在 SayAll 中完成普通语音的 RC001-MS 或 RC003-MS

## 测试前准备

1. 使用与本分支当前源码状态一致的 App，确认“系统设置 → 隐私与安全性 → 蓝牙”已允许 SayAll；验证实体按键绑定时还需允许“输入监控”和“辅助功能”。
2. 先连接耳机。第一次测试在卡拉 OK 独立输出区域选择该耳机，不要直接使用扬声器，避免麦克风与扬声器形成回授啸叫。
3. 在“连接与语音”确认目标遥控器已连接，并先完成一次普通“按住语音键 → 说话 → 松开”的基线。
4. 准备 `MiRemoteV 2ch` 或 `BlackHole 2ch`，并准备豆包、微信输入法、Typeless 或 QuickTime Player 中至少一个真实目标，用于验证普通语音回归和路由隔离。
5. 打开“关于 → 打开日志目录”，记录本轮开始时间。日志不得包含音频正文。

## 用例 1：页面开关与默认关闭

1. 完全退出并重新启动 App，进入“连接与语音”。
2. 确认“本地卡拉 OK”按钮显示“开启返听”。
3. 点击“开启返听”，确认状态提示需要按住遥控器语音键，并确认系统输入法语音识别没有被启动；在不按语音键时对遥控器说话。
4. 点击“关闭返听”。

预期结果：每次启动均默认关闭；开启前成功中和语音键的 Fn / Command 触发，开启后不主动请求遥控器开麦，空闲时没有声音；关闭后恢复用户原来的语音键模式，普通语音仍输出到所选虚拟麦克风。

失败判定：重启后自动开启；开启时唤起系统输入法语音识别；无法中和语音键却仍显示已开启；开启后未按语音键却持续发送开麦、重试或保活命令；关闭后仍有本地声音或没有恢复原语音键模式；普通虚拟麦克风配置被修改。

## 用例 2：默认无绑定与自定义按键手势

1. 对目标遥控器执行“恢复默认”，重启 App；快速双击语音键，确认卡拉 OK 状态不变化。
2. 进入“按键”，选择普通实体键，例如菜单键；把“双击”设为“系统与媒体 → 切换本地卡拉 OK”。
3. 双击已绑定的菜单键开启模式，再次双击关闭。
4. 分别把该动作改绑到另一个键的单击和长按，验证对应手势均能独立开关，未绑定手势保持原动作。
5. 重启 App，确认模式恢复关闭，但用户配置的映射仍保留。

预期结果：任何默认映射都不包含卡拉 OK；只有用户明确选择的普通按键及手势会切换模式。单击、双击、长按和不同遥控器 Profile 分别持久化且互不覆盖，一次手势只切换一次。

失败判定：恢复默认后仍有实体键切换；语音键双击被硬编码；配置一个手势却修改其他手势或设备；一次动作连续切换；重启后映射丢失或模式自动开启。

## 用例 3：真实遥控器音频自动路由

1. 开启本地卡拉 OK，保持 5 秒不按语音键并说话。
2. 按住遥控器语音键说话至少 3 秒，确认耳机出现本地返听。
3. 松开语音键，确认当前返听在缓冲播放结束后停止，页面回到已开启、等待语音键的状态。
4. 重复“按住 → 说话 → 松开”至少 5 次，无需重新开启模式。
5. 在一次语音流进行中关闭卡拉 OK，确认当前流被安全结束；随后按住语音键验证普通语音路径。

预期结果：不按语音键时 RC003 不产生音频，App 也不主动开麦；每次实体语音流开始后，拾取到的 PCM 自动进入物理输出，松开结束本段，模式仍保持开启以等待下一段。关闭后不再本地播放，普通语音恢复到虚拟麦克风。

失败判定：开启模式本身产生空流重试；按住语音键后没有本地声音；松开后播放器持续发声；第二次按住不能自动返听；关闭当前流卡死、重复播放或影响后续普通语音。

## 用例 4：独立输出设备与普通语音隔离

1. 把 SayAll 普通“语音输出”设为 `MiRemoteV 2ch` 或 `BlackHole 2ch`，记录其选择。
2. 在“卡拉 OK 输出设备”选择耳机，开启并按住语音键说话；同时在 QuickTime 新建音频录制中观察普通虚拟麦克风电平。
3. 关闭卡拉 OK，把 macOS 系统声音输出改为另一个物理设备，再开启；确认仍从明确选择的耳机返听。
4. 把卡拉 OK 输出改为“跟随系统声音输出”，再次开启；确认改从当前系统物理输出返听。
5. 重启 App，确认卡拉 OK 仍记住最后的独立输出选择，而普通“语音输出”仍是步骤 1 的设备；再执行一次普通语音输入。

预期结果：卡拉 OK 人声只进入其独立选择的物理输出，不进入虚拟麦克风、不触发 Fn / Command、不产生转写或本地历史；“跟随系统”只跟随物理系统输出。选择卡拉 OK 设备、开关模式及设备回退都不修改普通“语音输出”，关闭后普通语音只走既有虚拟麦克风路径。

失败判定：卡拉 OK 列出或选择虚拟设备；选择卡拉 OK 设备后普通“语音输出”改变；卡拉 OK 同时触发系统输入法或目标语音工具；音频被保存或转写；重启后独立选择丢失；关闭后普通语音无声、重复或改走扬声器。

## 用例 5：耳机、扬声器与输出变化

1. 使用耳机完成用例 4。
2. 降低系统音量后切到内置扬声器，短时间按住语音键测试；出现啸叫立即松开并关闭模式。
3. 卡拉 OK 明确选择 USB 或蓝牙耳机后将其断开，再按住语音键；确认只临时回退到新的系统物理输出，并且保存的独立选择没有被改写。重新连接耳机并刷新设备后，再次开启应恢复使用该耳机。
4. 构造只有虚拟输出可用的环境。

预期结果：始终排除虚拟输出；明确选择的可用设备优先于系统默认，设备暂时缺失时安全回退且不改写选择。物理输出变化不会让声音误入 MiRemoteV / BlackHole；没有物理输出时拒绝开启或安全关闭。

失败判定：设备变化导致崩溃、无穷重连或虚拟输出泄漏；页面显示活动但没有有效物理输出；无法快速停止啸叫。

## 用例 6：蓝牙断连、重连和多遥控器

1. 模式开启且正按住语音键返听时，关闭蓝牙或让目标遥控器断开。
2. 恢复蓝牙并等待同一遥控器重连；再次按住语音键。
3. 两只遥控器环境中，用 A 开启模式，再操作 B 的语音键。

预期结果：断连立即结束当前本地流并显示等待；重连后同一设备保持模式开启，再次按住即可返听，不会主动开麦。B 不会接管 A 的本地路由。

失败判定：断连后继续播放或保留活动状态；自动切换到 B；重连产生重复播放、并发流或主动开麦循环。

## 用例 7：前台、后台、锁屏与睡眠

1. 在 SayAll 前台开启，再切到其他 App；按住语音键确认后台返听，再用已绑定的普通按键关闭。
2. 再次开启，分别测试锁屏、屏幕睡眠、整机睡眠和唤醒。
3. 开启后直接退出 App。

预期结果：普通前后台切换不影响返听和已绑定动作；锁屏、睡眠或退出会关闭模式并结束活动流，唤醒或重启后不会自动恢复。

失败判定：后台映射失效；锁屏或睡眠期间仍收音/播放；唤醒或重启后未经用户操作自动开启。

## 用例 8：系统权限状态

1. 保持蓝牙权限允许，完成页面开关、语音键 Fn / Command 中和和本地返听。
2. 撤销辅助功能和输入监控权限，再验证页面开关和语音键返听；单独记录实体映射手势是否因权限按既有规则被阻止。无论权限状态如何，都确认无法中和语音键时返听会拒绝开启，而不是同时触发输入法。
3. 撤销蓝牙权限后重新启动 App。

预期结果：页面开关及蓝牙音频路由本身不额外索取无关权限；语音键硬件中和成功后才允许开启，实体映射遵守既有 HID/辅助功能权限边界。蓝牙权限缺失时模式不可开启。

失败判定：本地返听强制索取无关权限；权限撤销绕过原有按键安全门；没有蓝牙权限仍显示正在播放。

## 稳定功能回归

- 分别在开关缺失/默认关闭、明确关闭、开启、使用后再关闭四种状态完成 RC003 `STREAM_START → AUDIO → STREAM_STOP`，确认关闭态与正式版虚拟麦克风、Fn 按住和 Fn 点按行为等价。
- 验证手机、Apple Watch、网页版语音继续只走虚拟麦克风，不进入本地卡拉 OK。
- 验证普通语音输出选择与测试音、卡拉 OK 独立输出选择、音频设备刷新、睡眠释放与恢复、双遥控器 Profile、普通按键单击/双击/长按没有相互影响。
- 在 `800 × 650` 窗口逐一点击设置侧边栏入口，并重点检查“连接与语音”：页头、状态、按钮和安全说明可滚动访问，窗口尺寸不变，中英文、浅色和深色无小于 12pt 的中文文字或横向裁切。

## 日志收集与判读

1. 记录测试开始和结束的本地时间，通过“关于 → 打开日志目录”复制对应日志。
2. 开启前应出现 `KARAOKE VOICE KEY neutralized=true`，随后才出现 `KARAOKE MODE enabled ... input=voice_button`；关闭后出现 `disabled`，并由后续 `VOICE FN MAPPING ... neutralized=false` 证明原语音键模式已恢复。
3. 仅开启并空闲时，不应出现 `KARAOKE HOST_OPEN`、卡拉 OK 发出的 `ATVV MIC_OPEN host_request`、`KARAOKE KEEPALIVE` 或循环重试。
4. 按住语音键时应出现实体来源的 `ATVV STREAM START`，随后 `ATVV AUDIO routed ... route=local_karaoke accepted=true`，批次和样本数应增长。
5. 松开后应出现 `ATVV STREAM summary ... route=local_karaoke`，等待缓冲归零；再次按住应产生一条新的完整流。
6. 关闭态的普通语音日志应回到 `route=virtual_audio` 或既有 `fn_tap`，不能继续出现 `local_karaoke`。
7. `scripts/verify-rc003-hold-to-talk.sh` 是历史固件能力判定器：它只读取包含旧主动开麦对照的日志。新版本不再主动开麦，因此对纯新会话返回 `inconclusive` 属于预期，不能据此判定路由失败。

## 自动化、代理实测与用户实测边界

- 自动化覆盖：默认无绑定、任意普通按键手势绑定与持久化、内部动作不重复执行、实体/主机流来源区分、卡拉 OK 独立输出选择与配置导入导出、普通语音输出不变、物理输出回退、虚拟输出排除、语音键硬件中和与关闭恢复接线、默认关闭、系统暂停关闭、稳定虚拟音频路径保留，以及卡拉 OK 状态机不包含主动开麦、保活或能力恢复。
- 日志判定器自动化仍覆盖历史 RC003“主机空流后实体 HTT 有 PCM”、主动主机 PCM、缺少对照、仅实体流、非 RC003、顺序错误和只采用最近会话等边界。
- 代理可完成 Swift 测试、自检、Debug/Release 编译、签名检查和静态界面检查；没有真实遥控器 PCM 和声学环境时，不能证明实际音量、延迟、音质或啸叫表现。
- 用户或真实桌面仍需完成 RC001 / RC003 的自定义按键单击/双击/长按、卡拉 OK 开启时输入法不被触发及关闭后原语音键恢复、连续多次语音键返听、独立耳机/扬声器/外接声卡选择与拔插回退、第三方语音工具隔离、前后台、权限、锁屏睡眠、断连重连和多遥控器。
