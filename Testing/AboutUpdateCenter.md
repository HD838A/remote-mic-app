# 设置页版本中心与跨版本更新测试手册

## 适用范围

- 适用版本：macOS `1.9.21` Pre-release 及后续版本
- 测试目标：验证设置页版本中心、App 图标切换、正式/预发布更新通道、通用硬件公告、本地化更新内容和跨版本 Sparkle 安装。

## 测试前准备

1. 使用已签名、公证并从最终 Sparkle ZIP 解压的 `1.9.21` App 检查界面。
2. 跨版本用例准备当前稳定版 `1.9.18` 和上一预览版 `1.9.20`，且每次放在独立可写目录，避免相互覆盖测试状态。
3. 退出其他 `com.hd838a.RemoteMic` 进程；不要清空用户偏好来改变测试结果。
4. App 内置 stable feed 为 `https://download.sayall.app/mac/channels/stable/appcast.xml`；开启预发布检查后同时解析同架构 stable 与 preview 通道并选择语义版本更高者。真实 UI 候选验收仍只通过本地 `127.0.0.1` feed 注入固定候选字节。UI 测试输出目录必须位于持久目录，不能位于 Git worktree、`/tmp`、`/private/tmp` 或 `$TMPDIR`；完成 Sparkle 首次启动、退出、二次启动和 attestation 前不得清理。

## 用例 1：设置页结构与最小窗口

1. 在真实生产窗口最小尺寸 `1020 × 772` 依次点击连接、按键、统计、设置；另使用截图 harness 在 `800 × 650` 做窄宽压力渲染，不把该尺寸表述为真实窗口验收。
2. 在设置页检查顶部品牌与更新双栏、权限与隐私、通用、诊断与日志、支持区域。
3. 确认设置页末尾和侧边栏均没有分享入口；打开个人中心，在顶部展开/收起二维码。
4. 分别切换跟随系统、简体中文和 English。

预期结果：侧边栏不再显示独立的“权限”入口，页头显示“设置”；内容左右边距为 28pt；顶部不显示“应用与更新”标题，左栏使用放大的 App Logo，并在 Logo 下方完整显示名称和一句话介绍；右栏显示当前版本，唯一的“检查更新”按钮与预发布开关位于同一行，检测到更新时继续显示待更新版本和 Release Notes；内容随后按“权限与隐私 → 通用 → 诊断与日志 → 支持”排列，分享模块已迁至个人中心顶部，设置页和侧边栏不重复提供入口；窗口尺寸不跳变；设置页不显示术语表或退出按钮；三个语言选项始终同时显示，没有下拉框或横向裁切；中文最终字号不小于 12pt。

失败判定：任一入口无法点击、页面或版本内容被裁切、窗口自动改变大小、语言被折叠、出现术语表入口，或控制项与红黄绿按钮重叠。

## 用例 1A：App 图标选择与资源缺失回退

资源基线：`faceted-duck.png` 为 Apple Silicon 与 Intel 共用的 `1024 × 1024` RGBA PNG，SHA-256 `569101880e6c10654fdc9eec208cd104a3f5eefb9ae32d8a3fe981620a84da5a`。构建和验证不得缩放、重新压缩或改写该文件，四角必须保持透明。

1. 在设置页打开“通用 → 应用图标”，检查两个只显示图形、不显示名称文字的选项；使用旁白时应分别读出“经典鸭”和“几何鸭”。
2. 分别构建 Apple Silicon 与 Intel 版本；两种架构都应加载 `Resources/AppIcons/faceted-duck.png`，并在设置中使用同一个稳定标识 `faceted-duck`。
3. 每次选择后检查 Dock、Command-Tab 应用切换器、设置页顶部和侧边栏顶部品牌图标，再退出并重新启动 App。
4. 使用隔离偏好首次启动，确认默认选择 v2“几何鸭”。保存“经典鸭”后重启，确认保留选择。
5. 保存不存在的图标标识后启动，确认回退 v2；移除 v2 资源后启动，确认回退可用的“经典鸭”。
6. 按构建架构检查安装包内 App 的 `AppIcon.icns` 与对应仓库文件逐字节一致；确认包内没有 `Assets.car`、`AppIcon.icon` 或 `CFBundleIconName`；退出 App 后检查 Finder 和 Launchpad，确认默认主图标为 v2，图标不显示通用文件图标或蓝色系统材质。

7. 打开任意原生确认弹窗，例如退出回眸记录或检查更新。浅色和深色下，弹窗使用当前运行时圆角 Logo；切换到另一个图标后再次打开弹窗，弹窗使用新图标。
8. 检查静态 App 包的 Finder 图标。Apple Silicon 保留原静态兼容资源；Intel 候选 ICNS 从公开圆角 PNG 生成。两者都不得出现白色底板或通用文件图标。
9. 在 Intel Mac 上打开生产窗口，点击黄色最小化按钮。分别查看 Dock 左侧应用图标和右侧窗口缩略图的小 Logo。恢复、关闭重开、退出重启后重复检查，并记录 macOS 版本、App Build、候选源码 SHA 和截图。两个位置都必须保留圆角；窗口状态和导航不得改变。

预期结果：页面使用紧凑的页面内图标按钮，不显示“经典鸭”“几何鸭”等可见名称，也不使用下拉框、Popover 或 Sheet；两个选项均显示真实图像并保留无障碍名称，点击后立即更新 Dock、应用切换器和设置页顶部图标，重启后保持选择；Apple Silicon 静态资源保留原字节，Intel 静态资源使用公开透明圆角 Logo；两架构运行时 PNG 使用同一份公开原始字节，并增加一致的透明安全边距；没有保存选择时默认使用 v2；明确保存的旧版选择继续保留；保存标识指向缺失资源时优先回退 v2，v2 缺失时回退经典鸭，App 正常启动。Finder、Launchpad 和 App 包文件默认显示无白色系统底板的 v2 主图标，不把运行时切换误报为修改安装包。

失败判定：出现空白图标、低分辨率缩放或透明边缘异常；选择后 Dock、应用切换器、设置页或侧边栏顶部仍显示旧图标；重启后丢失选择；资源缺失导致崩溃、不可见选项被选中，或运行时修改 App 包文件。

2026-10-13 候选边界：用户在 2.0.0 build 248 确认 Dock 右侧窗口缩略图的小 Logo 仍为方形。资源检查证明旧 Intel ICNS 的四角不透明；当前候选改为透明圆角。原始 Intel 用例、覆盖安装缓存和白底回归尚未验收，不能用构建或应用图标重应用日志代替现场结果。已核对固定私有组件的 `MembershipAppIcon`：正常路径读取宿主当前图标，缺图时保留私有 PNG 回退。用户于 2026-10-13 要求先合入，再自行打包安排 Intel 验收；此安排不改变用例的通过标准。

2026-10-04 验证：图标、打包及设置页相关 85 项自动化测试通过，48 项 Self Test 通过。Apple Silicon Release App 构建和 `scripts/verify-app.sh` 通过，十档 ICNS 图层的透明通道、透明四角及打包图标字节一致性通过。

生产设置视图使用隔离偏好，在 `1020 × 772` 下完成中英文、浅色/深色共 4 张离屏截图。默认 v2 选中态、设置页和个人中心图标已逐张检查。截图为 `2040 × 1544` PNG，保存在 [截图目录](历史截图证据已按仓库清理规则移出)；该结果不替代 Intel Ventura、Finder/Launchpad 缓存、Dock、应用切换器和真实退出重启验收。本轮未生成或发布 Developer ID 公证安装包。

## 用例 1B：固定侧边栏品牌与个人中心图标

1. 在生产最小窗口 `1020 × 772` 打开按键页。侧边栏宽度按当前语言最宽一行测量（区间 `104–136pt`，中英文都约 `129pt`），文字到左缘和右缘均为 `15pt`；顶部 `44 × 44pt` Logo 在左，`16pt` Oxanium SemiBold 600 的 `SayAll` 及紧凑版本行在右。Logo 距窗口控制区下沿 `16pt`，不与原生窗口按钮重叠。
2. 依次点击全部可见导航入口，包括连接、回眸、设置和个人中心；在页面中滚动，确认顶部品牌区和底部个人中心保持固定。安装包包含较多可选功能时，滚动侧边栏中间导航区并点击全部入口。
3. 确认侧边栏没有独立分享按钮；最后一项个人中心保留原有账号名或“我的”，图标为 `person.crop.circle` 系统个人账户图标。
4. 在设置页切换“经典鸭”和“几何鸭”，确认顶部 Logo 立即同步，底部个人账户图标保持不变；切换页面、退出并重启后仍显示所选图标。资源缺失回退按用例 1A 执行。
5. 分别检查中文、English、浅色和深色；检查红黄绿按钮、顶栏拖动区域、导航选择态、中文字号和窗口尺寸。
6. 在包含键位方案的构建中检查完整 `Button Profiles` 分两行显示；图标与整个文字块垂直居中。用两行、三行和无空格长用户名检查底部账户区：文字完整、按宽度换行，人物图标与文字块居中，区域按需增高。

预期结果：顶部 Logo、品牌与版本号不随所选页面或滚动变化；侧边栏和设置页的 `SayAll` 均使用 Oxanium SemiBold 600，版本和导航仍使用系统字体；版本取自安装包 `CFBundleShortVersionString`，与设置页当前版本一致；分享只在个人中心顶部显示；顶部 Logo 使用与设置页同一图标选择及回退规则，个人中心保持系统个人账户图标，登录状态只影响原有文字；导航图标为 `18pt`，文字为 `13pt`，水平间距 `8pt`，图标左缘为 `15pt`；导航行最小高 `44pt`，账户区最小高 `56pt`，多行时随内容增高。文字左对齐，保留完整名称，不缩小字体、不省略用户名，也不按每 8 个字符插入换行。选中项为圆角淡强调色底，更新圆点在设置行右侧。中间导航空间不足时可纵向滚动，所有入口可访问，顶部品牌区和底部入口不被挤出窗口。

失败判定：品牌只在某一页出现、顶部 Logo 缺失或未同步、品牌字体未生效、版本固定为设计稿示例、侧边栏残留分享按钮、个人中心仍显示 App Logo 或不可点击、账号文字丢失、导航入口无法到达、控件与窗口按钮重叠、窗口几何改变，或中文小于 12pt。

离屏验证：使用生产 App 的 `REMOTE_MIC_SETTINGS_SCREENSHOT_DIR` 入口，并分别设置 `REMOTE_MIC_SETTINGS_SCREENSHOT_APP_ICON=standard`、`faceted-duck` 和不存在的标识；隔离的截图偏好、空历史及空授权目录不会改写用户配置或读取本机录音、转写记录和 Agent 授权。该入口证明生产视图的静态图标、回退与布局，实时切换、导航、个人中心分享与重启仍按上述真实窗口步骤验收。

多入口与换行压力夹具：设置 `REMOTE_MIC_SETTINGS_SCREENSHOT_SIDEBAR_FIXTURE=1`，生产 `SettingsView` 使用合成扩展页元数据和虚构账号，不读取真实会话；`long` 模式使用三行英文名。四种语言/外观组合均需检查。夹具只验证公开宿主的实际导航布局，不证明私有页面内容、权益或真实账号登录。审核设计见[存档第八版 HTML](../Screenshots/design-drafts/sidebar-compact/v8/review.html)。

本次是同步布局变更，无新增请求、取消、超时或重试分支；沿用既有导航与账户状态链路，不为排版写入用户名或高频日志。日志收集方法见 [RuntimeLogging.md](RuntimeLogging.md)。

## 用例 2：无更新与更新信息不可用

1. 使用与当前 feed 相同或更高 Build 的 App 打开设置页。
2. 等待自动信息检查结束，再点击“检查更新”。
3. 在隔离网络环境或 Cloudflare stable、preview 任一通道暂时不可用时开启预发布检查。

预期结果：正式版打开应用或设置页时可以自动检查，预览版启动、定时刷新和其他后台路径均不启动 Sparkle 自动检查；预览版只有在设置页主动点击“检查更新”后才显示候选信息。没有更高版本时，Release Notes 和“更新到”按钮消失，原位置仅显示紧凑的“已是最新版本”状态，后续内容自然上移且不保留大片空白；两个通道都不可用时显示更新信息不可用且不弹额外错误提示；只有一个通道可用时继续检查该通道，但绝不把低于当前版本的项目显示为更新。

失败判定：预览版在启动或后台定时路径弹出更新 UI、预览版进入设置页时自动联网检查、把“没有更新”显示为错误、弹出候选源失败提示、保留上一个通道的旧版本号、显示低于当前版本的“最新版本”，或稳定更新检查被阻止。

## 用例 3：发现更新与本地化说明

1. 使用低 Build 版本检查固定 `v1.9.21` appcast。
2. 在中文界面查看设置页版本中心，再切换 English。
3. 点击“更新到 1.9.21”，观察 Sparkle 标准更新界面。

预期结果：页面显示当前版本、最新版本 `1.9.21` 和对应语言更新内容；待更新版本的 Release Notes 位于版本检查区域右侧，并随语言切换；更新按钮进入标准下载与安装流程。更新说明资产无法下载时仅显示说明不可用，更新按钮仍可使用。

失败判定：显示语义 key、语言不切换、读取错误版本的说明、更新按钮无响应，或说明加载失败阻断更新。

## 用例 4：设置入口新版本红点

1. 使用低于固定候选版本的 App 打开主设置窗口，但先停留在“按键”等其他页面。
2. 等待后台更新检查发现候选版本，观察侧边栏“设置”齿轮图标。
3. 点击“设置”，再切换到其他页面，观察齿轮图标。
4. 退出并重新启动 App，让更新检查再次发现同一个候选版本。
5. 把固定候选替换为更高版本并再次检查。

预期结果：首次发现候选版本后，设置齿轮右上角显示不遮挡图标的红点；点击“设置”后红点立即消失；同一候选版本在重新启动后保持已读，不重复显示；检测到更高版本时红点重新出现。旁白会把红点读作“有新版本可用”。

失败判定：无更新时出现红点、红点出现在其他侧边栏入口、点击设置后不消失、同一候选每次启动都重复出现、较新候选不再提醒，或红点遮挡齿轮/改变侧边栏布局。

## 用例 5：正式与预发布通道切换

1. 在低于最新正式版的 App 中关闭预发布检查并点击“检查更新”。
2. 开启预发布检查，再点击“检查更新”。
3. 再关闭预发布检查并点击“检查更新”。

预期结果：关闭时只访问同架构 stable 通道；开启时同时解析同架构 stable 与 preview 通道，并选择语义版本更高者交给 Sparkle；再次关闭后立即清除候选结果并恢复仅检查 stable，不需要重启 App。stable 为 `1.9.21`、preview 为 `1.9.20` 时必须选择正式版 `1.9.21`；stable 为 `1.9.18`、preview 为 `1.9.21` 时必须选择预发布版 `1.9.21`。

失败判定：通道切换后仍保留旧版本或旧更新内容、开启预发布后漏掉版本更高的正式版、正式更新查不到、显示低于当前版本的更新，或两个通道都不可用时仍显示旧结果。

## 用例 6：跨版本真实更新

分别执行：

- `1.9.20 → 1.9.21`：上一预览版到新候选版本。
- `1.9.18 → 1.9.21`：当前正式版到候选版本。

每次使用 Sparkle 官方 CLI，仅为当次调用传入固定候选 appcast，不修改 App 偏好。完成安装后检查：

- App 版本为 `1.9.21` 且 Build 高于 `173`。
- App 能正常启动、退出并第二次启动。
- 主窗口和更新完成提示位于前台。
- 签名、公证票据、Sparkle Framework 符号链接与五个 helper 的 `0755` 权限正确。
- 没有新增 Remote Mic `.ips` 或 `.crash`。

失败判定：下载、授权、替换或重启任一步失败；安装后版本不正确；helper 失去执行权限；第二次启动退出；出现新崩溃报告。

## 用例 7：新硬件支持公告与手动 PKG

1. 复制 `Announcements/hardware.example.json`，把示例版本替换为已实际发布且可下载的独立安装 PKG，再通过
   `REMOTE_MIC_UI_TEST_MODE=1` 与
   `REMOTE_MIC_UI_TEST_HARDWARE_ANNOUNCEMENTS_URL=http://127.0.0.1:<端口>/hardware.json`
   注入本地测试源。
2. 以 `1020 × 772` 打开设置页，分别切换简体中文和 English。
3. 点击公告中的“下载安装包”/“Download Installer”。
4. 分别测试已过期公告、返回 404 的公告源和超时源。

预期结果：公告卡片显示本地化标题和说明，按钮使用公告返回的直接 PKG URL 打开默认浏览器；过期公告不显示；公告源失败时设置页、Sparkle 检查和 App 启动均不受阻。正式公告源只接受 `download.sayall.app` 或 GitHub Raw 的 HTTPS 地址；本地 HTTP 仅限 UI 测试模式。

失败判定：公告网络请求阻塞 App 启动或 Sparkle、显示过期内容、按钮打开的 URL 与响应不一致、语言切换后文本不更新，或最小窗口出现裁切。

- [ ] 菜单栏“检查更新”和设置页检查使用同一 Sparkle updater。
- [ ] 配置导入导出、Dock 图标与启动窗口开关保持原功能。
- [ ] App 图标只展示安装包内真实可用选项，切换、重启恢复和资源缺失回退均通过。

## 日志收集

1. 在设置页打开日志目录，收集本次启动对应的 `.rmlog` 加密会话文件并交给受控支持环境分析，完整方法见 [运行日志测试手册](RuntimeLogging.md)；不要按明文读取或要求 App 解密。支持人员重点检查 `UPDATE CHECK`、`source=cloudflare_channel`、`HARDWARE ANNOUNCEMENT` 与 `APP_ICON CHANGE`；图标日志只包含已注册的可用稳定标识或固定 `unavailable`、阶段、结果与稳定原因码，不记录未知导入标识。缺失构建公钥时日志闭锁，不回退明文。
2. Console：按进程筛选 `RemoteMic`、`Autoupdate`、`Updater` 和 `Installer`。
3. 崩溃报告：`~/Library/Logs/DiagnosticReports/` 中本次测试时间之后的 Remote Mic 报告。
4. Sparkle CLI 使用 `--verbose` 保存完整输出；退出码 `4` 表示没有新版本，不判失败。

## 自动化、代理实测与用户实测边界

自动化可以验证更新策略、stable/preview 与 Apple Silicon/Intel 通道派生、非法 feed 拒绝、更新说明 URL、语言状态、发布脚本和产物结构；本机代理可以验证最终打包 App 的启动、页面截图、固定 appcast 跨版本安装、签名和公证。Cloudflare 通道只能由生产部署后的 HTTP 与字节比较证明；预览版主动检查和正式版自动提示仍需在最终签名安装包中进行真实 UI 验收。

公告自动化只能验证 JSON 解码、过期过滤、受信任来源和链接传递；无法替代真实后端/CDN 可用性、默认浏览器下载、PKG 签名/公证或用户在升级后重新启动 App 的验收。

App 图标自动化可以验证任意数量选项的过滤、缺失资源回退、稳定标识持久化、设置页结构以及构建脚本按目录打包图标；新增图标的清晰度、透明边缘、Dock 与 Command-Tab 实际刷新、重启后的视觉结果仍需在用户提供最终原始资产后使用真实生产 App 人工验收。
