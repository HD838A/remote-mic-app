# 关于页版本中心与跨版本更新测试手册

## 适用范围

- 分支：`codex/about-update-center-1.8.6`
- 目标版本：macOS `1.8.6 (67)` Pre-release
- 测试目标：验证关于页版本中心、正式/预发布更新通道、本地化更新内容和跨版本 Sparkle 安装。

## 测试前准备

1. 使用已签名、公证并从最终 Sparkle ZIP 解压的 `1.8.6` App 检查界面。
2. 跨版本用例分别准备已发布的 `1.7.8`、`1.8.3` 和 `1.8.5` App，且每次放在独立可写目录，避免相互覆盖测试状态。
3. 退出其他 `com.hd838a.RemoteMic` 进程；不要清空用户偏好来改变测试结果。
4. 正式源使用 App 内置 `SUFeedURL`；候选测试只对当次 Sparkle CLI 调用覆盖固定 `v1.8.6/appcast.xml`。

## 用例 1：关于页结构与最小窗口

1. 以 `1020 × 772` 打开设置窗口，依次点击连接、按键、统计、权限、关于。
2. 在关于页检查官网、GitHub、版本与更新、配置、Dock、启动窗口和语言区域。
3. 分别切换跟随系统、简体中文和 English。

预期结果：所有侧边栏入口、页头和主要控件均可见；窗口尺寸不跳变；关于页不显示术语表或退出按钮；三个语言选项始终同时显示，没有下拉框、裁切或滚动条；中文最终字号不小于 12pt。

失败判定：任一入口无法点击、页面或版本内容被裁切、窗口自动改变大小、语言被折叠、出现术语表入口，或控制项与红黄绿按钮重叠。

## 用例 2：无更新与更新信息不可用

1. 使用与当前 feed 相同或更高 Build 的 App 打开关于页。
2. 等待自动信息检查结束，再点击“重新检查”。
3. 在隔离网络环境或候选 API 暂时不可用时开启预发布检查。

预期结果：没有更高版本时显示“已是最新版本”；退出码 `4` 或候选源不存在不显示错误弹窗；候选解析失败时页面仍通过稳定源完成检查，已安装版本不受影响。

失败判定：把“没有更新”显示为错误、弹出候选源失败提示、保留上一个通道的旧版本号，或稳定更新检查被阻止。

## 用例 3：发现更新与本地化说明

1. 使用低 Build 版本检查固定 `v1.8.6` appcast。
2. 在中文界面查看版本中心，再切换 English。
3. 点击“更新到 1.8.6”，观察 Sparkle 标准更新界面。

预期结果：页面显示当前版本、最新版本 `1.8.6` 和对应语言更新内容；语言切换后说明随之切换；更新按钮进入标准下载与安装流程。更新说明资产无法下载时仅显示说明不可用，更新按钮仍可使用。

失败判定：显示语义 key、语言不切换、读取错误版本的说明、更新按钮无响应，或说明加载失败阻断更新。

## 用例 4：正式与预发布通道切换

1. 在低于最新正式版的 App 中关闭预发布检查并重新检查。
2. 开启预发布检查，等待结果刷新。
3. 再关闭预发布检查并重新检查。

预期结果：关闭时只显示稳定 feed 的最高版本；开启时显示最新非草稿 Release 的候选版本；再次关闭后立即清除候选结果并恢复稳定结果，不需要重启 App。

失败判定：通道切换后仍保留旧版本或旧更新内容、正式更新查不到，或者预发布源失败时没有回退稳定源。

## 用例 5：跨版本真实更新

分别执行：

- `1.8.3 → 1.8.6`：正式版到候选版本。
- `1.7.8 → 1.8.6`：跨多个中间版本。

每次使用 Sparkle 官方 CLI，仅为当次调用传入固定候选 appcast，不修改 App 偏好。完成安装后检查：

- App 版本为 `1.8.6 (67)`。
- App 能正常启动、退出并第二次启动。
- 主窗口和更新完成提示位于前台。
- 签名、公证票据、Sparkle Framework 符号链接与五个 helper 的 `0755` 权限正确。
- 没有新增 Remote Mic `.ips` 或 `.crash`。

失败判定：下载、授权、替换或重启任一步失败；安装后版本不正确；helper 失去执行权限；第二次启动退出；出现新崩溃报告。

## 稳定功能回归

- [ ] 默认关闭预发布检查时，行为与上一正式版一致。
- [ ] 预发布开关缺失/默认、明确关闭、开启、使用后再关闭四种状态均通过。
- [ ] 菜单栏“检查更新”和关于页检查使用同一 Sparkle updater。
- [ ] 配置导入导出、Dock 图标与启动窗口开关保持原功能。
- [ ] 版本历史 Sheet 能打开并显示当前语言内容。
- [ ] 连接、按键、统计和权限页面在最小窗口下无回归。

## 日志收集

1. App 日志：`~/Library/Logs/RemoteMic/runtime.log`，重点搜索 `UPDATE FEED` 与 `UPDATE CHECK`。
2. Console：按进程筛选 `RemoteMic`、`Autoupdate`、`Updater` 和 `Installer`。
3. 崩溃报告：`~/Library/Logs/DiagnosticReports/` 中本次测试时间之后的 Remote Mic 报告。
4. Sparkle CLI 使用 `--verbose` 保存完整输出；退出码 `4` 表示没有新版本，不判失败。

## 自动化、代理实测与用户实测边界

自动化可以验证版本比较、feed 解析、更新说明 URL、语言状态、脚本和产物结构；本机代理可以验证最终打包 App 的启动、页面截图、固定 appcast 跨版本安装、签名和公证。真实用户机器上的权限授权、网络环境和更新后的日常使用仍属于用户实测边界，不得由单元测试替代。
