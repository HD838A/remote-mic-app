# 自定义 APP 打开与输入框聚焦测试手册

## 适用范围

- 适用版本：macOS Preview `1.8.6 (67)` 及包含同一修复的后续版本
- 功能分支：`codex/shortcut-capture-conflicts`
- 功能状态：第一阶段开发验证中
- 测试目标：验证遥控器普通按键可以打开任意 macOS `.app`，并按配置只激活 APP、发送聚焦快捷键，或聚焦用户记录的 Accessibility 输入框。
- 本手册不把单元测试、构建成功或系统自带 APP 测试等同于第三方 APP 验收。

## 测试前准备

1. 退出已经安装的其他 Remote Mic 版本，运行本次提供的测试包。
2. 在“系统设置 → 隐私与安全性”中确认 Remote Mic 已获得：
   - 辅助功能权限。
   - 输入监控权限。
3. 打开 Remote Mic 的“按键映射”页面，并开启“自定义按键映射”。
4. 准备一个不会影响日常工作的普通按键。建议先使用“主页键双击”，避免覆盖当前单击动作。
5. 第一轮使用 TextEdit 验证通用流程；第二轮至少选择一个实际需要使用的第三方 APP，例如 Codex、Claude、cmux 或 Proma。

如果覆盖 `.app` 后系统权限记录发生变化，请先重新确认权限，再开始测试，不要把权限问题误报为聚焦算法问题。

## 用例 1：选择并打开任意 APP

1. 在测试按键的“双击”动作中选择“打开自定义 APP”。
2. 页面应自动滚动到同页编辑区；确认动作按“基础按键 / 系统与媒体 / 自定义动作 / 打开具体 APP”分组铺开，没有长下拉列表或按键编辑弹窗。
3. 点击“添加 APP”，选择 `/System/Applications/TextEdit.app`。
4. 在同一编辑区将“聚焦方式”设为“只打开 APP”。
5. 彻底退出 TextEdit，按下映射按键两次。

预期结果：

- TextEdit 被启动并切到前台。
- 不出现系统错误提示音。
- 不创建多个 TextEdit 进程。
- Remote Mic 的 HID 监控继续工作。

继续验证：

- TextEdit 已经运行但位于后台时，双击按键应切回 TextEdit。
- TextEdit 已经在前台时，双击按键不应创建额外窗口或重复实例。

失败判定：APP 没有打开、没有切到前台、出现重复实例、按键后监控停止，或系统错误提示音持续出现。

## 用例 2：使用 APP 自带快捷键聚焦

只有在目标 APP 确实提供“聚焦输入框”快捷键时测试此策略。

1. 为目标 APP 查明并人工验证其聚焦输入框快捷键。
2. 将“聚焦方式”设为“使用 APP 快捷键聚焦”。
3. 未点击录入前，当前值应显示“尚未录入”而不是“等待按键”，页面不能表现为已经进入输入状态。
4. 点击“录入快捷键”后，原位置应切换为醒目的录入入口；按下该快捷键后立即显示“快捷键录入成功”，不出现额外 Sheet。
5. 在目标 APP 中点击侧边栏、工具栏或其他控件，让输入框失去焦点。
6. 切到其他 APP 后触发映射按键。
7. 目标 APP 已在前台时，再次把焦点移到侧边栏并触发映射按键。

预期结果：两种情况下目标 APP 都切到或保持前台，光标最终出现在输入框中，可以立即输入文字。

失败判定：APP 被激活但输入框没有焦点、快捷键发送到错误 APP、出现额外窗口，或只有从后台切入时有效而前台场景无效。

## 用例 2A：录入已被系统或其他 APP 占用的快捷键

1. 确认“系统设置 → 键盘 → 键盘快捷键 → Spotlight”中的 `Command + Space` 保持启用，不要临时关闭它。
2. 在任意普通按键的“自定义快捷键”编辑区，确认初始页面只显示当前值和“录入快捷键”按钮。
3. 不点击录入，直接按 `Command + Space`。
4. 返回无线麦，再点击“录入快捷键”；看到录入入口后按 `Command + Space`。
5. 确认页面显示 `⌘空格` 和“快捷键录入成功”。
6. 关闭动作编辑区后重新打开，确认 `⌘空格` 仍然存在。
7. 使用真实遥控器触发该动作。

预期结果：

- 第 3 步保持普通系统行为，证明无线麦没有常驻拦截键盘。
- 第 4 步录入期间 Spotlight 不弹出，系统或其他 APP 的原动作不执行。
- 第 5～6 步显示并保存正确组合键。
- 第 7 步由现有快捷键执行路径正常唤起 Spotlight。

失败判定：未点击录入时无线麦拦截快捷键；点击录入后 Spotlight 抢先弹出；页面一直停留在录入状态；没有成功提示；保存后组合键丢失；或遥控器执行时没有触发原系统快捷键。

## 用例 3：记录 Accessibility 输入框并自动聚焦

1. 将“聚焦方式”设为“聚焦已记录的输入框”。
2. 阅读页面内说明，点击“开始学习输入框”；目标 APP 应直接打开，不出现开始确认弹窗。
3. 在三秒内点击 TextEdit 正文编辑区；返回 Remote Mic 后应在原编辑区看到成功或失败状态，不出现结果弹窗。
4. 点击“测试打开与聚焦”。
5. 在 TextEdit 中点击字体大小、工具栏或其他控件，让正文编辑区失去焦点。
6. TextEdit 位于前台时再次执行“测试打开与聚焦”。
7. 切到其他 APP，再通过真实遥控器触发映射动作。
8. 退出并重新打开 Remote Mic，重复第 5～7 步。

预期结果：

- 记录过程不读取或保存输入框中的文字。
- 无论目标 APP 未运行、位于后台还是已经在前台，最终焦点都回到已记录的正文输入区。
- Remote Mic 重启后记录仍然有效。
- 聚焦失败时只记录日志，不停止 HID 监控，也不把它显示成辅助功能权限失效。

失败判定：焦点停留在侧边栏、搜索框、工具栏或其他输入框；重启后配置丢失；APP 已在前台时失效；或者失败后其他按键不再响应。

## 用例 4：实际第三方 APP 验收

对 Codex、Claude、cmux、Proma 等每个实际使用的 APP 分别执行一次，不能用 TextEdit 结果代替。

每个 APP 至少覆盖：

- [ ] APP 未运行时可以启动并聚焦。
- [ ] APP 位于后台时可以激活并聚焦。
- [ ] APP 已在前台、焦点位于左侧边栏时可以重新聚焦输入框。
- [ ] APP 已在前台、焦点位于顶部工具栏或其他文本框时可以重新聚焦输入框。
- [ ] Remote Mic 重启后配置仍然有效。
- [ ] 目标 APP 重启后配置仍然有效。

如果目标 APP 更新后 Accessibility 结构改变，应重新记录输入框。重新记录前不能把旧记录偶然聚焦到其他控件视为成功。

## 用例 5：单击、双击、长按与多遥控器

- [ ] 单击绑定只触发一次。
- [ ] 双击绑定不会同时执行单击动作。
- [ ] 长按绑定只启动或激活一次，不会因物理按键重复而连续发起启动请求。
- [ ] 两个遥控器可以保存不同的 APP 动作引用，切换遥控器后不会串用按键映射。
- [ ] 手机遥控器和网页遥控器能够显示所选自定义 APP 的名称并执行对应动作。

## 用例 6：安全和异常情况

1. 尝试记录密码框、Token 输入框、搜索框或设置页面输入框。
2. 配置完成后移动或卸载目标 APP，再触发动作。
3. 临时关闭辅助功能权限后测试“聚焦”策略。
4. 导出配置，在另一份干净配置中重新导入。

预期结果：

- 危险输入框应被拒绝记录，不能因为屏幕位置相似而被选中。
- APP 缺失、Profile 缺失或聚焦失败只写日志，不停止 HID 监控。
- 导入后 APP Profile、单击/双击/长按引用和聚焦策略保持一致。
- 旧版配置仍可以导入，原有按键 raw value 不受影响。

## 稳定功能回归

- [x] 遥控器语音键仍能正常触发既有语音流程。
- [x] 方向键、返回键、菜单键和音量键的原有动作正常。
- [ ] 无线麦在后台、其他 APP 的输入框获得焦点时，按住遥控器左/右键至少 2 秒，文本光标应通过系统原生连发持续移动；单击仍只移动一次。monitored/seized、非匹配动作和无线麦前台边界已通过硬件模拟，实体遥控器仍待验收。
- [x] 预置 APP 动作仍能打开 Codex、Claude、cmux 等已安装 APP。
- [x] 自定义键盘快捷键仍能录入、保存和执行。
- [ ] 已启用 Spotlight 的情况下可以直接录入 Command-Space，录入期间 Spotlight 不弹出，保存后真实遥控器可以正常唤起 Spotlight。
- [x] 自定义快捷键切换到其他动作、禁用动作后，再切回“自定义快捷键”仍显示并执行原快捷键；重启 APP 后仍保留，只有“恢复默认”才清除。
- [x] 同一按键触发方式在“自定义快捷键”和“打开自定义 APP”之间切换时，同时保留已录入快捷键、已选 APP、聚焦策略和已学习输入框；当前动作只决定哪一项启用，导出导入后所有保留配置仍可切回使用。
- [x] 基础按键中的 Command-Return、Shift-Return、Command-C、Command-V、Command-Q 均只执行一次，不因按住遥控器而重复。
- [x] 系统与媒体中的“上一首（⌘←）”和“下一首（⌘→）”均只执行一次。
- [x] “禁用按键”只显示在动作编辑标题栏、位于关闭按钮左侧；开启后当前触发不执行动作，关闭后恢复为 Escape，动作网格中不再出现“禁用”。
- [x] 按键映射页面在 `800 × 650` 窗口下没有裁切、错位或异常改变窗口大小。
- [x] 按键映射卡片、动作按钮、帮助文字和状态文字的中文显示字号均不小于 12pt。
- [x] 点击单击、双击或长按后在同一页面完成动作选择和附加配置，不出现按键编辑 Popover、快捷键 Sheet 或输入框学习 Alert。
- [x] 切换所有侧边栏页面后，页面内容和导航状态正常。
- [x] 同时连接两只尚未绑定 HID 指纹的遥控器，选择其中任意一只后分别执行菜单键单击和双击；两种动作都进入日志且执行，系统先枚举另一只设备不能导致当前遥控器无响应。

## 发现问题时需要提供的信息

1. 目标 APP 名称、版本号和 Bundle ID。
2. 使用的聚焦方式。
3. 失败时 APP 是未运行、后台还是已经在前台。
4. 触发前光标或焦点所在位置，例如“左侧边栏”。
5. 实际结果和预期结果。
6. 问题发生的大致时间。
7. 日志片段：右键菜单栏图标选择“显示日志”，或提供：
   `~/Library/Logs/RemoteMic/runtime.log`

日志中重点查找 `APP ACTION` 和 `APP FOCUS`。日志显示 `opened` 只代表 APP 启动或激活成功，不代表输入框已经真正聚焦；只有实际看到光标进入目标输入框才算通过。

## 当前验证边界

- 自动化测试覆盖动作持久化、旧配置兼容、APP 启动调用、聚焦策略路由、候选匹配和危险输入框拒绝。
- 自动化测试覆盖系统占用组合键所需的事件捕获与阻止传播、单次完成、自动重复和合成事件过滤，以及权限失败提示；它不能替代真实 Spotlight 和真实遥控器验收。
- 硬件模拟已覆盖 HID 独占成功与 monitored fallback：匹配的左右方向键在其他 APP 前台走系统原生事件，非匹配动作继续由 App 连发，无线麦前台继续抑制方向连发；模拟不能替代 WindowServer 与实体遥控器自动连发验收。
- 本轮尝试进行本机 GUI 验收时桌面会话处于锁定状态，无法操作设置页，因此“Command-Space 录入”和成功反馈仍保留为待人工验收，不能标记通过。
- TextEdit 已完成 APP 选择、只打开 APP 和目标输入框记录操作。
- 本次本机 UI 回归已确认动作编辑区默认保持紧凑，“打开具体 APP”可按需展开，禁用 Switch 与新增固定组合键均可见且无文字截断。
- 用户已完成本轮自定义快捷键、自定义 APP、输入框学习、配置保留、页面布局和双遥控器按键路线的真机验收，并确认全部通过。
- 目标 APP 后续升级如果改变 Accessibility 结构，可能需要重新学习输入框；这是配置失效边界，不影响已验证的当前版本行为。
