# 已连接遥控器设备卡测试手册

- 适用版本/分支：当前待验证 PR 或已合入 `main` 的精确 Commit；历史分支 `codex/ble-reconnect-backoff-20260824` 只作为对应 Bug 记录中的审计证据
- 适用页面：设置 → 连接与语音；设置 → 按键映射

## 测试前准备

1. 准备一台 macOS 14 或更高版本的测试机，已授予无线麦所需的蓝牙、输入监控和辅助功能权限。
2. 准备两只可被无线麦识别的 RC001/RC003 遥控器；如需历史 profile 场景，先在同一偏好域登记至少 3 个遥控器。
3. 打开运行日志：`~/Library/Logs/RemoteMic/runtime.log`。

## 用例 1：只显示已连接遥控器

1. 只让第 2、4 个已登记遥控器保持蓝牙连接，其他已登记遥控器断开。
2. 打开“连接与语音”。
   - 预期：纵向设备卡只显示第 2、4 个已连接遥控器；不会显示断开的历史设备。
3. 打开“按键映射”。
   - 预期：页头横向设备卡只显示已连接遥控器，标题、开关和卡片均可见，不出现横向挤压或裁切。

失败判定：任一断开 profile 仍显示为设备卡；已连接设备不出现；卡片遮挡标题/开关；切换页面后列表状态不一致。

## 用例 2：全部断开与首次使用

1. 断开所有已登记遥控器，或使用没有已连接 profile 的全新测试偏好启动 App。
2. 打开“连接与语音”。
   - 预期：设备选择区域显示查找状态；页面原有“立即重新连接”按钮仍可操作。
3. 打开“按键映射”。
   - 预期：设备选择区域显示查找状态并提供“立即重新连接”，不会出现伪造的“未连接”设备卡。
4. 连接一只新遥控器并等待无线麦完成发现。
   - 预期：新遥控器完成 Ready 后自动登记并出现在两个页面的设备卡中；无需重启 App。

失败判定：首次用户看到空白且没有查找/重连提示；新设备完成发现后不出现；为了显示设备卡而删除历史 profile 或清空按键映射。

## 用例 3：断开与重连实时更新

1. 保持一只遥控器连接，确认其卡片出现。
2. 断开该遥控器并等待状态刷新。
   - 预期：卡片消失，页面转为空状态查找/重连提示。
3. 重新连接同一遥控器。
   - 预期：同一 profile 卡片重新出现，名称、电量、选中状态和按键映射保持不变。

## 用例 3A：三行信息与跨语言排序

1. 同时连接苹果遥控器 Type-C、小米蓝牙遥控器 2 Pro 和 Chromecast 遥控器；系统蓝牙名称分别设置为不含个人信息的测试名称。
2. 打开“连接与语音”和“按键映射”，逐张核对卡片。
   - 预期：第一行只显示型号通用名称，第二行显示 macOS 当前蓝牙名称，第三行保持“已连接 + 可用电池/充电状态”；系统名不得替代型号名。
3. 将一台设备改名为较长的中文名称，再回到 App 或切换页面触发刷新。
   - 预期：第二行更新且单行尾部截断；悬停和 VoiceOver 可读完整型号名与系统名，中文字号不低于 12pt。
4. 使用包含 `Chromecast`、“苹果”和“小米”的型号组合核对顺序。
   - 预期：按通用型号名的拉丁化/拼音顺序显示，即 `Chromecast`、`苹果`、`小米`；中文按拼音首字母参与排列。
5. 同时连接两台同型号遥控器，分别将系统名设为“阿姨”和“北京”；再把两台改成相同名称并重复切页、断开和重连。
   - 预期：同型号先按系统名称拼音排序；名称相同时顺序仍稳定，不因重绘或状态刷新跳动。没有可读系统名时显示“系统名称未知”并排在同型号有名称的卡片之后。
6. 对 1 台、2 台和 3 台以上设备分别检查布局。
   - 预期：1～2 张固定宽度卡片靠右紧凑显示；3 张以上才允许横向滚动，且不显示滚动条。排序不改变当前选中项、映射或语音路由。

失败判定：首行出现系统名称/序列号；第二行用型号名冒充系统名；中文未按拼音顺序；同名设备顺序跳动；缺名导致卡片退回两行；第三行状态或电池表现改变；两台设备开始滚动或卡片平分空白。

## 用例 4：历史蓝牙缓存失败后停止主动连接风暴

1. 在同一偏好域保留至少 3 个带蓝牙 identifier 的 profile，只让其中 1 个遥控器在线，另外 2 个历史遥控器保持离线。
2. 启动无线麦并记录至少 3 分钟日志。
   - 预期：在线遥控器正常进入 `BLE READY`；每个离线 profile 最多进行一次 `source=target_identifier` 缓存直连，失败后日志出现 `cached_identifier_bypassed=true` 并转入 `BLE SCANNING`，不会继续每约 11 秒重复 `BLE CONNECT TIMEOUT`。
3. 在在线遥控器上完成一次普通按键和一次完整语音。
   - 预期：历史 profile 的扫描不影响当前设备；普通按键只执行一次，语音第一次即完成 `STREAM_START → AUDIO → STREAM_STOP`。
4. 选中一个离线 profile 并点击“立即重新连接”。
   - 预期：用户操作会重置退避并立即允许一次缓存探测；如果仍失败，再次回到被动扫描，不恢复无限固定间隔重试。
5. 让该遥控器重新进入可发现状态。
   - 预期：扫描发现后使用原 profile 恢复 Ready，名称、HID 绑定和全部按键映射不变，不生成重复 profile。
6. 对能够连续制造连接失败的真机环境核对 `BLE RECONNECT scheduled`。
   - 预期：`failure_count` 逐次增长；`delay_ms` 围绕 3、6、12、24、48 秒加入 ±10% 抖动，封顶档为 54～60 秒且永不超过 60 秒。Ready 后下一次失败重新从第一级开始。
7. 在已经调度较长退避后关闭并重新打开系统蓝牙，再让遥控器恢复 Ready，随后制造一次新的普通断连。
   - 预期：退避等待期间仍能收到系统蓝牙状态变化；关闭或 resetting 会取消旧的长延迟，重新开启后由新的连接周期立即出现 `BLE SCANNING`，不会继续等待原 48/60 秒，也不会接受断电前 attempt 的晚到回调。Ready 后的新失败从第一级退避开始。
8. 在已连接时停止 bridge 并立即关闭/重开蓝牙，再重新启动连接；另在长退避期间撤销蓝牙权限或制造 unsupported 状态。
   - 预期：停止态会释放保留的 manager，重新启动后仍能扫描；unauthorized/unsupported 会取消旧 timer，不会继续创建新 manager 或自动重连。

失败判定：离线缓存仍持续按固定 3 秒等待主动连接；日志声称绕过缓存后仍出现连续 `source=target_identifier`；用户手动重连不能立即尝试；设备恢复后丢失原 profile 或映射；一个设备恢复导致其他在线设备断开或重复执行按键。

## 稳定功能回归

- 连接页的语音状态、音频输出、手机/Apple Watch/网页版入口和重连按钮仍可用。
- 按键映射页的实体图、单击/双击/长按配置、当前选中按键和映射持久化不变。
- 多遥控器同时在线时，按键事件仍按 profile 路由，不因列表过滤而合并配置。
- 中文文字最终显示字号不低于 12pt；在 `800 × 650` 离屏压力截图和真实生产最小窗口 `1020 × 772` 中都不出现逐字换行或裁切。
- 浅色和深色外观都检查三行层级、选中描边、长名称截断、状态色与电池图标；型号名和系统名均可通过悬停与无障碍读取完整内容。

## 日志收集

记录每个用例的本地开始/结束时间，并复制对应时间段的 `~/Library/Logs/RemoteMic/runtime.log`。重点核对 `BLE` Ready/断开、发现、`failure_count`、`delay_ms` 和 `cached_identifier_bypassed`；日志不包含设备 UUID、遥控器名称以外的用户内容或按键映射正文。

## 验证边界

- 自动化状态机测试覆盖退避等待期的 off/resetting/powered-on 恢复决策，但不能实际切换系统蓝牙或驱动真实 CoreBluetooth 回调。
- 代理离屏截图不能替代真实 CoreBluetooth、HID、系统权限和第三方语音工具验收。
- 双遥控器隔离、首次配对、系统设置返回后的重新发现、电池读数和充电状态必须在真实 RC001/RC003 上完成。
- 自动化覆盖拼音/拉丁化排序、同名稳定次序、空系统名后置和三行代码接线；Foundation 转写测试不能替代 macOS/Windows 各自的真实本地化显示与多设备 UI 验收。
