# 实体遥控器按键偶发无响应诊断手册

## 适用范围

- 分支：`fix/bug-1.9.0-test-permission-history-hid-20260819`
- 适用版本：包含 2026-08-19 HID 分层诊断的无线麦SayAll.app 候选包
- 重点设备：小米 RC003；其他已支持实体遥控器可作稳定基线

## 测试前准备

1. 确认输入监控和辅助功能已授权，自定义按键映射已开启。
2. 为 OK 键配置一个结果明确、可重复执行的普通动作，例如回车。
3. 打开 `~/Library/Logs/RemoteMic/runtime.log`，记录测试开始时间，不要清空其他用户日志。
4. 同时确认遥控器语音键可正常开始、传输并停止，以区分 BLE 语音链路与 HID 按键链路。

## 用例 1：正常 OK 单击基线

1. 在普通文本输入框中短按并松开 OK 键 10 次，每次间隔至少 1 秒。
2. 每次应只执行一次配置动作。
3. 每次日志应依次出现可对应的 `HID REPORT accepted`、`HID EDGE pressed=ok`、`HID GESTURE button=ok` 和 `HID BUTTON button=ok`；松开时应出现 `HID EDGE ... released=ok`。

失败判定：动作缺失、重复，或日志在任意一层中断。

## 用例 2：连续使用与语音交替

1. 连续完成 20 轮“按住语音键说一句并松开 → 等待文字上屏 → 短按 OK”。
2. 交替执行方向键、菜单键和 OK 键，持续至少 5 分钟。
3. 所有按键应按现有配置执行，实体 Mac 键盘保持可用，语音链路不应因新增日志受影响。

失败判定：OK 偶发无动作、其他按键行为变化、实体键盘受阻或语音异常。

## 故障日志判读

- 没有任何新的 `HID REPORT`：报告未进入 App 的 IOHID 回调范围，优先检查真实设备、系统 HID/权限和监听生命周期。
- `HID REPORT callback_rejected`：查看 `reason` 与系统错误码。
- `HID REPORT rejected reason=...`：按原因检查监听状态、权限、位置或设备路由。
- `parse_failed`：报告到达但格式未被当前解析器接受。
- 有 `accepted`，没有 `HID EDGE pressed=ok`：解析出的 usage 没有形成新的 OK 按下边沿，检查 report 内容变化或残留按下状态。
- 有 `HID EDGE pressed=ok`，没有 `HID GESTURE`：检查手势等待、释放事件和辅助动作配置。
- 有 `HID GESTURE`，没有 `HID BUTTON`：检查动作执行前置条件或 `HID ACTION failed`。
- 有 `HID BUTTON button=ok` 但界面无结果：HID 链路已执行到动作层，应转查目标 App、辅助功能注入和前台焦点。

## 稳定功能回归

- RC003 普通方向、返回、菜单、主页、TV 和音量键。
- 单击、双击、长按及允许连发的方向键。
- 遥控器语音 `STREAM_START → AUDIO → STREAM_STOP`。
- MacBook 实体方向键与普通键盘输入。
- 断连、重连、权限关闭后重新授权。

## 日志与隐私

提交完整 `runtime.log`，并注明故障发生的本地时间、按键、预期动作、实际结果、遥控器型号以及当时语音是否正常。诊断日志不包含原始 HID payload、设备指纹、蓝牙地址、输入文字或语音内容。

## 验证边界

自动化和私有模拟能够验证代码分层与既有行为回归，不能替代真实 RC003 固件、macOS IOHID 回调、输入监控/辅助功能权限历史和目标 App 行为。只有真机再次出现故障并获得分层日志后，才能确认精确根因与正式行为修复。

2. 在目标 App 连续单击两个音量键，再按住和松开。

## 用例 5：快速 TV、音量自定义与源头映射恢复

适用：包含 TV/音量事件级兜底修复的 macOS 包；现场 Build 267 不含本次改动。
测试设备需包含反馈所用的 Intel Mac 和 Xiaomi 遥控器。
Siri Remote 和 Chromecast 同时执行以下适用的普通按键用例。
Windows 与网络控制入口未修改，保留稳定基线检查。

1. 开启自定义映射和对应权限，将音量减配置为逗号。
2. 关闭该键的双击、长按动作，并开启快速连按。
3. 在微信输入框中慢按十次，再快速完整点击十次。
4. 每次只输入一个逗号；系统音量不得变化。
5. 给 TV 配置打开 App，关闭次级手势并开启快速连按。
6. 在微信中慢按十次，再快速完整点击十次。
7. 配置动作应执行，输入框不得新增圆点或其他字符。
8. 长按音量减后松开，等待五秒；系统音量不得持续变化。
9. 改回默认音量动作，确认每次点击只变化一次。
10. 确认普通键盘逗号、反引号、音量和 Fn 语音正常。
11. 按住遥控器键时断连，再重连；首击应正常且无残留动作。
12. 连接第二只受支持遥控器，确认两只设备不串用配置。

恢复检查须分别执行，不能用一次重启代替：

- 关闭自定义映射：接管的普通键恢复系统原有行为；重新开启后自定义动作正常。
- 正常退出 App：原有系统映射恢复；重新打开后首击正常。
- 强制退出 App 后重新打开：读取恢复记录；正常退出后原映射仍可恢复。
- 撤销权限：停止接管并尝试恢复；重新授权后首击正常。
- 重启系统及重新连接：不能把旧服务记录恢复到新服务。
- 如原来有外部映射，退出后应恢复；运行期间外部新改的映射应保留。

失败判定：额外圆点、额外音量变化、原动作丢失、普通键盘受阻，或松键后仍连发。
恢复失败、恢复到错误设备、Fn 或原映射被覆盖也判失败。

保留复现时间对应的 `~/Library/Logs/RemoteMic/*.rmlog`，通过私有渠道提供。
检查 `HID NATIVE MAPPING phase=prepare result=verified` 早于设备激活。
这里的 verified 只证明 UserKeyMapping 回读一致。
`native_delivery=unobserved` 不代表真实系统事件已经被验证。
源头映射回读成功时，TV 和音量仍必须登记事件级兜底。
对应原生事件应记录 `HID FILTER suppressed`。
退出、关闭映射和权限撤销后检查 `phase=restore` 的结果。
失败时检查 `reason`、`attempted`、`restored`、`failed` 和 `pending`。
同时保留 `HID REPORT`、`HID FILTER` 与 `HID BUTTON` 的先后关系。
配置动作已提交，不能替代微信输入结果和系统音量的检查。

自动化覆盖模拟服务映射、异常恢复、TV/音量兜底拦截及同码普通键盘保护。
代理尚未在反馈设备执行此流程，也未改动本机系统映射。
真实原始报告、系统音量、微信文字和双设备隔离仍待现场验收。

### 用例 5 的跨硬件补充

- 小米全部十二键各慢按、快按十次，方向键另测按住连发。
- 左右默认动作必须执行一次，不能因屏蔽原生动作而失效。
- 苹果遥控器逐型号测试普通键、触摸和独立语音。
- Chromecast 测试方向、确认、返回、音量、静音及专用键。
- 各类设备分别在按住时关闭映射、撤销权限、退出和断连。
- 重新准备失败时，已按住动作必须取消；恢复后首击正常。
- 三类设备同时连接时，分别退出和重连，不能跨家族恢复映射。
- 对每类设备按键期间，穿插电脑键盘的同码输入，不能被吞。
- 按普通键执行 App 动作后，立即完成一次语音输入。
- 首字、尾字和松键响应必须保持稳定。
