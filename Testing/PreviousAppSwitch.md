# 一键切回上一个 App

适用范围：包含 `switchToPreviousApp` 动作的 macOS 候选构建。此动作与保留选择状态的 `Command-Tab` 分开；现有绑定和 TV 默认动作不迁移。

## 准备

1. 授予辅助功能和输入监控权限，连接受支持遥控器，启用自定义按键。
2. 打开两个不同的 App，依次激活 A、B；关闭已有系统切换器。
3. 在按键映射的“系统与媒体”中，把 TV 单击设为“切回上个 App”。双击和长按保持未设置，快速连续按保持关闭。

## 操作与判定

1. 按下并松开 TV：A 应直接成为前台，不需要 OK、Return 或第二次按键。切换器持续停留即失败。
2. 再按 TV：B 应成为前台。重复五轮，检查一次点击只切换一次。
3. 按住 TV 超过一秒：只执行一次，不得在 A、B 间不断往返。松开并间隔一秒后再次点击仍可切换。
4. 在空白测试文档中输入普通字母：不得触发 Command 快捷键、留下 Tab 或额外 Return。切换动作不得提交目标 App 中的文本。
5. 重启 SayAll，检查绑定保留；导出并重新导入当前版本配置后重复步骤 1、2。
6. 撤销辅助功能权限后触发：不得发送部分按键；恢复权限与监听后应可再次使用。
7. 分别在全屏空间、多显示器、减少动态效果开启、只有一个可切换 App 时检查。结果遵循原生 Command-Tab 规则；不保证恢复最小化窗口，也不启动尚未运行的 App。

出现停留在切换器、需要确认、连续切换、残留修饰键、输入框收到额外回车或绑定丢失，均判定失败。

## 稳定路径回归

- 将 TV 改回 `Command-Tab`，执行 [系统切换器测试](AppSwitcherRemoteControl.md)：仍可停留、左右选择、OK 确认、TV 前进、断连和超时释放。
- 现有系统切换器会话期间 TV 仍按原规则前进选项；一键动作不会改变既有模态路由。
- 普通自定义快捷键和语音键保持原行为。新动作不需要组合动作私有模块。
- 旧配置可继续读取，默认 TV 仍为 `appSwitcher`。新动作使用新增枚举值；旧版本不认识它，降级前应把相关绑定改回旧动作并导出旧版可读配置。

## 日志与自动化

从 SayAll 的“文件 → 打开日志所在文件夹”收集本次测试时间段；分享前去除无关日志。搜索 `KEYBOARD PREVIOUS_APP`，同一 `operation_id` 应恰好有一个 `requested` 和一个 `completed`。四个事件提交状态分别为 `command_down`、`tab_down`、`tab_up`、`command_up`。

`result=submitted` 仅表示事件已提交，`user_visible_result=unknown` 明确不能替代屏幕验收；`result=failed` 不得作为成功。权限拒绝由现有 HID 权限门禁报告，不会进入注入路径。任何提交失败仍尝试释放 Command；如底层事件创建或系统权限持续失败，不能承诺释放已被系统接收。

```sh
swift test --disable-keychain --filter RemoteButtonsTests
```

自动化覆盖完整事件顺序、每个事件提交失败后的清理与下一次调用、无权限不发送、配置持久化、HID 按住去重及与持久切换会话的隔离。它不发送真实系统按键，不能替代物理遥控器、权限 UI 和真实前台切换验收。中文/英文、浅色/深色以及生产最小窗口尺寸下的动作按钮截图仍须由候选构建补齐；完成前 PR 保持 Draft。
