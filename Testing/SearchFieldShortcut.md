# 搜索框快捷键（⌘F）手工验收

本手册覆盖「设置窗口内按 ⌘F 聚焦当前页面主搜索框」与「编辑 > 查找…」菜单项。
对应的自动化回归见 `Tests/RemoteMicTests/SearchFocusTests.swift`。

## 前置条件

- 完成首次引导，设置窗口可打开且为 key window。
- 语言分别用简体中文与 English 各跑一遍（菜单文案来自 `common.action.find`）。
- 若构建包含私有组件，同时覆盖「组合动作」「按键方案」「常用语」三个私有页面。

## 用例 1：有搜索框的页面

| 步骤 | 期望 |
| --- | --- |
| 进入「按键」页，展开任一按键的动作编辑区，并把动作筛选切到包含「自定义/组合动作」 | 「搜索组合动作」输入框出现 |
| 把焦点放到别处（例如点一下侧边栏空白处），按 ⌘F | 光标进入「搜索组合动作」输入框，出现聚焦环 |
| 输入若干字符后再按 ⌘F | 内容与选区不变，焦点保持在输入框（不清空、不重复选中） |
| 打开「编辑」菜单 | 「查找…」项为可用状态，右侧显示 ⌘F |

私有页面同理：分别进入「组合动作」「按键方案」「常用语」页按 ⌘F，
焦点应落在该页**库搜索框**（宏库 / 方案库 / 常用语库），
而不是步骤编辑器或绑定编辑器里的上下文筛选框。

## 用例 2：没有搜索框的页面

| 步骤 | 期望 |
| --- | --- |
| 进入「连接」或「回眸」页，按 ⌘F | 无任何反应：不弹窗、不提示音、不改变当前焦点 |
| 打开「编辑」菜单 | 「查找…」项为置灰状态 |
| 在「按键」页收起组合动作编辑器（该搜索框从视图树移除）后再按 ⌘F | 同上：静默、菜单项置灰 |

## 用例 3：回归重点

- **快捷键录入不被破坏**：在「按键」页进入自定义快捷键录入状态，按 ⌘F。
  录入态的 CGEvent tap 在 `headInsertEventTap` 位置先吞掉 keyDown，
  应正常把 ⌘F 录成快捷键，而不是被「查找…」消费、也不产生聚焦副作用。
  若此用例失败，说明 tap 位置或吞噬条件被改动，须先排查
  `ShortcutCaptureMonitor.swift` 的 `handle(type:event:)`。
- **标准编辑快捷键仍可用**：在任意输入框里验证 ⌘A / ⌘C / ⌘V / ⌘Z / ⇧⌘Z。
  这些菜单项 `target = nil`，仍应路由到当前聚焦的文本框。
- **窗口快捷键仍可用**：⌘Q 退出、⌘W 关闭、⌘M 最小化。
- **浮窗场景**：若「常用语」以独立浮窗打开，浮窗为 key window 时按 ⌘F
  不得把设置窗口里的搜索框抢过来（宿主只在设置窗口是 key window 时广播）。
- **语言切换后**：切换中英文后菜单标题与「查找…」文案正确、快捷键仍生效。

## 通过判据

用例 1、2、3 全部符合期望，且 UI 布局、控件位置、搜索框外观与改动前一致
（本次不改动任何页面布局，只增加键盘入口与菜单项）。
