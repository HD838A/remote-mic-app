# 虚拟麦克风名称测试手册

## 适用范围

- 当前修复：`codex/fix-intel-pkg-conflicting-naming`，基线 `3ee46f2549cd707a6a2f001901733c1e67e903a0`。适用于 2.0.0 候选包。
- 平台：Apple Silicon（macOS 14+）及 Intel（macOS 13+）。每个平台独立验收。
- 行为：全新安装显示 `SayAll`。旧用户继续使用 `MiRemoteV 2ch`。旧驱动修复、升级和驱动缺失后的恢复保持原名称。
- 身份：主 UID `MiRemoteV2ch_UID`、Box UID、Model UID、Bundle ID、二声道、USB transport、隐藏端点、可执行文件、HAL 安装路径及包 ID 不变。
- 两种签名负载仅暂存在安装器目录。HAL 中只部署一种；不得把两种负载同时安装到 HAL。
- 本次修改不迁移第三方设置，不清除本产品音频选择、向导完成状态和按键映射。

## 测试前准备

1. 使用可恢复的独立测试 Mac 或虚拟机。真实音频验收必须使用真实 Mac 和真实遥控器。
2. 分别准备全新系统、健康旧驱动、需要更新的旧驱动、已使用新名称的系统，以及两种名称各自的驱动缺失状态。
3. 保存本产品当前音频选择、向导完成状态和按键映射。通过第三方工具可见设置记录其麦克风选择；不得读取第三方私有文件。
4. 准备 BlackHole 2ch 和同名物理设备，验证兼容回退及身份隔离。
5. 安装测试只使用原生流程产出的 Developer ID 签名、公证、staple 包。核验 Team ID `L3QHLDRPAY`。本地 ad-hoc 产物只用于自动化，不能分发给用户。
6. 安装前保留可恢复快照。故障注入仅在测试副本中执行，不破坏用户系统驱动。

## 安装与恢复用例

| 前置条件 | 操作 | 预期结果 | 失败判定 |
| --- | --- | --- | --- |
| 无驱动、无本产品 App、无历史 receipt、无本产品音频配置或名称记录 | 安装 | 显示 SayAll，HAL 仅一个实例 | 出现旧名、重复实例或错误 UID |
| 健康且同版本旧驱动 | 升级 App | 原驱动逐字节保留，仍显示 MiRemoteV 2ch | 原驱动被替换或名称变化 |
| 可信旧驱动版本/架构需更新 | 安装新版 | 使用新版 legacy 负载，显示旧名 | 改名或旧选择失效 |
| 驱动缺失，有旧 App、receipt 或本产品历史音频配置 | 安装 | 恢复 legacy 负载 | 被当成全新安装 |
| brand 名称记录存在，驱动缺失 | 重装 | 恢复 SayAll | 恢复为旧名 |
| legacy 名称记录存在，驱动缺失或签名损坏 | 重装 | 恢复旧名称 | 被改名 |
| 本产品旧驱动签名损坏或缺少执行权限，无名称记录 | 安装 | 安装成功；按驱动实际名称修复，名称无法读取时恢复 legacy 负载 | 停止安装、原 UID 或配置变化 |
| 当前驱动与可信名称记录冲突 | 安装 | 安装成功；保持实际驱动名称，旧记录移入废纸篓，新记录与名称一致 | 停止安装、名称变化或记录丢失 |
| 两个可信名称记录并存 | 安装 | 安装成功；实际名称可读时按实际名称恢复，否则使用兼容旧名称；旧记录可恢复 | 因冲突停止安装或 UID/配置变化 |
| 本产品 SayAll 驱动名称标记缺失 | 安装 | 安装成功；按完整名称常量修复，仍显示 SayAll | 改成旧名称或接受损坏驱动 |
| 记录对象不可信（符号链接或权限不可信） | 安全故障注入 | 保留原文件，记录安全失败；修复对象后重新安装成功 | 覆盖不可信对象或把安全失败记为安装成功 |
| 同产品 Bundle ID 位于多个 HAL bundle | 安装 | 停止 | 并存或只覆盖其中一个 |
| 目标路径属于其他驱动，或路径父级为符号链接/可被普通用户写入 | 安装 | 停止 | 覆盖或修改其他软件 |
| 候选负载签名无效、名称形态错误、权限操作失败或名称记录写入失败 | 对测试副本注入故障后安装 | 停止并恢复原驱动，失败副本可恢复 | 原驱动丢失或失败被记为成功 |
| 完成安装后再次运行同一安装包 | 重试 | 保留健康驱动及原名称，无重复实例 | 重命名或重复安装 |
| 首次安装已选 brand，App/receipt 已写入，但驱动安装失败或取消 | 再次安装 | 沿用首次名称记录，安装 SayAll | 因残留 App/receipt 改选旧名 |
| 旧用户安装已选 legacy，驱动安装失败或取消 | 再次安装 | 保留原驱动和名称记录，继续使用旧名 | 原驱动丢失或改名 |
| 任一名称形态 | 卸载、再安装 | 卸载至 Trash，保留本地设置和名称记录；重装恢复原名称 | 永久删除、改变 BlackHole 或改变原名称 |

真实安装需补充管理员授权、取消安装、其他目标卷、重启、睡眠唤醒，以及 CoreAudio 未运行/重启失败场景。音频未实际加载时，安装日志只能记录 `audio_loaded=unknown`。

`preinstall` 在负载写入前保存名称记录。实际驱动名称优先于旧记录。更新冲突记录前，先把可信旧记录移入 root 废纸篓。写入失败时恢复原记录。记录表示已选名称，不表示驱动已安装或音频可用。名称证据冲突必须通过实际驱动名称、历史记录或兼容规则完成安装；不能因为冲突本身停止安装。只有记录对象不可信、签名无效、权限操作失败或回滚失败等安全故障才阻断本次安装。取消安装后保留记录，后续安装沿用该选择。

## 安装成功的验收标准

正常安装、升级、可信记录冲突和本产品历史驱动修复，都必须安装成功。停止安装不算通过。

1. 分别运行两种架构的最终签名 PKG。
2. 分别勾选和不勾选“苹果遥控器 Siri Remote”。
3. 确认 Installer 显示安装成功，App 和驱动通过签名校验。
4. 启动 App 两次，确认版本、音频 UID 和原配置正确。
5. 再次运行同一 PKG，确认安装成功且没有重复驱动。
6. 保留日志及最终安装结果。只看到名称选择或驱动复制不算通过。

名称证据冲突、旧驱动名称无法读取、名称记录并存和升级重试都必须得到安装成功。安全故障注入只验证文件保护和回滚；它不能把“冲突时停止安装”作为通过条件。修复故障后必须重新安装成功。

## App 与第三方语音回归

1. 分别安装两种名称。刷新音频设备。设备列表、检测状态、选择按钮、向导及语音核对卡必须显示系统真实名称。
2. 验证历史 UID 的优先级。同名物理 SayAll 不能通过兼容麦克风门禁；已有 MiRemoteV 2ch 名称回退和 BlackHole 回退保持可用。
3. 安装新版 App 配旧驱动，再测试旧版 App 配新驱动。最后通过 Sparkle 只更新 App。原音频 UID、向导完成状态和按键映射必须保持不变。
4. 在豆包、微信、Vokie、Typeless 可见界面选择同一麦克风。按住遥控器语音键说话，正常释放。记录从按下到首个有效 PCM 与可观察首字的耗时；确认尾字完整、正常停止无 flush、连续会话和断连恢复。
5. 对小米、iPhone 和网页来源执行完整语音到文字旅程。其他受支持硬件按 [硬件合同](HardwareCompatibilityContract.md) 分平台执行。
6. App 显示设备存在或音频入队不能代表第三方文字已经写入。最终文字未上屏即判定失败。
7. 向导完整回归按 [FirstRunOnboarding.md](FirstRunOnboarding.md) 执行。主设置页在 `800 × 650` 下检查连接页、设备选择和滚动。

## 自动化命令

```sh
scripts/build-doubao-driver.sh
scripts/test-driver-naming.sh
RELEASE_VARIANT=intel scripts/build-doubao-driver.sh
RELEASE_VARIANT=intel scripts/test-driver-naming.sh
swift test --disable-keychain --filter 'DriverNamingTests|DoubaoAudioDeviceTests|OnboardingFlowTests'
```

`install-doubao-driver.sh` 也使用相同的名称判定；已有驱动时仍拒绝覆盖。驱动缺失时按名称记录和历史证据恢复原形态。

`test-driver-naming.sh` 调用生产名称分类器、PKG 安装替换/回滚代码及直接安装代码。它在自建副本中替代 root 权限与状态写入，不安装系统 HAL；fixture 保留，不永久删除。健康驱动保留用例检查原目录 inode、`changed=0` 和无替换备份，防止“替换成相同字节”误报通过。

新增 5 个用例执行完整 `preinstall`、模拟 App/receipt 负载残留、生产 `postinstall` 的名称检查与驱动部署代码，再运行新的安装尝试。用例覆盖新用户重试、历史用户重试、健康旧驱动重试、记录写入失败及损坏记录。记录内容、权限、写入与读取使用真实文件；root 所有者、硬件架构、receipt 查询、停止进程和 chown 被替代。后续 App 校验、系统服务重启与启动不在该副本测试范围内。

历史验证：两种架构各 19 个副本场景通过；Swift 定向测试 74 项通过。Intel 原生属性探针因本机不能执行 x86_64 而跳过。原生探针只加载本次构建的插件，核验名称、身份、transport 和端点数量，不启动真实音频。这些结果不替代最终签名包的真实安装、取消与语音验收。

2026-10-08 修复新增 14 个恢复用例。它们执行完整生产 `preinstall` 和 `postinstall`，验证最终完成提示、App/驱动签名、名称记录、原配置和第二次安装。两个用例先注入记录写入失败，再确认回滚与重试安装成功。测试使用小型签名 fixture App，并替代 root 所有者、硬件架构、receipt、停止进程、chown 和音频服务操作。目标是隔离卷，App 不会实际启动。该结果只证明脚本完成，不能替代真实 Installer、CoreAudio、App 启动及 Intel 现场安装。
