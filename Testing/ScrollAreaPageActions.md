# 滚动区域与翻页动作测试手册

## 适用范围

- 分支：`codex/scroll-region-learning-20261030`（基线 `origin/main` = `f44b5e14`）
- 平台：macOS；RC001 / RC003 通过蓝牙连接
- 目标：确认「向上翻页 / 向下翻页」滚动的是**正确的区域**，并且不移动焦点、不移动指针、不误翻侧栏

## 测试前准备

1. 安装本次测试包并启动 App，授予辅助功能与输入监控权限。
2. 在「按键映射」页把方向上设为「向上翻页」、方向下设为「向下翻页」，其余按键保持默认。
3. 准备内容长于一屏的样本：cmux 终端、WorkBuddy 或 Claude 的对话、Chrome 长网页、企业微信会话列表。
4. 记录测试开始时间，保留 `~/Library/Logs/RemoteMic/runtime.log`。

## 用例 1：预置区域（原生 App，cmux）

1. 把 cmux 切到前台，光标停在终端内容区，先滚到最底部。
2. 单击方向上键，再单击方向下键；随后按住方向上键 2 秒。

预期：内容按页移动，约一屏；指针不在 cmux 上时也仍然滚动 cmux；侧栏与标签条不动；按住行为由连发策略决定，本次不做通过条件。

失败：内容不动、只动侧栏、指针所在窗口被滚动、方向相反。

## 用例 2：Electron 应用（WorkBuddy / Claude / Codex）

1. 同一按键在 WorkBuddy 对话页执行一次向上、一次向下。
2. 在 Claude 与 Codex 上重复。

预期：对话区按页移动；未学习过的 WorkBuddy / Claude 显示「需学习」，不执行翻页也不退回窗口中心；已学习的记录在 App 重启后仍能定位。

失败：翻错区域、翻到右侧面板、什么都不发生却没有提示。

## 用例 3：学习滚动区域

1. 在按键映射页选择 WorkBuddy 的自定义 App 配置，点「学习滚动区域」。
2. 倒计时内点一下对话消息区；观察卡片状态与提示。
3. 点「测试向下翻页」。
4. 点「恢复预置」，再观察状态。

预期：学习后显示「已学习」；测试显示内容已移动；恢复预置后回到「需学习」；学习与测试都不读取对话内容。

失败：学习成功但测试不动、把侧栏记成区域、恢复预置后仍按旧记录翻页。

## 用例 4：指针没落在可滚动区域

1. 对微信执行学习（其界面没有可定位的滚动区域）。
2. 对任意 App 学习时，把指针停在标题栏或工具栏。

预期：明确显示「没有识别到可滚动区域」，不写入记录、不改成「已学习」。

失败：静默成功、写入空区域、之后翻页报权限错误。

## 用例 5：输入框聚焦时翻页

1. 在 WorkBuddy 输入框里输入一段文字，保持光标在输入框。
2. 单击方向上 / 下键。

预期：对话区滚动，输入框内光标位置与文字不变。

失败：光标在输入框内上下移动、输入框内容被改动。

## 用例 6：权限与异常

1. 撤销辅助功能权限后触发翻页。
2. 恢复权限，再触发。
3. 按住翻页键期间断开遥控器。

预期：权限缺失时不执行且不崩溃，恢复后立即可用；断连后不再有翻页事件。

失败：崩溃、恢复后需要重启、断连后继续翻页。

## 用例 7：窗口与显示器

依次在最大化、四分之一窗口、全屏、分屏、副屏下重复用例 1 的一上一下。

预期：每次都在当前前台窗口内翻页，不落到后台窗口。

失败：翻到别的显示器或后台窗口、全屏下无反应。

## 用例 8：自然滚动

在「系统设置 → 鼠标 / 触控板」分别开启和关闭「自然滚动」，各重复用例 1。

预期：开与关都表现为「向上翻页看更早内容」。

失败：任一设置下方向相反（记录设置状态与机型）。

## 稳定功能回归

- 方向上 / 下仍映射原方向动作时行为不变，包括按住连发。
- 「向上滚动 / 向下滚动」仍按行滚动、仍在窗口中心。
- 语音键按下开始、释放结束，首字与尾字不受影响。
- 打开 App、聚焦输入框、自定义快捷键、组合动作不受影响。
- 按键映射页新增的两个动作显示中英文名称，最小窗口 `1020 × 772` 不裁切。

## 日志

重点查 `SCROLL PAGE`：`bundle`、`direction`、`strategy`、`result`、`verified`、`elapsed_ms`。`result=needsCalibration` 表示该 App 没有预置区域；`result=regionMismatch` 表示记录失效。

## 验证边界

- 自动化只覆盖纯逻辑：步长、方向、预置筛选、匹配与歧义、配置兼容、动作分组与连发白名单。
- 不能由自动化证明：原生翻页动作是否真的滚动、Electron 是否接受像素滚轮、自然滚动下的方向、全屏与多显示器行为。
- 以上用例必须在真实遥控器与真实目标 App 上执行，单元测试与构建通过不能替代。
