# 菜单栏图标显隐测试手册

## 适用范围

- 适用版本：包含 #379 清理集成修复的待验证 PR 或其合入后的精确 `main` Commit。
- 平台：macOS 14 及以上。
- 目标：验证 Dock 与菜单栏入口可以独立显示或隐藏，入口全部隐藏后仍可恢复设置窗口，并且后台连接、按键与语音主路径不受影响。

## 测试前准备

1. 退出其他无线麦SayAll.app 实例，启动本分支构建的 App。
2. 完成 Onboarding，进入“设置 → 通用”。
3. 记录测试开始时间；发生异常时保留 `~/Library/Logs/RemoteMic/runtime.log` 对应时间段。
4. 准备 Finder、Launchpad 和 Spotlight 三种重新启动入口。

## 用例 1：只隐藏菜单栏图标

1. 保持“在 Dock 中显示应用图标”开启。
2. 关闭“在菜单栏中显示应用图标”。
3. 关闭设置窗口，通过 Dock 图标重新打开。
4. 重新开启菜单栏图标。

预期结果：菜单栏图标立即消失，Dock 图标与后台运行保持正常；通过 Dock 打开的仍是原设置窗口。重新开启后菜单栏图标只出现一个，鼠标左键和右键均显示状态菜单；第一项“打开主界面…”可打开或激活主窗口。

失败判定：App 退出、出现重复菜单栏图标、Dock 图标异常消失、连接或语音运行时被停止，或重新开启后左右键失效。

## 用例 2：只隐藏 Dock 图标

1. 保持菜单栏图标开启。
2. 关闭 Dock 图标。
3. 关闭设置窗口，点击菜单栏图标，再选择第一项“打开主界面…”重新打开。

预期结果：Dock 图标按用户偏好保持隐藏；鼠标左键和右键均可打开菜单，选择“打开主界面…”后可恢复窗口且 Dock 图标仍隐藏。

失败判定：两个入口一起消失、设置窗口无法恢复，或菜单栏状态展示不再随连接和语音状态更新。

## 用例 3：两个入口都隐藏后恢复

1. 关闭 Dock 图标和菜单栏图标。
2. 保持设置窗口打开，切换到 Finder 后再切回，确认窗口没有被强制关闭。
3. 使用红色按钮或 `⌘W` 关闭设置窗口。
4. 分别从 Finder、Launchpad 和 Spotlight 再次启动无线麦；每次恢复后再次关闭窗口再测试下一个入口。
5. 退出 App 后重新启动，确认冷启动也能显示设置窗口。

预期结果：两个入口隐藏时后台进程可继续运行；再次启动已运行实例或冷启动都打开设置窗口，用户可以重新开启任一入口。不会出现第二个 App 实例或第二套连接/音频运行时。

失败判定：启动无反应、出现重复实例、设置窗口无法恢复、每次启动创建新的菜单栏图标，或登录项/普通启动进入不可访问的纯后台状态。

## 用例 4：配置导入兼容

1. 导出一份菜单栏图标关闭的配置。
2. 开启菜单栏图标后重新导入该配置。
3. 再导入一份不包含 `showStatusBarIcon` 字段的旧配置。

预期结果：新配置导入后菜单栏图标按配置立即关闭；旧配置不覆盖当前菜单栏偏好。导入成功或部分导入提示继续使用现有规则。

失败判定：导入后界面开关与实际入口不一致、旧配置意外改变当前偏好，或配置被误判为无效。

## 用例 5：菜单点击与主界面入口（#799）

1. 关闭主窗口，分别用鼠标左键和右键点击菜单栏图标。
2. 每次确认第一项为“打开主界面…”，第二项为分隔线，其后为连接与音频状态及原有操作。
3. 分别再次点击同一菜单栏图标、按 Esc 和点击菜单外部取消菜单，确认菜单收起且不会打开主窗口；重新打开菜单并选择第一项，确认主窗口出现。
4. 主窗口已打开时重复步骤 1–3，确认只激活现有窗口，不创建重复窗口。
5. 用键盘选中首项并按 Return，确认可打开主窗口；再覆盖键盘取消。
6. 隐藏 Dock 图标并重复以上操作。重启后确认 Dock 偏好保留，菜单栏入口仍可用。
7. 分别检查中文、英文及浅色、深色；连接状态变化或切换语言后重新打开菜单，首项顺序仍保持正确。
8. 切到其他 App 后重复展开和收起，确认后台状态及隐藏 Dock 不影响菜单取消。

预期结果：鼠标左右点击行为一致，首项分别显示“打开主界面…”或“Open Main Window…”。取消只关闭菜单，选择首项才打开或激活主窗口。Dock 显隐独立于菜单点击，不影响后台连接。

失败判定：左键仍直接打开窗口、首项缺失或不是主界面入口、刷新后首项下移、菜单无法取消或取消时意外打开窗口、重复创建窗口或 Dock 偏好被覆盖。

## 日志收集

菜单点击另筛选 UI STATUS_MENU：AppKit 开始打开菜单时，记录同一 operation_id 的 requested、opening 与 closed；隐藏状态项或菜单被替换时可记录 cancelled。状态项未收到的点击不可观察，不能据此推断点击或显示成功。日志只表示原生菜单生命周期，屏幕显示与主窗口激活仍需按用例实测。

筛选 `UI ENTRY_POINT`。每个菜单栏显隐操作应具有同一 `operation_id` 的 `phase=requested` 和 `phase=completed`；`source` 为 `launch`、`status_bar_toggle` 或 `configuration_import`，`change` 为 `created`、`removed` 或 `none`。日志只记录布尔状态和稳定来源，不包含路径、设备身份、用户内容或第三方 App 状态。

`result=passed` 只表示 AppKit 创建或移除调用已完成，不能单独证明屏幕像素、Finder 重新启动或系统菜单栏最终可见。
