# 首次使用成功率优化测试手册

## 适用范围

- 候选版本：Remote Mic `v1.8.14 (106)`
- 分支：`release/pre-v1.8.14`
- 平台：Apple Silicon macOS 14 及以上；Intel 独立包 macOS 13 及以上
- 本轮边界：只准备候选代码，不生成、签名、公证或发布安装包

## 测试前准备

1. 准备一个全新测试账号和一个已完成 Onboarding 的升级账号。
2. 准备 RC003、MiRemoteV 2ch、BlackHole 2ch、豆包、Typeless 和至少一个其他语音工具。
3. 后续生成候选产物后，再准备四种驱动状态：未安装、健康同版本、损坏或不可执行、错误架构或旧版本。
4. 问题发生时记录时间；结束后在“权限与隐私”点击“发送诊断信息”。“打开日志所在文件夹”只用于确认加密 `.rmlog` 存在。

## 用例 1：权限卡点与诊断

1. 在权限页依次保持蓝牙、输入监控、辅助功能未授权。
2. 确认页面每次只突出当前最先阻塞的一项，并只有一个主要修复按钮。
3. 点击“复制设置诊断”，粘贴到纯文本编辑器。

预期结果：修复动作打开或请求正确权限；摘要含版本、系统大版本、架构、当前步骤、失败码、布尔状态、阶段耗时和最近重试，不含用户名、路径、设备名、UUID、蓝牙地址、输入文字、音频或密钥。

失败判定：出现多个同等级主要操作、权限错误地被判为已通过、轮询每秒重复写相同事件，或摘要含个人/设备内容。

## 用例 2：遥控器、音频与语音自愈

1. 分别制造遥控器未连接、已连接但未收到按键、没有音频设备、所选设备消失、输出未就绪。
2. 在语音页分别制造未开始、无声音、未松开、无文字。
3. 每个状态点击页面唯一主要修复操作后重新执行原流程。

预期结果：操作复用现有重连、HID 重建、设备刷新、音频重配和语音重试链路；恢复后当前门禁变为通过，稳定蓝牙、按键和音频行为不变。

失败判定：修复跳到无关页面、建立第二套硬件链路、默认映射变化，或必须重启 App 才能恢复本可自愈的状态。

## 用例 3：完成页定向回跳

1. 到达完成页后分别撤销权限、断开遥控器、停用所选输出。
2. 点击“修复受影响项目”。

预期结果：分别返回权限、遥控器或音频页；不会清除已有连接、按键映射、Dock、启动、语言或更新偏好。

失败判定：总是返回欢迎页、进入错误阶段、仍能打开主面板，或现有用户设置丢失。

## 用例 4：单一安装入口（后续候选产物）

1. 打开 Apple Silicon 和 Intel DMG。
2. 检查根目录只存在对应的 `Install Remote Mic*.pkg`。
3. 分别在未安装、健康同版本、损坏、错误架构和旧版本驱动状态安装。
4. 在没有 Xcode 或 Command Line Tools 的普通用户机器执行。

预期结果：普通用户只需双击一个 PKG；健康同版本驱动原样保留，其他异常状态被安全安装或升级；App 安装后启动；无需下载开发工具。

失败判定：DMG 并列 App/Applications/卸载入口、健康驱动仍被替换、异常驱动被错误保留、安装脚本要求开发工具，或 App/Sparkle 可执行权限损坏。

## 稳定功能回归

- RC003 普通 `STREAM_START → AUDIO → STREAM_STOP` 首次尝试成功。
- 普通按键、自定义快捷键、双击、长按、Typeless Fn 点按保持原行为。
- BlackHole 2ch 和其他已安装回环设备仍可完成 Onboarding，不强制选择 MiRemoteV 2ch。
- 中英文 `1020 × 772` 页面不裁切，中文字号不低于 12pt。

## 日志与验证边界

自动化覆盖失败码、定向回跳、事件去重、摘要字段、脚本语法、DMG 根目录约束和禁止开发者工具命令。模拟硬件和单元测试不能替代真实权限历史、RC003、第三方输入工具、驱动安装、管理员授权、CoreAudio 重启和安装后启动；这些必须在生成后续候选安装包时执行。

权限依赖复核继续保留现有三项门禁：普通按键需要输入监控和辅助功能，Typeless Fn 点按至少需要辅助功能；尚无足够真实证据证明豆包或其他工具可安全缩减完整首次流程权限。
