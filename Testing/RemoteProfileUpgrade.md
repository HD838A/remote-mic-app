# 遥控器配置升级兼容性

适用：当前候选的遥控器型号解码、配置升级和损坏恢复。旧版本号只作为历史背景。

## 准备与操作

1. 在隔离测试账号或隔离 UserDefaults 中保存旧 Chromecast 型号值 `chromecase_voice_remote`。同时保存小米设备、自定义按键映射和选中设备。
2. 用候选版本读取设置。
3. 检查没有“遥控器设备配置”读取失败提示，两个设备、选中设备和自定义映射均保留。
4. 保存配置并再次启动，确认当前型号值为 `chromecast_voice_remote`，映射仍一致。
5. 使用正常当前型号配置重复步骤；使用真正损坏的 JSON 确认仍告警并保留 `.corrupt` 备份。
6. 在隔离配置写入无法解码的合成 JSON 后启动 App，确认设置页内联显示损坏配置告警；告警不遮住健康配置，中文字号不小于 12pt，重启后不重复弹出无关提示。

丢失任一原有设备、绑定或映射，或旧拼写触发告警，均判定失败。损坏配置必须保留 `.corrupt` 备份并显示可读告警；不得静默丢弃健康配置。不要用用户生产设置进行破坏性实验。

## 用户数据完整性回归

以下用例必须在自动化中覆盖，并在发布前按真实窗口/重启路径抽验：

1. **同型号双设备隔离**：两台同型号遥控器分别保存不同自定义动作；连接第二台、切换画布、重启后，两台设备的动作仍各自独立，第二台首次出现时不能继承第一台的映射。
2. **自动选中不覆盖偏好**：上次选中小米，Apple 先连接且小米晚于重连宽限期才连接；当前画布可以临时回退，但重启后仍应恢复到小米，且两边映射不变。
3. **冲突合并不丢数据**：两条档案存在不同自定义映射时，不得自动合并；只有双方共享稳定硬件身份时才允许合并同一设备的 HID/BLE 档案，且必须保留合并前档案快照、双方动作和交互设置。
4. **旧格式升级**：删除旧档案中缺失的可选字段前，保存自定义映射；新版本读取后设备、选中项和动作保持不变，缺失字段补默认值而不是覆盖映射。
5. **损坏配置**：无法解码时保留原始数据备份，显示告警；不得用默认映射写回并静默删除旧档案。
6. **同型号同名设备**：两台同型号、同名但序列号或指纹不同的遥控器必须保留两条档案和两套映射，不得因为名称相同而合并。
7. **导入与恢复**：导入完整配置后设备、选中项、动作、快捷键和 APP 档案保持不变；从合并前快照恢复后，双方原始档案和选中项可验证恢复。
8. **握手顺序**：HID 先到、BLE 后到或反向到达时，新标识不得写入另一台已连接遥控器的档案；无法证明同一台设备时保持独立档案。

9. **同一设备先有 HID**：用未登记的小米 RC001 或 RC003 先触发普通按键，再让 BLE 完成握手。分别检查首次登记和升级前已拆成「未知型号 HID + 已识别型号 BLE」的档案。仅在系统身份指纹唯一匹配时保留原 HID 档案，型号、蓝牙名称、电量和语音路由随该档案更新。原映射和选择保留，重启后仍只有一条档案。身份不符、型号冲突或双方自定义配置不同时不得把两条档案并为一条。

10. **BLE 先到与整组绑定**：先连接两只小米，选中 A 后按 B 的第一枚普通按键。B 有可核对指纹时必须走 B 的档案。无法证明身份时 B 要保持独立，A 的映射、播放与选中项不能被 B 的指纹覆盖。另准备两条同设备的历史档案，在其中一条保存独立基础绑定与设备方案。启动两次并再次触发运行期去重，检查绑定仍能执行。两条各有独立配置或配置库存读取失败时应保留两条，不能删去未知引用。

## 跨版本档案连续性

以下用例必须覆盖 1.9.21 → 2.0.8 → 2.0.9 的真实持久化形状：

1. **原档案沿用**：保存一条 1.9.21 格式档案，包含固定 UUID、蓝牙标识、HID 指纹、自定义动作、快捷键、App 配置、双击/长按、连发和交互设置。用当前版本加载并连续重启三次，UUID、选中项和全部自定义类别必须不变。
2. **重新登记沿用**：同一档案加载后，再次用相同蓝牙标识和相同 HID 指纹登记，必须返回原 UUID，不能新增档案。
3. **旧版覆盖恢复**：写入当前 fallback 档案，同时保留 `buttonInteractionMigrationBackup` 中的旧自定义档案和指向旧 UUID 的 `unifiedBaseBindings`。启动后必须把旧自定义类别补入当前档案，并把作用域绑定重映射到当前 UUID。当前选中项不能改变。再用同一 fallback 场景删除 `unifiedBaseBindings`，确认仅靠未知型号、无 HID 指纹的单条 fallback 和同蓝牙标识的旧档案也能恢复快捷键、App 配置、双击/长按和连发。
4. **HID/BLE 分裂恢复**：同一设备同时存在 BLE-only 当前档案和 HID 当前档案，旧档案同时带两者标识。恢复必须优先匹配 HID 档案，作用域绑定必须落到 HID 档案；BLE-only 档案不能被写入另一台设备的配置。
5. **不覆盖当前配置**：当前档案已有自定义动作时，恢复不得用备份值覆盖；只允许补齐作用域绑定。
6. **歧义不猜**：两条当前档案共享同一 HID 指纹时，旧档案的恢复目标不唯一，必须保持原状。
7. **无档案不猜**：孤儿绑定找不到任何历史档案时，必须保持旧 UUID 和默认动作，不得猜测归属。
8. **同型号隔离**：两条同型号但标识不同的当前档案，备份只匹配其中一条时，另一条必须保持默认。
9. **2.0.8 去重后只剩备份**：当前活动档案为已知型号、快捷键仍为默认，旧档案只在 `buttonInteractionMigrationBackup`，且没有 `unifiedBaseBindings`。启动后必须补回旧 `.customShortcut` 动作和快捷键；已有自定义动作不得覆盖；重启后保持。
10. **快捷键恢复只执行一次**：完成上一条恢复后，把当前档案快捷键重置为默认，再次启动不得从旧快照回放。
11. **冲突快捷键不猜**：两份历史档案给同一按键不同快捷键时，保持当前默认值，不得任选其一。
12. **切换档案立即评估**：多设备下先选中 A，再选中 B；B 的旧快捷键只在备份时，切换后必须恢复 B，A 保持默认。
13. **重置和导入不回放**：完成快捷键恢复后执行“恢复默认”，或导入另一份配置，再次启动不得从旧快照补回快捷键。

上述任一项在健康档案上改变 UUID、删除自定义类别、把配置写到另一台设备或在重启后回退，均判定失败。已由 1.9.21 覆盖的 fallback 保留当前 UUID，只恢复配置，不伪造旧 UUID。

自动化基线：`RemoteProfileContinuityTests` 覆盖上述 1.9.21 → 2.0.8 → 2.0.9 连续性、fallback 恢复、HID 优先重映射、不覆盖当前配置、歧义不猜、无档案不猜、同型号隔离、去重后只剩备份的快捷键恢复和一次性标记。

## 证据与边界

运行 `swift test --disable-keychain`。定向复验可使用 `--filter 'RemoteButtonsTests|RemoteDeviceNameIntegrationTests|RemoteProfilePersistenceTests|RemoteProfileContinuityTests|SettingsPageRegressionTests'`。
2026-11-20 定向运行 **319 tests / 4 suites passed**；公开模式全量 **1567 tests / 113 suites passed**。测试驱动真实 AppSettings 加载，覆盖隔离配置、损坏恢复、同型号设备隔离、自动回退、旧格式升级、内联告警布局和现有持久化基线。
2026-11-22 新增 **27 项跨版本连续性测试**；覆盖原 UUID 沿用、1.9.21 fallback 恢复、无作用域绑定的 fallback 恢复、2.0.8 去重后只剩备份的快捷键恢复、一次性标记、切换档案恢复、重置/导入不回放、冲突不猜、HID 优先重映射、不覆盖当前配置、无档案不猜和同型号隔离。定向 27 项通过，公开模式全量 **1643 tests / 114 suites passed**，公开模式构建通过。
自动化不替代用户升级验收。此修改不改变硬件协议、语音会话和音频路径。
现场失败日志可由用户主动提供 `.rmlog`，支持环境仅提取稳定错误类型；不得提交原始日志或私钥。
