# 自定义快捷键预设与标准键盘选择测试手册

## 适用范围

- 适用版本：`1.9.3 (125)` 当前功能工作区编译包。
- 适用分支：功能通过 PR 合入前使用当前开发分支；合入后使用对应 `main` 提交。
- 测试包：`dist/SayAll.app`（只有实际完成 Developer ID 签名、公证和验证的包才可作为安装测试包分发；普通本地编译产物只用于开发机验证）。
- 测试目标：确认用户不按实体键盘，也能从常用组合或标准键盘配置遥控器快捷键；同时保留原有快捷键录入方式和旧配置。

## 测试前准备

1. 退出其他版本的无线麦，记录本次测试包版本、Build 和 Commit。
2. 在“系统设置 → 隐私与安全性”中为本次测试包开启“输入监控”和“辅助功能”。如果替换 App 后权限失效，先重新授权并彻底退出、重新打开 App。
3. 连接一只小米无线遥控器，并确认一个未承载重要动作的普通按键可被识别；建议使用“菜单键双击”。
4. 打开“按键映射”，启用自定义映射，点击待测按键的单击、双击或长按卡片，再选择“自定义快捷键”。
5. 准备 TextEdit，保留一段可复制、粘贴、撤销和查找的普通文本。不要用密码框、Token 输入框或生产数据测试。
6. 确认 Spotlight 的系统快捷键仍为 `Command + Space`，不要为了测试临时关闭它。

## 用例 0：动作分类快速筛选

1. 点击一个普通遥控器按键的单击、双击或长按卡片，打开动作编辑区。
2. 检查顶部依次显示“全部 / 基础按键 / 系统与媒体 / 自定义动作”四个胶囊按钮，默认选中“全部”。
3. 依次点击四个筛选项，检查下方动作列表立即更新。
4. 选择“自定义动作”，确认“自定义快捷键”等自定义项和“打开具体 APP”动作都可访问；再切回“全部”。
5. 关闭动作编辑区并编辑另一个遥控器按键，确认筛选恢复为“全部”。

预期结果：选中项使用清晰的语义蓝胶囊，其余项保持可辨识边框；每次只筛选动作候选，不修改当前映射，不立即执行动作，也不改变已保存的快捷键或目标 APP。四个按钮在 `800 × 650` 中文、英文、浅色和深色界面中保持单行、文字不小于 12pt 且无横向滚动。

失败判定：筛选后动作丢失或分类错误；“自定义动作”看不到具体 APP 动作；切换筛选即执行或改写当前动作；编辑其他按键时保留难以理解的旧筛选；按钮裁切、换行、文字过小或依赖下拉框、Popover、Sheet。

## 用例 1：常用组合无需实体键盘

1. 在自定义快捷键编辑区选择“常用组合”。
2. 依次检查复制、粘贴、剪切、撤销、重做、全选、保存、查找、切换 APP、聚焦搜索、关闭窗口、退出 APP、锁定屏幕、截取区域和强制退出。
3. 点击“复制”，关闭动作编辑区后重新打开。
4. 将 TextEdit 放到前台并选中一段普通文本，用真实遥控器触发该映射，再执行粘贴确认剪贴板内容。
5. 返回设置页，将同一映射改为“聚焦搜索”，再次关闭并重新打开动作编辑区。
6. 用真实遥控器触发映射。

预期结果：

- 点击预设时只保存，不会立刻执行复制、锁屏、退出或其他系统动作。
- 当前快捷键分别显示 `⌘C` 和 `⌘Space`，关闭编辑区或切换页面后不会丢失。
- 遥控器触发“复制”只复制一次；触发“聚焦搜索”会打开 Spotlight。

失败判定：选择预设时立即执行动作；显示的组合与预设不符；重新打开后丢失；遥控器触发无效、触发两次或执行其他动作。

## 用例 2：标准键盘配置单键或组合键

1. 选择“标准键盘”。
2. 不选择任何组合键，直接选择 `Space`，确认当前值为单独的 `Space`。
3. 依次选择 Command 和 Shift，确认二者都显示选中；再点一次 Shift，确认只有 Command 保持选中。
4. 在主键区选择字母 `K`，确认当前快捷键为 `⌘K`。
5. 分别从主键区、方向与导航键、扩展功能键、数字键盘选择 `Return`、`Page Down`、`F20` 和数字键盘 `Enter`。
6. 选择 Fn，再选择 `F12`；关闭并重新打开编辑区。
7. 在 `800 × 650` 测试窗口中滚动整个编辑区，检查全部键区均可到达；再分别检查浅色、深色和英文界面。

预期结果：

- 组合键可以全部留空，也可以多选和取消；选择主键后立即保存单键或组合键。
- `Return` 与数字键盘 `Enter`、普通数字与数字键盘数字保持不同虚拟键码语义。
- `F1` 至 `F20`、方向键、Home、End、Page Up、Page Down、向前删除和数字键盘均可选。
- 重开后当前值和组合键状态一致；页面不使用下拉列表、Popover 或 Sheet，中文文字不小于 12pt，窄窗口中没有横向裁切或窗口几何变化。

失败判定：必须按实体键盘才能保存；组合键只能单选；键区缺失；普通键与数字键盘键混淆；重开后组合变化；任一键不可通过滚动到达、文字裁切或字号过小。

## 用例 3：单独左/右修饰键

1. 在“单独修饰键”中依次选择左 Option 和右 Option，每次都关闭并重新打开编辑区确认显示名称。
2. 使用能区分左右虚拟键码的本机测试工具或目标 APP，分别用真实遥控器触发左、右 Option。
3. 对左/右 Command、Control、Shift 和 Fn 重复配置与触发。
4. 每次触发后立即在实体键盘输入普通文字并使用其他系统快捷键。

预期结果：

- 配置显示明确的左/右名称，重启 App 后仍保持。
- 目标 APP 收到对应一侧修饰键的一次按下和一次释放。
- 触发后修饰键不会保持按下；实体键盘输入、窗口切换和后续快捷键均正常。

失败判定：左右侧被合并、只收到按下没有释放、触发后菜单或键盘保持修饰状态、后续文字变成符号或系统快捷键异常。

## 用例 4：真实键盘录入单键、单独修饰键和组合键

1. 点击“录入快捷键”，看到醒目的等待按键状态后单独按下 `Space`，确认页面显示录入成功和 `Space`，且本次空格没有输入到其他 APP。
2. 再次录入，单独按下并释放左 Option，确认页面只在释放后完成录入并显示“左 Option”；对右 Command、左/右 Control、Shift 和 Fn 重复检查。
3. 再次录入，先按住 Command，再按 `Space`，确认不会提前保存为单独 Command，Spotlight 没有弹出，页面显示 `⌘Space`。
4. 同样验证单独的 `F5` 和一个方向键可以录入且不带修饰符。
5. 不点击录入时直接按另一个系统快捷键，确认无线麦不会常驻拦截。
6. 通过预设改成 `⌘C`，再通过真实键盘录成 `⌥⌘Esc`，确认三种入口可互相覆盖当前值。

预期结果：只有主动进入录入状态后才捕获一次键盘事件；普通单键保存零修饰标志，单独修饰键保留左右侧键码并发送成对按下/释放，修饰键后接主键时保存完整组合；录入、预设和标准键盘共用同一当前值，执行结果一致。

失败判定：单键必须附加修饰键才能保存；修饰键按下时过早完成导致组合键无法录入；左右侧被合并；未进入录入状态也拦截键盘；系统快捷键抢先执行；页面一直等待；三种入口保存到不同配置或切换后出现旧值。

## 用例 5：前后台、触发方式与持久化

分别覆盖以下独立状态：

- [ ] 无线麦在前台、目标 APP 在后台。
- [ ] 无线麦在后台、TextEdit 在前台。
- [ ] 目标 APP 刚启动尚未稳定。
- [ ] 单击触发只执行一次。
- [ ] 双击触发不同时执行单击。
- [ ] 长按触发不因遥控器连发而重复执行快捷键。
- [ ] App 重启后配置保持。
- [ ] 切换到其他动作再切回后配置保持。
- [ ] 导出再导入后，普通单键、组合键、预设、标准键盘和单独左右修饰键的键码与标志保持。
- [ ] 两只遥控器的独立 Profile 不串用配置。

任一状态出现动作丢失、重复、发给错误 APP、配置串用或重启后变化，都判定失败。

## 稳定功能回归

- [ ] 旧版已录入的自定义快捷键无需迁移即可显示和执行。
- [ ] Escape、Return、方向键、音量和播放控制等内置动作行为不变。
- [ ] 语音键仍只负责现有语音输入与 Fn 功能。
- [ ] 实体遥控器单击、双击、长按识别行为不变。
- [ ] iPhone Nearby、Apple Watch 和网页版遥控器仍只触发 Mac 端已有白名单映射。
- [ ] 自定义 APP 的快捷键聚焦录入入口与输入框学习不受影响。
- [ ] 关闭自定义映射后恢复默认行为，再开启时配置仍保留。
- [ ] `800 × 650` 下逐一点击设置页所有侧边栏入口，导航、页头、主要控件和滚动无裁切且窗口几何不变。

## 日志收集

1. 记录失败发生的本地时间、遥控器按键、单击/双击/长按、已配置快捷键、目标 APP 及前后台状态。
2. 从菜单栏打开日志目录，或收集 `~/Library/Logs/RemoteMic/runtime.log`。
3. 重点查找 `SHORTCUT CAPTURE`、`HID BUTTON`、`SHORTCUT ACTION submitted` 和对应按键动作记录。
4. 日志中的“收到按键”或“入队”不代表目标 APP 已经执行快捷键；必须同时描述屏幕上的最终结果。
5. 不要在日志说明中附带密码、Token、私人输入内容或生产数据。

## 自动化、代理实测与用户实测边界

- 自动化覆盖：预设键码与修饰标志、标准键盘关键分区、F1/F20、导航键和数字键盘、左右 Option 键码、单独修饰键按下/释放与释放标志清空、普通自定义快捷键执行回归、设置页结构、本地化和编译。
- 代理可完成：源代码检查、自动化、编译、离屏页面截图及静态字号/布局检查；这些结果不能证明 WindowServer、系统热键、第三方 APP 或实体遥控器最终响应。
- 用户或真实桌面会话必须完成：Spotlight 实际打开、Left/Right Option 等左右语义、当前权限门提示、真实遥控器三种触发、不同前后台状态、浅色/深色/英文页面，以及双遥控器 Profile。
- 未完成真实遥控器、权限门和真实目标 APP 验收前，只能说明开发与自动化验证通过，不能说明已经完成真机验收。
