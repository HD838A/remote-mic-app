# 蓝牙断连后的虚拟麦克风释放测试

## 适用版本或分支

- 版本：当前待验证 PR 或已合入 `main` 的精确 Commit；原功能分支 `codex/fix-window-background-drag` 仅用于历史审计
- 平台：macOS 14 及以上
- 设备：RC001、RC003；双遥控器用例需两只已登记设备
- 虚拟设备：`MiRemoteV 2ch`

## 测试前准备

1. 安装并选择 `MiRemoteV 2ch` 作为 Remote Mic 的语音输出。
2. 准备一款可选择麦克风的会议或录音 App。
3. 分别准备“跟随系统默认输入”和“明确选择 MiRemoteV 2ch”两种配置。
4. 打开 `~/Library/Logs/RemoteMic/runtime.log`，记录每个用例的本地开始与结束时间。
5. 确认 MacBook 内置麦克风可正常录音；若使用台式 Mac，准备另一个可用的物理输入设备。

## 用例 1：单遥控器移出范围后释放

1. 连接一只 RC001 或 RC003，确认 App 显示已连接。
   - 预期：日志出现 `AUDIO REBIND finished reason=bluetooth_ready success=true`，遥控器语音可用。
2. 让遥控器离开蓝牙范围或关闭遥控器，直到 App 显示断连或重连中。
   - 预期：尾音排空后日志出现 `AUDIO RELEASE completed reason=bluetooth_not_ready`。
3. 用“音频 MIDI 设置”或 CoreAudio 检查 `MiRemoteV 2ch`。
   - 预期：设备仍显示在列表中，但 Remote Mic 不再保持音频 IO 运行。

失败判定：最后一只遥控器断开超过 2 秒后仍无 `AUDIO RELEASE completed`，或 Remote Mic 仍保持该设备运行。

## 用例 2：系统默认输入自动回退与恢复

1. 遥控器已连接时，把 macOS 系统默认输入设为 `MiRemoteV 2ch`，会议 App 选择“系统默认”。
2. 让遥控器断连。
   - 预期：日志出现 `AUDIO DEFAULT_INPUT fallback_applied`；系统默认输入切到内置麦克风或其他物理输入；会议 App 能录到本机声音。
3. 让遥控器重新连接。
   - 预期：日志出现 `AUDIO DEFAULT_INPUT restore_applied`；系统默认输入恢复为 `MiRemoteV 2ch`；遥控器语音恢复。

失败判定：断连后仍以 `MiRemoteV 2ch` 作为系统默认输入、物理麦克风无声，或重连后虚拟音频未恢复。

## 用例 3：断连期间尊重用户手动选择

1. 按用例 2 触发自动回退。
2. 断连期间，手动把系统默认输入改为另一个 USB 麦克风。
3. 重新连接遥控器。
   - 预期：日志出现 `AUDIO DEFAULT_INPUT restore_skipped`；默认输入保持用户选择的 USB 麦克风。
   - 预期：蓝牙照常重连，Remote Mic 仍重新绑定自己的语音输出；系统输入改动不能阻止无线麦音频通道恢复。

失败判定：重连覆盖了用户断连期间手动选择的输入设备，或因为系统输入被修改而没有恢复 Remote Mic 音频通道。

## 用例 4：断连期间修改 Remote Mic 语音输出

1. 遥控器连接时，在 Remote Mic 中记录当前“语音输出”设备，然后让遥控器断连。
2. 在 Remote Mic 中把“语音输出”改为另一个可用虚拟设备。
3. 重新连接遥控器。
   - 预期：蓝牙照常重连；Remote Mic 绑定最新选择的设备，不恢复原来的设备。
4. 再次断连，把 Remote Mic 的“语音输出”改为“不输出语音”，然后重连。
   - 预期：蓝牙仍可连接和执行普通按键，但不重新建立虚拟音频输出。

失败判定：重连后仍绑定旧设备，或把“不输出语音”自动改回虚拟设备。

## 用例 5：第三方 App 明确固定虚拟设备

1. 在会议 App 内明确选择 `MiRemoteV 2ch`，不要选择“系统默认”。
2. 断开遥控器并尝试录音。
   - 预期：Remote Mic 释放 IO，但会议 App 可能继续绑定常驻虚拟设备并收到静音。
3. 把会议 App 改为“系统默认”或物理麦克风。
   - 预期：本机录音恢复。

这不是失败：macOS 没有通用接口替第三方 App 修改其内部固定设备选择。

## 用例 6：双遥控器

1. 同时连接两只已登记遥控器。
2. 只断开其中一只。
   - 预期：没有 `AUDIO RELEASE completed`，另一只遥控器语音仍可用。
3. 再断开最后一只。
   - 预期：尾音排空后释放虚拟音频。

失败判定：第一只断开就导致另一只失去语音，或最后一只断开后不释放。

## 用例 7：手机与网页语音

1. 蓝牙遥控器断开时，分别从附近手机和网页版开始语音。
   - 预期：开始语音时自动重新绑定虚拟设备，音频正常进入 `MiRemoteV 2ch`。
2. 手机或网页语音传输期间制造蓝牙状态变化。
   - 预期：活动语音不被蓝牙断连释放动作切断。
3. 停止手机或网页语音，且没有任何蓝牙遥控器在线。
   - 预期：尾音排空后释放虚拟音频。

失败判定：手机/网页语音无法开始、传输中被蓝牙断连切断，或结束后持续占用。

## 用例 8：测试音

1. 没有蓝牙遥控器在线时发送测试音。
   - 预期：自动绑定设备，测试音完整播放。
2. 等待测试音结束。
   - 预期：没有其他语音来源时自动释放虚拟音频。

失败判定：测试音无法发送、被提前截断，或结束后持续占用。

## 用例 9：异常重连扫描窗口

适用：包含 PR #921 集成修正的候选。准备已登记 RC003，并记录候选源码提交。

1. 在没有已保存目标的独立配置中持续查找超过 20 秒，再唤醒设备。
   - 预期：持续扫描，不出现 `BLE SCAN TIMEOUT` 或恢复退避空窗。
2. 恢复已登记设备配置，分别覆盖缓存查询未命中、首次连接失败且 `cached_identifier_bypassed=true` 两种情况。
   - 预期：仍查询系统已连接候选；只允许采用已保存身份对应的设备。
3. 若没有可用候选且扫描无结果，等待 20 秒。
   - 预期：相同 generation 出现 `BLE SCAN TIMEOUT`，然后按既有 3～60 秒退避继续尝试，最终连接以 `BLE READY` 确认。
4. 分别在扫描期间执行手动重连、停止 App、休眠和蓝牙关闭再开启。
   - 预期：旧扫描窗口不能结束新一轮连接；停止或挂起时不继续扫描重试。
5. 设备恢复后，立即测试第一次普通按键及两次连续语音。
   - 预期：按键可用，首字和尾字完整；已就绪链路不被旧计时器断开。

失败判定：首次发现进入退避、扫描停滞不再重试、连接其他设备、旧计时器误断新连接，或首次语音失效。

本轮自动化覆盖生产共用发现顺序、统一准入、超时重试、递增退避、generation、生命周期和挂起判定。真实断线、离场、系统连接候选、休眠及语音回归仍待 RC003 现场验证；未触发目标失败条件不能记为通过。日志从 App 的“显示日志”入口收集，保留上述事件顺序，不采集语音内容。

## 用例 10：闲置后首次缓存直连失败

适用：包含 2026-11-11 缓存周期探测修复的候选。准备已登记 RC003，记录源码提交与版本。

1. 保持 App 运行，让现场 Mac 长时间睡眠后唤醒，复现首次 `BLE CONNECT TIMEOUT` 和 `cached_identifier_bypassed=true`。
   - 预期：扫描与退避持续推进。
2. 保持设备可用，等待冷却到期后的下一轮发现。
   - 预期：缓存直连探测间隔至少 60 秒，出现 `reason=cached_target_cooldown_elapsed`，随后通过实际连接和 `BLE READY` 确认恢复。
3. 设备离线至少 5 分钟，再使其恢复可用。
   - 预期：失败计数持续增长，退避保持上限 60 秒；缓存探测不会把重试重置为每 3 秒一次，设备恢复后能自动连接。
4. 在等待期间分别执行手动重连、退出、睡眠、蓝牙关闭再开启。
   - 预期：沿用即时手动恢复和系统挂起规则，旧回调不能结束新连接。
5. 恢复后立即完成第一次普通按键、极速语音按下/释放、两次连续语音及一次异常中断恢复。
   - 预期：首字及时，尾字完整，正常音频终态无丢弃、中断或 pending 样本。

失败判定：持续扫描数分钟后仍无缓存探测、冷却期内重复主动探测、退避被清零、连接其他设备、旧回调破坏新会话，或第一次语音不可用。

自动化验证策略与生产入口接线。反馈机器的真实睡眠、无线链路、RC003 和目标语音工具验收待完成。未复现首次连接失败时，本用例应记录为未覆盖。

## PR #921 唤醒发现补充验证

RC001 与 RC003 共用本次修改的 BLE 发现路径。下列用例分别执行并记录型号、源码提交、自动化结果、真实设备结果和目标语音工具结果。当前两个型号的新分支实机结果均待完成。

1. 使用已登记的小米遥控器，睡眠唤醒后通过同一 operation_id 和 generation 的 `BLE DISCOVERY operation_id=<操作号> ... source=target_identifier result=empty|skipped|not_adopted` 确认缓存未采纳目标，随后由 `connected_peripheral` 接回。另一轮覆盖无候选时 20 秒 `BLE SCAN TIMEOUT`，退避重连后接回。
2. 每次恢复后立即完成第一次语音、极速按下/释放、五次连续会话，记录首个有效 PCM 与可观察首字耗时；正常结束要求首尾完整、中断样本为零且 pending 归零。
3. 遥控器离线至少五分钟后恢复，验证扫描窗口、既有 3～60 秒退避、缓存冷却探测和首次语音；同时覆盖停止、睡眠、蓝牙开关及旧代次窗口作废。

未命中目标分支记为未覆盖。2026-11-07 的两次作者历史记录未证明新增系统候选兜底或 20 秒超时分支命中。当前集成候选的这些实机用例待验收；源码接线、策略测试与构建各自只证明对应边界。未触发发现流程的静默链路反馈需独立定位。

## 稳定功能回归

- RC003 普通语音：`STREAM_START → AUDIO → STREAM_STOP`，无需主动 `MIC_OPEN`，尾音完整。
- RC001 短语音尾包不丢失。
- Fn 轻触模式在断连时完成停止手势，不遗留 Fn 按下状态。
- 音频设备改变后，遥控器在线时仍能自动恢复；遥控器离线时不会因硬件监听重新占用。
- App 退出后不保留 Remote Mic 的音频 IO。

## 验证边界

- 自动化测试验证生命周期与默认输入决策，不等于真实 CoreBluetooth、CoreAudio 驱动和第三方 App 验收。
- 代理可验证构建、单元测试、日志和本机 CoreAudio 状态。
- RC001 / RC003 距离断连、双遥控器、真实会议 App、手机与网页语音必须由真实硬件和真实 App 完成。
