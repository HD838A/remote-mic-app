# 蓝牙断连后的虚拟麦克风释放测试

## 适用版本或分支

- 分支：`codex/fix-window-background-drag`
- 平台：macOS 14 及以上
- 设备：RC001、RC003；双遥控器用例需两只已登记设备
- 虚拟设备：`MiRemoteV 2ch`

## 测试前准备

1. 安装并选择 `MiRemoteV 2ch` 作为 Remote Mic 的语音输出。
2. 准备一款可选择麦克风的会议或录音 App。
3. 分别准备“跟随系统默认输入”和“明确选择 MiRemoteV 2ch”两种配置。
4. 记录每个用例的本地开始与结束时间；用例结束后通过“权限与隐私 → 发送诊断信息”提交当天和昨天的脱敏日志。
5. 确认 MacBook 内置麦克风可正常录音；若使用台式 Mac，准备另一个可用的物理输入设备。

## 用例 1：单遥控器移出范围后释放

1. 连接一只 RC001 或 RC003，确认 App 显示已连接。
   - 预期：日志出现 `AUDIO REBIND finished reason=bluetooth_ready success=true`，遥控器语音可用。
2. 让遥控器离开蓝牙范围或关闭遥控器，直到 App 显示断连或重连中。
   - 预期：尾音排空后日志出现 `AUDIO RELEASE completed reason=bluetooth_not_ready`。
3. 用“音频 MIDI 设置”或 CoreAudio 检查 `MiRemoteV 2ch`。
   - 预期：设备仍显示在列表中，但 Remote Mic 不再保持音频 IO 运行。

失败判定：最后一只遥控器断开超过 2 秒后仍无 `AUDIO RELEASE completed`，或 Remote Mic 仍保持该设备运行。

## 用例 2：系统默认输入自动回退与恢复

1. 遥控器已连接时，把 macOS 系统默认输入设为 `MiRemoteV 2ch`，会议 App 选择“系统默认”。
2. 让遥控器断连。
   - 预期：日志出现 `AUDIO DEFAULT_INPUT fallback_applied`；系统默认输入切到内置麦克风或其他物理输入；会议 App 能录到本机声音。
3. 让遥控器重新连接。
   - 预期：日志出现 `AUDIO DEFAULT_INPUT restore_applied`；系统默认输入恢复为 `MiRemoteV 2ch`；遥控器语音恢复。

失败判定：断连后仍以 `MiRemoteV 2ch` 作为系统默认输入、物理麦克风无声，或重连后虚拟音频未恢复。

## 用例 3：断连期间尊重用户手动选择

1. 按用例 2 触发自动回退。
2. 断连期间，手动把系统默认输入改为另一个 USB 麦克风。
3. 重新连接遥控器。
   - 预期：日志出现 `AUDIO DEFAULT_INPUT restore_skipped`；默认输入保持用户选择的 USB 麦克风。
   - 预期：蓝牙照常重连，Remote Mic 仍重新绑定自己的语音输出；系统输入改动不能阻止无线麦音频通道恢复。

失败判定：重连覆盖了用户断连期间手动选择的输入设备，或因为系统输入被修改而没有恢复 Remote Mic 音频通道。

## 用例 4：断连期间修改 Remote Mic 语音输出

1. 遥控器连接时，在 Remote Mic 中记录当前“语音输出”设备，然后让遥控器断连。
2. 在 Remote Mic 中把“语音输出”改为另一个可用虚拟设备。
3. 重新连接遥控器。
   - 预期：蓝牙照常重连；Remote Mic 绑定最新选择的设备，不恢复原来的设备。
4. 再次断连，把 Remote Mic 的“语音输出”改为“不输出语音”，然后重连。
   - 预期：蓝牙仍可连接和执行普通按键，但不重新建立虚拟音频输出。

失败判定：重连后仍绑定旧设备，或把“不输出语音”自动改回虚拟设备。

## 用例 5：第三方 App 明确固定虚拟设备

1. 在会议 App 内明确选择 `MiRemoteV 2ch`，不要选择“系统默认”。
2. 断开遥控器并尝试录音。
   - 预期：Remote Mic 释放 IO，但会议 App 可能继续绑定常驻虚拟设备并收到静音。
3. 把会议 App 改为“系统默认”或物理麦克风。
   - 预期：本机录音恢复。

这不是失败：macOS 没有通用接口替第三方 App 修改其内部固定设备选择。

## 用例 6：双遥控器

1. 同时连接两只已登记遥控器。
2. 只断开其中一只。
   - 预期：没有 `AUDIO RELEASE completed`，另一只遥控器语音仍可用。
3. 再断开最后一只。
   - 预期：尾音排空后释放虚拟音频。

失败判定：第一只断开就导致另一只失去语音，或最后一只断开后不释放。

## 用例 7：手机与网页语音

1. 蓝牙遥控器断开时，分别从附近手机和网页版开始语音。
   - 预期：开始语音时自动重新绑定虚拟设备，音频正常进入 `MiRemoteV 2ch`。
2. 手机或网页语音传输期间制造蓝牙状态变化。
   - 预期：活动语音不被蓝牙断连释放动作切断。
3. 停止手机或网页语音，且没有任何蓝牙遥控器在线。
   - 预期：尾音排空后释放虚拟音频。

失败判定：手机/网页语音无法开始、传输中被蓝牙断连切断，或结束后持续占用。

## 用例 8：测试音

1. 没有蓝牙遥控器在线时发送测试音。
   - 预期：自动绑定设备，测试音完整播放。
2. 等待测试音结束。
   - 预期：没有其他语音来源时自动释放虚拟音频。

失败判定：测试音无法发送、被提前截断，或结束后持续占用。

## 稳定功能回归

- RC003 普通语音：`STREAM_START → AUDIO → STREAM_STOP`，无需主动 `MIC_OPEN`，尾音完整。
- RC001 短语音尾包不丢失。
- Fn 轻触模式在断连时完成停止手势，不遗留 Fn 按下状态。
- 音频设备改变后，遥控器在线时仍能自动恢复；遥控器离线时不会因硬件监听重新占用。
- App 退出后不保留 Remote Mic 的音频 IO。

## 日志收集

1. 在“权限与隐私”点击“发送诊断信息”；本地 `.rmlog` 为加密文件，不能直接复制为文本。
2. 标注用例、设备型号、会议 App、会议 App 的输入模式、开始/结束时间。
3. 重点搜索：`BLE DISCONNECTED`、`AUDIO RELEASE`、`AUDIO DEFAULT_INPUT`、`AUDIO REBIND`、`ATVV STREAM summary`。
4. 不需要提交用户语音内容。

## 验证边界

- 自动化测试验证生命周期与默认输入决策，不等于真实 CoreBluetooth、CoreAudio 驱动和第三方 App 验收。
- 代理可验证构建、单元测试、日志和本机 CoreAudio 状态。
- RC001 / RC003 距离断连、双遥控器、真实会议 App、手机与网页语音必须由真实硬件和真实 App 完成。
