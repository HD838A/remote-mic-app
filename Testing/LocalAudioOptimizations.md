# 本地最小音频优化验收

适用分支：`local/minimal-audio-optimizations-20260907`。稳定基线：`e464c52`。

## 准备

- 退出其他 Remote Mic 实例后启动本次独立测试包；不覆盖 Applications 中的版本。
- 确认蓝牙、输入监控和辅助功能权限，RC003 已连接，微信输入法沿用原配置，输入为 MiRemoteV 2ch。
- 先用原有包记录正常短语音、续接、倒计时行为，CPU 对照使用相同 Release 配置和窗口状态。

## 必测流程

| 场景 | 操作 | 预期 / 失败判定 |
| --- | --- | --- |
| 普通语音 | 按住即说 5 秒，松开，重复 5 次；切换前台 App 后再试 | 首句和尾句可识别，松开正常结束；第二次才成功即失败 |
| 续接 | 每段 50～60 秒松开，在 2 秒内重按，至少连续 3 段 | 微信保持同一会话；每段重新 60 秒倒计时；橙/红提醒正常；重复 Fn 或清空音频即失败 |
| 等待超时 | 50～60 秒松开后不重按，等 2 秒 | 正常释放 Fn、停止静音和提醒；下一次可正常输入 |
| 锁屏/熄屏 | 空闲时锁屏、熄屏，再解锁；随后第一次语音 | 无活跃录音时释放引擎，唤醒后恢复；首次无声音即失败 |
| 等待与系统事件交错 | 续接等待期间发生熄屏/锁屏；2 秒内重按或等超时 | 等待仍属活跃语音，不能被提前释放；超时后才能收尾 |
| 断连/重连 | 空闲与续接等待期间分别关闭遥控器，重新连接 | 等待和 Fn 正常清理；最后设备断连后释放；重连首句正常 |
| 设备选择 | 暂停期间手动更改系统输入或 App 音频设备，再恢复 | 不覆盖用户的新选择；MiRemoteV 无效时不能误报可写入 |
| 首次设置/测试音 | 检查原有语音样本门禁、播放测试音 | 收到首批样本才通过；测试音不被空闲释放截断 |

Fn 点按模式另测短语音、快速重按、续接和断连，排空结束不能吞掉停止 Fn。其他已有音源若启用，测试活跃期间锁屏不能被本次资源释放中断。

## 资源检查

- 分别在设置窗口可见、关闭后录音 30 秒，对照活动监视器中的 CPU；不要把构建过程计入。
- 运行 `pmset -g assertions`，核对空闲熄屏后与 MiRemoteV 相关的 CoreAudio 断言是否解除，再实际等待自动系统睡眠。其他进程的断言应单独区分。
- 亮屏且遥控器连接时保留音频预热是预期行为，本轮不实现逐句开关引擎。
- 日志：`~/Library/Logs/RemoteMic/runtime.log`；记录测试时间和现象，关注 `SYSTEM AUDIO`、`AUDIO RELEASE`、`AUDIO HEALTH`、`continuation_`、`VOICE FN HOLD`。
