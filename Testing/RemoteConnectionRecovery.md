# 遥控器有限恢复与手动连接测试

- 适用：PR #1072 当前候选 Head；macOS；产品行为以 `feature/remote-connection-lifecycle/PRODUCT_SPEC.md` 为准。
- 状态：自动化与生产 UI 证据见 PR；以下真实设备用例尚未验收，不代表兼容或发布通过。

## 测试前准备

1. 准备真实 RC001、RC003 及已配对的 Mac，完成蓝牙、输入监控和辅助功能授权。
2. 分别在两只遥控器上保留不同的普通按键映射，确认已完成至少一次真实语音连接。
3. 准备已配置正确麦克风和 Fn 行为的目标语音工具。
4. 在 App 内打开日志入口，记录开始和结束时间。需要反馈时只发送脱敏诊断或项目支持的加密日志，不粘贴设备身份或语音内容。

## 用例 1：旧档案长期离线

1. RC003 保持连接，RC001 关机或离开范围。
2. 重启候选 App，等待至少十分钟，不重复打开连接页。
3. 检查 RC001 位于“连接过的设备”且显示未连接，原型号和映射仍保留。
4. 在 RC003 上执行普通按键和第一轮完整语音。

预期：RC001 不出现每分钟盲连；发现窗口结束后无周期连接尝试；RC003 正常工作。
失败：旧档案固定间隔连接超时、日志持续增长、映射丢失或在线设备被断开。

## 用例 2：设备返回与单设备手动恢复

1. 让离线 RC001 开机并返回范围。
2. 分别在发现窗口内、窗口结束后、仅系统 HID 连接且不广播时操作。
3. 自动恢复未出现时打开连接页，点击 RC001 对应的“连接”。
4. 确认其成功后复用原档案，第一次按键和语音即成功。

预期：有可观察出现事件时立即进入有限恢复；未观察到时可直接手动操作，不等待分钟级退避。
失败：必须重启电脑或 App；没有手动入口；第二、第三次语音才可用；新建重复档案。
分别记录：出现到观察、观察到发起、发起到 Ready、按下到首个 PCM 和可观察首字的时间。无法观察的阶段写未知。

## 用例 3：预算耗尽与取消

1. 让刚在线的设备断开并保持不可达，观察自动恢复。
2. 等待最多三次或总计 60 秒的预算结束。
3. 重复前台切换、广播观察、蓝牙关闭再打开和睡眠唤醒。
4. 点击该设备“连接”，在连接过程中取消；五秒后再次重试。

预期：耗尽后显示自动连接已暂停，重复事件不重置预算。手动操作最长 30 秒且至多一次握手，取消后无迟到 Ready。重复点击不启动并行连接。
失败：自动无限重试、主计时被每次扫描重置、取消后仍报成功、重试按钮永远无法恢复。

## 用例 4：坏设备与多设备隔离

1. 让其中一台持续握手失败，同时让另一台正常出现。
2. 在正常设备收音时，对另一台执行连接、失败和取消。
3. 让故障设备短暂 Ready 后反复断开，再测试每次 Ready 超过三十秒的周期掉线。

预期：发现不被坏候选占住；正常设备的普通键、Fn 和音频不被另一台的状态取消。短暂 Ready 不刷新预算，十分钟内六次自动连接上限仍生效。
失败：错误设备串线、当前语音被结束、尾字丢失、恢复计数永远从零开始。

## 用例 5：改名、蓝牙和权限

1. 在系统设置中给已登记设备改名，然后重新连接。
2. 分别测试蓝牙关闭、权限不足、系统睡眠和会话恢复。
3. 检查页面原因和系统设置入口，恢复条件后使用未耗尽预算或手动恢复。

预期：改名不改变身份和映射；外来硬件仍不误识别；蓝牙或权限阻断时不做无效连接；系统睡眠没有新扫描。
失败：改名后拒绝原设备、错误匹配其他型号、关闭蓝牙仍尝试连接、耗尽设备被系统通知自动复活。

## 用例 6：页面和稳定回归

1. 在生产最小整窗 1067 × 760 中，检查连接页和按键页之间的导航及滚动。
2. 核对中英文、浅深色、全部断开、一在线一离线、恢复中、失败和暂停。
3. 全部断开时确认直接展开“连接过的设备”，没有指向同一列表的重复查看按钮。
4. 用鼠标及键盘操作连接、取消、重试和折叠；主卡片继续只显示在线设备。
5. 对普通按键、极速语音按下/释放、快速连续两句、异常断连和睡眠后第一次语音执行稳定回归。

预期：中文不低于 12pt；主要操作、失败原因可达；名称可辨认；无窗口几何变化。正常语音不 flush，尾包自然排空。
失败：入口不可见、文字被缩小或裁切、操作错误设备、首次语音失败或首尾音损失。
Apple、Chromecast 和手机/网页/Watch 入口分别回归，不以小米通过替代其他来源。

## 自动化与证据边界

- `RemoteConnectionRecoveryTests` 使用虚拟时间验证预算、冷却、短暂 Ready、周期掉线、取消、迟到结果和多设备独立性。
- `BluetoothLifecycleTests` 验证既有发现、扫描、代次和会话门禁；`AppLoggerTests` 验证密集拒绝事件的聚合上限。
- 生产 `SettingsView` 的隔离夹具截图只证明页面渲染；夹具不会发起真实蓝牙或录音。
- 模拟、策略测试与构建不能证明真实 CoreBluetooth 的发现时机、功耗、首字、尾音和第三方工具文字结果。
- 本 PR 只改 macOS；Windows 未修改，跨平台等价验收仍未完成。

## 日志判定

核对 `BLE DISCOVERY_WINDOW`、`BLE RECOVERY_WINDOW`、`BLE RECOVERY_ATTEMPT`、`BLE CONNECTING`、`BLE READY` 和 `BLE DISCONNECTED`。
使用窗口 operation_id 与 attempt_id 关联请求、尝试和唯一终态。Ready 只证明本地握手，不能代替最终文字上屏。
等待或暂停时不应出现周期超时；`BLE REJECTED` 与 `BLE ADOPT IGNORED` 应聚合，不逐设备刷屏。
