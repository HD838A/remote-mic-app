# SayAll 跨平台硬件功能兼容合同

## 文档地位与适用范围

- 版本：1.0，2026-09-05。
- 适用于 SayAll 当前及未来接入的实体遥控器、蓝牙设备、USB/HID 设备、带触摸表面的控制器，以及其他能够提供按键或语音输入的硬件。
- 同时约束 macOS 与 Windows 产品。平台可以使用不同系统 API、驱动和虚拟音频设备，但用户可观察到的功能语义、生命周期、失败处理和验收门槛必须一致。
- 具体设备测试手册可以增加型号专属能力和用例，不得降低本合同。语音硬件还必须同时满足 [`HardwareVoiceAudioContract.md`](HardwareVoiceAudioContract.md)。
- 本合同中的“必须”是兼容和发布门禁；“建议”允许按平台实现，但偏离时必须在设备手册中说明原因、替代行为和实机证据。

## 核心原则

1. 统一的是产品行为，不是底层协议。BLE、HID、USB、厂商服务、macOS `CGEvent` 或 Windows `SendInput` 都只能作为适配层实现细节。
2. 能力必须显式声明。硬件没有麦克风、触摸、电池或某个物理键时，应标记为不支持或未知，不得伪造数据、复用含义不同的按键或静默改用其他输入源。
3. 第一次操作就必须成功。不能把第二次或第三次按键、语音会话成功视为兼容。
4. 正常生命周期必须完整闭合。按下必须对应释放或取消，语音开始必须对应正常排空完成或带原因的强制结束，触摸开始必须对应结束或取消。
5. 真实设备验收不可替代。单元测试、协议回放、模拟器、构建、签名和安装器各自只能证明自身边界。

## 平台无关适配器合同

每个硬件适配器必须提供以下稳定信息，名称可以按语言实现，但语义不得改变：

| 字段 | 要求 |
| --- | --- |
| `adapter_id` | 标识协议或适配器实现，跨版本保持稳定 |
| `model_id` | 标识真实硬件型号，不把多个能力不同的型号伪装成同一型号 |
| `instance_key` | 只用于进程内路由和配置关联；不得直接写日志或上传 |
| `capabilities` | 显式声明按键边沿、语音流、触摸、连续滚动、电池、电源等能力 |
| `connection_state` | 至少区分发现、连接、可用、断开、权限不足和不可用 |
| `sequence` | 同一适配器内事件顺序单调递增，支持定位重复、迟到和乱序事件 |

适配器必须输出规范化事件，不允许业务层直接依赖厂商原始包：

- 按键：`began → ended`，异常时为 `began → cancelled(reason)`。
- 触摸：`began → changed* → ended`，异常时以 `cancelled(reason)` 结束。
- 语音：`started → audio* → stopping/draining → completed(normal)`；异常时结束为 `completed(forced, reason, interrupted_samples)`。
- 电池：`known(percent, charging)` 或 `unknown(reason)`，不得用默认 100% 代替未知。

以下边沿规则是强制要求：

- 第一枚真实按下边沿立即向上层提交，不等待双击、长按或防抖计时器；语音键尤其不得经过这些计时器。
- 重复 `began`、无匹配 `ended` 和取消后的迟到释放必须被去重并记录原因，不能产生第二次用户动作。
- 断连、适配器停止、配置切换、权限撤销、系统休眠或会话被替代时，必须按确定顺序取消该设备的所有活动按键、连发、修饰键、触摸和语音状态。
- 重连后的第一枚按键、第一次触摸和第一次语音会话必须可用，不得复用上一连接的按住状态、计时器或音频 generation。

## 基础功能一致性要求

| 功能 | 所有新硬件必须遵守的行为 |
| --- | --- |
| 设备档案 | 每只设备独立保存型号、映射、手势、快速连按选项和可用能力；多设备不得串用配置 |
| 单击 | 无次级手势时在一次完整按下/释放中执行一次；可安全即时执行的路径不得无故延迟 |
| 双击 | 使用统一 `300 ms` 判定窗口；仅在配置双击动作时启用，第二击成立后取消待定单击 |
| 长按动作 | 使用统一 `550 ms` 阈值；只适用于普通按键。语音键按住表示维持语音会话，不得等待该阈值才开始收音 |
| 按住连发 | 无双击/长按和私有单击覆盖时，按住 `350 ms` 后开始；返回/删除每 `50 ms`，方向与音量每 `100 ms`；松键或取消立即停止 |
| 连发白名单 | 只有删除、方向、滚动、音量等明确允许重复的动作可以连发；打开 App、自定义快捷键、组合动作、App 切换器等动作默认只执行一次 |
| 连续快速按 | 使用同一按键级产品选项；默认关闭时保持 `600 ms` 稳定释放门禁，开启后每个真实完整边沿都执行。该选项不能绕过双击/长按识别 |
| 键位映射 | 使用跨平台稳定动作 ID；UI 只展示硬件真实存在的按键，不强行补齐其他型号的物理布局 |
| 编辑捕获 | 进入明确的“选择按键”状态后只捕获，不执行原动作；离开页面、取消、隐藏窗口或断连后立即恢复正常路由 |
| App 切换器 | 具备启动、前进/后退选择、确认、返回取消、超时、断连和权限失效清理；所有退出路径必须释放 Command 或 Alt 等修饰键 |
| 多设备 | 不同设备、相同按键和并行会话按实例隔离；一只设备断连不得取消另一只设备的有效状态 |
| 电池与充电 | 硬件声明支持时显示真实百分比和充电状态；读取失败显示未知，不伪报健康 |
| 权限与不可用 | 明确告诉用户缺少的权限、驱动或系统能力；恢复条件满足后无需重启电脑，至多按平台要求重启 App 或服务 |

## 语音、触摸与物理按键的优先级

对于同时具有语音和触摸能力的硬件，语音是最高优先级路径：

1. 从语音键 `began` 到音频尾包与输出队列自然排空完成，屏蔽同一物理设备的触摸移动、滚动和点击输出。
2. 屏蔽不能停止触摸采集线程、语音音频、实体按键边沿或错误诊断；只禁止向操作系统提交触摸派生动作。
3. 语音期间已经开始的触摸接触必须保持抑制，直到手指离开。排空结束时不能补发积压的移动、滚动或点击；下一次新接触才恢复。
4. 默认不屏蔽其他物理设备、鼠标或触控板。若某个平台必须全局屏蔽，设备手册必须说明范围和实机原因。
5. 正常松键不得通过 flush 音频换取更早恢复触摸；恢复时点必须服从“首字快、尾字全”的语音完整性规范。

## macOS 与 Windows 的等价语义

| 产品行为 | macOS | Windows | 一致性要求 |
| --- | --- | --- | --- |
| 删除 | Delete/退格语义 | Backspace 语义 | 按住时连续向前删除，松键立即停止 |
| 方向导航 | 对前台目标提交方向键或等价公开输入 | 对前台目标提交方向键或等价公开输入 | 单击一次移动一格，按住按统一节奏连续移动 |
| 音量 | 系统媒体音量动作 | 系统媒体音量动作 | 一次按键一次变化，按住连续变化 |
| App 切换器 | Command-Tab 生命周期 | Alt-Tab 生命周期 | 支持选择、确认、取消、超时和异常释放修饰键 |
| 语音输出 | 当前产品使用 `MiRemoteV 2ch` | 使用 Windows 版本声明的 SayAll 虚拟麦克风端点 | 用户选择的是 SayAll 音频路径；不得静默回退电脑内置麦克风 |
| 输入投递 | 使用受支持的 macOS 输入/辅助功能能力 | 使用受支持的 Windows 输入能力 | 以最终前台 App 行为为准，API 调用成功不等于用户结果成功 |
| 安装与授权 | App、helper、驱动和系统权限由安装流程处理 | App、服务/驱动和系统权限由安装流程处理 | 普通用户不需要开发者账号、SDK、抓包工具、命令行或额外硬件 |

平台确实无法提供的能力必须采用以下顺序处理：

1. 优先实现用户结果等价的公开系统能力；
2. 无法等价时显示“此平台不支持”或“状态未知”；
3. 在设备手册和发布说明中列出差异；
4. 不得用含义不同的动作、电脑麦克风或虚假状态静默替代。

## 语音音频硬性门槛

所有声明 `voice_stream` 的硬件必须满足 [`HardwareVoiceAudioContract.md`](HardwareVoiceAudioContract.md)，并至少保证：

- 硬件按下后立即进入真实硬件收音路径，记录 `trigger_down_to_first_pcm_ms`；能观察最终文字时记录 `trigger_down_to_first_transcript_observation_ms`。
- 正常松键保留有序尾包，等待解码、线程投递和虚拟麦克风输出自然排空；不得 flush、清空或截断在途缓存。
- 快速连续会话使用独立 generation，上一会话迟到数据不得进入下一会话。
- 断连、超时、服务崩溃等异常终止必须记录 `completion=forced`、原因和中断样本数。
- macOS 和 Windows 都必须使用遥控器真实麦克风；硬件音频不可用时明确失败，不回退电脑麦克风。

## 日志与诊断合同

日志必须能够从原始入口追踪到最终用户结果，并至少区分：

- `received`：收到原始硬件事件；
- `normalized`：形成规范化边沿或音频帧；
- `routed` / `submitted`：提交给动作或音频输出；
- `completed`：已观察到本产品能够确认的最终结果；
- `ignored` / `cancelled` / `failed`：包含稳定原因码；
- 连发：一次按住只记录开始和聚合终态，包含间隔、次数和停止原因，不逐次刷屏；
- 语音：包含 generation、首包耗时、待排空/中断样本数和正常或强制完成状态；
- 触摸抑制：包含是否因语音屏蔽、被屏蔽的事件数量和恢复边界。

不得记录设备地址、序列号、原始实例标识、用户语音或文字内容、窗口标题、文件路径、凭据或第三方 App 私有状态。平台无法观察的结果必须写为未知，不能把推测写成成功。

## 每种硬件的最低实机测试矩阵

### A. 所有硬件

| 用例 | 必须验证 |
| --- | --- |
| 新设备首次连接 | 无历史配置时完成发现、授权、建档，第一次操作成功 |
| 已配对重连 | App 重启、设备休眠唤醒和系统重启后配置保持 |
| 全部物理键 | 每键至少单击 3 次，事件和用户动作一一对应 |
| 手势 | 支持配置的普通键覆盖单击、双击、短按后长按、真实长按和取消 |
| 按住连发 | 返回/删除、方向、滚动、音量分别按住至少 2 秒，松开后立即停止 |
| 连续快速按 | 选项关闭和开启分别验证 5～8 次快速完整点击 |
| 编辑捕获 | 进入、取消、切页、关窗、隐藏、断连后均不残留捕获状态 |
| App 切换器 | 启动、前进、后退、确认、返回取消、超时、断连和权限撤销 |
| 异常恢复 | 按住时断连、权限撤销、适配器停止和系统睡眠，不留按键、修饰键或计时器 |
| 多设备 | 两只设备的配置、事件、统计和断连互不影响 |
| 安装/升级 | 普通用户安装、升级、卸载和恢复不依赖开发工具或手工命令 |

### B. 声明语音能力的硬件

- 极速按下/释放至少 10 次；正常短句至少 10 次；较长输入、快速连续两句、收音中断连和恢复各覆盖一次。
- 在真实虚拟麦克风与至少一个目标语音工具中验证首字、尾字和最终文字，不以“已收到包”或“已入队”代替。
- 验证硬件不可用时不回退电脑麦克风；正常路径 `audio_interrupted_samples=0`、`audio_pending_samples=0`、`completion=normal`。

### C. 声明触摸能力的硬件

- 覆盖移动、轻触、实体按压抑制、顺逆时针滚动、慢速/快速、接触结束、断连和休眠唤醒。
- 同时声明语音时，逐项验证语音活动和尾音排空期间无移动、滚动、点击；保持接触跨过恢复时点不能补发动作，抬手后的新接触正常。

### D. 声明电池或电源能力的硬件

- 覆盖正常电量、低电、充电、读取失败、断连、重连和刷新；不同平台读取不到时显示未知。

### E. 平台矩阵

- macOS：产品声明支持的最低版本和当前主版本；Developer ID/Hardened Runtime/公证产物；权限未授予、已授予和撤销恢复。
- Windows：产品声明支持的最低版本和当前主版本；安装版与便携版（若发布）；标准用户与管理员安装边界；输入注入、虚拟麦克风、睡眠唤醒和安全软件提示。
- 每个平台必须独立完成真实硬件验收。macOS 通过不能推导 Windows 通过，Windows 通过也不能替代 macOS。

## 自动化最低要求

每个新适配器至少提供：

1. 原始包/报告到规范化按键、触摸和音频事件的解析测试；
2. 重复 down、无匹配 up、迟到 up、乱序、分片、断连和权限撤销测试；
3. 单击、双击、长按、按住连发和连续快速按配置的状态机测试；
4. 多设备实例隔离与旧 generation 拒绝测试；
5. 若有语音，覆盖首包、尾包自然排空、快速连续会话、背压和强制终止；
6. 若有触摸，覆盖参数范围、点击/滚动互斥、实体按压抑制和语音期间抑制；
7. macOS 与 Windows 各自的动作语义测试，不把某个平台的系统 API 名称写入共享协议层。

## 兼容状态与发布门禁

| 状态 | 允许的结论 |
| --- | --- |
| 研究中 | 只有协议或开源项目研究，不对用户展示兼容 |
| 候选 | 适配器与自动化完成，可提供明确标注的内部测试包 |
| 兼容 | 对应平台的完整实机矩阵、安装、日志和稳定功能回归通过 |
| 推荐 | 在兼容基础上完成目标语音工具、长时间稳定性、升级和支持材料验证 |

出现以下任一情况不得标记为兼容或推荐：

- 第一次按键或第一次语音会话失败；
- 正常语音丢首字、尾字或通过 flush 结束；
- 松键、断连或权限变化后仍残留连发、触摸、语音或修饰键；
- 同型号在 macOS 与 Windows 的用户行为不一致且未明确说明；
- 需要普通用户安装开发工具、抓包软件、SDK，或拥有开发者账号；
- 只完成模拟器、单元测试、构建、签名或安装器验证，没有真实硬件和最终用户流程证据。

## 新硬件交付清单

每次接入新型号必须在对应 PR 或交付记录中逐项回答：

- 型号、传输方式和能力声明是什么；
- 与现有硬件相比，已对齐、物理不存在、平台不支持和仍待验证的功能分别是什么；
- 事件、手势、连发、语音、触摸和断连生命周期在哪里实现；
- macOS 与 Windows 分别使用什么公开或可分发的系统路径；
- 自动化、模拟硬件、真实设备、目标语音工具、安装包分别验证了什么；
- 哪些用例尚未完成，以及为何仍只能称为候选。
