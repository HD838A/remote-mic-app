# 组合动作私有模块集成测试手册

## 适用版本或分支

- 分支：最新 `main` 或由其直接创建的预览候选。
- 适用版本：当前修复分支及其后续候选；`1.8.18 (110)` 和 `1.8.22 (114)` 均存在快捷指令 SwiftPM 资源路径崩溃，不得继续分发。

## 合并后私有包版本与宿主集成

组合动作私有包已通过 PR [GetSayAll/sayall-macro-platform#3](https://github.com/GetSayAll/sayall-macro-platform/pull/3) 合入 `main`。本次宿主集成固定使用完整 commit：

```text
b71482ccb3c5d3be319abe7cd61915ab90cbc3ba
```

本地开发或验证时，将私有包 checkout 到该 commit（不得使用浮动的 `main`）：

```bash
git -C /Users/andy/Develop/Src/AISrc/sayall-macro-platform fetch origin main
git -C /Users/andy/Develop/Src/AISrc/sayall-macro-platform checkout --detach b71482ccb3c5d3be319abe7cd61915ab90cbc3ba
```

宿主通过 `Package.swift` 的 `SAYALL_MACRO_PLATFORM_PATH` 注入本地包；最小测试命令为：

```bash
SAYALL_MACRO_PLATFORM_PATH=/Users/andy/Develop/Src/AISrc/sayall-macro-platform \
REQUIRE_SAYALL_MACRO_PLATFORM=1 \
swift test
```

构建 App 时继续使用 `./scripts/build-app.sh`，并同时设置 `SAYALL_MACRO_PLATFORM_PATH` 与 `REQUIRE_SAYALL_MACRO_PLATFORM=1`；构建后运行 `REQUIRE_SAYALL_MACRO_PLATFORM=1 ./scripts/verify-app.sh "dist/SayAll.app"` 检查模块确实被打包。CI、预览候选和签名发布 workflow 都必须使用同一个 40 位 SHA；修改 pin 后在宿主仓库执行：

```bash
./scripts/verify-release-dependency-pins.sh
```

该脚本会确认 macOS CI、预览和正式发布三条 workflow 的私有包 revision 一致且为完整 SHA。私有包缺失时，公开构建仍应保持组合动作入口隐藏并回退到原按键行为；本手册中的自动化验证不能替代最终签名包、真实遥控器、Intel Mac 和不同前后台状态的人工验收。

## 测试前准备

1. 本机存在私有仓库 `sayall-macro-platform`，并通过 `SAYALL_MACRO_PLATFORM_PATH` 注入构建。
2. 无线麦已获得输入监控和辅助功能权限。
3. 准备一个没有组合动作资格数据的新 macOS 测试账户，以及一个保留旧组合动作资格数据的升级测试账户。
4. 准备真实遥控器；另准备 iOS 或 Web Remote 检查同一绑定入口。
5. 至少安装 Codex、Claude 或 Chrome 中一个目标 App。

本地构建命令：

```bash
SAYALL_MACRO_PLATFORM_PATH=/Users/andy/Develop/Src/AISrc/sayall-macro-platform \
EARLY_ACCESS_SERVICE_URL=https://config.sayall.app \
REQUIRE_SAYALL_MACRO_PLATFORM=1 \
REQUIRE_EARLY_ACCESS_CONFIGURATION=1 \
./scripts/build-app.sh
```

`EARLY_ACCESS_SERVICE_URL` 仍可能供同一 App 中的其他私有功能使用，不是组合动作的访问条件。组合动作不得因为该配置存在而发起资格请求。

构建结果位于 `dist/SayAll.app`。使用以下命令检查资源包、包含标记和签名结构：

```bash
REQUIRE_SAYALL_MACRO_PLATFORM=1 \
./scripts/verify-app.sh "dist/SayAll.app"
```

验证最终 ZIP 时必须先临时挪开同版本 `/private/tmp/remote-mic-swiftpm/<版本>-<Build>` 构建缓存，再从全新目录解压并打开设置窗口；否则 SwiftPM 生成的绝对构建路径可能掩盖安装包资源错误。验证结束后恢复原缓存目录。

## 用例一：公开构建回归

步骤：不设置 `SAYALL_MACRO_PLATFORM_PATH` 构建并启动 App。

预期：关于页没有组合动作邀请码入口，侧边栏没有“组合动作”；普通单击、双击、长按映射全部维持原行为。

失败判定：公开构建依赖私有仓库、出现空白入口或任意按键被私有模块接管。

## 用例二：组合动作免邀请码

步骤：注入私有模块后，先使用没有旧组合动作资格数据的新账户启动 App，再使用保留旧有效、过期或已撤销资格数据的升级账户启动；每次都检查“关于”页、侧边栏、组合动作页面和资格服务请求。

预期：所有账户都直接显示“组合动作”侧边栏并可创建、保存和执行本机动作；“关于”页不显示组合动作邀请码录入区域；启动、打开页面和完全退出后重新启动均不请求组合动作资格服务，也不因组合动作创建设备身份。旧资格数据只为兼容保留，其缺失、过期或撤销都不影响组合动作入口和执行。

失败判定：需要输入邀请码才能看到或执行组合动作；显示组合动作兑换入口；组合动作因资格缺失、过期或撤销而隐藏或停止执行；启动或打开页面时出现组合动作资格请求或新建设备身份。

### 用例二 A：其他受邀私有功能边界

步骤：在组合动作无需邀请码可见的同一 App 中，检查其他受邀私有功能的入口、Feature Flag 和本地开关；不要输入或伪造其他私有功能的邀请码。

预期：组合动作开放不会自动显示、授权或开启其他受邀私有功能；这些功能继续遵守各自的组件、Feature Flag 和资格策略，本地开关仍默认关闭。

失败判定：组合动作开放导致其他受邀私有功能绕过自身资格、自动出现或自动开启，或者与组合动作共享错误的可见性状态。

### 用例二 B：文本编辑快捷键

步骤：聚焦组合动作名称、快捷键或网址等文本输入框，依次验证 `Command-A`、`Command-C`、`Command-V`、`Command-X`、`Command-Z` 和 `Shift-Command-Z`；再切换到其他普通文本输入框重复验证。

预期：快捷键由 AppKit responder chain 交给当前聚焦输入框，选择、复制、粘贴、剪切、撤销和重做均按标准 Mac App 行为执行；不触发退出、关窗或遥控器映射。

失败判定：任一标准编辑快捷键无效、被全局监听吞掉、作用于错误输入框或触发其他 App 行为。

## 用例三：页面与本机配置

步骤：创建组合动作，分别添加打开 App、打开网址、等待 App、录入快捷键、运行本机快捷指令、执行已有组合动作和学习输入框步骤；保存、重新进入并测试执行。

预期：页面内完成主要配置；中文字号不小于 12pt；数据重启后保留；学习记录可测试和重新学习；敏感输入框被拒绝。页面底部明确说明“学习输入框”只负责把光标放到目标 App，“回眸”中的 Codex MCP / TOML 只负责授权读取本地历史，两者互不替代。“运行快捷指令”和“执行已有组合动作”均在卡片内搜索选择，不使用长下拉框或连续弹窗；前者显示名称、Identifier 和可用状态，可刷新并测试运行，导出不包含快捷指令本体；后者执行最新已保存版本并只保存稳定 ID。“打开网址”在卡片内输入完整 URL，只允许 `http` / `https` 并使用系统默认浏览器，保存、撤销和导入导出后内容不丢失。

失败判定：数据丢失、需要连续弹窗、输入框误聚焦、敏感输入框可被学习，或页面让用户误以为 MCP / TOML 能完成输入框聚焦。

### 用例三 C：运行本机快捷指令

步骤：准备一条无破坏性的本机快捷指令，选中并测试；随后改名、删除并刷新；再把组合动作导入到缺少该快捷指令的另一台 Mac。分别检查 Remote Mic 前台、后台、首次系统隐私授权、iCloud 尚未同步和接近 60 秒运行时间的情况。

预期：列表在页面打开和 App 回到前台时自动刷新，也可手动刷新；改名后仍按 Identifier 匹配并显示新名称；删除、未同步或另一台 Mac 缺失时保留保存名称并显示“本机不可用”，不得执行同名的其他项目。运行失败、拒绝授权或超时只停止当前组合动作，不误报辅助功能权限，不停止 HID 监控。

失败判定：使用名称而不是 Identifier 执行、缺失时误执行同名项、导出携带快捷指令内容、测试无反馈、错误权限分类、失败后遥控器失效，或未经真实系统验证就宣称人工验收完成。

### 用例三 D：打开指定网址

步骤：添加“打开网址”，输入包含路径、查询参数和锚点的有效 `https` 地址并测试；分别在 Remote Mic 前台、后台和真实遥控器绑定下执行。切换动作、撤销、重启、导出及重新导入后复查。再输入 `file:`、`javascript:`、自定义 Scheme、带用户名密码和缺少 Host 的地址。

预期：有效地址只交给当前系统默认浏览器打开一次，完整 URL 不丢失；所有配置操作在步骤卡片内完成，不使用 Picker、Sheet 或连续弹窗。危险或无效地址不能保存或执行，显示普通步骤失败，不误报辅助功能权限失效，也不停止 HID 监控。

失败判定：危险 Scheme 被执行、使用非默认浏览器、完整 URL 被截断、前后台结果不同、导入导出丢失、失败后普通按键或语音不可用，或仅凭注入式单元测试宣称真实浏览器验收完成。

### 用例三 E：执行已有组合动作

步骤：先保存两个可独立运行的子动作，再在父动作中添加“执行已有组合动作”，通过卡片内搜索选择子动作并测试。修改并保存子动作后再次测试父动作；删除子动作、跨 Mac 导入父动作、建立 A→B→A 循环及超过 8 层的链分别验证。

预期：父动作执行子动作的最新已保存版本，当前动作不会出现在自身候选中；选择区不使用 Picker、Sheet 或连续弹窗。导出只记录名称和稳定 ID，不复制子动作；缺失时不按名称猜测。直接/间接循环在保存前被拒绝，运行时仍有防御，超过 8 层安全停止且不影响 HID、普通语音和其他按键。

失败判定：执行旧版本、错误同名动作、循环卡死、深度无限增长、导出泄露子动作内容、失败后继续执行后续步骤或停止遥控器监控。

### 用例三 B：组合动作页面信息层级与新增 App

步骤：在没有打开新建区域时记录遥控器大小，点击“新建”后再次观察；创建并选择一个包含“打开 App”步骤的组合动作，输入超过 20 个字符的名称，并依次查看飞书、微信、天气、豆包、OpenCode 和 WorkBuddy 的已安装过滤结果。

预期：新建区域展开前后遥控器保持相同尺寸；“测试动作”和可用状态的“保存修改”与“新建”使用同一种主要按钮颜色；组合动作名称标签与输入框位于同一行，输入最多保留 20 个字符；步骤编号与动作名称字号一致；已选择 App 的真实图标显示在名称前，Bundle ID 紧跟名称显示；新增预置 App 仅在实际安装时出现。注入私有模块后，侧边栏主页面顺序为“按键、组合动作、统计、连接、权限、关于”，不因资格状态插入或移除组合动作页面。

失败判定：展开新建区域导致遥控器缩放、主要按钮颜色层级不一致、名称超过 20 个字符、步骤标题字号不一致、App 图标或 Bundle ID 缺失、未安装 App 出现在列表中，或主页面顺序错误。

### 用例三 F：遥控器绑定变化提示

步骤：先在“按键”页面把左键单击设置为“打开 Codex”；返回组合动作页面，为组合动作 A 勾选左键单击但暂不保存；保存后再切换到组合动作 B，为它勾选同一触发方式；最后取消勾选并保存。

预期：文字位于遥控器左侧时右对齐，位于右侧时左对齐，文字和遥控器向页面中间靠拢。首次勾选时页面直接显示“左键单击目前执行：打开 Codex”和“保存后将改为：组合动作 A”；准备替换时显示当前组合动作 A 和保存后的组合动作 B；取消绑定时显示保存后恢复的按键动作。提示只在存在未保存的绑定变化时出现，保存或撤回变化后消失，全程不弹出额外窗口。

失败判定：不显示保存前后的动作、显示错误的按键或触发方式、替换其他组合动作时仍显示按键页动作、保存后提示不消失、左右文字对齐方向错误，或提示遮挡遥控器和触发选项。

### 用例三 A：最终 App 脱离构建缓存打开快捷指令

步骤：

1. 从最终 ZIP 或 DMG 全新解压 App，不从 SwiftPM 产物目录直接运行。
2. 临时挪开该版本对应的 `/private/tmp/remote-mic-swiftpm/<版本>-<Build>` 和 CI 构建目录。
3. 不提供组合动作资格，启动 App 并点击侧边栏“组合动作”。
4. 分别验证已有宏列表和没有宏时的空状态；退出后再次启动重复点击。

预期：页面标题、空状态、按钮、步骤编辑和绑定区域均正常显示；进程持续运行；本地化来自 `Contents/Resources/SayAllMacroPlatform_SayAllMacroRemoteMic.bundle`。

失败判定：`EXC_BREAKPOINT / SIGTRAP`、`could not load resource bundle`、页面显示原始本地化 key、只有构建缓存存在时才可打开，或第二次启动行为与第一次不同。

## 用例四：真实遥控器绑定

步骤：把同一组合动作分别绑定到单击、双击和长按，使用真实遥控器触发；完全退出并重新启动 App 后重复测试。

预期：对应手势执行一次且不会继承导航长按重复；重启后绑定和执行能力保持不变，不依赖资格状态。

失败判定：触发次数错误、普通映射被永久覆盖、重启后绑定丢失，或执行被资格状态阻止。

## 用例五：手机遥控

步骤：使用 Nearby 和 Web Remote 触发同一按键的单击、双击、长按。

预期：行为与实体遥控器一致；私有模块存在时无需资格即可执行组合动作，模块缺失时安全回落到原映射。

失败判定：不同入口行为不一致、仍要求组合动作资格，或模块缺失时错误执行私有绑定。

## 安装与覆盖升级

### 用例六：覆盖已安装版本

步骤：记录 `/Applications/SayAll.app` 当前版本和 Build；如果仍存在旧 `/Applications/Remote Mic.app` 或 `/Applications/无线麦.app` 也一并记录；确认测试包的 Build 更高；从最终 DMG 运行图形化 Installer。

预期：Installer 成功；App 被原子更新为测试包版本；MiRemoteV 2ch 健康时不重复替换；App 能自动或手动启动；用户设置仍保留。

失败判定：出现通用安装错误、PackageKit 跳过 App payload、App 被删除、驱动无故重装或 App 无法启动。

### 用例七：旧包失败保护

步骤：在已安装更高 Build 的夹具环境运行较低 Build 的安装包；记录安装前后 App 版本、Build、签名和 SHA-256。

预期：安装在 `preinstall` 明确停止；提示现有版本更新；原 App 的版本、Build、签名和文件摘要均不变化。

失败判定：旧包覆盖新版、原 App 被退出后未恢复、任何 App 文件被删除或修改。

安装失败日志：

```bash
tail -n 300 /var/log/install.log
log show --last 30m \
  --predicate 'process == "Installer" OR process == "installd"' \
  --style compact
```

## 日志收集

通过 App 内诊断导出或 Console 收集 `Remote Mic` 日志。记录私有模块是否加载、组合动作页面是否可见、按键、触发方式和是否由私有模块接管；不得记录输入框文本、学习到的完整特征、设备标识、凭据或 Token。组合动作测试期间出现资格请求本身即为失败证据。

## 验证边界

私有模块已用自动化覆盖“无需邀请时入口直接可见、兑换入口保持隐藏、可创建组合动作”和旧资格数据兼容；宿主继续覆盖可选模块接入、页面委托、事件路由和缺少模块时的 no-op 回退。“打开网址”覆盖 Schema、安全校验、导入导出、页面结构和注入式执行；“执行已有组合动作”覆盖最新版本解析、缺失依赖、保存前与运行时循环防御、8 层深度限制和页面内搜索。自动化不会真的启动浏览器、运行用户真实快捷指令或代替真实遥控器链路。其他受邀私有功能的资格和开关测试属于独立功能边界，不得用组合动作免邀请码测试替代。Build 67 曾因降级安装与破坏性 `preinstall` 在当前 Mac 真实安装失败；`1.8.17 (109)` 已在当前 Apple Silicon Mac 完成用例六和用例七，详见 `Bugs/2026-08-14-macro-preview-installer-deleted-newer-app.md`。
