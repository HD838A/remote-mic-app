# 安装器隐私政策同意测试手册

## 适用范围

- Apple Silicon 与 Intel 的 `SayAll-<版本>-<Build>-<架构>-install.pkg`。
- 简体中文与英文系统语言。
- 全新安装与覆盖升级安装。
- 不含卸载包；卸载包没有许可步骤。

## 测试前准备

1. 使用经过 Developer ID 签名和公证的候选包；ad-hoc 包只能验证资源存在，不能作为发布验收。
2. 记录候选包 SHA-256、`CFBundleVersion`、官网政策更新日期和 `https://sayall.app/privacy/policy.json` 的 `sha256`。
3. 准备一台可回滚的测试 Mac 或虚拟机；确认可以恢复安装前的 `/Applications/SayAll.app`、音频驱动和系统扩展状态。
4. 确认测试账号不需要真实会员权益；许可页出现在安装前，不依赖 App 登录。
5. 记录当前系统语言和区域设置；切换语言后重新启动 Installer。

## 判定边界

系统许可页的按钮文案由 macOS Installer 决定，本功能不要求自定义字样。macOS 27 实测许可页会弹出“同意/不同意”确认面板，点“同意”继续安装、点“不同意”取消安装并退出安装器；许可页底部是“打印…/保存…/返回/继续”。验收目标是：许可页必须出现、正文与官网一致、用户必须经过该页才能继续安装，返回或关闭安装器不会产生安装结果。若目标系统的文案不同，应记录该系统版本的实际文案和行为，不能把文案差异误判为功能失败。

## 用例 1：简体中文许可页

1. 将系统语言设为简体中文，双击候选安装包。
2. 在“简介”页点击“继续”。
3. 检查许可页标题、更新日期、各章节和末尾官网地址。
4. 不点击任何按钮，尝试滚动到底部。

预期结果：许可页出现在“简介”之后、目标磁盘/安装类型之前；正文与 `https://sayall.app/privacy/` 当前中文正文逐字一致；日期为 `2026-11-05` 或候选包锁文件记录的日期；末尾显示 `https://sayall.app/privacy/`；文本可完整滚动，无截断、乱码或空白页；许可页至少提供前进和返回/拒绝两个操作，macOS 27 会弹出“同意/不同意”确认面板。

失败判定：没有许可页、正文缺段、日期或 URL 缺失、中文乱码、按钮不可用、许可页出现在安装完成之后。

## 用例 2：英文许可页

1. 将系统语言设为 English，重新启动 Installer。
2. 重复用例 1。

预期结果：显示英文正文，与 `https://sayall.app/en/privacy/` 当前正文逐字一致；日期和 URL 对应英文页面；其余布局与中文一致。

失败判定：显示中文、英文缺段、日期不匹配、URL 指向中文页或文本截断。

## 用例 3：拒绝安装

1. 在许可页点击“不同意”；如果系统只显示“返回”，点击“返回”并在简介页关闭安装器。

预期结果：Installer 返回简介或退出；不写入 `/Applications/SayAll.app`、不安装或修改音频驱动、不写入安装 receipt、不启动 App。

失败判定：仍然继续安装、部分写入文件、留下 receipt 或启动 App。

## 用例 4：同意并完成安装

1. 在许可页点击“同意”；macOS 27 等只显示“继续”的系统点击“继续”。
2. 完成目标磁盘、安装类型和授权步骤。
3. 安装结束后检查 `/Applications/SayAll.app`、`MiRemoteV 2ch` 和可选 Siri Remote 组件。
4. 启动 App，确认首次使用流程正常。

预期结果：安装正常完成；App、驱动和可选组件与未加许可页的候选包一致；App 版本、Build、签名和权限行为不变；许可页不写入用户目录或 App 容器。

失败判定：安装失败、组件缺失、签名校验失败、App 无法启动或出现新的权限提示。

## 用例 5：覆盖升级

1. 先安装上一个正式版。
2. 双击新候选包，完成许可页并同意。

预期结果：许可页同样出现；升级后 App 与驱动更新到候选版本；旧 App、驱动备份、receipt 和本地设置按既有升级逻辑处理；不会因为许可页改变卸载或回滚路径。

失败判定：升级跳过许可页、旧版本残留、驱动回滚失败或 receipt 异常。

## 用例 6：正文与官网逐字一致

1. 展开候选包：`pkgutil --expand <pkg> /tmp/sayall-license-expanded`。
2. 读取 `Resources/zh-Hans.lproj/License.txt` 和 `en.lproj/License.txt`。
3. 与 `https://sayall.app/privacy/policy.json` 中对应语言的 `text` 比较。
4. 计算 SHA-256，与本仓 `packaging/doubao-driver/privacy-policy.lock.json` 比较。

预期结果：两份正文逐字节一致；SHA-256 与锁文件一致；`Distribution` 包含 `<license file="License.txt"/>`；包内没有额外的政策副本或旧日期文本。

失败判定：任一字节不同、哈希不同、缺少语言、锁文件日期与正文日期不同。

## 用例 7：政策漂移必须阻断发布

1. 在测试分支修改官网 `policy.json` 的正文但不同步本仓快照。
2. 运行 `scripts/verify-installer-privacy-policy.py --remote --policy-json <修改后的 policy.json>`。
3. 运行 `scripts/notarize-release.sh` 的 `privacy-policy-remote-verify` 等价命令。

预期结果：命令以非零状态退出并打印首个差异；发布流程在构建 PKG 前停止；未生成新的签名包或上传资产。

失败判定：校验通过、只打印警告、继续签名或发布。

## 用例 8：命令行安装边界

1. 执行 `sudo installer -pkg <候选包> -target /`。

预期结果：命令行安装不显示许可页，直接安装；这是已知限制，不得记录为“用户已同意”。安装结果与图形安装一致。

失败判定：把命令行安装结果当作许可页验收通过，或命令行安装产生与图形安装不同的组件状态。

## 证据要求

- 中文和英文许可页各一张实际运行截图，包含完整窗口、日期、首段和末尾 URL；截图只放 PR 附件，不入库。
- 记录候选包 SHA-256、展开后的两份 `License.txt` SHA-256、`policy.json` 日期和 `sha256`。
- 记录“不同意”后的文件系统与 receipt 检查结果。
- 记录签名、公证、staple 和 `spctl` 结果；ad-hoc 包不能替代。
