# 动作执行结果 HUD 测试手册

适用版本：`feat/draggable-feedback-hud-20261127` 候选构建（常显监控面板）。功能来源：Issue #1208「动作执行结果反馈」。
本文只定义验证方法和证据口径，不新增产品规则。产品行为以 Issue #1208、确认设计稿和 `AGENTS.md` 为准。

## 1. 测试前准备

1. 使用 `SAYALL_PRIVATE_PLATFORM_MODE=public` 构建公开候选包；需要验证组合动作时使用完整集成本地包，并确认私有组件版本与 `config/release-dependencies.json` 一致。
2. 准备至少一个第三方 App（例如文本编辑器）和一个非输入类 App，用于前台/后台切换。
3. 连接实体遥控器，确认按键映射可用；至少配置：
   - 一个「打开 App」动作；
   - 一个「自定义快捷键」动作；
   - 一个组合动作（至少 2 步，其中一步为脚本或快捷指令，便于制造失败）。
4. 确认「设置 → 通用 → 动作执行结果提示」的两个开关默认关闭（即显示成功和失败提示）。「关闭所有提示」打开后隐藏全部 HUD；「关闭成功提示」打开后只隐藏成功。测试关闭状态时再手动打开。
5. 如果需要固定截图/预览，可使用调试入口：
   - 离屏证据：`REMOTE_MIC_ACTION_FEEDBACK_SCREENSHOT_DIR=<目录>`，输出 12 张中英/浅深 × 待命/成功/失败 PNG。
   - 实机浮层预览：`REMOTE_MIC_ACTION_FEEDBACK_PREVIEW=success|failure`。该入口只用于测试，不改变普通启动。
6. 准备脱敏测试数据；截图中不得出现用户输入、真实账号、设备标识、路径或第三方 App 内容。

## 2. 成功反馈

### 用例 S1：前台第三方 App 中执行成功

步骤：

1. 切换到第三方 App，让输入焦点留在该 App。
2. 按配置为「打开 App」的遥控器按键。
3. 观察屏幕底部。

预期：

- 首次触发后出现常显监控面板：半透明材质、宽度固定 `320pt`；状态行显示“待命”和本次次数，下方一行显示“已执行「打开微信」”一类动作名与耗时。
- 成功行约 1.3 秒后回到待命态，面板本身不消失；前台 App 不失去输入焦点。
- 不出现第二条提示，不排队；日志有 `ACTION FEEDBACK operation_id=... action_id=openWeChat result=success ... presentation=shown`。
- 目标 App 打开失败时不得显示成功；应转为失败反馈。

失败判定：焦点变化、键盘输入被抢、成功提示停留超过约 2 秒、同一触发出现多条提示、目标 App 明明打不开却显示成功。

### 用例 S2：连续快速成功

步骤：

1. 在 1.3 秒内连续按同一成功动作 3 次。
2. 再快速触发两个不同成功动作。

预期：

- 同一动作合并为“已执行「动作名」×3”，面板仍只有一行，状态行次数随之增加，1.3 秒重新计时。
- 不同动作合并为“已执行 N 个动作”，不滚动显示名字。
- 不排队、不闪出多条 HUD。

### 用例 S3：只关闭成功提示

步骤：

1. 保持「关闭所有提示」关闭，打开「关闭成功提示」。
2. 触发成功动作。
3. 再触发一个失败动作。

预期：

- 成功动作不显示 HUD；日志记录 `presentation=disabled_success`。
- 失败仍然显示。
- 退出并重启 App 后保持；导出/导入配置后保持同一值。

### 用例 S4：关闭所有提示

步骤：

1. 保持两个开关关闭，触发一个失败动作，确认 HUD 显示。
2. 打开「关闭所有提示」；观察当前 HUD 和开关状态。
3. 再触发成功动作，再触发一个失败动作。
4. 关闭「关闭所有提示」；退出并重启 App，再次触发成功和失败。

预期：

- 打开「关闭所有提示」时，当前 HUD 立即消失并清空会话计数（面板回到不显示状态），「关闭成功提示」变灰且不可操作；关回该开关后需要等下一次动作面板才重新出现。
- 两个动作仍执行；成功和失败 HUD 都不出现；日志分别记录 `presentation=disabled_success` 和 `presentation=disabled_failure`。
- 关闭「关闭所有提示」后，成功和失败按「关闭成功提示」的当前值恢复；重启后保持。

## 3. 失败反馈

### 用例 F1：辅助功能权限缺失

步骤：

1. 在系统设置中撤销无线麦 SayAll 的辅助功能权限。
2. 按一个需要注入按键的动作（例如「自定义快捷键」或方向键）。
3. 点击 HUD 的“打开系统设置”。

预期：

- 显示 error 气泡：标题「动作名」未执行，原因行“缺少辅助功能权限”，正文说明不能发送按键，主操作“打开系统设置”。
- 不自动重试，不改变其他按键和语音会话；点“打开系统设置”后失败行收起，面板仍常驻并显示最近一条失败记录。
- 恢复权限后再次按键可正常执行。

失败判定：静默无反馈、显示成功、自动重复弹窗、抢占前台焦点。

### 用例 F2：目标 App 未安装 / 未运行

步骤：

1. 为一个自定义 App 配置动作；先退出该 App，再按按键。
2. 卸载或移走该 App（使用可恢复的测试副本），再按按键。

预期：

- 未运行：显示“目标 App 未运行”，建议打开 App 后再按；主操作是“打开 App”。
- 不存在：显示“找不到目标 App”，主操作是“重新选择”，点击后打开按键映射设置。
- 两种情况分类不同，不显示成功。

### 用例 F3：快捷键未送达

步骤：

1. 配置一个自定义快捷键动作，目标 App 不接受该快捷键或组合键被系统占用。
2. 触发动作。

预期：

- 显示“快捷键未送达”，建议检查占用并重试；主操作“重试”。
- 重试会重新执行同一动作；如果成功，HUD 被新的成功提示替换。
- 不显示快捷键正文。

### 用例 F4：组合动作失败

步骤：

1. 创建一个至少 3 步的组合动作，其中一步脚本以非零状态退出。
2. 触发该组合动作。
3. 再创建一个依赖缺失或已被删除的组合动作并触发。

预期：

- 失败提示包含动作名、原因行和可执行动作，不显示脚本输出、脚本源码或退出码的完整内容。
- 依赖缺失显示“动作配置不可用”，主操作“重新选择”。
- 成功时显示“已执行「组合动作名」”。
- **边界**：当前私有组件只公开最终 terminal，不公开失败步骤序号；HUD 显示“共 N 步 · 原因”，不能声称具体第几步。若后续私有接口提供步骤 ID，再补精确步骤验收。

### 用例 F5：超时

步骤：

1. 使用一个会卡住的目标 App 或输入框聚焦场景触发动作。
2. 等待超过动作超时阈值。

预期：

- 显示“「动作名」超时”和“超过 10 秒”一类原因，主操作“重试”。
- 分类与普通执行失败不同；成功提示不能覆盖它。
- 不阻塞下一次按键，不延长语音会话。

### 用例 F6：取消

步骤：

1. 在组合动作执行期间取消（按另一键或使用现有取消路径）。

预期：

- 不显示 HUD；只记录结果分类 `cancelled`。
- 快捷面板内执行时，面板内显示“已取消”，不额外弹出屏幕 HUD。
- 不把取消显示为成功或失败。

## 4. 位置、层级与焦点

### 用例 P1：普通前台窗口

步骤：

1. 将前台窗口放在主屏，触发成功和失败动作各一次。

预期：

- 未拖动过时面板水平居中、下缘距可见区域底部 56pt；宽度固定 320pt，待命态和失败态不左右跳动。面板不激活无线麦 SayAll，不抢键盘焦点。
- 面板常驻期间始终接收自身范围内的鼠标事件（拖动需要），面板外点击不受影响；面板覆盖范围内的下层点击不再穿透。
- 浮层位于前台窗口所在屏幕；多屏不复制。

### 用例 P2：全屏与语音会话

步骤：

1. 让第三方 App 全屏，触发动作。
2. 在语音会话进行中触发成功和失败动作。

预期：

- 浮层在普通全屏空间可见，不把前台 App 退出全屏。
- 浮层层级为 `.screenSaver`：盖住 Dock、菜单栏和其他 App 的全屏窗口；仍盖不住锁屏、Mission Control、系统权限弹窗和 DRM 视频。
- 语音首字延迟、连续会话和松键尾字不受影响；HUD 不发送、不拦截 Fn 事件。
- `#1121` 倒计时若已合并，HUD 上移到倒计时上方；当前主线未合并时只验证不与系统语音条重叠。

### 用例 P3：悬停、拖动与计时

步骤：

1. 触发成功，指针停在面板上超过 2 秒。
2. 触发失败，指针停在面板上超过 30 秒。
3. 按住面板拖动，保持按住超过 1.3 秒后再松手。

预期：

- 成功行在悬停或拖动期间暂停 1.3 秒倒计时；移开指针、松手后按剩余时间回到待命态。
- 松手后指针仍停在面板上时继续暂停，直到指针移开。
- 失败不自动消失，指针移开也不消失；只有点关闭或触发下一次动作才收起。
- 收起旧提示后不复活；新失败直接替换旧失败行。

### 用例 P4：拖动落点与位置记忆

步骤：

1. 触发成功，把面板拖到屏幕右上角，等待成功行回到待命态。
2. 再次触发成功，再触发一次失败。
3. 在第二台显示器触发一次，拖到左下角；回到第一台显示器再触发。
4. 退出并重启 App 后重复步骤 2。

预期：

- 同一显示器复用最后一次拖动的位置；成功和失败共用同一落点，气泡变大时按当前可见区域夹回（边距 8pt）。
- 两台显示器各自记住各的位置，不互相覆盖；第二台显示器拔掉后回到默认落点。
- 重启后位置仍然保留；位置只存在本机偏好中，不进入可导出的便携配置，也不出现在日志里（日志只记 `placement=stored|default` 和坐标）。

## 5. 复制诊断

步骤：

1. 触发失败，点击“复制诊断”。
2. 粘贴到纯文本编辑器检查。
3. 检查日志同一条 operation ID。

预期：

- 按钮变为“已复制”，约 2 秒后恢复；不弹第二条提示。
- 内容只含版本/构建、系统版本、时间、operation ID、动作 ID、步骤、分类、耗时和脱敏说明。
- 不含动作名、快捷键正文、脚本源码/输出、输入内容、窗口标题、文件路径或设备标识。
- 不会自动上传。

## 6. 日志收集

1. 复现后打开「设置 → 诊断与日志」。使用“发送诊断信息”或在 Finder 中取得加密支持日志。
2. 本地调试可读取 `~/Library/Logs/RemoteMic/runtime.log`，只提取 `ACTION FEEDBACK` 行；不要把完整日志、用户输入、窗口标题或第三方 App 内容贴进 Issue 或 PR。
3. 用同一个 `operation_id` 关联执行结果与面板显示/隐藏；`presentation=disabled_success` / `presentation=disabled_failure` 表示对应提示被设置关闭，`phase=shown kind=success|failure|idle session_count=... placement=stored|default width=... height=... x=... y=... ignores_mouse=false` 用于核对真实面板几何、当前是否空闲态以及是否使用记忆位。
4. 收到事件、完成解码或已入队都不能当作最终成功；以 `result=success` 或失败分类及面板状态为准。

## 7. 设置页与回归

### 用例 R1：设置入口

步骤：

1. 在生产最小窗口（整窗 `1067 × 760`，内容区 `1067 × 732`）打开「设置 → 通用」。
2. 滚动到“动作执行结果提示”。
3. 确认“关闭所有提示”和“关闭成功提示”两个开关在同一行；分别切换；重启 App。

预期：

- 该行位于启动行为之后；标题、说明和两个开关在同一行；中文文字不小于 12pt；开关和说明完整可见，不被裁切。
- 打开「关闭所有提示」时，「关闭成功提示」变灰且不可操作，成功和失败都隐藏；关闭「关闭所有提示」后恢复。
- 生产最小窗口内可通过滚动到达；本次已在内容区 `1067 × 732` 的离屏生产内容截图中滚动到该行并确认两个开关。`1067 × 1200` 只作为溢出区域截图辅助，不表述为生产窗口尺寸。
- 重启后保持；配置导出/导入后保持。

### 用例 R2：现有提示与动作不受影响

步骤：

1. 触发现有设置页提示（例如保存、导入、权限提示）。
2. 触发普通方向键、按住连发、音量键和 App 切换器。

预期：

- 现有 `NoticeCenter` 提示仍按原位置和时长工作；HUD 不重复显示相同结果。
- 方向键/滚动/音量/App 切换器不显示成功 HUD，避免连续操作时刷屏；失败仍显示。
- 动作执行、语音首字、松键尾字、断连恢复与此前一致。

## 8. 自动化与证据

本地自动化：

```bash
swift build --disable-keychain
swift test --disable-keychain --filter ActionFeedback
swift test --disable-keychain
```

已覆盖：

- 成功/失败/超时分类、合并计数、优先级、成功行 1.3 秒后回到待命态。
- 失败停在失败态直到关闭；关闭「关闭所有提示」走 `reset()` 清空会话计数与最近一条。
- 常驻判据（会话计数大于 0 才显示面板）、空闲态保留最近一条与本次次数。
- 成功与失败的悬停、拖动暂停，松手后按剩余时长继续。
- 位置归一化还原、拖动夹边、换屏后保持角落、按显示器分别记忆。
- 打开「关闭所有提示」时成功和失败都不显示；打开「关闭成功提示」只隐藏成功；失败被关闭时记录 disabled_failure。
- 复制诊断脱敏、动作可用性、布局、屏幕选择、组合动作 terminal 映射、按键注入最终完成回调。
- 两个开关的默认值、持久化和配置导入/导出往返；中英文 key 覆盖。

## 9. 验证边界
