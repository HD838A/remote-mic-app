# iPhone 呼出 Typeless 的 Fn 点按测试手册

## 适用版本与分支

- 开发分支：`fix/iphone-typeless-fn-tap`
- 适用平台：macOS 14 及以上、当前兼容的 SayAll iPhone App
- 状态：等待官方 Developer ID 签名、公证候选完成真机验收

## 测试前准备

1. 安装版本号与候选一致的官方签名、公证 Mac App，不使用 ad-hoc 或本地未签名包。
2. 确认 MiRemoteV 可用，macOS 默认输入或 Typeless 输入设备选择正确。
3. 授予 SayAll 输入监控和辅助功能权限，开启“语音键模拟 Fn 点按”。
4. 打开 Typeless 并让普通可编辑输入框获得焦点。
5. 连接 iPhone；另准备 Apple Watch 和 Web 遥控用于共享路径回归。
6. 记录 Mac、iPhone、Typeless 版本、测试时间和当前输出设备；回声测试时先将 Mac 主机静音。

## 用例一：iPhone 正常语音

1. 点按 iPhone 语音按钮开始，说一段包含数字和停顿的 5～10 秒语音。
2. 再次点按停止，等待文字上屏。
3. 连续执行三次。

预期：每次只启动一次 Typeless、只停止一次；首字和尾字完整，三次均有文字结果。日志中每次会话有两组 `PHONE VOICE FN DOWN/UP posted`，且 `enqueue_failures=0`。

失败判定：Typeless 没有呼出、出现整段 Fn 长按、需要第二次语音才成功、首尾缺字、重复启停或 Fn 卡住。

## 用例二：极短语音与快速重启

1. 开始后约一秒立即停止。
2. 停止后立即再次开始，说 3～5 秒后停止。
3. 重复三轮。

预期：短语音仍完成开始点按、完整音频和停止点按；后一会话等待前一会话排空，不交错、不忙死。

失败判定：短语音整段丢失、上一段进入下一段、第二段提示占用、产生多余 Fn 点按或必须重启 App。

## 用例三：目标 App 前后台状态

分别让 Typeless 的输入目标处于：

1. 已在前台且输入框聚焦；
2. App 在后台；
3. App 已打开但输入框失焦。

每种状态使用现有打开 App / 聚焦动作后立即从 iPhone 开始语音。

预期：目标输入位置就绪后才发送第一次 Fn 点按；等待期间的首段音频被缓存并完整进入正确输入框。

失败判定：文字进入旧窗口、首次无效、开头丢失、等待取消后仍向错误位置发送 Fn。

## 用例四：关闭 Fn 点按模式

1. 关闭“语音键模拟 Fn 点按”。
2. 使用兼容 Fn 长按语义的目标工具从 iPhone 开始和停止语音。
3. 检查普通移动语音音频和停止排空。

预期：开始时 Fn Down，整段录音期间保持，尾音排空后 Fn Up；不会额外产生两次点按。

失败判定：关闭后仍执行 Typeless 双点按、音频被延迟丢弃、停止前释放 Fn 或 Fn 无法释放。

## 用例五：Watch 与 Web 共享入口

1. 分别从 Watch 和 Web 遥控开始、说话、停止。
2. 每个来源执行正常语音和一次极短语音。
3. 在一个来源停止未完成时尝试由另一来源开始。

预期：Watch 和 Web 与 iPhone 使用相同的双点按时序；不同来源保持互斥，停止完成后可正常接管。

失败判定：只有 iPhone 生效、来源串线、音频进入错误会话、停止后长期占用或 Fn 卡住。

## 用例六：回声路径隔离

1. Mac 主机保持静音，从 iPhone 录入并观察本地与远程端是否仍听到回声。
2. 仅打开 Mac 主机输出，再重复同一句。
3. 仅打开远程控制客户端的“播放远端电脑声音”，再重复。

预期：主机静音时 SayAll 的虚拟麦克风链路不会自行产生可听回放。只在某个播放端开启后出现的回声，应归因于该端扬声器到 iPhone 麦克风的声学回灌，并通过耳机、关闭远端声音播放或降低扬声器音量消除。

失败判定：所有物理播放端都静音且未监听 MiRemoteV 时仍稳定出现二次声音；此时需保留录屏、路由截图和日志继续诊断。

## 稳定功能回归

- 实体小米蓝牙遥控器的 Typeless 双点按、普通按键和语音完整性不变。
- iPhone 普通按键、授权、断线重连和来源互斥不变。
- MiRemoteV 保持 16 kHz PCM 既有链路，增益与声道布局不变。
- 退出 App、撤销权限、移动端断开以及快速重启后 Fn 均不保持按下。
- Typeless 以外的原长按目标在关闭点按模式时继续可用。

## 日志收集

提供 `~/Library/Logs/RemoteMic/runtime.log`，并注明测试来源和准确时间。重点核对：

```text
PHONE VOICE FN DOWN posted
PHONE VOICE FN UP posted
MOBILE VOICE started source=iphone
MOBILE VOICE audio_summary
MOBILE VOICE stopped source=iphone
```

每次 Typeless 会话应有四个成功边沿；`audio_summary` 应有非零采样且 `enqueue_failures=0`。日志不得包含音频内容或识别文字。

## 自动化、代理实测与用户实测边界

- 自动化覆盖双点按、首段缓存、排空后停止、原长按兼容、快速重启和来源生命周期。
- 本机可完成源码测试和构建，但没有项目要求的 Developer ID 身份，不能合法生成供用户安装的候选包。
- 真实 iPhone、Watch、Web、MiRemoteV、Typeless 最终文字上屏、系统权限历史和声学回声必须使用官方签名、公证候选由用户验收；完成前不得标记为真机通过。
