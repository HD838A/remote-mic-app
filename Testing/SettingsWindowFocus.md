# 设置窗口失焦行为测试手册

## 适用范围

- 适用版本：当前待验证 PR 或已合入 `main` 的精确 Commit；原功能分支 `codex/fix-settings-window-focus` 只作为历史审计来源
- 平台：Apple Silicon macOS 14 及以上；Intel macOS 13 及以上
- 目标：确认无线麦SayAll.app 设置窗口在失去应用焦点后保持可见；窗口只通过系统红色关闭按钮或 `⌘W` 关闭。

## 测试前准备

1. 退出其他无线麦SayAll.app 实例，启动本分支构建的 App：`./script/build_and_run.sh`。
2. 打开设置窗口，确保它没有最小化或全屏。
3. 准备一个无模态窗口的其他 App，例如 Finder 或 TextEdit。
4. 记录测试开始时间；如果同时发生异常，保留 `~/Library/Logs/RemoteMic/runtime.log` 对应时间段。

## 用例 1：Dock 图标关闭时切换 App

1. 打开设置窗口，在“偏好设置”中关闭“在 Dock 中常驻显示应用图标”。
2. 确认设置窗口仍在屏幕上，且 Dock 应用图标立即消失。
3. 关闭窗口。从菜单栏选择“打开主界面…”，确认 Dock 应用图标出现，且设置开关仍为关闭。
4. 在主界面选一个非默认页面并滚动。用 Finder 或 TextEdit 挡住主界面，再点 Dock 应用图标。
5. 使用红色关闭按钮关闭设置窗口。重新从菜单栏打开后，用 `⌘W` 再关闭一次。

预期结果：从菜单栏主动打开后，Dock 图标在窗口失焦时继续显示。点击图标会带回同一个窗口，保留页面、滚动位置和未提交的表单输入。两种关闭操作都让临时图标消失，菜单栏入口仍可使用。

失败判定：关闭开关后图标仍保留、从菜单栏打开后图标未出现、窗口失焦后图标消失、Dock 点击无法带回同一窗口，或关闭窗口后临时图标仍显示。

## 用例 2：Dock 图标显示时切换 App

1. 在“偏好设置”中开启“在 Dock 中常驻显示应用图标”。
2. 保持设置窗口打开，点击 Finder 或 TextEdit。
3. 通过 Dock 图标和 `⌘Tab` 分别切回无线麦SayAll.app。
4. 关闭主界面并确认 Dock 应用图标仍显示。点击图标重新打开窗口。

预期结果：窗口失焦后仍可见，且两种切回方式都能恢复同一窗口为活跃窗口。

失败判定：任一切换方式让窗口关闭、隐藏、重建，或改变窗口位置与尺寸。

## 用例 3：标准关闭与最小化边界

1. 关闭 Dock 偏好，再使用 `⌘W` 关闭设置窗口。
2. 通过菜单栏图标重新打开设置窗口。
3. 点击红色关闭按钮，再次从菜单栏图标打开。
4. 点击黄色最小化按钮，然后从 Dock 或菜单栏图标恢复窗口。

预期结果：`⌘W` 与红色按钮都会关闭设置窗口，隐藏临时图标，保持菜单栏服务运行。黄色按钮只最小化，临时应用图标仍显示，点击它可恢复同一窗口。分别检查 Dock 左侧应用图标与右侧窗口缩略图的小 Logo，两个位置均保留圆角。

失败判定：失焦才会关闭、`⌘W` 或红色按钮无效、最小化变成关闭、Dock 图标出现方形角，或关闭设置窗口导致无线麦进程退出和菜单栏图标消失。

## 稳定功能回归

- [ ] 设置窗口可移动、缩放和进入/退出全屏。
- [ ] 全部侧边栏入口、主要控件和滚动在真实生产最小窗口 `1020 × 772` 下未裁切；`800 × 650` 仅作为离屏压力截图检查。
- [ ] 鼠标左键和右键均可显示状态菜单，第一项“打开主界面…”可恢复并激活原窗口。
- [ ] Onboarding 已完成后启动或重新打开设置窗口，默认进入当前侧边栏第一项；调整侧边栏顺序后无需同步修改启动入口。
- [ ] 关闭 Dock 常驻开关并开启“启动时自动打开主面板”。在已完成引导的 App 中退出并重启。主界面自动打开，Dock 临时显示，关窗后隐藏。关闭自动打开设置后重启，后台启动保持图标隐藏。
- [ ] 临时显示时导入同为关闭的配置，图标保留到关窗。导入开启配置后关窗，图标常驻。将已开启的偏好导入为关闭时，图标立即隐藏。
- [ ] 临时显示时，从图标菜单选择 macOS 的“在程序坞中保留”。关窗和退出后固定图标仍在。App 在后台时，点击固定图标可重新打开主界面。测试后恢复系统原有固定状态。
- [ ] 关闭设置窗口不影响蓝牙连接、音频状态或按键映射。

## 日志收集

按测试时间段筛选 `UI DOCK_POLICY`。同一 `operation_id` 应有一条 `requested` 和一条 `completed`。从菜单栏打开、随启动自动打开、关闭窗口、切换开关、导入配置的 `source` 分别为 `status_menu_open`、`launch_open`、`window_close`、`dock_toggle`、`configuration_import`。观察 `temporary`、`target_policy` 和 `result`。失焦和最小化不改变策略。`dock_visible=unknown` 表示实际 Dock 图标显隐需要在屏幕上确认。

## 验证边界

- 自动化：覆盖持久开关和临时状态的激活策略，以及菜单入口、关窗和开关的状态接线。检查失焦、最小化、恢复和 `⌘W` 保留既有窗口路径。实际 Dock 点击和图标变化仍需在运行的 App 中验收。
- 代理实测：Apple Silicon Release App 已启动并显示生产设置窗口；截图和摘要见 `历史截图证据已按仓库清理规则移出`。该结果不替代 Intel Dock 外观验收。
- 用户实测：build 248 的右侧窗口缩略图标记仍为方形。需要在实际 Intel 系统运行用例 1–3，独立记录左侧应用图标与右侧窗口标记，并检查最小化、恢复、退出、重启及白底回归；通过后才能确认现场问题已经消除。
