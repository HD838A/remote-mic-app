# 设置窗口失焦行为测试手册

## 适用范围

- 分支：`codex/fix-settings-window-focus`
- 平台：macOS 14 及以上
- 目标：确认无线麦SayAll.app 设置窗口在失去应用焦点后保持可见；窗口只通过系统红色关闭按钮或 `⌘W` 关闭。

## 测试前准备

1. 退出其他无线麦SayAll.app 实例，启动本分支构建的 App：`./script/build_and_run.sh`。
2. 打开设置窗口，确保它没有最小化或全屏。
3. 准备一个无模态窗口的其他 App，例如 Finder 或 TextEdit。
4. 记录测试开始时间；如果同时发生异常，保留 `~/Library/Logs/RemoteMic/runtime.log` 对应时间段。

## 用例 1：Dock 图标关闭时切换 App

1. 在“偏好设置”中关闭“在 Dock 中显示应用图标”。
2. 打开设置窗口。
3. 点击 Finder 或 TextEdit 的窗口。
4. 观察无线麦SayAll.app 设置窗口，然后通过菜单栏的无线麦图标再次打开设置窗口。

预期结果：设置窗口仅变为非活跃外观并保留在原位置；切回无线麦后仍是同一个窗口，不丢失当前页面、滚动位置或未提交的表单输入。关闭 Dock 图标不得让设置窗口被应用隐藏。

失败判定：切换 App 后设置窗口被移出屏幕、重新打开时变成新窗口、当前页面/输入丢失，或需要重启无线麦才能再次打开。

## 用例 2：Dock 图标显示时切换 App

1. 在“偏好设置”中开启“在 Dock 中显示应用图标”。
2. 保持设置窗口打开，点击 Finder 或 TextEdit。
3. 通过 Dock 图标和 `⌘Tab` 分别切回无线麦SayAll.app。

预期结果：窗口失焦后仍可见，且两种切回方式都能恢复同一窗口为活跃窗口。

失败判定：任一切换方式让窗口关闭、隐藏、重建，或改变窗口位置与尺寸。

## 用例 3：标准关闭与最小化边界

1. 先使用 `⌘W` 关闭设置窗口。
2. 通过菜单栏图标重新打开设置窗口。
3. 点击红色关闭按钮，再次从菜单栏图标打开。
4. 点击黄色最小化按钮，然后从 Dock 或菜单栏图标恢复窗口。

预期结果：`⌘W` 与红色按钮都会关闭设置窗口但保持无线麦菜单栏服务运行；黄色按钮只最小化，恢复后保留窗口状态。

失败判定：失焦才会关闭、`⌘W` 或红色按钮无效、最小化变成关闭，或关闭设置窗口导致无线麦进程退出和菜单栏图标消失。

## 稳定功能回归

- [ ] 设置窗口可移动、缩放和进入/退出全屏。
- [ ] 全部侧边栏入口、主要控件和滚动在默认窗口与 `800 × 650` 下未裁切。
- [ ] 菜单栏左键可打开设置，右键仍显示状态菜单。
- [ ] “在 Dock 中显示应用图标”和“启动时自动打开主面板”偏好仍可保存并在重启后生效。
- [ ] 关闭设置窗口不影响蓝牙连接、音频状态或按键映射。

## 日志收集

设置窗口失焦、关闭、最小化均不记录专用业务日志。若同时出现 App 退出、音频或连接异常，请提供 `~/Library/Logs/RemoteMic/runtime.log` 的测试时间段，并补充 macOS 版本、App 版本、Dock 图标开关状态、切换目标 App、实际窗口表现；日志本身不能证明窗口是否仍在屏幕上。

## 验证边界

- 自动化：检查窗口创建代码明确设置 `hidesOnDeactivate = false`、`canHide = false`，并保留 `performClose` 的 `⌘W` 关闭路径。
- 代理实测：当前自动化会话没有可操作的无线麦SayAll.app 图形窗口，未完成用例 1–3 的可见交互验收。
- 用户实测：需要在真实 macOS 图形会话运行用例 1–3；通过后才能确认现场的失焦隐藏现象已经消除。
