# 蓝牙设备名称验证

关联 [Issue #406](https://github.com/HD838A/remote-mic-app/issues/406)。本手册记录候选实现的验证方法与证据，不替代[硬件兼容合同](HardwareCompatibilityContract.md)和[语音音频合同](HardwareVoiceAudioContract.md)。

## 行为与兼容边界

- “连接与语音”和“按键映射”复用三行设备卡片：第一行是型号目录的通用名称，第二行是系统当前蓝牙名称，第三行是连接与电池状态；两行名称均保持单行截断，悬停提示与无障碍标签提供完整内容。菜单栏、连接状态和引导中的通用状态文案保持原语义。
- 有效系统名称作为既有档案的 `customName` 缓存。默认名称使用有限的精确别名集合识别，不通过前缀、后缀猜测；苹果遥控器还会将与同一设备非空 HID `SerialNumber` 完全相同的系统名称视为默认名。用户手动设成这些值时无法与默认名区分，采用型号展示；这不是对系统“是否设置过自定义名”的判定。
- 未改名设备保留全部同型号历史档案的顺序编号；改名和离线档案仍占原位置。相同自定义名称按全部历史档案顺序从 1 编号，跨型号、区分大小写；Unicode 规范等价的名称归为同组。组内仅剩一个名称时不加编号。
- 保留用户名称中的数字，接受自动编号与用户字面名称偶然相同。内部设备选择、按键映射和语音路由使用身份标识，不使用展示名称。
- 空、缺失、无法唯一关联的结果保留缓存；确认为出厂名时清除缓存。名称不变时不写入配置。缓存复用现有字段，不迁移 UUID、HID 指纹或映射。
- 已启动并获蓝牙授权时，在启动、连接就绪/重连、回到前台、打开设置或切换相关页面时重新查询。名称回调仅作补充；没有周期轮询。不保证应用持续处于后台时即时更新。离线档案在重新连接后刷新。
- 小米使用已就绪连接的 CoreBluetooth UUID 重新查询系统名称。苹果通过现有 HID 指纹关联 HID `DeviceAddress`，再精确匹配重新枚举的 IOBluetooth 配对设备；重复 HID 接口允许同一地址，冲突地址不猜测。当前连接读到的完整系统名称只在进程内供第二行显示；已有 `customName` 仍只缓存非出厂自定义名。MAC 与读取的序列号元数据仅用于本次内存关联和判断，不新增持久化字段或输出日志。多接口序列号相同可合并；缺失、空白或冲突时不据此判断默认名，也不猜测字符串格式。
- Chromecast 当前宿主档案没有设备级身份，保留适配器原有名称行为；本次不通过相同名称猜测系统设备。共享卡片规则适用于已有缓存。
- 取消配对、换电脑等导致系统身份变化时遵循现有档案规则，不通过相同名称合并档案。



## 自动化

```sh
swift test --disable-keychain --disable-automatic-resolution --skip-update \
  --filter 'RemoteDeviceName|BluetoothLifecycleTests|RemoteButtonsTests|SettingsPageRegression'
```

- `RemoteDeviceNamePolicyTests`：出厂别名、苹果序列号精确匹配/不匹配/缺失及非苹果隔离、空值、Unicode、数字后缀、历史默认编号、跨型号同名编号及重分组。
- `RemoteDeviceNameIntegrationTests`：名称持久化、重启加载、无变化/不可用不覆写、其他设备与映射不变、HID/地址精确关联及歧义拒绝、已改名设备按 UUID 重新发现、序列号元数据不串设备/多接口冲突、旧缓存纠正后持久化及历史编号恢复。
- 生命周期、按键和设置页面既有回归用例继续执行。自动化不证明系统名称通知、私有苹果组件或实际音频可用。



## 候选程序实际运行检查

在同一候选 Commit 的生产设置窗口验证，记录 Commit、App 版本、macOS 版本和硬件型号；截图公开前将测试名称设置为不含个人信息的内容。

1. 两台同型号设备保持默认名称，核对编号与旧版一致；给其中一台设置唯一名称，再检查另一台的原编号。
2. 把两台设备设为同一自定义名称，检查 `名称 1`、`名称 2`；断开一台、重启 App、切换选中设备，确认档案顺序、各自映射与设备身份不串线。
3. App 连接期间在系统设置改名，回到 App，再切换“连接与语音”/“按键映射”；无需重新连接即在第二行显示新名，第一行始终保持通用型号名。手动改为已识别的默认名（包括本设备序列号）时，第一行不变，第二行显示系统实际返回的名称；不要将手动改名记录为清除系统别名或恢复出厂设置。
4. App 关闭时改名，再启动并等待设备连接就绪；离线时名称保留，重连后刷新。拒绝蓝牙授权或系统查询不可用时不清空缓存、不额外触发授权弹窗。
5. 检查中文/英文、浅色/深色、长名称、Unicode 等价名称、带数字名称。生产最小窗口 `1020 × 772` 下逐个打开受影响入口，确认卡片、导航和滚动无裁切；悬停与 VoiceOver 可获取完整名称。`800 × 650` 仅作为离屏压力检查。
6. 名称刷新前后分别验证按键选择与各设备映射、`STREAM_START → AUDIO → STREAM_STOP`、松键、连续两次语音、双设备不串音，按上述硬件与音频合同记录真实结果。没有执行则保持待验证。
7. 检查 `REMOTE NAME REFRESH` 日志的进程内 `operation_id`、触发原因及 `requested/resolved/changed/unavailable` 计数。相同名称刷新 `changed=0`；无匹配结果增加 `unavailable`。日志不得包含名称、UUID、MAC、指纹或其哈希；计数完成不代表硬件或音频可用。



## 苹果候选 App 仍待完成的三项验证

1. **读取与关联**：支持型号连接后，系统设置自定义名与卡片一致；外部苹果适配器提供的指纹须与宿主 HID 指纹一致，且 HID 地址能唯一关联 IOBluetooth；单台实物可验证这一点。未改名以及手动改回默认名称均保留型号展示规则。
2. **改名刷新**：分别验证运行中改名再回到前台、关闭 App 时改名再启动、断开后改名再重连；不依赖名称回调，不通过重连实现前台刷新。
3. **身份与隔离**：改名、重启及重连不生成额外档案，选中状态、按键映射和语音路径不变。有第二台支持设备时补做同名、断开其中一台及跨设备隔离；单台实物不能证明多台硬件验收。

若公开 API 无法对苹果设备提供有效关联，保留原展示并记录型号/系统版本及脱敏结果，再决定是否补充适配；不得用名称匹配作为降级方案。



## A2854 独立 API 实物验证（2026-09-18）

验证环境：单只 Type-C A2854、macOS 15.7.9。使用独立只读探针，不运行候选 App，不主动扫描/连接，不轮询名称；系统页面名称由用户确认，改名和断开/重连由用户手动操作。公开记录不包含真实名称、序列号或设备标识。

- 初次采集时用户确认从未改名；系统显示名、IOBluetooth 名称与 HID `SerialNumber` 相同。7 个 HID 接口归属一个唯一身份和地址，可唯一关联到一个已连接的 IOBluetooth 设备。
- 保持连接改成测试名称后，重新枚举 `pairedDevices()` 能读到新名，新启动的探针也能读到新名；HID 身份和地址不变，HID `Product` 仍是原名称。
- 用户随后是**手动改回原字符串**，不是清除自定义名称或系统恢复默认；重新枚举正确读到这一变化。再断开并重连后，名称、身份和地址仍正确。
- 只读旧对象可得到旧名；本次未观察到 `peripheralDidUpdateName` 或 `kIOBluetoothDeviceNameChangedNotification`。探针没有主动建立 BLE 连接，不能据此断言通知永不工作。继续采用事件触发的显式查询，不新增通知机制或轮询。
- CoreBluetooth 按 HID 服务 `1812` 查询未取得该遥控器；按 HID UUID 查询可取得对象，但改名后仍可能读到旧名。此次结果支持苹果使用 HID 身份与 IOBluetooth 名称关联，不把小米路径直接推广到苹果。
- 本实验仅证明该型号/系统的公开 API 路径；未验证候选 App、外部苹果适配器的指纹实现、Lightning 型号、其他系统版本、取消配对后身份、按键映射或音频链路。



## 已有证据与待完成项

- 基线：上游 `main` 的 `014d2b2f94cd59f8c9509a59d9c289f6642fe513`；修改前相关 136 项测试通过。
- 本地 macOS 15.7.9、两台小米遥控器的只读 API 实验：重新查询 CoreBluetooth 连接设备和重新枚举 IOBluetooth 配对设备均读到系统改名；持有的旧对象与 HID `Product` 可能仍是旧名。BLE UUID 与 HID 唯一 ID、HID 地址与 IOBluetooth 地址分别一致。无轮询实验中，用户恢复名称后一次显式查询得到更新；未观察到名称回调。该探针没有建立独立 BLE 连接，不能据此断言生产连接不会收到回调。
