# 私有功能公开宿主边界测试手册

## 适用范围

- 分支：`codex/remove-secret-ai-entry` 及其合入后的版本。
- 范围：公开 Mac 宿主与可选私有组件之间的显示、生命周期和稳定功能边界。
- 本手册不记录资格获取方式、内部触发方式、邀请码或服务配置。

## 测试前准备

1. 准备一份不包含私有组件的公开构建。
2. 准备一份包含兼容私有组件、但没有既有授权状态的内部构建。
3. 如需验证兼容性，另准备一份已经由私有组件授权的测试用户环境。
4. 确认本地私有功能开关初始为关闭，并准备脱敏网络与应用日志。

## 用例 A：公开宿主不提供资格入口

1. 分别启动公开构建和未授权的内部构建。
2. 逐一打开设置页和菜单中的所有用户入口。
3. 保持 App 前台、切换后台再返回，并完成一次睡眠恢复。

预期：公开宿主不显示资格申请、解锁或邀请码入口，不因页面浏览、前后台切换或睡眠恢复创建相关身份或发起资格请求。出现任何此类入口或请求均判定失败。

## 用例 B：无私有组件构建

1. 清除 `SAYALL_AI_PACKAGE_PATH`、`SAYALL_MACRO_PLATFORM_PATH`、`SAYALL_MEMBERSHIP_PACKAGE_PATH` 和 `SAYALL_PRIVATE_ARTIFACT_PACKAGE_PATH`，不要依赖宿主目录旁边的私有仓库自动探测。
2. 完成测试与 Release 构建。
3. 启动 App 并逐一检查全部设置页。

预期：App 可正常构建和运行，不显示私有页面、私有入口或私有组件文案；蓝牙、按键映射、统计、权限和关于页保持可用。私有功能只能通过显式路径变量启用；缺少路径时应保持公开模式。

如果设置了任一私有路径变量但路径不存在、包清单不完整或构件校验失败，构建必须直接失败；不得静默回退到公开模式。

## 用例 C：已授权用户兼容性

1. 使用已有授权测试环境启动包含私有组件的构建。
2. 确认私有组件按自身授权状态显示对应页面。
3. 检查本地功能开关状态，完成一次开启、使用和再次关闭。

预期：已有授权状态不因公开入口移除而丢失；本地功能开关默认关闭，关闭后不继续发起私有功能请求，也不影响稳定语音路径。

## 用例 D：稳定功能回归

分别在无私有组件、私有组件未授权、已授权但关闭、开启使用后再关闭四种状态验证：

1. RC003 `STREAM_START → AUDIO → STREAM_STOP` 首次语音路径。
2. 普通遥控器按键、自定义映射、Nearby iPhone、Apple Watch 入口和 Web Remote。
3. 在最小支持窗口逐一打开所有设置页，确认导航、页头、主要控件和滚动无裁切。

预期：私有功能缺失或关闭时，现有稳定功能与上一正式版行为等价。任一稳定功能退化均判定失败。

## 日志收集

通过 App“文件 → 打开日志目录”收集必要时间段日志。提交前必须移除 Token、资格凭证、设备标识、用户语音文字及其他私密内容；不得记录或提交内部资格获取信息。

## 验证边界

- 自动化覆盖公开宿主不包含资格触发调用、无私有组件完全隐藏、完整 Swift 测试、Release 构建和发布说明保密门禁。
- 自动化不能替代真实 RC003、真实 Apple Watch、生产私有组件、资格服务、第三方语音工具及最小窗口可见界面验收。
- 对外发布前仍需完成两架构签名、公证、安装包和公开下载字节验证。
