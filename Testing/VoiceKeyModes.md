# 语音键模式测试手册

## 适用范围

- 适用分支：`codex/voice-key-command-modes` 及包含该功能的 macOS 版本。
- 适用系统：Apple Silicon 使用 macOS 14 或更高版本；Intel 使用 macOS 13 或更高版本。
- 功能范围：Fn/地球键（默认）、左 Command 长按、右 Command 长按、右 Option 长按，以及既有 Fn 点按兼容模式。
- 本手册不把模拟 HID、单元测试、构建、签名或截图视为 RC003、iPhone、Apple Watch、网页版、系统权限或第三方语音应用的真实环境验收。

## 测试前准备

1. 安装待测“无线麦SayAll.app”，记录版本、Build、分支、Commit、Mac 架构和 macOS 版本。
   - 预期：App 能正常启动，版本信息与待测提交一致。
2. 准备 RC003（小米蓝牙遥控器 2 Pro）；如需多设备用例，再准备第二个可独立连接的 RC003。
   - 预期：每个设备都能单独连接并完成一次稳定 Fn 语音。
3. 准备 `MiRemoteV 2ch` 或另一个已经验证的回环音频设备，并准备“设备缺失”测试条件。
   - 预期：设备可用时能看到输入电平；缺失时 SayAll 明确报告不可用，不静默吞掉语音。
4. 分别准备并记录版本与快捷键设置：豆包输入法、微信输入法、Typeless，以及一个明确声明支持独立左/右 Command 长按的测试 App。
   - 预期：每个 App 的语音快捷键与本轮选择的 SayAll 模式一致；不把“普通 Command”支持误写为“能区分左右 Command”。
5. 准备已授权的 iPhone、Apple Watch 和网页版会话；每个入口均需能够单独开始、传输和停止语音。
6. 先记录输入监控、辅助功能和音频设备的初始状态；测试权限变化前保存一份 `runtime.log` 基线。

## 用例 1：设置界面与配置

1. 在真实生产设置窗口 `1020 × 772` 中打开“按键映射”，逐一点击所有受影响的侧边栏入口，再返回映射页。
   - 预期：侧边栏、页头、遥控器卡片、语音键三段选择、Fn 点按区、恢复默认按钮和纵向滚动均完整可达；窗口几何不被页面改变。
2. 分别使用中文和英文检查映射页。
   - 预期：无横向裁切，中文最终显示字号不小于 12pt。
3. 使用项目截图 harness 在 `800 × 650` 压力尺寸渲染映射页。
   - 预期：仅用于发现布局溢出，不表述为生产 App 支持 `800 × 650` 真实窗口。
4. 依次选择 Fn/地球键、左 Command、右 Command、右 Option。
   - 预期：Fn 模式可设置“语音键模拟 Fn 点按”；Command 模式停用该开关，并显示权限与目标 App 兼容性说明。
5. 关闭并重新打开 App。
   - 预期：所选模式持久化；默认和旧版本仍为 Fn/地球键。
6. 导出配置并检查 JSON；再导入不含 `voiceKeyMode` 的旧配置。
   - 预期：新配置包含当前模式；旧配置回退 Fn/地球键且不丢失其他设置。
7. 确认语音键区域没有“短按语音键定位输入框”开关。
   - 预期：语音键设置只包含语音触发模式及 Fn 点按兼容设置。

## 用例 2：语音键极速响应边界

1. 在豆包、微信输入法或其他目标语音 App 中点击输入框，按下 RC003 语音键后立即讲话并释放。
   - 预期：按下后立即开始语音会话，释放后立即结束；不等待双击窗口或长按阈值，不触发输入框聚焦副作用。
2. 连续执行三次短语音，再执行一次约 10 秒长语音。
   - 预期：每次均形成完整且唯一的 `STREAM_START → AUDIO → STREAM_STOP`，首段和尾音不丢失。
3. 在普通按键上配置双击或长按动作后，重复步骤 1～2。
   - 预期：普通按键的手势识别不影响语音键响应。

失败判定：语音键按下后出现可感知等待、短按被解释为聚焦、释放后会话延迟结束、首个会话失败或音频重复。
7. 在语音进行中导入一个会改变语音键模式或 Fn 点按状态的配置。
   - 预期：整次导入被拒绝，语音键和其他配置均保持原值；结束语音后可重新导入。

失败判定：控件缺失或裁切、左右 Command 显示为同一个选项、中文小于 12pt、旧配置被拒绝、默认变为 Command、Command 与 Fn 点按同时启用、被拒绝的导入仍修改了任一配置。

## 用例 2：RC003 Fn 稳定基线

1. 选择 Fn/地球键并关闭 Fn 点按，聚焦豆包输入法或微信输入法的目标输入框。
2. 执行短于 1 秒、约 10 秒、连续三次以及重连后的第一次语音。
3. 核对一次完整事件序列：`STREAM_START → AUDIO → STREAM_STOP`，不得要求预先主动发送 `MIC_OPEN`。
   - 预期：每次只形成一组 Fn 按下/释放，首段和尾音完整，文字只上屏一次。
4. 重复普通遥控器按键、音量、返回和自定义映射。
   - 预期：现有稳定功能与正式版等价。
5. 让遥控器久置断开，或让 Mac 完成一次真实休眠与唤醒；按遥控器电源键恢复，直到方向键已经能控制 Mac。
   - 预期：RC003 重新进入 BLE Ready；即使 HID service 晚于 Ready 出现，SayAll 也会在有限恢复窗口内重新应用 Fn 和电源键映射。
6. 不点击“立即重新连接”，直接在目标输入框执行唤醒后的第一次语音。
   - 预期：第一次就触发目标语音输入并收到完整音频，不能以第二次或第三次成功作为通过。
7. 检查本次 `runtime.log`。
   - 预期：如果首次 Ready 曾出现 `VOICE FN MAPPING ... matched=0`，随后应出现有限次数的 `HID MAPPING RECOVERY scheduled`，并在首次语音前以 `completed` 结束；不得持续轮询。

失败判定：必须点击“立即重新连接”、出现 `HID MAPPING RECOVERY exhausted`、第二次或第三次才成功、Fn 卡住、首段或尾音丢失、音频重复、稳定普通按键行为改变。

## 用例 3：Typeless Fn 点按回归

1. 选择 Fn/地球键并开启 Fn 点按，确保 Typeless 与 SayAll 使用同一回环设备。
2. 按住 RC003 语音键讲话并松开，覆盖短句、约 10 秒和快速重试。
   - 预期：开始时一次 Fn tap，音频排空后一次配对 Fn tap；遥控器仍必须物理按住才能采音。
3. 切到任一 Command 模式后重复。
   - 预期：Fn 点按关闭，不再额外发送 Fn tap。

失败判定：只发送一次 tap、排空前提前结束、切到 Command 后仍发送 Fn tap、映射不完整时仍允许 Fn 点按会话开始。

## 用例 4：RC003 左右 Command 长按

分别对左 Command 和右 Command 执行：

1. 在明确支持对应侧 Command 的测试 App 中设置语音快捷键，选择相同 SayAll 模式并重新连接 RC003。
2. 执行短于 1 秒、约 10 秒、连续三次和重连后的第一次语音。
   - 预期：只产生一次正确侧的 keyDown 和一次无修饰 flags 的 keyUp，音频和文字完整。
3. 按住期间短暂按普通字母键或遥控器普通键。
   - 预期：记录目标 App 是否触发 Command 组合；SayAll 不应额外重复 Command，但此模式本身存在组合键冲突风险。
4. 分别在豆包、微信、Typeless 中按其真实快捷键能力测试。
   - 预期：只有明确支持对应 Command 长按的 App 才应通过；不支持是兼容性结论，不得伪装为 SayAll 已兼容。

失败判定：keyDown/keyUp 不配对、左右侧发送错误、一次会话重复发送、松开后 Command 仍影响键盘、音频链路被阻断。

## 专项用例：RC003 HID 晚到恢复（全模式）

分别选择以下配置执行完整矩阵：Fn/地球键、Fn/地球键并开启 Fn 点按、左 Command、右 Command。

1. 在 Fn 点按已开启时退出 SayAll，让遥控器久置进入休眠，再先启动 SayAll、后唤醒遥控器。
   - 预期：HID service 尚未出现期间设置开关仍保持开启，日志出现 `VOICE FN TAP mode_pending_mapping reason=no_matching_service`；此时不得发送软件 Fn，HID 恢复完成后自动启用，不要求用户重新打开开关。
2. 每种配置下都让遥控器久置断开，或让 Mac 完成一次真实休眠与唤醒；按遥控器电源键恢复，直到方向键已经能控制 Mac。
   - 预期：RC003 重新进入 BLE Ready；即使 HID service 晚于 Ready 出现，SayAll 也会在有限恢复窗口内重新应用当前所选模式和电源键映射，不会强制切回 Fn。
3. 不点击“立即重新连接”，直接执行恢复后的第一次语音。
   - 预期：Fn/地球键产生一组 Fn 按下/释放；Fn 点按先中和 F5 并产生配对 tap；左/右 Command 先中和 F5，再分别产生正确侧的 Command 按下/释放。每种模式的第一次语音都必须收到完整音频，不能以第二次或第三次成功作为通过。
4. 检查本次 `runtime.log`。
   - 预期：如果首次 Ready 出现 `VOICE FN MAPPING ... matched=0`，随后出现有限次数的 `HID MAPPING RECOVERY scheduled`，并在首次语音前以 `completed` 结束；不得持续轮询或出现无条件切换 `voiceKeyMode=fn`。
5. 记录输入监控、辅助功能和目标第三方 App 的实际结果。
   - 预期：Fn 硬件映射不依赖辅助功能；Fn 点按和左右 Command 按既有权限门禁工作。权限不足应明确提示，不得把模式静默改成 Fn。

失败判定：`matched=0` 时 Fn 点按开关自行关闭、必须手动重新开启、必须点击“立即重新连接”、出现 `HID MAPPING RECOVERY exhausted`、当前选择被改成 Fn、第一次语音失败、左右 Command 侧别错误、F5 未中和、按键未释放、首段或尾音丢失。

## 用例 5：iPhone、Apple Watch 与网页版

对三个入口分别执行以下矩阵：

1. Fn/地球键模式开始、讲话、停止，重复两次并覆盖停止后立即重新开始。
   - 预期：保持既有 Fn 稳定基线，不要求 RC003 连接。
2. 左 Command 和右 Command 模式分别重复。
   - 预期：与 RC003 使用同一侧别和成对生命周期。
3. SayAll 在前台、后台各执行一次；目标 App 在前台、后台各执行一次。
   - 预期：SayAll 后台仍按既有授权工作；目标 App 不在前台时不保证接收文字，但不得留下按键或输入源会话。

失败判定：入口互相串线、停止错误来源时释放当前来源、Fn 稳定路径回归、后台后按键卡住或音频会话无法清理。

## 用例 6：多来源与输入源重叠

1. 在 Command 模式先开始 RC003，再开始 iPhone、Watch 或 Web；先停止 RC003。
   - 预期：Command 仍保持按下，输入源不恢复，移动或 Web 音频继续；最后一个来源停止后才发送 keyUp。
2. 反向执行：先开始移动或 Web，再开始 RC003，并先停止移动或 Web。
   - 预期：同上；同一来源重复 start/stop 不增加额外边沿。
3. 在显式 Command 语音会话仍活动时，按下并释放实体键盘 Fn。
   - 预期：Fn owner 结束后不得提前恢复显式语音会话持有的输入源；Command 最终停止时只恢复一次。
4. 在任一来源活动时断开另一个来源。
   - 预期：只清理断开的 owner；剩余来源仍可完成当前语音。

失败判定：第一个来源停止就 keyUp、输入源提前恢复、最后停止后不释放、恢复两次、剩余来源音频被错误终止。

## 用例 7：权限缺失、恢复与会话中撤回

1. 缺少辅助功能时选择 Command 并尝试 RC003、iPhone、Watch、Web。
   - 预期：提示授权；软件 Command 注入失败时拒绝本次开始并清理，不留下 keyDown。
2. 在不重启 App 的情况下恢复辅助功能后重试。
   - 预期：设置自动重新应用，下一次会话正常。
3. Command 会话中撤回辅助功能。
   - 预期：现有 Command 被强制释放；后续开始被拒绝，直到权限恢复。
4. 默认 Fn 模式下，通过 iPhone、Watch 或 Web 开始软件 Fn 长按，再撤回辅助功能。
   - 预期：即使没有开启普通按键映射和 Fn 点按，也必须触发清理并释放软件 Fn。
5. 缺少、恢复和会话中撤回输入监控。
   - 预期：实体 Fn 输入源监听按权限状态启动或停止；停止时恢复受管理输入源，不留下会话。

失败判定：权限变化只能重启后生效、撤权后修饰键卡住、默认 Fn 移动路径不清理、权限失败仍报告语音已开始。

## 用例 8：RC003 与 HID 中和边界

1. RC003 未连接时选择 Command，再使用移动或 Web 语音。
   - 预期：移动或 Web 可按软件 Command 路径工作；设置保留。
2. RC003 蓝牙语音可见但没有匹配 HID service 时按语音键。
   - 预期：保留用户 Command 选择，但拒绝并关闭本次 RC003 microphone stream，不发送软件 Command；日志标记 `voice_key_not_neutralized`。
3. 使用两个 RC003：第一个已 Ready 后连接第二个；再覆盖 `reconnecting → ready` 与重复 `ready → ready`。
   - 预期：每个设备第一次 Ready 和重连 Ready 都重新应用 HID；重复 Ready 通知不重复重启设置。
4. 在可构造环境中制造部分 HID 中和失败。
   - 预期：事务回滚，Command RC003 流被拒绝；不得在未完全中和时发送软件 Command。
5. 中和恢复后执行第一次语音。
   - 预期：第一次即成功，不能以第二次或第三次成功作为通过。

失败判定：未中和仍发送 Command、第二台设备不重应用、部分成功被当作完全成功、重连后第一次失败。

## 用例 9：音频设备缺失与恢复

1. 在回环设备可用时，对 Fn、左 Command、右 Command 各完成一次语音。
   - 预期：设备状态就绪，音频完整。
2. 移除或禁用所选回环设备，再尝试所有入口。
   - 预期：开始被拒绝并关闭本次流，不发送或遗留语音键。
3. 恢复设备并刷新，不重启 App 再试。
   - 预期：音频和语音键生命周期恢复正常。

失败判定：设备缺失仍报告开始成功、按键已按下但音频不可用、设备恢复后必须重启、尾音排空失败。

## 稳定功能回归

- 普通按键映射、双击、长按、应用打开和自定义快捷键保持原行为。
- 默认 Fn、Fn 点按、RC003 普通 `STREAM_START → AUDIO → STREAM_STOP`、iPhone、Watch、Web 的既有语音路径均需回归。
- 切换模式、断连、退出 App、关闭映射和权限变化后，不得留下 Command、Fn、输入源或音频会话。
- 配置导入导出、旧配置默认值、中英文资源和设置窗口全部侧边栏入口保持可用。

## 自动化、代理与用户实测边界

- 自动化已覆盖：枚举与迁移、左右键码与 flags、owner-aware keyDown/keyUp、失败回滚、每个 Bridge Ready 策略、F5 映射事务、配置导入原子门禁、输入源多 owner 和设置页布局门禁；部分 BridgeAppModel 权限/回调接线仍是源码范围断言，运行环境未加载 `REMOTE_MIC_HARDWARE_SIMULATION_PATH`，不等于硬件事件回放。
- 代理截图可以证明生产 SwiftUI 视图在指定渲染尺寸没有明显裁切，但不能替代真实窗口点击、系统权限、音频设备、前后台和第三方 App 行为。
- 模拟 HID 只能证明映射事务和状态机；不能证明 RC003 固件、第二台真实设备或真实 F5 事件顺序。
- 未执行的 RC003、iPhone、Apple Watch、网页版、豆包、微信、Typeless、左右 Command 测试 App、真实权限与前后台用例必须标记为“未验收”。

## 日志收集

1. 记录测试开始和结束时间，复制 `~/Library/Logs/RemoteMic/runtime.log` 对应片段。
2. 重点检查：`ATVV STREAM`、`MOBILE VOICE`、`VOICE KEY`、`VOICE FN MAPPING`、`VOICE INPUT`、`HID PERMISSIONS`、`CONFIGURATION IMPORT`、音频设备准备和 cleanup。
3. 关联来源、事件先后与最终结果；“收到事件”“解码成功”或“入队成功”不等于用户语音已经可用。
4. 分享日志前移除语音内容、转写文字、设备地址、UUID、账号、令牌和密钥。
