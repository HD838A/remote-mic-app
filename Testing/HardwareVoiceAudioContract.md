# 通用硬件语音音频合同

## 适用范围

本手册适用于无线麦SayAll.app 当前及以后接入的所有实体遥控器、蓝牙设备、Watch 或其他硬件语音输入。它是硬件兼容的共同验收门槛；具体设备手册可以增加步骤，但不能降低本合同要求。

本合同是 [`HardwareCompatibilityContract.md`](HardwareCompatibilityContract.md) 的语音音频子规范，同时适用于 macOS 与 Windows。macOS 当前使用 `MiRemoteV 2ch`；Windows 使用该版本声明的 SayAll 虚拟麦克风端点。两端可以采用不同驱动和系统 API，但都必须遵守相同的首字、尾字、顺序、异常和真实硬件验收要求。

## 不可降低的产品要求

1. 按下后立即进入真实收音路径，不等待双击窗口、长按阈值或无必要的防抖；首个有效 PCM 和首字必须尽快出现。
2. 正常松键不丢尾音、尾字，不直接 flush、清空或截断音频缓存。
3. 采集尾包、解码、主线程投递和输出播放必须保持顺序；正常停止必须自然排空。
4. 只能在断连、超时、helper 崩溃等异常恢复路径强制终止；此时必须明确标记完整性失败，不能伪装为正常成功。

## 每种硬件的最低测试矩阵

| 用例 | 必须观察 | 失败判定 |
| --- | --- | --- |
| 首次按下 | 按下到首个有效 PCM/首字耗时 | 有手势等待、固定长按延迟或首段缺失 |
| 正常短句 | 收音、松键、尾包和排空顺序 | 尾字缺失、`interrupted_samples>0` 或正常路径 flush |
| 较长句 | 持续收音期间无静默断流 | 中途丢帧、重排、队列溢出或第三方工具未收到完整流 |
| 快速连续两句 | 第一段排空期间再次按下 | 第二段首字缺失、Fn 短暂释放或 `stale_generation` |
| 取消/断连 | 取消、蓝牙断开、helper 退出后的恢复 | 卡住收音、永久占用设备、错误复用旧会话 |
| 跨硬件切换 | 当前硬件停止后切换另一硬件 | 上一 generation 数据进入下一会话或首字/尾字丢失 |
| 跨平台等价 | 在 macOS 与 Windows 各自的虚拟麦克风路径完成相同短句 | 某个平台回退电脑麦克风、首次会话失败或最终文字明显不完整 |

## 日志验收

正常停止应能找到同一 `audio_generation` 的完整链路，并满足：

```text
audio_interrupted_samples=0
audio_pending_samples=0
completion=normal
```

同时记录 `trigger_down_to_first_pcm_ms`；能够观察目标工具文字时，再记录
`trigger_down_to_first_transcript_observation_ms`。只看到“收到音频”“已入队”或“已排空”不能单独判定用户输入完整。

## 验收边界

单元测试、协议回放、硬件模拟、构建和签名只能证明各自边界；每种硬件仍必须在真实设备、真实虚拟音频设备和目标语音工具上完成首字低延迟与尾字完整验收。一个平台的通过结果不能推导另一个平台通过。
