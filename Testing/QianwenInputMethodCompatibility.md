# 千问输入法兼容模式测试

## 适用范围

- 平台：macOS 14 及以上
- 硬件：小米蓝牙遥控器 2 Pro / RC003
- 音频：`MiRemoteV 2ch`
- 第三方工具：千问输入法 Mac 版

## 测试前准备

1. 千问保留“右 Command”语音快捷键，关闭“短按也能开始输入”，并把麦克风明确选择为 `MiRemoteV 2ch`，不使用“系统默认”。
2. SayAll 中确认 RC003、输入监控、辅助功能和 `MiRemoteV 2ch` 均可用。
3. 打开 `~/Library/Logs/RemoteMic/runtime.log`。

## 用例 1：默认关闭

关闭“千问兼容模式”，重启 SayAll 并按住遥控器语音键。

预期：行为与稳定版一致，语音键映射为 Fn；系统默认麦克风不变化。

## 用例 2：按住说、松开停

1. 开启“千问兼容模式”，点击普通文本输入框。
2. 按住语音键说话，再松开。

预期：SayAll 选择 `MiRemoteV 2ch`；千问启动、收到完整语音并自动确认，不需要再点对勾，输入框不残留蓝色组合输入线。日志在尾音排空后出现 `QIANWEN COMMAND UP` 和 `QIANWEN CONFIRM F20`，随后重新装载硬件右 Command 映射。

失败：千问不启动、使用内置麦克风、丢开头或尾音、松开后仍未结束，或右 Command 保持按下。

## 用例 3：VoiceOver 与全局按键状态

1. 短按和长按语音键各三次。
2. 每次结束后点击不同 Dock 图标，并按一次 Command-F5。

预期：遥控器语音键不会打开 VoiceOver；Dock 正常打开 App，不会在 Finder 中显示 App；实体 Command-F5 仍由 macOS 正常处理。

## 用例 3A：无输入光标时先定位当前 App

1. 先在 Codex 执行：保持 Codex 位于最前面，但点击对话内容区域，让输入框失去光标。
2. 点按一次遥控器语音键并松开。
3. 等 Codex 编辑框出现光标后，再长按语音键说话并松开。
4. 在另一个具有聊天输入框的 App 重复以上步骤。

预期：第一次点按不保留语音内容，也不切换 App 或关闭页面弹层，只在当前最前面 App 里定位最可能的聊天输入框；焦点就绪后硬件右 Command 映射恢复。第二次长按正常输入并自动确认。

Electron / Chromium 类 App 允许在同一次点按内等待最多约 2.75 秒建立 Accessibility 树。日志应先出现 `APP FOCUS manual_accessibility`，随后出现 `APP FOCUS succeeded`和 `QIANWEN FOCUS ready`。

失败：第一次点按开始转写到错误窗口、光标没有进入任何聊天输入框、切换了 App、映射未恢复，或第二次长按没有启动千问。多输入框 App 聚焦到非目标聊天框时记录 App 和页面，作为后续定向规则输入。

微信单独回归：光标已在微信聊天输入框时，直接长按必须立即启动千问，不得再出现 `ATVV MIC_CLOSE request` 或 `QIANWEN FOCUS requested`。光标不在输入框时，短按只在微信主窗口内点击编辑区的窗口相对位置；不读取或保存聊天内容，不对其他 App 启用该降级。

## 用例 4：快速重按

第一次松开后立即再次按住语音键说话，再松开。

预期：旧会话的尾音排空不会确认新会话；第二次松开后才确认，且最终不残留按键状态。

## 用例 5：断连、关闭与退出

分别在语音进行时断开 RC003、关闭千问模式、退出 SayAll。

预期：立即释放右 Command；重新连接或启动后可再次使用。系统默认输入、输出始终不被千问模式修改。

## 用例 6：Fn 点按互斥

依次开启千问模式和“语音键模拟 Fn 点按”。

预期：任一模式开启都会关闭另一模式，一次语音不会同时产生右 Command 和 Fn。

## 用例 7：配置兼容与 Icon

1. 导出开启千问模式的配置并导入到干净设置。
2. 导入缺少新字段的旧配置。
3. 检查 Dock 与“应用程序”中的图标。

预期：新配置恢复千问模式，并把导入配置里的普通扬声器覆盖为 MiRemoteV；旧配置默认关闭；App 使用圆角透明 Icon，不显示白色直角方块。

## 用例 8：MiRemoteV 暂时不可用

1. 在受控测试环境中让 `MiRemoteV 2ch` 暂时不出现在音频输出列表，但保留千问兼容模式。
2. 启动 SayAll 并按住语音键。
3. 恢复 `MiRemoteV 2ch`，等待系统音频设备变化通知，再次按住语音键。

预期：设备缺失期间 SayAll 显示音频不可用，Mac 扬声器没有电流声、语音或测试音；设置不保存实体扬声器作为千问输出。设备恢复后自动重新绑定 MiRemoteV，下一次长按恢复正常输入。

失败：缺失期间任何 RC003 PCM 从实体扬声器播放、千问回退内置麦克风并继续输入，或设备恢复后必须手动重新选择才能工作。

## 用例 9：微信回眸读取进程

在微信连续完成至少 3 次“短按定位、长按说话、松开确认”，每次检查回眸和运行进程。

预期：3 次均新增一条微信回眸；没有残留的 `QianwenHistoryReader` 进程。千问历史不可读或 Helper 超过 3 秒时只漏掉该次回眸，不影响语音键释放、自动确认和下一次语音。

## 自动化与人工边界

- 自动化覆盖完整硬件右 Command 映射、缺少安全焦点时的屏蔽/释放/聚焦/重装载、排空后 Command 释放、F20 确认、快速重按、开关互斥、配置兼容、MiRemoteV 缺失时失败关闭、所有运行时重绑入口，以及历史 Helper 的启动失败、超时与强制结束。
- 自动化不能证明真实 RC003、千问和 macOS VoiceOver 的最终联动，必须按以上用例人工验收。
