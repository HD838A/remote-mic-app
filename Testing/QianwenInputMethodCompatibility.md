# 千问输入法兼容模式测试

## 适用范围

- 开发分支：`codex/qianwen-voice-mode`
- 平台：macOS 14 及以上
- 硬件：小米蓝牙遥控器 2 Pro / RC003
- 音频：`MiRemoteV 2ch`
- 第三方工具：千问输入法 Mac 版

## 测试前准备

1. 使用经过项目签名与公证流程的候选 App，不使用未公证安装包替换正式 App。
2. 在千问输入法中保留默认“右 Command”语音快捷键和“系统默认”麦克风。
3. 在无线麦确认 RC003、输入监控、辅助功能和 `MiRemoteV 2ch` 均可用。
4. 记录测试前系统默认麦克风，并打开 `~/Library/Logs/RemoteMic/runtime.log`。

## 用例 1：默认关闭

1. 保持“千问兼容模式”关闭。
2. 重启无线麦并按住遥控器语音键。

预期：行为与稳定版一致，语音键仍映射为 Fn；系统默认麦克风不变化。

失败：关闭状态仍发送右 Command，或修改默认麦克风。

## 用例 2：首次开启

1. 连接 RC003，在“连接与语音”开启“千问兼容模式”。
2. 不修改千问快捷键和麦克风设置。
3. 点击普通文本输入框，按住遥控器语音键说话，松开结束。

预期：无线麦自动选择 `MiRemoteV 2ch`；系统默认麦克风临时变为该设备；千问由右 Command 启动并第一次收到完整语音。

失败：仍发送 Fn、千问未启动、使用内置麦克风、必须第二次才成功、丢开头或尾音。

## 用例 3：Fn 点按互斥

1. 开启千问模式后再开启“语音键模拟 Fn 点按”。
2. 重新开启千问模式。

预期：任一模式开启都会关闭另一模式，不会同时产生右 Command 和 Fn。

失败：两个开关同时有效，或一次语音产生两组触发。

## 用例 4：断连与重连

1. 千问模式生效时断开 RC003。
2. 确认默认麦克风恢复后重新连接。
3. 再执行一次语音。

预期：断连恢复此前麦克风；重连后重新临时选择 `MiRemoteV 2ch`；第一次语音成功。

失败：断连后默认输入仍停留在虚拟设备、重连不恢复模式，或音频通道无声。

## 用例 5：尊重用户手动修改

1. 千问模式生效时，在系统设置手动选择另一只麦克风。
2. 触发音频设备刷新、睡眠唤醒和一次语音。

预期：无线麦不覆盖用户的新选择，自动关闭千问兼容模式并恢复 Fn 映射；日志记录放弃本次默认输入管理。

失败：用户选择被静默改回 `MiRemoteV 2ch`。

## 用例 6：关闭、退出和设备变化

分别验证关闭模式、退出无线麦、拔掉原默认麦克风、更换无线麦语音输出。

预期：原设备仍可用时恢复原设备；原设备不可用时回退到可用物理输入；不留下右 Command 映射或失效的默认输入。

失败：退出后仍保持 App 管理的映射或虚拟默认输入，或者覆盖用户在测试期间的新选择。

## 用例 7：配置兼容与 Icon

1. 导出开启千问模式的配置并导入到干净设置。
2. 导入缺少新字段的旧配置。
3. 检查 Dock 与应用程序中的图标。

预期：新配置恢复千问模式；旧配置默认关闭；App 使用仓库圆角透明 Icon，不显示白色直角方块。

失败：旧配置意外开启、Fn 点按同时开启，或最终 App 仍使用旧方形 Icon。

## 稳定功能回归

- 普通 Fn 长按、Typeless Fn 点按、普通按键映射、测试音和配置导入导出保持可用。
- RC003 仍走无需主动 `MIC_OPEN` 的 `STREAM_START → AUDIO → STREAM_STOP`。
- 关闭千问模式时，系统默认输入行为与上一正式版等价。

## 自动化与人工边界

- 自动化覆盖右 Command HID usage、默认输入所有权、用户改选保护、开关互斥、配置兼容和设置页结构。
- 构建与 App 验证覆盖资源和圆角 Icon，但不证明千问最终收到语音。
- RC003、真实千问、系统默认输入切换、断连重连、睡眠唤醒、最终文字上屏和 Dock 缓存必须人工验收。
