# 首次使用设置向导测试手册

## 适用范围

- 版本：Remote Mic `v1.8.10 (102)` Pre-release 候选
- 候选分支与标签：`release/pre-v1.8.10` / `v1.8.10`
- 平台：macOS 14 及以上
- 功能状态：候选自动化验证完成；真实升级、权限、RC003、兼容麦克风和第三方语音工具仍等待现场验收
- 目标：确认首次启动必须通过完整设置向导，并通过真实权限、RC003、MiRemoteV 2ch、第三方语音工具和实体按键形成可用闭环。

## 测试前准备

1. 准备已安装 MiRemoteV 2ch 的测试 Mac、RC003 遥控器，以及豆包输入法、Typeless 和至少一个其他语音工具。
2. 退出其他 Remote Mic 实例，备份需要保留的个性化设置。
3. 使用独立测试账号或清除本 App 的 Onboarding 测试键，确保进入全新流程；不要删除用户正式配置。
4. 打开 `~/Library/Logs/RemoteMic/runtime.log`，记录每个失败用例的大致时间。
5. 窗口保持 `1020 × 772`，分别使用中文和英文执行布局检查。

## 用例 1：启动门禁、不可跳过与恢复

1. 全新状态启动 App。
2. 检查顶部只显示“准备 › 设置 › 试一下”，页面没有步骤编号、总数、百分比、“跳过”或“稍后继续”。
3. 在欢迎页关闭窗口，再从菜单栏打开；应仍停留在欢迎页。
4. 选择一个语音工具并进入权限页，退出 App 后重新启动。
5. 确认直接恢复到权限页，不能看到主设置页。
6. 在任一未满足门禁的页面尝试继续。

预期结果：未完成当前流程版本时每次启动都显示向导；关闭窗口和退出 App 只保存当前位置，不构成旁路；缺少实时条件时主按钮禁用。

失败判定：能打开主设置页、存在跳过/稍后入口、重启回到错误页面、只点击系统设置就被判定成功，或欢迎页出现前主动弹出系统权限。

## 用例 2：语音工具分支

分别从头运行三次：豆包、Typeless、其他语音工具。

预期结果：

- 未选择时不能继续。
- 选择 Typeless 并通过权限后，现有“语音键模拟 Fn 点按”启用。
- 选择豆包或其他工具时，该模式关闭。
- 重新运行向导时会重新要求选择，但不会清除其他按键配置。

失败判定：选择没有保存、分支与 Fn 点按状态相反、切换分支破坏普通按键配置，或选择页面使用长下拉列表。

## 用例 3：蓝牙、输入监控与辅助功能

对三项权限分别执行“未决定 → 拒绝 → 从系统设置恢复 → 允许”：

1. 点击每一行唯一的权限操作。
2. 拒绝权限并返回 App，确认该行仍未通过且不能继续。
3. 从页面打开正确的系统设置，允许权限，再切回 App。
4. 如系统要求重启 App，退出并重启，确认仍恢复到权限页并重新检测。

预期结果：三项全部实时有效后才可继续；返回前台或重启后自动刷新；输入监控与辅助功能说明不会暗示读取或保存用户键盘内容。

失败判定：拒绝后仍通过、打开错误设置页、状态不刷新、只允许两项即可继续，或系统权限窗口连续无序弹出。

## 用例 4：遥控器连接与实体按键

1. 从系统蓝牙中取消 RC003 配对，进入连接页。
2. 确认 App 显示等待连接且不能继续。
3. 完成系统配对，等待 App 实际连接。
4. 只连接但不按键，确认仍不能继续。
5. 按一个普通实体按键，确认页面显示已收到并允许继续。
6. 断开遥控器、重新连接后重复。

预期结果：系统蓝牙列表中的“已连接”不能替代 App 实际连接；必须收到普通实体按键事件。

失败判定：未连接或未收到按键即可继续、语音键误算普通按键、按键被两只遥控器重复计数，或重新查找导致 App 卡死。

## 用例 4A：已安装用户升级后的首次连接恢复

1. 安装一个此前可正常使用 RC003 的正式版本，完成权限、配对和普通按键设置，保持遥控器已配对。
2. 通过与用户一致的 Sparkle 更新路径升级到包含本修复的候选版，不先手动退出或重启新版本。
3. 首次启动后进入 Onboarding 遥控器页，按一个普通实体按键。
4. 如果页面短暂出现“已收到实体按键”但仍显示正在查找，保持 App 运行并等待自动恢复，不执行重启。
5. 连接后按普通按键，再执行一次普通 `STREAM_START → AUDIO → STREAM_STOP` 语音输入。
6. 断开遥控器并返回该页，点击“重新查找”，确认即使此前没有可重连的 bridge 也会重新启动发现。

预期结果：实体按键已到达但 BLE 尚未 Ready 时只触发一次恢复，不因连续按键反复重连；无需重启 App 即转为已连接；普通按键和 RC003 语音基线保持正常。日志在空 bridge 恢复时出现一次 `BLE RECONNECT starting_missing_bridges`。

失败判定：状态一直停留到重启、每次按键都中断并重新建立连接、点击“重新查找”仍无新连接尝试、连接恢复后普通按键或语音失效，或稳定已连接状态被额外重连。

## 用例 5：MiRemoteV 2ch

1. 在没有 MiRemoteV 2ch 的环境进入音频页，确认显示未检测到并提供安装说明。
2. 安装或恢复设备后点击重新检查。
3. 检测到设备但不选择，确认不能继续。
4. 点击“选择 MiRemoteV 2ch”，等待音频输出状态就绪。
5. 删除或停用设备后重复检查。

预期结果：设备必须存在、被选中且实际音频输出就绪；设备变化后状态可刷新。

失败判定：仅按过选择按钮就通过、选择了其他设备仍通过、输出未就绪仍继续，或操作替换/修改用户已有音频设备。

## 用例 6：真实端到端语音文字

对豆包、Typeless 和其他工具分别执行：

1. 点击向导输入框，确认光标在其中。
2. 按住 RC003 语音键，说“无线麦已经连接成功”，说完后松开。
3. 观察实时检查：语音键完整按下并松开、收到真实遥控器声音、MiRemoteV 2ch 正常、文字出现。
4. 分别制造以下失败：只触发会话但不产生音频、音频设备失效、开始后不松开、没有文字上屏。

预期结果：只有会话开始、PCM 样本数量大于零、松开后会话结束、兼容麦克风就绪且输入框出现非空文字时才允许继续。无线麦不记录音频内容或输入框文字。

失败判定：只有 `STREAM_START` 就通过、没有文字仍通过、松开后仍在收音、文字出现在其他窗口却误判，或日志包含音频内容/测试文字。

## 用例 7：三个普通按键与完成

1. 在按键页重复按同一个普通按键三次。
2. 确认只算一个已体验按键且不能继续。
3. 再按两个不同普通按键。
4. 进入完成页，点击“打开无线麦”。
5. 确认进入现有主设置页；退出并重启不再出现向导。
6. 在主面板记录当前兼容麦克风、按键映射、Dock、启动和预发布更新设置。
7. 在“关于”页点击“重新运行设置向导”，确认立即回到欢迎页，重启后仍处于向导。
8. 重新完成向导并返回主面板，确认第 6 步记录的现有设置仍保留。

预期结果：“关于”页明确说明重新运行只用于复查权限、遥控器、兼容麦克风和语音输入，不会清除现有连接、按键映射或其他设置。

失败判定：重复同一按键可通过、语音键被计入、完成按钮不进入设置、完成版本未保存、重新运行仍可绕过向导，或重新运行后现有用户配置丢失。

## 用例 8：布局、语言与稳定功能回归

- [ ] 中文与英文在 `1020 × 772` 下逐页检查，无文字或按钮裁切，无意外窗口尺寸变化。
- [ ] 所有中文文字最终显示字号不低于 12pt。
- [ ] 浅色、深色、降低透明度和增强对比度下内容可读。
- [ ] 浅色模式左右均为浅色体系；深色模式左右均为深色体系，不出现黑白分栏。
- [ ] 键盘 Tab、Return、Space 和 VoiceOver 可到达选择卡、权限按钮、返回与继续。
- [ ] 完成后依次打开连接与语音、按键映射、统计、权限与隐私、关于，页头、主要控件和滚动正常。
- [ ] RC003 普通 `STREAM_START → AUDIO → STREAM_STOP` 语音基线正常。
- [ ] 普通按键默认动作、自定义快捷键、双击、长按和多遥控器行为未变化。
- [ ] 菜单栏状态、Sparkle 更新和“启动时自动打开主面板”在已完成用户中保持原行为。

## 用例 9：锁屏离屏截图隐藏入口

1. 保持 Mac 锁屏或不依赖当前屏幕读取权限。
2. 执行 `~/.codex/skills/remote-mic-onboarding-screenshots/scripts/capture.sh <仓库绝对路径> <输出目录> both`。
3. 检查输出目录下 `light/` 和 `dark/` 各包含 `01-welcome.png` 到 `08-complete.png`。
4. 逐张查看全部 16 张截图，并在执行前后核对用户正式 Onboarding 进度未变化。
5. 不设置截图环境变量正常启动 App，确认不会显示截图入口、额外窗口或调试菜单。

预期结果：锁屏状态仍能从生产 `OnboardingView` 生成全部页面；每张为有效 PNG 且像素尺寸有效；浅色和深色分别保持一致视觉体系；隐藏入口不修改正式偏好，也不影响正常启动。

失败判定：依赖屏幕录制权限、输出设计稿或重绘图、缺少任一页面、左右黑白分栏、正式向导进度变化，或普通用户能在界面中发现截图入口。

## 日志收集

右键菜单栏图标选择“显示日志”，或提供 `~/Library/Logs/RemoteMic/runtime.log`。记录问题发生时间、macOS 版本、所选语音工具、权限状态、遥控器连接状态和实际结果。

日志中的“收到事件”“解码成功”或“入队成功”都不能单独证明向导通过；必须同时核对页面实时状态和最终文字结果。不要提供音频、输入框文字、蓝牙地址、外设标识或其他个人信息。

## 自动化、代理实测与用户实测边界

- 自动化覆盖步骤顺序、阶段、所有门禁、流程版本、当前位置、语音工具、完成和重新运行持久化。
- 自动化覆盖“已收到 HID 按键但 BLE 未连接”只请求一次恢复，以及 `reconnect()` 在 bridge 尚未创建时进入蓝牙启动分支；它不是真实 CoreBluetooth 回调或 Sparkle 升级验收。
- 编译与单元测试不能触发或证明真实系统权限、RC003、MiRemoteV 2ch、豆包、Typeless、其他第三方工具或文字上屏。
- 代理可在有图形会话时检查页面布局和基础交互，但不能替代用户机器上的权限历史、真实硬件和第三方 App 配置。
- 代理可在锁屏状态通过隐藏离屏入口验证生产页面的静态布局和浅色/深色外观；这不证明权限弹窗、遥控器、驱动或文字上屏链路真实通过。
- 用例 2～8 的真实设备与第三方工具结果全部通过后，才能把功能状态改为“已完成”。
