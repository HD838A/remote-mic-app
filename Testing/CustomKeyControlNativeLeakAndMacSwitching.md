# 自定义按键 Control、原始行为泄漏与跨 Mac 切换测试手册

## 适用范围

- 适用分支：`codex/fix-hid-mapping-controls-switching`。
- 测试目标：验证 Control + 方向键、RC003 自定义映射不再泄漏原始系统动作，以及跨 Mac handoff 会停止当前 Mac 的 SayAll 自动重连并准确暴露系统边界。
- 本次不提供可分发安装包；只有经过 Developer ID 签名、公证、staple 和 Gatekeeper 验证的候选包才可交付用户安装。

## 测试前准备

1. 准备一只 RC003、一台测试 Mac；跨 Mac 用例另准备 MacBook 与 Mac mini。
2. 为候选 App 开启蓝牙、输入监控和辅助功能权限。
3. 确认系统 Mission Control 的 `Control + ↑ / ↓ / ← / →` 仍为默认快捷键。
4. 打开 TextEdit、浏览器输入框及至少一个会监听全局快捷键的工具；不要使用密码、Token 或生产数据。
5. 记录测试 Commit、macOS 版本、遥控器型号，以及每个用例开始/结束时间。

## 用例 1：Control + 四个方向键

1. 在“按键映射”选择一个普通遥控器按键，动作选择“自定义快捷键”。
2. 进入“标准键盘”，选中 Control，再依次选择 ↑、↓、←、→。
3. 再使用实体键盘录入一次 Control + 对应方向键，确认结果不显示 `fn`。
4. 每次关闭并重新打开编辑区，确认显示 `⌃` 与对应方向。
5. 在 Finder 或桌面前台触发映射，观察 Mission Control/Space 行为。

预期结果：四个组合均能保存、重启后保留，并只提交一次 Control + 对应方向键。失败判定：方向键缺失、Control 丢失、显示与执行不一致、触发两次或修饰键卡住。

## 用例 2：音量键映射不泄漏系统音量

1. 将音量加映射为复制，将音量减映射为粘贴。
2. 在 TextEdit、浏览器普通文本框和用户反馈中曾失败的输入框分别测试复制/粘贴。
3. 每次观察系统音量 HUD 和实际音量。
4. 取消两项动作但保持自定义映射开启，再次按音量键。

预期结果：配置动作时只执行复制/粘贴，不出现音量 HUD、音量不变化；取消动作后按键不执行复制/粘贴，也不泄漏系统音量。失败判定：任何双重触发、系统音量变化或不同输入框结果不一致。

## 用例 3：全部普通按键原始行为

1. 依次测试电源、上、下、左、右、确定、返回、音量加、主页、音量减、菜单、TV。
2. 每个按键配置一个容易观察且可恢复的动作，分别测试单击、双击与长按。
3. 对方向键进行按住连发，松开后立即使用 Mac 实体键盘。
4. 暂停或退出全局快捷键工具后重复；再开启该工具测试其不应收到遥控器原始键。

预期结果：每次只执行 SayAll 配置动作；电源不锁屏，音量不变化，TV 不触发原符号键，方向键不同时移动系统焦点；松开或断连后实体键盘无卡键。失败判定：任一原始行为泄漏、配置动作丢失、重复或实体键盘受影响。

## 用例 4：关闭、重启与权限失败恢复

1. 关闭自定义映射，确认系统原始按键恢复；重新开启后配置仍保留。
2. 退出并重开 App，重复用例 2 的音量键检查。
3. 撤销输入监控或辅助功能权限，确认 App 停止接管而不是进入半接管状态。
4. 恢复权限并重新检测，确认设备级中和与自定义动作一起恢复。

预期结果：只有完整写入和读回设备级映射后才启动按键监听；失败时明确显示无法安全接管，不能出现“自定义动作偶尔生效、系统原动作也生效”的状态。

## 用例 5：同一只遥控器在两台 Mac 之间切换

1. 在 Mac A 连接 RC003，记录 `BLE READY` 时间，点击“暂停本机 SayAll 并打开蓝牙设置”。
2. 确认页面显示“本机 SayAll 连接已暂停”，日志出现 `BLE HANDOFF paused ... app_reconnect=false system_pairing_unchanged=true`。
3. 保持 Mac A 上 SayAll 运行 2 分钟，期间让 Mac A 休眠并唤醒一次；确认没有重新进入该遥控器的 `BLE CONNECTING` / `BLE READY`。
4. 退出并重新打开 Mac A 上的 SayAll，确认日志出现 `BLE HANDOFF startup_paused_count=... app_reconnect=false`，且该遥控器仍不被 App 连接。
5. 在 Mac A 系统蓝牙中选择“断开连接”；不要先“忽略此设备”。在 Mac B 尝试连接，并验证普通按键与语音。
6. 如 Mac B 找不到遥控器，同时长按 Home + Menu 进入配对模式，再连接；记录该步骤是否导致 Mac A 或 Mac B 丢失已有配对记录。
7. 切回 Mac A 前，在 Mac B 执行同样的暂停与系统断开。然后在 Mac A 点击“恢复本机 SayAll 连接”，确认日志出现 `BLE HANDOFF resumed app_reconnect=true system_pairing_unchanged=true` 并恢复语音。

预期结果：暂停后 SayAll 自己不会在发现扫描、唤醒或重启时抢回 RC003；显式恢复后才重新建立 App 级 BLE/ATVV 会话。系统设置是否能在不“忽略此设备”的情况下释放 HID、遥控器是否重新广播、旧 Mac 是否被系统 HID 自动抢回，必须逐项记录。

失败判定：暂停状态未持久化、暂停后仍出现该遥控器的 SayAll `BLE CONNECTING` / `BLE READY`、唤醒或重启绕过暂停、恢复后不能连接，或页面/日志把 App 级暂停描述为系统配对已迁移。

边界判定：若暂停 SayAll 后仍必须“忽略此设备”，则已排除 App 自动重连为唯一根因，剩余问题属于 macOS 系统 HID 或 RC003 固件/配对能力，不能继续用纯 CoreBluetooth 代码宣称修复。

## 稳定功能回归

- [ ] 语音键按下立即开始、松开立即结束，不受本次普通按键映射影响。
- [ ] 连续两次语音会话及异常断连恢复正常。
- [ ] 两只遥控器的独立 Profile 不串用动作或快捷键。
- [ ] 暂停其中一只遥控器时，另一只遥控器仍可正常连接、按键和语音。
- [ ] 自定义映射关闭时 macOS 原生方向、音量、Home 等行为恢复。
- [ ] iPhone、Apple Watch、网页版普通按键行为不变。
- [ ] `800 × 650` 逐一访问受影响设置入口，跨 Mac 提示、按钮、页头和滚动不裁切、不改变窗口几何。

## 日志收集

1. 从菜单栏打开日志目录，收集失败时间段的 `runtime.log`。
2. 重点检查 `VOICE FN MAPPING`、`HID START`、`HID REPORT`、`HID BUTTON`、`SHORTCUT ACTION submitted` 与 `BLE HANDOFF`。
3. 成功接管应出现 `native_buttons_suppressed=true native_button_mappings=12 suppression_scope=locations=...`。
4. 日志中的动作提交不代表系统原始事件没有泄漏；必须同时记录音量 HUD、Mission Control、目标输入框和第三方工具的最终屏幕行为。
5. 不记录输入内容、设备标识、密码或 Token。

## 自动化、代理与用户实测边界

- 自动化可证明映射集合、读回回滚、Profile 配置读取、Control + 方向键标志、handoff 暂停持久化、启动/discovery 排除、恢复顺序和页面接线。
- 代理环境不能证明 WindowServer、系统音量、电源路径、Mission Control、第三方全局事件监听和真实蓝牙广播。
- RC003 全部按键、不同输入框和两台 Mac 往返切换必须由真实硬件完成；在此之前只能称为候选修复与明确的系统边界。
