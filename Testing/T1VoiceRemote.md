# T1 蓝牙语音验收

## 范围

本次候选覆盖该样机的 macOS 蓝牙语音。样机使用 `0x620A:0x0407`、DIS `hid_mouse` 和 `shenzhen_xingwei`，验证固件 `0.0.1`。T1 的键盘和指针直通系统。正面独立按键映射使用本机样机的标准蓝牙 HID；2.4 GHz 和 Windows 未纳入此轮。使用一只 T1 与一只现有小米遥控器验证互不干扰；同时连接多只同指纹 T1 时应报告语音不可用。

## 操作与通过条件

1. 在 macOS 蓝牙设置配对 T1，在 SayAll 连接页添加它。确认真实型号、系统名称、电量和可用状态。输入监控缺失时应用须显示原因，不能宣告语音准备完成。
2. 打开本地空白文本，在所选输入工具使用 SayAll 虚拟麦克风。按住 T1 语音键说「第一段，到这里结束」，松手；约三秒后重复第二段。两次须分别上屏且末字完整，系统搜索不应抢走焦点。
3. 比较按下到首段 PCM 与首字，以及松手到断流和释放输入工具语音键的时长。事件应为 `START_SEARCH → MIC_OPEN → AUDIO_START → PCM → HID release → MIC_CLOSE → AUDIO_STOP → CAPS`。重复停止不能结束下一轮。
4. 重新配对或唤醒后验证第一段。测试按住时断连、应用退出、关麦无确认或重协商无确认。确认语音会话有界结束，恢复后可以重新录音。退出后核对 T1 搜索键的原有系统映射。
5. 以相同输入工具测试小米 RC001／RC003 的按住、松手、连续短句与恢复。测试 T1 时，本机其他键盘、指针及小米遥控器的普通键保持原有行为。

## 当前证据

- 独立探针在按需模式下验证了两轮连续松手关麦。停止确认分别耗时约 435 和 449 毫秒。设备在会话之间需要重协商。
- 使用 SayAll 开发分支的实际蓝牙桥，两次松手均收到正常停止。离线转写得到「第一段到这里结束」和「第二段到这里结束」。其中第二段首次操作没有触发采集，重试成功。需要继续复测连续会话。
- 在 macOS 公共构建的日常连接页，测试档案显示 T1 名称和连接状态。测试包预置已完成首次引导，首次引导目前没有 T1 选项。
- 在日常应用连续录制两段 T1，日志显示 Fn 按下和松开各提交两次，宿主关麦后分别 431 和 430 毫秒收到正常停止确认，两次均重新协商成功。首包 PCM 分别在设备开始报告后的 46 和 103 毫秒到达，物理按下时刻仍待测。分别解码并播放 51,968 和 45,312 个采样到 MiRemoteV 2ch，日志所报丢弃、中断和待处理采样为零。
- 同一构建内，小米 RC001 三个会话正常结束，分别完整播放 35,040、89,760 和 59,280 个采样到 MiRemoteV 2ch。完整的小米语音和异常恢复矩阵仍待验收。
- 使用独立的 AVFoundation 采集器从 MiRemoteV 2ch 读回下一条 T1 测试语句，离线转写为「虚拟麦克风读回到这里结束」。对应应用会话正常停止，54,272 个样本全部播放，丢弃、中断及待处理采样为零。
- Build 450 在系统蓝牙中只断开 T1，保留配对。应用随后自动启动恢复，约 7.5 秒后重新完成语音协商并校验全部 12 个按键映射。小米在恢复期间保持连接。
- 自动重连后，T1 返回键成功删除 TextEdit 的标记。随后两次按住语音键并松手，微信输入法在同一文稿连续写入「蓝牙第一段尾号 379。蓝牙第二段尾号 846。」两轮均在松手后正常关麦；应用分别向虚拟麦克风交付 68,096 和 73,984 个采样，排空后释放 Fn。下一轮按下前已重新协商，两个尾号均完整。
- 语音会话超时、录制中断连、其他 T1 固件和 Windows 仍待专项验收。

## 正面按键与背面键盘

- 正面画布按实体布局显示。四个方向键、中间确认、电源、返回、主页、菜单、静音及侧边音量加减可进入现有单击、双击、长按和按住编辑器。
- 真机对照中，正背面的四个方向键生成完全相同的键盘报告。正面确认键生成标准 Return（usage `0x28`）。启用映射时，相同 usage 经过同一动作配置。背面字母、修饰键、空格和飞鼠指针保持设备原生路径。
- 将「上」临时映射为退格，正背面各按一次后，TextEdit 文稿正好删除两个字符，应用日志记录两次单击动作。测试后已恢复「上」的原动作和按住设置。
- Build 450 对正面返回键进行一次单按和五次连按。五次按下跨时 1.02 秒，最短间隔 225 毫秒。T1 报告六组完整的按下与松开，SayAll 记录六次单按退格，TextEdit 实际删除六个字符。
- 映射关闭时逐键检查原生输入。开启后把一个方向键临时设成易辨认的快捷键，从正背面各按一次，核对两次都只执行一次映射动作。再检查确认键、其他方向键、侧边音量、飞鼠和背面字母。电源键安排在确认原生映射已屏蔽之后测试。
- 在按住普通键时断连，确认没有遗留保持键或后续补发动作。恢复连接后测试同一配置，同时确认小米遥控器和 Mac 键盘原有行为。

## 蓝牙连接与授权

- 在 macOS 已连接 T1 的情况下，使用未授权输入监控或辅助功能的本地构建打开 SayAll。T1 卡片显示「已连接 · 需授权」，蓝牙链路保持连接，语音键无法开启麦克风。授权后回到 SayAll，确认可用状态恢复。实际断开蓝牙后，设备状态必须退出已连接。
- 在连接页切换小米和 T1。小米显示对应型号的真机图，T1 显示与按键页同款正面图。确认 T1 预览没有可编辑控件，也没有显示「未识别的遥控器」。
- 当小米遥控器的语音通道已就绪、已启用自定义按键但系统缺少输入监控或辅助功能授权时，卡片显示「已连接 · 需授权」。悬停状态可看到按键映射需要的两项权限。
