# T1 蓝牙语音验收

## 范围

本次候选覆盖该样机的 macOS 蓝牙语音。样机使用 `0x620A:0x0407`、DIS `hid_mouse` 和 `shenzhen_xingwei`，验证固件 `0.0.1`。T1 的键盘和指针直通系统。普通按键映射、2.4 GHz 和 Windows 未纳入此轮。使用一只 T1 与一只现有小米遥控器验证互不干扰；同时连接多只同指纹 T1 时应报告语音不可用。

## 操作与通过条件

1. 在 macOS 蓝牙设置配对 T1，在 SayAll 连接页添加它。确认真实型号、系统名称、电量和可用状态。输入监控缺失时应用须显示原因，不能宣告语音准备完成。
2. 打开本地空白文本，在所选输入工具使用 SayAll 虚拟麦克风。按住 T1 语音键说「第一段，到这里结束」，松手；约三秒后重复第二段。两次须分别上屏且末字完整，系统搜索不应抢走焦点。
3. 比较按下到首段 PCM 与首字，以及松手到断流和释放输入工具语音键的时长。事件应为 `START_SEARCH → MIC_OPEN → AUDIO_START → PCM → HID release → MIC_CLOSE → AUDIO_STOP → CAPS`。重复停止不能结束下一轮。
4. 重新配对或唤醒后验证第一段。测试按住时断连、应用退出、关麦无确认或重协商无确认。确认语音会话有界结束，恢复后可以重新录音。退出后核对 T1 搜索键的原有系统映射。
5. 以相同输入工具测试小米 RC001／RC003 的按住、松手、连续短句与恢复。测试 T1 时，本机其他键盘、指针及小米遥控器的普通键保持原有行为。

## 当前证据

- 独立探针在按需模式下验证了两轮连续松手关麦。停止确认分别耗时约 435 和 449 毫秒。设备在会话之间需要重协商。
- 使用 SayAll 开发分支的实际蓝牙桥，两次松手均收到正常停止。离线转写得到「第一段到这里结束」和「第二段到这里结束」。其中第二段首次操作没有触发采集，重试成功。需要继续复测连续会话。
- 在 macOS 公共构建的日常连接页，测试档案显示 T1 名称和连接状态。测试包预置已完成首次引导，首次引导目前没有 T1 选项。
- 在日常应用连续录制两段 T1，日志显示 Fn 按下和松开各提交两次，宿主关麦后分别 431 和 430 毫秒收到正常停止确认，两次均重新协商成功。首包 PCM 分别在设备开始报告后的 46 和 103 毫秒到达，物理按下时刻仍待测。分别解码并播放 51,968 和 45,312 个采样到 MiRemoteV 2ch，日志所报丢弃、中断和待处理采样为零。
- 同一构建内，小米 RC001 三个会话正常结束，分别完整播放 35,040、89,760 和 59,280 个采样到 MiRemoteV 2ch。完整的小米语音和异常恢复矩阵仍待验收。
- 使用独立的 AVFoundation 采集器从 MiRemoteV 2ch 读回下一条 T1 测试语句，离线转写为「虚拟麦克风读回到这里结束」。对应应用会话正常停止，54,272 个样本全部播放，丢弃、中断及待处理采样为零。
- 需要继续验收目标听写应用自动上屏、极速按键和连续会话、断连和超时恢复以及 Windows。
