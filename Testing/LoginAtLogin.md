# 登录时自动启动测试手册

适用版本或分支：`codex/login-at-login`（后续合入版本以发布说明为准）。

## 测试前准备

1. 使用 macOS 13 或更高版本的独立测试用户，安装无线麦 SayAll.app 到“应用程序”目录。
2. 在“系统设置 → 通用 → 登录项与扩展”中确认无线麦当前未列为“登录时打开”。
3. 关闭无线麦后重新打开，完成既有 Onboarding；如需验证不自动显示窗口，先在“关于”关闭“启动时自动打开主面板”。
4. 记录开始时间，并准备收集无线麦运行日志和系统登录项截图。

## 用例 1：默认关闭与用户主动开启

1. 打开无线麦的“关于”页面，找到“登录时自动启动”。
2. 确认开关默认关闭，页面说明写明默认关闭。
3. 仅由测试者手动开启该开关。
4. 打开“系统设置 → 通用 → 登录项与扩展”，确认无线麦出现于“登录时打开”。

预期结果：全新或未注册状态下开关为关闭；只有用户开启后才请求系统注册，无线麦出现在正确的系统登录项列表。

失败判定：首次打开已自动启用、没有用户操作就注册、开关显示与系统列表不一致，或误注册了其他 App/辅助进程。

## 用例 2：系统要求批准

1. 在系统中拒绝、关闭或移除无线麦的登录项后，回到 App 并再次开启开关。
2. 如果 App 显示“macOS 需要你的允许”，点击“打开登录项设置”。
3. 在系统设置中允许无线麦，然后切回 App。

预期结果：App 在返回前台时刷新为已开启；系统未批准时保留清晰说明和直达入口，不显示误导性的“已启用”。

失败判定：没有恢复入口、打开错误的系统设置页、批准后仍不刷新，或在未批准时宣称已可登录启动。

## 用例 3：关闭与注销后登录

1. 在 App 中关闭“登录时自动启动”，确认系统登录项列表移除无线麦。
2. 注销当前 macOS 用户并重新登录，确认无线麦没有自动运行。
3. 再次手动开启该开关，完全退出无线麦，注销并重新登录。
4. 确认无线麦自动运行；分别验证“启动时自动打开主面板”开启和关闭时，主窗口与菜单栏入口符合已有设置。

预期结果：关闭后不会在下一次登录启动；开启后在下一次登录启动。登录项只负责启动 App，不改变 Onboarding、蓝牙授权、遥控器、音频、手机连接或现有窗口偏好。

失败判定：关闭后仍自动启动、开启后未自动启动、每次登录重复拉起多个进程，或已有遥控器/语音/窗口行为回归。

## 用例 4：更新与稳定回归

1. 保持登录项开启，通过现有 Sparkle 候选更新流程升级无线麦；更新后再次注销并登录。
2. 重复用例 1 至 3，并在 800 × 650 窗口逐一进入受影响的“关于”页面，确认页面可滚动、开关和必要说明未裁切。
3. 验证菜单栏可打开设置、Dock 图标显示开关、普通启动窗口开关、检查更新及退出仍正常。

预期结果：更新后登录项状态和实际登录启动保持一致；设置页布局、现有应用偏好和稳定功能不回归。

失败判定：更新后状态丢失或指向旧 App、设置窗口裁切、菜单栏入口失效，或登录项改变了其他设置。

## 用例 5：单实例与多版本互斥

1. 准备两个都包含单实例守卫、Bundle ID 均为 `com.hd838a.RemoteMic` 的不同版本，分别放在两个明确路径。
2. 先启动较旧版本，再通过 Finder、`open -n` 和直接运行较新版本可执行文件逐一尝试启动较新版本。
3. 退出全部实例，交换版本顺序，重复上一步。
4. 保持一个版本运行并启用登录项，再手动打开另一个版本；随后注销并重新登录。
5. 对一个运行中的版本执行 Sparkle 候选更新，确认更新前后的宿主交接只保留一个实例。
6. 每一步都用“活动监视器”或 `pgrep -fl '/RemoteMic$'` 核对进程，并验证菜单栏、设置窗口、遥控器按键和第一次 `STREAM_START → AUDIO → STREAM_STOP`。

预期结果：同一时间只有一个无线麦进程；再次打开时已有实例被激活，不会再次初始化 BLE、虚拟音频或 HID，也不会出现成对的启动/停止生命周期。

失败判定：同一时间存在两个同 Bundle ID 进程、两个菜单栏图标、重复音频设备占用、遥控器连接互相踢下线、HID 映射被另一实例恢复，或登录/更新后同时拉起两个实例。

兼容边界：历史旧版不包含守卫。必须分别记录“旧版先运行、新版后启动”和“新版先运行、历史旧版后启动”；后一顺序仍需依靠移除历史副本避免旧代码绕过守卫，不能把它误记为双向兼容已经通过。

## 日志与验证边界

- 日志：导出 `~/Library/Logs/RemoteMic/runtime.log`，记录测试时间、App 版本、系统版本、系统登录项界面与注销/登录结果；日志不应包含账户密码或其他敏感信息。
- 自动化：`LoginItemServiceTests` 覆盖默认关闭、注册、取消注册、待系统批准与注册失败；设置页回归测试覆盖原生 `SMAppService.mainApp`、恢复入口和不使用 `UserDefaults` 伪造状态。
- 单实例自动化：`ApplicationInstanceGuardTests` 覆盖锁竞争和释放；自动化不能证明 Finder、`open -n`、登录项或 Sparkle 的真实进程交接。
- 代理实测边界：构建、单元测试和静态设置页检查不能证明 macOS 在真实注销/登录后会启动 App。
- 用户实测边界：必须由真实 macOS 13+ 用户账户完成“开启 → 注销 → 登录”、系统拒绝/批准、关闭后不启动，以及 Sparkle 更新后的再次登录验收后，才能宣称完成真实环境验收。
