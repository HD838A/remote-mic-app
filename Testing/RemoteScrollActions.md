# 遥控器滚动动作测试手册

## 适用范围

- 分支：`feature/scroll-actions`（基线 `origin/main` `e62e70e`，版本 1.9.8）
- 平台：macOS；RC001 或 RC003 通过蓝牙连接，`mode=seized` 与 `mode=monitored` 两种连接模式都需覆盖
- 目标：确认新增的「向上滚动 / 向下滚动」两个按键动作能滚动前台窗口的内容区，按住可连续滚动，并且不改变既有方向键、音量键和语音功能。

## 测试前准备

1. 安装并启动包含本改动的 Mac App（`dist/SayAll.app`）。
2. 授予输入监控和辅助功能权限，并启用「自定义按键映射」。定位前台窗口依赖辅助功能权限，权限缺失时滚动动作不会执行。
3. 连接遥控器，记录运行日志中的 `HID CONNECTED mode=...`。
4. 在「按键映射」页把方向上映射为「向上滚动」，方向下映射为「向下滚动」，其余按键保持默认。
5. 准备一个内容长于一屏的会话：Claude Desktop 或 ChatGPT 桌面版（Electron）各准备一个。
6. 记录测试开始时间，完整保留 `~/Library/Logs/RemoteMic/runtime.log`。

## 用例一：Electron 聊天应用的对话区滚动（Claude Desktop）

1. 把 Claude Desktop 切到前台，滚动到对话最底部，点击输入框使其获得键盘焦点。
2. 把鼠标指针移到 Claude Desktop 窗口之外（例如桌面或另一个窗口上），之后不再触碰鼠标。
3. 单击遥控器方向上键。
4. 单击遥控器方向下键。
5. 按住方向上键约 2 秒后松开。

预期结果：第 3 步对话区向上滚动几行，显示更早的消息，输入框中的光标位置和已输入文本不发生变化；第 4 步向下滚动回到更新的消息；第 5 步在按住期间持续匀速向上滚动，松开后立即停止。全过程滚动发生在 Claude Desktop 窗口内，鼠标指针所在的其他窗口不滚动。

失败判定：对话区不动、只有输入框光标移动、滚动落在鼠标指针下方的其他窗口、松开后仍继续滚动，或方向反了（按上键看到的是更新的消息）。

## 用例二：另一个第三方 Electron 应用（ChatGPT 桌面版）

按用例一的第 1 至 5 步在 ChatGPT 桌面版重复一次。

预期结果：与用例一一致。

失败判定：与用例一一致；若两个应用表现不同，记录各自的应用版本。

## 用例三：原生应用与浏览器

分别在 Safari 长网页、Finder 列表视图和「无线麦」自身设置页重复单击与按住操作。

预期结果：Safari 与 Finder 的内容区正常滚动；无线麦自身在前台时滚动动作仍然执行（滚动动作不受方向键在自身前台时的连发限制约束），且不会产生系统错误提示音。

失败判定：任一场景出现无响应、错误音、窗口跳动或滚动落到错误窗口。

## 用例四：窗口与显示器布局

依次在以下布局重复用例一的第 3 至 5 步：

1. 目标应用窗口最大化；
2. 目标应用窗口缩到屏幕左上角约四分之一大小；
3. 目标应用进入全屏；
4. 目标应用与另一应用分屏（Split View）；
5. 双显示器，目标应用位于非主显示器。

预期结果：每种布局下滚动都发生在当前前台窗口内。

失败判定：某种布局下滚动落到另一显示器、落到后台窗口或完全无效果，需记录具体布局、窗口位置和显示器排列。

## 用例五：连接模式与断连

1. 在 `mode=seized` 下完成用例一。
2. 在 `mode=monitored` 下完成用例一，并额外确认按住滚动期间 MacBook 实体方向键仍然可用。
3. 按住滚动键期间断开遥控器蓝牙，日志出现 `HID DISCONNECTED` 后确认滚动立即停止。
4. 重新连接后再执行一次单击和按住。

预期结果：两种模式行为一致；断连立即停止滚动；重连后映射继续可用。

失败判定：断连后滚动继续、重连后需要重启 App、或 `mode=monitored` 下实体方向键被拦截。

## 用例六：权限缺失与恢复

1. 撤销辅助功能权限后返回 App，单击滚动键。
2. 重新授予权限并回到目标应用，再次单击滚动键。

预期结果：权限缺失时不滚动，并按既有权限提示路径引导；恢复权限后立即可用。

失败判定：权限缺失时崩溃、静默失败且恢复后仍不可用，或反复弹窗。

## 用例七：系统「自然滚动」设置

在「系统设置 → 触控板/鼠标」分别打开和关闭「自然滚动」，各重复用例一的第 3 至 4 步。

预期结果：无论该设置如何，按上键都显示更早的消息。

失败判定：关闭或打开自然滚动后方向相反。此项为已知风险点，出现即记录设置状态和机型。

## 稳定功能回归

- 方向上、下、左、右四个方向键映射为原方向动作时行为不变，包括 350ms 后 100ms 连发。
- 音量加减、确定、Home、菜单、TV、返回和关机键的既有动作与连发不变。
- 自定义快捷键、打开应用、双击和长按手势仍各自执行一次。
- 语音功能（RC003 `STREAM_START → AUDIO → STREAM_STOP`）不受影响。
- 「按键映射」页的动作分组仍为四组，新增两项出现在「基础按键」组内，中英文名称完整不裁切。

## 日志收集

出现失败时记录：App 版本、遥控器型号、连接模式、目标应用及其版本、窗口布局、显示器数量、鼠标指针位置、自然滚动设置，并附完整运行日志。重点核对 `HID CONNECTED mode=...`、`HID BUTTON`、`HID GESTURE`、`HID DISCONNECTED` 顺序。

## 验证边界

- 已完成（自动化）：`scripts/test.sh` 自检 43 项全部通过，其中新增一项覆盖滚动动作的分组、连发白名单和持久化标识符；`xcrun swift build` 通过；`scripts/build-app.sh` 产出 ad-hoc 签名的 `dist/SayAll.app` 并通过 `codesign --verify --deep --strict`。
- 未完成（自动化）：`Tests/RemoteMicTests` 的 Swift Testing 套件在本机无法运行——当前机器只安装 Command Line Tools，缺少 `Testing` 模块。新增的滚动单测（方向与行数、窗口中心定位与回退、分组与连发、序列化）只完成了编译期类型校验，必须在装有 Xcode 的机器或 CI 上执行一次。
- 未完成（真机）：用例一至七全部未在真实遥控器上验收。滚动事件的实际投递、窗口定位、`natural scrolling` 语义和 Electron 应用的滚动响应都无法由单元测试证明。
- 自动化只能证明动作枚举、事件方向与定位函数的输入输出；不能证明真实 CGEvent 滚轮事件被目标窗口接收。
