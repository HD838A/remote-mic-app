# Mac 麦克风语音输入测试

适用：`codex/mac-microphone-session-20261024` 候选。行为以 [产品规范](../feature/mac-microphone-input/PRODUCT_SPEC.md) 为准。

## 准备

1. 使用本次源码构建的 Developer ID 签名、公证测试包。记录 Commit、版本、macOS、输入工具和设备类别，不在公开证据中记录身份或内容。
2. 在输入工具中选择与 SayAll 连接页相同的虚拟麦克风。准备内置麦克风、可插拔物理麦克风及实体遥控器。
3. 准备一个公开辅助功能可访问的普通文本框。测试文字使用不含个人信息的短句。记录原系统输入、输出和输入法设置。
4. 分别测试豆包、微信输入法、Typeless，以及用户实际使用的其他工具。分别覆盖按住模式和 Fn 点按模式。

## 三入口与界面

| 操作 | 预期与失败判定 |
| --- | --- |
| 悬停开始按钮 | 显示“仅在不使用遥控器时使用”。缺失或文字不符为失败。 |
| 连接页开始，快捷键停止 | 先回原文本框，再收音；菜单与按钮状态同步；只产生一段文字。 |
| 菜单开始，连接页停止 | 回到控制页后仍可停止；停止时回原输入位置；不得向设置页输入。 |
| 快捷键开始，菜单停止 | 只控制同一个会话，无额外窗口抢占；菜单文字反映当前状态。 |
| 连续按住快捷键 | 只触发一次；松开再按才触发下一次。不得循环开关。 |
| 设置冲突、纯修饰键或 Fn | 显示不可用；页面按钮和菜单仍可使用。清除后不保留旧注册。 |
| 录入快捷键后取消、离页或关窗 | 退出录入并恢复原快捷键；录入期间不得触发语音。 |
| 关闭并重启 | 输入选择和快捷键保存；麦克风保持关闭。 |
| 中英、明暗、1020×772下点击受影响导航项 | 导航、卡片、按钮与滚动可用；无裁切，无低于12pt中文。800×650仅为离屏压力测试。 |
| 检查输入行的开始、收音、准备和停止状态 | 输入设备、设备名称、收音状态和启停按钮保持同一行；快捷键另起一行并与设备列对齐。状态和按钮不得截断。 |
| 设备名称过长、权限失败或快捷键冲突 | 设备名称可尾部截断，悬停可读全名；错误说明在输入行下方完整显示，不挤走启停按钮。 |

## 独立状态与恢复

| 状态与操作 | 预期与失败判定 |
| --- | --- |
| 首次请求权限，允许 | 只由明确启动请求触发授权；允许后只开始当前会话。 |
| 拒绝或撤销麦克风权限 | 就地说明并可打开系统设置；不触发输入工具，不静默回退。 |
| 辅助功能权限缺失 | 明确提示并可打开相应设置；不报告已收音。 |
| 准备时取消，再允许权限 | 保持停止；迟到回调不得重新开始。 |
| 无内置麦克风、物理设备失效 | 要求显式选择；拔出正在使用的设备后停止，不切到其他麦克风。 |
| 虚拟输出缺失或选中普通扬声器 | 拒绝启动；不通过扬声器播放用户语音。 |
| 外接耳机、合盖与外接屏 | 所选来源清晰；不可用则停止，不改变系统默认设备。 |
| 前台文本框、从连接页恢复、从 Dock 打开设置 | 回到同一输入位置；没有有效输入位置时提示，不向旧位置误输入。 |
| 密码框、无焦点、目标 App 退出 | 不开始；运行中目标失效时停止并记录原因。 |
| 收音时切换其他 App 或输入框 | 停止，不继续向新目标送音；之后显式重试可恢复。 |
| 休眠、唤醒、退出或异常采集失败 | 释放麦克风与语音键，异常终态为 forced；恢复后不自动重开。 |
| 准备期间快速点两次、停止期间连点 | 不重入；下一次显式启动只在停止完成后发生。 |

## 音频完整性和稳定回归

1. 首字：分别测量点击/快捷键到首个有效 PCM 与可观察首字的耗时。说完整短句，首字不能遗漏。日志中的引擎启动耗时不能替代用户入口到首字的实测。
2. 尾字：在最后一个字刚说完时停止，确认尾字完整；记录 capture 最后一批、输出排空完成、最后语音键边沿的顺序。正常完成不得 flush。
3. 连续会话：快速完成至少20次开始、短句、停止。每次只出现一组开始/结束，无尾音串到下一次，无第二次才成功。
4. 遥控器互斥：遥控器正在说话时点击开始应被拒绝；Mac正在准备、收音和停止时按遥控器，音频不得混入。分别检查系统硬件 Fn 映射，软件拒绝日志不能代替这一验证。
5. 默认稳定路径：不启用此功能，覆盖 RC003 的 `STREAM_START → AUDIO → STREAM_STOP`、RC001、Apple Remote、Chromecast、手机和网页的现有路径。只验收当前实际可用的硬件，不将缺少包或硬件标记通过。
6. 检查系统默认输入、输出与第三方麦克风选择。开始和停止本功能不得改变这些设置；既有其他功能的设备生命周期行为应单独记录。
7. 使用内置扬声器及耳机各测一次，确认不回授、不重复识别。音量有声不等于完成，必须核对最终文字。

## 日志与验证记录

通过 App 的日志入口收集本次测试日志。保留 `MAC MICROPHONE`、`MAC MICROPHONE CAPTURE`、`MAC MICROPHONE SHORTCUT`、相关 `MOBILE VOICE`、`VOICE FN TAP` 和 `AUDIO` 事件。按 operation_id 与 voice_operation_id 对齐请求、权限、开始、首 PCM、采集停止、输出排空、结束键和最终终态。不要在公开记录中附用户语音、文字、身份、路径或凭据。

音频引擎在启动阶段可能产生配置通知。若当前输入设备仍是所选设备，日志应记录 `MAC MICROPHONE CAPTURE phase=configuration_changed result=ignored`，会话应继续等待首个 PCM。只有日志确认当前设备变更时，才允许记录 `result=failed` 并结束会话。

## 单行布局修正

此前把输入设备与启停控件分成两个横排，偏离确认设计。现已合并为一行，快捷键另起一行并对齐设备列。错误说明保留在输入行下方。

本次只改布局，不改变语音会话或音频代码。验证使用重新构建的生产页面，证据见 [单行截图清单](../Screenshots/mac-microphone-input/single-row/manifest.json)。此前的截图保留为历史证据；真实音频验收状态不变。
