# Mac 麦克风语音输入测试

适用：Mac 麦克风语音输入候选。行为以 [产品规范](../feature/mac-microphone-input/PRODUCT_SPEC.md) 为准。

## 准备

1. 使用本次源码构建的 Developer ID 签名、公证测试包。记录 Commit、版本、macOS、输入工具和设备类别，不在公开证据中记录身份或内容。
2. 在输入工具中选择与 SayAll 连接页相同的虚拟麦克风。准备内置麦克风、可设为系统默认输入的 AirPods 或外接耳机麦克风、可插拔物理麦克风及实体遥控器。
3. 准备一个公开辅助功能可访问的普通文本框。测试文字使用不含个人信息的短句。记录原系统输入、输出和输入法设置。
4. 分别测试豆包、微信输入法、Typeless，以及用户实际使用的其他工具。分别覆盖按住模式和 Fn 点按模式。

## 三入口与界面

| 操作 | 预期与失败判定 |
| --- | --- |
| 悬停开始按钮 | 显示“仅在不使用遥控器时使用”。缺失或文字不符为失败。 |
| 选择备用麦克风后点击“用<设备名>说话” | 按钮和菜单显示所选设备名称，例如“用MacBook Pro 麦克风说话”；只进入待命，等待至少30秒不能出现采集 started 或 first_pcm，不创建录音。 |
| 菜单栏入口 | 与连接页按钮使用同一设备名和启停语义；菜单选择只控制同一个音源，不直接开始收音。 |
| 已待命，键盘 Fn 按住说话后松开 | 按下才开始物理采集；原 Fn 传给输入工具；松开后采集尾部与输出自然排空，返回待命。 |
| 已待命，按点按模式的语音键 | 第一次按下开始，松开后继续；第二次按下结束并排空。键盘按住不重复切换。 |
| 未选择或已关闭时按 Fn | 不开始 Mac 采集；原按键仍传给其他应用。 |
| 普通按键、方向键附带 Fn 标志、SayAll 合成语音键 | 不触发 Mac 采集。Fn 只接受 keyCode=63 的真实修饰键边沿。 |
| 语音键/按住点按配置变化 | 退出当前音源选择；再次启用后使用页面显示的新配置，不继续使用旧监听。 |
| 连续按住快捷键 | 只触发一次；松开再按才触发下一次。不得循环开关。 |
| 关闭并重启 | 输入选择保存；麦克风保持关闭；页面不显示切换快捷键设置行。 |
| 中英、明暗、1020×772下点击受影响导航项 | 导航、卡片、按钮与滚动可用；无裁切，无低于12pt中文。800×650仅为离屏压力测试。 |
| 检查输入行的开始、收音、准备和停止状态 | 输入设备、设备名称、收音状态和启停按钮保持同一行；语音快捷键另起一行并与设备列对齐。状态和按钮不得截断。 |
| 设备名称过长、权限失败 | 设备名称可尾部截断，悬停可读全名；错误说明在输入行下方完整显示，不挤走启停按钮。 |
| 只有一个可用物理输入 | 备用麦克风仍显示下拉框，当前设备可见；选择器只有该设备，不退回纯文字。 |
| 下拉框内容 | 只列出当前可用、可采集的物理输入；不得显示未连接设备，不得显示“选择麦克风”占位项。没有可用输入时显示“无”并禁用，同时隐藏“用<设备名>说话”按钮。 |
| 启用后再操作下拉框 | 点击“用<设备名>说话”进入待命后，下拉框必须禁用，停用前不能切换设备。 |
| 切换快捷键设置 | 页面不显示“切换快捷键”行；本版本不提供设置入口。旧配置不得阻塞语音键。 |
| Fn 监听启动 | 日志记录 `tap=hid_head` 或 `tap=session_head`；两者都失败才提示无法监听。不得吞键或额外发送 Fn。 |

## Fn 与第三方语音工具共存

| 状态与操作 | 预期与失败判定 |
| --- | --- |
| 豆包已配置 Fn 语音快捷键，SayAll 已待命 | 按住 Fn：SayAll 日志出现 `phase=voice_key edge=down`，随后 `MAC MICROPHONE CAPTURE phase=started`；豆包同时打开自己的语音输入；原 Fn 不被 SayAll 吞掉。 |
| 松开 Fn | SayAll 尽快进入 stopping 并排空尾音；豆包收到原 release；SayAll 不重复触发。 |
| 豆包先按 Fn、SayAll 后启用 | 启用后按 Fn 仍必须触发；不能因豆包已占用 Fn 而只显示待命。 |
| 快速连按 20 次 | 每次一组 down/up；不丢第一次、不等待长按阈值、不出现第二次才成功。 |
| 退出豆包后按 Fn | 行为不变；“退出豆包”不能作为通过条件。 |

## 默认选择与系统默认输入

系统默认输入用于尚未保存选择时的初始值；保存后不持续跟随。用户在选择器中选择设备时，SayAll 会把该设备设为 macOS 系统默认输入；系统默认输出不得改变。

| 状态与操作 | 预期与失败判定 |
| --- | --- |
| 首次启动，未保存选择，系统默认输入为物理麦克风 | 选择器显示该物理设备；点击按钮后从该设备收音。不得覆盖为内置麦克风。 |
| 首次启动，系统默认输入为 SayAll / MiRemoteV 2ch / BlackHole 2ch 或其他虚拟、聚合设备 | 选择器回退到 Mac 内置麦克风；不得选中虚拟或聚合设备。 |
| 首次启动，无可用物理输入 | 选择器显示“无”并禁用；“用<设备名>说话”按钮不显示。不得显示“选择麦克风”占位项，不静默选择其他设备。 |
| 首次启动或应用自动选择麦克风 | 系统默认输入保持不变；只有用户在选择器中选择设备才允许切换。 |
| 在选择器中切换到另一可用物理麦克风 | macOS 系统默认输入切换为所选设备；SayAll 选择与系统设置一致；系统默认输出保持不变。 |
| 系统默认输入切换失败 | 不显示用户可见技术错误；日志记录失败；选择保留；本功能仍从所选设备直接收音，系统默认输入可能保持原值。 |
| 已保存选择后，在 macOS 设置中更改默认输入 | SayAll 的选择保持不变；重启后仍保持原选择。 |
| 已配对的 AirPods 或其他蓝牙音频未连接 | 不出现在下拉框；在下拉框看到的只能是当前可采集设备。先在 macOS 控制中心或系统设置连接后再测试。 |
| 已连接的 AirPods 或其他外接耳机被选中 | 设备出现在下拉框；选择后切换系统默认输入，点击“用<设备名>说话”进入待命，Fn 收音应产生 PCM 和文字。 |
| AirPods/外接耳机已启动采集但持续没有 PCM | 按住 Fn 且采集引擎已运行超过 2 秒仍无 PCM 时，页面显示“所选麦克风没有音频。请检查连接，或改用其他麦克风。”；日志记录 `no_audio`；不得以正常成功结束或静默回退。 |
| AirPods 准备时间较长 | 按住 Fn 后可能显示“正在准备”数秒（蓝牙 HFP 激活）；持续按住到“正在收音”再说话。首个 PCM 前松开必须回到待命，不记为无音频失败，也不禁用功能。 |
| 蓝牙输入采集路径 | 选择 AirPods 后按 Fn，日志应出现 `avcapture_started`，不得出现 `error_code=-10868`；出现首个样本时记录 `first_pcm`；松开后 `completed` 的 `samples` 必须大于 0。内置麦克风继续走原 `AVAudioEngine` 路径，不应出现 `avcapture_started`。 |
| 准备期间松开 Fn，随后再次按下 | 第一次取消本次采集并回到待命；第二次 Fn 必须能再次进入准备，并在按住足够久后正常收音和上屏。不得出现“再次按下仍停在待命”。 |
| 已选择 AirPods 或其他外接耳机，设备断开 | 停止并提示所选麦克风不可用；已保存选择回退到当前可用默认物理输入，下拉框不保留不可用项。 |
| 已选择设备，重启后该设备未连接 | 选择器只显示当前可用设备，不显示原设备的“未连接”项；原有不可用选择不得阻塞启停。 |
| 已启用（待命、准备、收音或停止）时操作选择器 | 选择器禁用；停用前不能切换设备或系统默认输入。 |

## 独立状态与恢复

| 状态与操作 | 预期与失败判定 |
| --- | --- |
| 首次请求权限，允许 | 只由明确选择音源触发授权；允许后进入待命，不自动采集。 |
| 拒绝或撤销麦克风权限 | 就地说明并可打开系统设置；不触发输入工具，不静默回退。 |
| 输入监控权限缺失或监听创建失败 | 说明无法监听语音键，可打开输入监控设置；不得显示已待命或已收音。 |
| 辅助功能权限缺失 | 只读监听及麦克风权限满足时可用；不要求输入框焦点，不为发键申请权限。 |
| 准备时取消，再允许权限 | 保持停止；迟到回调不得重新开始。 |
| 无内置麦克风、物理设备失效 | 回退到当前可用默认物理输入；没有可用输入时选择器显示“无”、按钮隐藏。正在收音时拔出设备必须停止并提示，不得静默把音频混到其他麦克风。 |
| 虚拟输出缺失或选中普通扬声器 | 拒绝启动；不通过扬声器播放用户语音。 |
| 外接耳机、合盖与外接屏 | 所选来源清晰；不可用则停止并提示，系统默认输出保持不变。输入切换只允许发生在用户明确选择设备时。 |
| 前台文本框、连接页、从 Dock 打开设置 | 开启和停止均不激活其他应用、不恢复焦点、不隐藏窗口；由用户选择文字输入位置。 |
| 密码框、无焦点、目标 App 退出 | 不以输入目标作为启停条件；不发送按键。第三方工具的输入限制由其自身处理。 |
| 收音时切换其他 App 或输入框 | 保持送音；切回 SayAll 可停止；不抢焦点、不自动关闭。 |
| 休眠、唤醒、退出或异常采集失败 | 释放麦克风，异常终态为 forced；恢复后不自动重开。 |
| 准备期间快速点两次、停止期间连点 | 不重入；下一次显式启动只在停止完成后发生。 |

## 音频完整性和稳定回归

1. 首字：先选择备用麦克风并等待界面显示待命，再用物理语音键启动输入工具。记录语音键按下到首个非零 PCM（trigger_down_to_first_pcm_ms）与可观察首字的耗时。说完整短句，首字不能遗漏。日志中的引擎启动耗时不能替代用户入口到首字的实测。
2. 尾字：在最后一个字刚说完时停止，确认尾字完整；记录 capture 最后一批、输出排空完成、送音停止的顺序。正常完成不得 flush。
3. 连续会话：快速完成至少20次开始、短句、停止。每次只出现一组开始/结束，无尾音串到下一次，无第二次才成功。
4. 遥控器互斥：遥控器正在说话时点击开始应被拒绝；Mac正在准备、收音和停止时按遥控器，音频不得混入。分别检查系统硬件 Fn 映射，软件拒绝日志不能代替这一验证。
5. 默认稳定路径：不启用此功能，覆盖 RC003 的 `STREAM_START → AUDIO → STREAM_STOP`、RC001、Apple Remote、Chromecast、手机和网页的现有路径。只验收当前实际可用的硬件，不将缺少包或硬件标记通过。
6. 检查系统默认输入、输出与第三方麦克风选择。仅当用户在选择器中选择设备时，允许改变系统默认输入；应用启动、自动默认选择和开始/停止本功能不得改变系统默认输入或输出。
7. 使用内置扬声器及耳机各测一次，确认不回授、不重复识别。音量有声不等于完成，必须核对最终文字。

## 日志与验证记录

通过 App 的日志入口收集本次测试日志。保留 `MAC MICROPHONE`、`MAC MICROPHONE CAPTURE`、`MAC MICROPHONE KEY_MONITOR`、`MAC MICROPHONE SHORTCUT`、相关 `MOBILE VOICE` 和 `AUDIO` 事件。备用麦克风路径不应额外产生 `VOICE FN TAP` 或合成语音按键。应先看到 `MAC MICROPHONE KEY_MONITOR phase=started ... tap=hid_head`（或回退为 `tap=session_head`），随后 `phase=armed capture_running=false`、真实按键的 `phase=voice_key`、`MAC MICROPHONE CAPTURE phase=started`、首次有效 PCM 和正常排空终态。只有 `phase=armed` 而没有 `phase=voice_key` 时，不能判定 Fn 监听通过。按 operation_id 与 voice_operation_id 对齐请求、权限、开始、首 PCM、采集停止、输出排空和最终终态。不要在公开记录中附用户语音、文字、身份、路径或凭据。

音频引擎在启动阶段可能产生配置通知。若当前输入设备仍是所选设备，日志应记录 `MAC MICROPHONE CAPTURE phase=configuration_changed result=ignored`，会话应继续等待首个 PCM。只有日志确认当前设备变更时，才允许记录 `result=failed` 并结束会话。
