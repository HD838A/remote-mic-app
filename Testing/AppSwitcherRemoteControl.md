# 遥控器操作 macOS Command-Tab 切换器测试手册

## 适用版本或分支

- 适用分支：包含 Command-Tab 临时会话实现的功能分支及后续预览版。
- 本手册覆盖完整临时模式：启动系统切换器、保持 Command、TV/绑定键继续发送 Tab、左右选择、OK 确认、返回取消，以及异常退出时可靠释放 Command。
- 多显示器、全屏空间、系统动画关闭和真实 RC003 仍必须按本文逐项人工验收。

## 测试前准备

1. 使用 macOS 桌面会话，打开至少三个不同 App，并确认辅助功能和输入监控权限均已授予无线麦SayAll.app。
2. 进入“按键映射”，启用自定义映射，将任意按键（例如 OK）单击绑定为 `Command-Tab`。
3. 将 TV 键暂时绑定为普通动作（例如 Escape），用于验证切换器活动期间 TV 被临时接管；测试完成后恢复原映射。
4. 准备一只已连接并能稳定发送 HID 报告的 RC003 遥控器；记录 App 版本、Build、遥控器型号和当前前台 App。

## 用例 1：首次触发保持 Command

1. 让任意非无线麦 App 处于前台。
2. 按一次绑定为 `Command-Tab` 的按键并松开。

预期结果：系统原生 App 切换器出现，当前选项保持高亮，Command 仍保持在切换会话中；不会立即完成切换，也不会向输入框写入字符。

失败判定：只出现一次普通快捷键后切换器立即消失、没有显示系统切换器、Command 没有保持、出现输入字符或系统进入异常修饰键状态。

## 用例 2：TV 发送下一次 Tab

1. 在用例 1 的切换器仍显示时按一次 TV 键并松开。
2. 连续重复 TV 键 3 次，每次都完整按下和松开。

预期结果：每次 TV 按键只让系统切换器向下移动一个 App；TV 原先绑定的 Escape 或其他动作不执行；Command 一直保持到会话结束。

失败判定：TV 执行原有动作、一次按键跳过多个 App、切换器消失、输入框出现字符或 Command 被提前释放。

## 用例 3：Command-Tab 可绑定到其他按键

1. 将 `Command-Tab` 从 OK 改绑到菜单、主页或其他普通按键。
2. 使用新绑定按键启动切换器，再按 TV。

预期结果：新绑定按键可以启动相同的系统切换器；TV 仍发送一次 Tab；不依赖固定的 OK 或 TV 启动入口。

失败判定：只有 OK 能启动、改绑后仍触发旧按键动作、TV 不能移动选项或出现重复 Tab。

## 用例 4：断连与停止释放 Command

1. 启动切换器后，在其仍显示时关闭遥控器、断开蓝牙或停止按键映射监听。
2. 重新连接遥控器并在实体键盘输入普通文字及其他 Command 快捷键。

预期结果：切换会话被取消，Command 被释放；重新连接后普通键盘输入、系统快捷键和遥控器普通映射均恢复正常。

失败判定：Command 卡住、普通文字变成快捷键、后续快捷键持续带 Command，或必须重启 App 才能恢复。

## 用例 5：左右方向键与 OK 确认

分别在独占与非独占监听模式执行本用例。非独占模式下左右键的原生按下与释放都必须被过滤，合成导航每次只提交一组按下/释放。退出切换器后，默认左右键仍可原生透传。

1. 启动切换器后，分别按右方向键和左方向键，观察高亮项每次移动一格。
2. 移动到目标 App 后按 OK。
3. 等待目标 App 成为前台，再查看日志中的 `HID APP SWITCHER selection bundle_id=`。

预期结果：左右键在临时模式中只移动系统切换器选项，不执行保存的原按键映射；OK 先按住 Option 再释放 Command，最后释放 Option，系统切换到高亮 App；日志在确认后记录最终前台 App 的 Bundle ID。

失败判定：方向键同时操作了原 App、一次跳过多个选项、OK 未切换或 Command 卡住、日志记录的最终前台 App 与屏幕结果不一致。系统未确认前只能通过系统高亮 UI 判断当前选项，因为 macOS 没有公开 API 读取该高亮项。

## 用例 6：返回键取消

1. 启动切换器并移动到另一个 App。
2. 按返回键。
3. 在原 App 中输入文字并测试普通 Command 快捷键。

预期结果：切换器关闭，不切换到新高亮 App；返回键原映射不执行；Command 已释放，键盘输入正常。

失败判定：切换到了新 App、返回键执行原动作、Command 卡住或切换器仍停留在屏幕上。

## 用例 7：无操作超时

1. 启动切换器后不再操作遥控器，等待至少 15 秒。
2. 检查切换器和实体键盘状态。

预期结果：最后一次切换器操作约 15 秒后会话自动取消并释放 Command；日志包含 `ended reason=timeout`。

失败判定：切换器长期不退出、Command 卡住、超时明显早于 15 秒，或每次导航后没有重新开始无操作计时。

## 用例 8：前台状态异常变化与权限失效

1. 启动切换器后，通过鼠标、系统自动化或其他输入方式强制激活另一个 App。
2. 另一次测试中，在切换器活动时撤销辅助功能或输入监控权限。

预期结果：检测到前台 App 异常变化或权限失效后，会话自动取消并释放 Command；权限恢复并重启监听后普通映射可继续使用。

失败判定：前台已变化但会话仍保持、权限撤销后 Command 卡住，或恢复权限后必须重启 Mac 才能正常输入。

## 用例 9：桌面环境组合

分别在只有两个可切换 App、目标 App 尚未启动、全屏空间、多显示器和“减少动态效果”开启的状态下，重复启动、左右移动、TV 前进、OK 确认和返回取消。

预期结果：行为遵循 macOS 原生切换器在该环境下的可用 App 和空间规则；无线麦不显示自制 App 列表，所有退出路径均释放 Command。

失败判定：特定显示器或空间中卡住修饰键、选项移动与系统 UI 不一致、目标未启动时出现虚构选项，或动画设置改变后无法确认/取消。

## 用例 10：目标 App 窗口全部最小化时恢复

1. 打开 Safari，按 `⌘M` 把它的窗口全部最小化；切换到另一个 App，确认屏幕上没有 Safari 窗口。
2. 用遥控器启动切换器，把高亮移到 Safari，按 OK。
3. 重复一次，但先保留一个 Safari 可见窗口，只最小化另一个窗口。

预期结果：第一次 Safari 最近一次最小化的窗口回到前台；第二次保持原有可见窗口，不额外弹出最小化窗口。两次结束后 Option 与 Command 均无残留。确认后约 0.5 秒若目标 App 仍无可见窗口，应用会用辅助功能把它最近的一个最小化窗口拉起，日志出现 `HID APP SWITCHER restore attempt=0 … result=restored`。

失败判定：OK 后只切换菜单栏、窗口仍留在程序坞；已有可见窗口时多弹出窗口；确认后 Option 或 Command 卡住，导致后续输入变成快捷键或需要重启 App；日志 `restore` 结果为 `noMinimizedWindow` 或 `notTrusted` 且窗口仍未回来。

实现约束：`Option` 按下与 `Command` 抬起必须分两个事件周期送达。同一批事件进入系统时，切换器处理 `Command` 抬起读到的是 `Option` 已松开的最终状态，窗口不会恢复；只改按键顺序、不加间隔仍会失败。确认后 1 秒内如果释放任务因调度异常没有执行，watchdog 会强制释放 `⌘`/`⌥` 并写入 `HID APP SWITCHER watchdog released_modifiers=true`；出现这条日志说明正常释放路径没有执行，应按缺陷记录并检查调度器是否持有任务。

## 用例 11：方向键按住连发

1. 启动切换器后按住右方向键超过 350ms，再按住左方向键。
2. 中途松开，观察是否立即停止。

预期结果：按住约 350ms 后每 100ms 移动一格，松开立即停止；日志出现 `HID APP SWITCHER button=left/right phase=repeat`；原方向键映射不执行。启动键本身仍只启动一次切换器，不因连发重复发送 Tab。

失败判定：按住不移动、移动间隔与设置不符、松开后仍继续移动、连发期间执行原映射，或每次连发都重新打开切换器。

## 用例 12：上下键进入窗口选择并用 OK 打开

1. 目标 App 打开两个以上窗口（可以全部最小化），启动切换器并选中它。
2. 按一次上或下方向键，观察是否进入该 App 的窗口选择（App Exposé）。
3. 用方向键改选另一个窗口，按 OK。
4. 重复一次，在窗口选择层按返回键。

预期结果：第一次按上下键进入窗口选择层，之后方向键只在窗口之间移动，不再切换 App，也不会变成 `⌘←`/`⌘→` 等系统快捷键；OK 打开当前高亮的窗口并把该 App 切到前台；返回键退出窗口选择层并释放 `⌘`。日志依次出现 `phase=window_selection`、`role=return` 或 `role=escape`。

目标 App 只有一个窗口时，窗口层里的高亮不稳定，OK 不依赖高亮：先发原生 Return（能恢复就立即恢复），200ms 后直接恢复那个唯一窗口并置前（日志 `single_window … activated=true`）；窗口数从目标 App 的辅助功能窗口列表读取。目标 App 从 Dock 的 `AXSelectedChildren` 读取（日志 `target bundle_id=`）；进入窗口层后该列表会消失，所以必须在进入前读取。

失败判定：上下键无反应、进入窗口选择后方向键仍在切换 App、OK 只切换菜单栏、返回键关掉整个切换器但没有退出窗口层，或结束后 `⌘` 仍被按下。

## 稳定功能回归

- 普通自定义快捷键仍只发送一次按下/释放组合。
- TV 在没有切换会话时仍执行其保存的原有动作。
- 切换会话外的普通方向键、确定、返回、双击、长按和应用打开映射不因本功能改变。
- monitored 模式下原生键盘事件抑制仍有效，不能出现重复字符。

## 日志收集方式

1. 记录现场时间、App 版本/Build、前台 App、按键映射和遥控器连接状态。
2. 保存运行日志并重点搜索 `HID APP SWITCHER`、`HID GESTURE`、`HID BUTTON`、`HID RELEASED`。
3. 日志中的动作提交不等于系统切换器最终显示正确；失败时必须同时记录屏幕现象和是否出现字符/卡键。

## 验证边界

- 自动化测试覆盖 Command 按下、Tab 按下/释放、重复选择、左右导航、确认时 Option 先按下与 Command 后释放的事件顺序和修饰标志、返回取消、15 秒无操作超时、前台变化、断连释放、最终前台 App 日志，以及确认后兜底恢复的调度与目标 App 判定。
- 最小化窗口是否真的回到前台由 Dock/WindowServer 决定，自动化只能证明事件顺序和标志；兜底恢复是否真的拉起窗口也必须在真实桌面会话按下文用例 10 人工确认。
- 代理可以检查日志和事件序列，不能替代 WindowServer、真实系统切换器和真实 RC003 的最终屏幕验收。
- 当前尚未声称真实 RC003、多显示器、全屏空间或系统动画关闭场景已完成。
