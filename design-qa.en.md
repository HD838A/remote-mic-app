# Design QA: Native macOS Settings Interface and Liquid Glass

[简体中文](design-qa.md)

## Review scope

- Settings window: `920 × 700` by default and `800 × 650` minimum, freely resizable
- Pages: Button Mapping, Macros when available, Statistics, Reflections, Connection, Permissions, and About
- The system unified toolbar owns the current page title; content does not repeat it

## Current implementation

- The root uses `NavigationSplitView`, a system `.sidebar` `List`, the native selection state, a 232pt ideal sidebar width, `.large` system density scoped to the sidebar/search, `.regular` density for the detail and split-view root, and `.searchable(placement: .sidebar)`. `.toolbar(removing: .sidebarToggle)` is attached directly to the sidebar column so the toolbar does not expose navigation that is absent from System Settings. Search keeps the detail visible, returns concrete settings with their parent page, and deep-links to the matching section.
- Connection, Statistics, Reflections, Permissions, and About use grouped `Form`, `Section`, `LabeledContent`, standard `Picker`, `Slider`, `Toggle`, `Button`, and `Link` controls. Large custom glass cards and status capsules no longer imitate System Settings. A healthy output is represented by the Picker and enabled actions; passive “ready to send a test tone” copy is not rendered. Unselected, unavailable, and failed output keeps one status row. Playing, completed, cancelled, and error feedback stays in the same Form row as the three audio actions without a separator, while routing guidance remains the native Section footer.
- Page titles, traffic-light controls, window dragging, and titlebar material remain native. The `.unified` toolbar owns its background, separator, and scrolled-content occlusion; do not force a transparent titlebar or suppress its separator. A large `ControlGroup(.navigation)` owns Back, Forward, and the forward-history menu; do not replace it with separate custom circles or a responder-chain sidebar action.
- Body text, supporting copy, section headings, and status use semantic `.body`, `.callout`, and `.headline` fonts. Chinese text must never render below 12pt.
- Sidebar entries use 20pt category-color tiles with 12pt monochrome SF Symbols, 5pt continuous corners, a subtle system-style shadow, and no outline. Rows use a 9pt leading inset and 7pt icon-to-label spacing. Tiles use adaptive AppKit system colors while retaining the native source-list selection background. Normal explanatory and ready-state text stays semantic primary/secondary; color is reserved for category recognition and real warning, success, or connection states.
- On macOS 26/27, navigation uses the system `ControlGroup(.navigation)`, `.buttonStyle(.glass)`, and `.controlSize(.extraLarge)` directly. It does not draw a shell with `glassEffect` or set a custom corner radius, background, or control size. Builds retain the macOS 14 deployment target while linking the selected Xcode SDK so the system owns Liquid Glass for the titlebar, toolbar, sidebar, and standard controls; macOS 14/15 render the same native structure with their corresponding system styles.
- Every page uses only three alignment modes: ordinary settings have a leading label and trailing control, business content follows the section leading edge, and complete controls such as segmented filters fill the available section width. A plain `GroupBox` must not rely on `LabeledContent` to invent a local label column.
- Supporting copy that explains one setting must stay inside the same `Form` row as that control, without a separator between them. Only copy that explains an entire section belongs in a `Section` footer.
- The mapping page uses the same native grouped `Form / Section` container as Connection and must not stack manual page padding, an outer `GroupBox`, or custom `contentMargins`; Form owns the titlebar safe-area spacing. The system `.unified` toolbar owns the full-width titlebar background and separator; pages must not add local materials or scroll-edge compatibility modifiers. The mapping canvas remains custom because it visualizes a real remote and exact button relationships; its transparent Form row removes row insets so the business visualization follows the section leading edge. The enable preference uses a leading label and trailing switch, while Remote is a block heading above a device card that fills the section width without a trailing-column or fixed-width cap. The two footer preferences keep explicit leading labels and trailing controls; HID status is a leading information row and Restore Defaults is a trailing action row.
- Mapping cards remain 64pt tall with at least 16pt of clear vertical space between adjacent cards. The voice card and every physical-button card must stay fully inside the canvas, while connectors continue to land on each card's vertical center.
- Statistics centers a native `Picker(.segmented)` without an `NSViewRepresentable` selection override and keeps the real Day / Week / All periods. macOS 26/27 uses the system `extraLarge` control size and macOS 14/15 uses the system `large` fallback; a 480pt slot only centers the picker, while the system owns its intrinsic segment width, height, shape, and selection appearance. The picker and the page's single local-only notice live in the first data Section's platter-free header and scroll away with the charts; neither may use `safeAreaBar`, `safeAreaInset`, or another fixed page header. After scrolling, the system `.unified` toolbar supplies the full-width titlebar-height background instead of a tall content-column rectangle. Charts and ranking remain native grouped Form sections; the ranking subtitle explains only its scope, and sharing is not repeated on Statistics. Reflections gives the recording preference, history/empty state, and local Agent access their own sections; recording purpose and privacy share the preference footer, the empty state only reports current state, “Local Agent Access” is the section header, and “Allow Access” is the preference label. Permissions keeps upgrade guidance in the required-permissions footer rather than rendering it as another permission row. About is the only Settings destination with the inline sharing panel; neither Statistics nor the sidebar duplicates that command. Configuration rows put the description on the leading side and keep the action name only on the trailing button. The Current Version row keeps its title and compact check result in the leading label column, while the installed version and one stateful update action stay in the trailing control column; never stack the status beneath the trailing button as a floating mini-panel. “You're Up to Date” is one conclusion and does not repeat the same meaning in a second sentence. The action checks when idle, checks again after a result or failure, changes to Update to X when an update is available, and is disabled while checking; Check for Updates and Check Again must never appear together. The intrinsic-width language segmented picker stays on the same trailing-control line as the other rows and must not use a fixed-width centering frame. The What's New row appears only for an available update and contains only that release's notes; About does not expose a misleading Version History action.
- The settings window uses a standard macOS menu bar: app menu (About, Hide ⌘H, Hide Others ⌥⌘H, Show All, Quit ⌘Q), File, Edit (with Find ⌘F focusing the search field; `.searchFocused` is a macOS 15+ capability and the item is disabled on macOS 14), View (Back ⌘[, Forward ⌘]), and a Window menu (Minimize ⌘M, Zoom, Bring All to Front, registered as `NSApp.windowsMenu`). Window position is restored by the system frame autosave and only centered when no saved frame exists; the sidebar is fixed at 232pt; Back and Forward offer symmetric history menus; the status-bar About item opens the settings About page instead of an NSAlert. Menu commands reach SwiftUI through `SettingsNavigationCoordinator`.
- Sidebar search supports a full keyboard loop: Return activates the first result, the results list supports arrow-key selection plus Return, and the located section shows one short accent outline fade. The search catalog must stay in sync with new settings rows; missing actionable settings count as defects.
- Waiting connection states (iPhone, Apple Watch, Web Remote) show a `.small` system `ProgressView` next to the status text instead of relying on colored text alone. Open TestFlight and Copy Link are auxiliary actions for the iOS App setting: they stay in that setting's Form row with its title, description, status, and Connect Phone action, align to the row's trailing edge, and do not introduce a separator before the Apple Watch row.
- Card-style selection buttons (device cards, action grid, focus strategy, custom app picker) share `SelectableCardButton`: low-opacity semantic-blue selection, hover darkening, and a system-style keyboard focus ring, with `.isSelected` exposed to accessibility; hand-drawn per-site selection fills are not reintroduced.
- The mapping page uses the same 700pt content column as the other pages while the canvas adapts to the available width; the editor panel appears and disappears with a system transition.
- Every sidebar destination remains vertically scrollable and reachable at `800 × 650`; changing pages must not change window geometry.

## Mandatory interaction, layout, and typography rules

- Chinese UI text must render at 12pt or larger. Do not shrink it below 12pt with `minimumScaleFactor`; wrap, truncate secondary copy, or adjust layout instead.
- Avoid long drop-down lists. Group larger option sets semantically and prefer in-page sections, button grids, or segmented controls.
- Keep related settings on one page. Reserve system sheets or dialogs for file selection, required permission authorization, and irreversible destructive actions.
- Do not hard-code sidebar selection colors, glass fills, or window-drag regions that duplicate system behavior. Category icon tiles may use adaptive system colors, but must not replace the native source-list selection state.

## Conclusion

The settings UI follows the native macOS settings structure. macOS 26 supplies current Liquid Glass chrome automatically; macOS 14 and 15 use their corresponding system materials without a custom blur implementation. Hardware, permission, audio-loopback, iPhone, Apple Watch, and Web Remote validation remains governed by `Testing/NativeSettingsInterface.md`.

The current structure and constraints are consolidated under Current implementation instead of being repeated as a chronological screenshot log. `Testing/NativeSettingsInterface.md` is the single source of truth for automation, build, real-window review, and remaining field-validation boundaries; each fixed issue retains its reproduction, logs, root cause, and verification evidence in its corresponding `Bugs/` document.
