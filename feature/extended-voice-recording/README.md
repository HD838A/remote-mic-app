# 延长语音录音与 iOS 点按录音

- 状态：iOS 点按录音等待人工验收；Mac 延长方案已撤回，RC001/RC003 边界提醒已交付
- 平台：macOS、iOS
- 对应任务：根目录 [`TODO.md`](../../TODO.md) 中“普通遥控器语音键突破一分钟录音限制”和手机伴侣 App 语音交互
- 人工测试手册：[`Testing/ExtendedVoiceRecording.md`](../../Testing/ExtendedVoiceRecording.md)

## 为什么开发

RC003 一直按住语音键时可能在约 60 秒结束 ATVV 会话。同时，iOS 原先只能按住录音，不适合需要连续说较长内容的用户。

## 用户功能

- 普通实体遥控器语音继续完全跟随遥控器发出的开始、音频和停止事件，不再由 Mac 定时续期、强制设置三分钟上限或超时重连。
- RC001 和 RC003 的单次语音会话接近遥控器约 60 秒边界时，53 秒将菜单栏活动图标变为黄色并开始闪烁，同时播放一次 macOS 系统提示音；57 秒将图标变为红色并继续闪烁。界面不显示精确倒计时。
- 颜色和提示音只提醒用户会话接近硬件边界。Mac 不新增本地 60 秒强制停止，也不发送 `STREAM_STOP` 或替代遥控器结束事件；会话仍由遥控器实际事件收尾。
- iOS 麦克风按钮短点按后保持录音，再次点按停止；继续支持按住开始、松手停止。
- iOS 按钮明确显示“开始录音”“正在准备”“正在录音”以及当前停止方式。

## 范围与非目标

本次不恢复已撤下的 Power 持续录音实验，不增加录音时长设置，不改变 iOS 固定单屏布局，也不宣称已经确认 RC003 固件的 60 秒机制。普通物理语音会话的 `MIC_EXTEND` 试验已因命令未实际写出而撤回，“突破一分钟限制”仍不在已交付范围内。

## 隐私与兼容边界

语音仍只在录音会话期间沿现有本地链路传输，不保存音频、不上传云端。iOS 在首次系统权限弹窗期间保留用户请求；已经授权后，App 进入非活动状态会停止录音，避免点按模式意外持续收音。底层 `MIC_EXTEND` 能力继续保留，但普通物理语音路径不调用它。

## 当前限制

自动化已验证 iOS 手势状态和 RC001/RC003 菜单栏提醒阈值。Build 248 已完成一次真实 RC003 长会话验收：53 秒黄色提示音和状态、57 秒红色状态、遥控器在约 60 秒发送 `STREAM_STOP`、本地音频正常收尾均有日志证据。Mac 公开日志不能确认豆包内部最终文字提交；真实 RC003 的一分钟边界仍需独立研究，本功能不声称可以通过定时 `MIC_EXTEND` 延长。iOS 与真实 Mac 的点按开始/再次点按停止仍等待真机验收。

### RC001/RC003 会话边界提醒

此提醒只针对 RC001 和 RC003。它不改变语音会话协议、音频顺序或停止生命周期：

| 会话时间 | 菜单栏行为 | 声音 |
| --- | --- | --- |
| 53 秒 | 活动图标变黄色并闪烁 | 播放一次 macOS 系统提示音 |
| 57 秒 | 活动图标变红色并继续闪烁 | 不重复播放提示音 |
| 会话结束 | 恢复当前连接状态的普通图标 | 不追加协议事件 |

不显示精确倒计时。其他型号不触发颜色或提示音。详细操作和真机证据见 [`Testing/StatusBarConnectionAppearance.md`](../../Testing/StatusBarConnectionAppearance.md)。
