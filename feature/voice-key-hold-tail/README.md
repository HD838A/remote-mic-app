# 语音键按住与首尾字完整性

- 状态：方案评审中，未批准开发
- 平台：macOS
- 适用模式：Fn/地球键、左/右 Command；左/右 Option 复用同一软件注入生命周期，纳入回归
- 相关证据：[PR #1029](https://github.com/HD838A/remote-mic-app/pull/1029)、[PR #936](https://github.com/HD838A/remote-mic-app/pull/936)
- 测试基础：[语音键模式测试手册](../../Testing/VoiceKeyModes.md)、[硬件语音音频合同](../../Testing/HardwareVoiceAudioContract.md)

本文件只保留公开行为、兼容边界和验证状态。详细研究、内部取舍和完整开发计划不进入公开仓库。

本次授权范围为方案文档修订。真机 spike 和产品实现分别等待批准。方案获批后，实施 PR 按[新功能开发规范](../../FEATURE_DEVELOPMENT.md)建立产品规范和测试手册。

## 验收目标（最高优先级）

本方案首先是为下面两个用户结果服务；更换 Fn 的实现只是手段，不是目的。

### 首字不能变慢

- 用户按下语音键后，必须尽快进入真实收音路径。
- 软件 Fn 必须在首个有效 PCM 之前按下，不能等首个 PCM 之后才注入。
- 实验必须由真实物理按下驱动，记录按下、按键提交、首个 PCM 和首段输出的独立时间。采集立即开始，不能通过推迟采集或 PCM 来满足顺序断言。
- 按键提交早于 PCM 还需要配合目标工具接受事件和进入采集的证据。目标状态只通过公开可见界面或受控对照测试判断，无法观察时记为 unknown。
- 不等待双击窗口、长按阈值或目标窗口准备，也不把 Fn 点按模式的启动延迟带进按住路径。
- 验收必须同时记录从硬件按下到首个有效 PCM，以及到可观察首字的耗时；只记录“按键事件已提交”不算通过。
- 同一硬件、同一目标工具、同一网络条件下，首字延迟不得比当前 Fn 硬件映射基线更慢。

### 尾字不能因释放时序丢失

- 正常松键时，App 不得 flush、清空、丢弃或截断仍在途的 PCM。
- 必须等待采集尾包、解码、主线程投递和输出队列自然排空后，再释放 Fn/Command。
- 日志必须能证明正常路径满足 `completion=normal`、`audio_interrupted_samples=0`、`audio_pending_samples=0`。
- 只能在校验失败、断连、超时或退出等异常路径强制结束；强制结束必须记录 `completion=forced`、未排空样本和原因。

### 这是本次修改的原因

RC003 的 Fn 按住通过原生 F5 经 macOS HID 映射产生，SayAll 无法延迟该物理映射的抬起。目标工具按抬起停止采集时，仍在本地输出队列中的尾音有被漏收的风险。[PR #1029](https://github.com/HD838A/remote-mic-app/pull/1029) 已让蓝牙软件语音键等待输出排空，该改动仍保留 Fn 硬件映射的兼容路径。

本方案验证主机按键释放时序这一类风险。回眸原始录音缺尾仍须独立核查，验收分别记录原始录音、实际输出与目标文字。单独延后按键释放不能作为接收前音频完整性的证据。

如果新方案不能同时守住首字和尾字，就不应合入。首字优先级高于尾字；但首字改善不能成为接受尾字丢失的理由，首字出现回退时即使尾字改善也判定失败。

### 100% 的边界

可交付证据需限定硬件、固件、macOS、目标工具和网络条件。正常完成用例要求零首字丢失、零尾字丢失，并保留 Build、会话 ID、日志摘要和录音。异常用例验证 forced 原因、样本计数和恢复结果，单独登记完整性失败。未覆盖条件继续标记为待验证。

## 为什么开发

语音键在不同模式下不应该有不同结尾。

RC003 的当前 Fn 按住路径如下。

```text
RC003 原生 F5
  → macOS HID UserKeyMapping
  → Fn / Globe
  → 目标语音工具
```

当前来源能力以主线 `f4c17229` 为基线。

| 来源与模式 | 当前按键路径 | 当前收尾与本方案边界 |
| --- | --- | --- |
| RC003，Fn 按住 | F5 → Fn 硬件映射 | 首个 spike 验证可选的软件 Fn 按住 |
| RC003，Command / Option | 已有软件注入 | 复用 #1029 的排空释放及既有 owner / generation |
| Apple Remote | 已有软件注入 | 先确认采集尾包和主线程投递完成，再排空输出 |
| iPhone、Watch、Web | 已有软件注入 | 复用各自语音停止代次与输出排空 |
| Chromecast | 已有软件按键驱动，支持按住或点按配置 | 保留对应模式与排空收尾，纳入回归 |
| Mac 麦克风 | 被动观察用户物理语音键 | 按[现有产品规范](../mac-microphone-input/PRODUCT_SPEC.md)只提供音频，原按键继续传递，无额外语音键注入 |

已有软件路径提供复用基线。来源能力、按键所有权和采集收尾需要分别声明，语义一致性通过完整首尾音验收确认。

## 产品行为

- 由 SayAll 注入的 Fn/地球键、左/右 Command、左/右 Option 共享按键所有权和释放语义。Mac 麦克风保留物理按键观察契约。
- 按下后立即开始，不等待双击或长按阈值。
- 正常松键后保留在途音频，等待自然排空，再释放语音键。
- 连续快速会话、断连、退出、权限撤回和远端超时都必须清理按键状态。
- 失败必须显式记录，不能把“音频已入队”“按键已注入”或“本地已排空”当成目标文字成功。

## 推荐方案

优先复用现有软件按键所有权、generation 和来源收尾。首个候选只验证 RC003 的软件 Fn 按住能力；其他来源按能力矩阵补齐缺口并回归。

```text
语音键模式：fn / left_command / right_command / left_option / right_option
        ↓
统一按住协调器
        ↓
来源适配：RC003、Apple Remote、Chromecast、iPhone、Watch、Web
        ↓
按下语音键
        ↓
收音与有序投递
        ↓
停止后进入 closing，保留当前 generation 的在途尾包
        ↓
来源确认采集、解码与主线程投递完成
        ↓
配置和命令缓存有序入队
        ↓
等待输出队列自然排空
        ↓
释放该 generation 持有的语音键
```

关键边界如下。

- RC003 软件 Fn 候选在会话前中和目标遥控器的 F5，核对映射读回后再启用。中和只作用于对应设备服务，恢复仅处理本进程持有的映射项。
- Command / Option 及其他已有软件路径复用现有注入、owner 与 generation。模式层统一管理按键注入和释放。
- 来源适配提供真实边沿、能力和采集收尾完成通知。closing 期间继续接收本代次尾包，新会话保持隔离。
- 输出队列为空只代表已入队数据排空。来源收尾、解码、主线程投递和上游缓存必须先完成。录音写入接收相同代次的完整 PCM，写盘结果与按键收尾分别记录。
- 正常停止不调用 flush；异常路径必须记录 `completion=forced`。
- 短尾保护窗口初始为零。只有目标工具采集滞后有证据时，才评估有界实验参数，并验证快速重按和结束耗时。目标 ASR 终稿在按键抬起后单独观察。

## 统一语义与来源边界

已有多条来源支持软件按键与排空。统一语义需要复用这些路径，并明确来源完成屏障、按键 owner 和会话 generation。

软件 Fn 的新增可行性验证先限定为 RC003 与豆包。其他硬件和工具分别保留已验证、未知或不支持状态。Mac 麦克风沿用物理按键观察，Fn Tap 沿用独立触发语义。

## Fn 点按模式的关系

Fn 点按模式用于点按切换式语音工具，例如 Typeless：

- 它中和 F5，然后由 SayAll 发一次 Fn 点按开始或结束听写。
- 目标工具不要求 Fn 在整段语音期间持续按住。
- 它和本方案的 Fn 按住模式互斥，不能把 Fn 点按当成 Fn 长按的替代实现。
- 本方案不得复用 Fn 点按的启动延迟、目标等待或两次点按逻辑。

## 权限与兼容边界

- 软件 Fn/Command 注入需要辅助功能 Accessibility 权限；现有硬件 Fn 路径不需要该权限。这是用户可见变化。
- 输入监控 Input Monitoring 仍按现有 HID 和遥控器路径要求。
- 不需要 root，不读取第三方 App 的私有文件、数据库或协议。
- F5 被中和期间，其他依赖 F5 的应用或动作可能暂时受影响；退出、切换模式或失败恢复时必须还原映射。
- 目标工具可能不接受软件 Fn。开放 PR [PR #936](https://github.com/HD838A/remote-mic-app/pull/936) 已记录系统听写忽略注入 Fn；这不等于豆包、微信输入法或 Typeless 也忽略，必须逐工具实测。
- 目标工具可能把软件 Fn 解释为 Globe/输入法切换，必须验证不会产生额外行为。
- 目标 ASR 可能在本地排空完成后仍未提交文字；需要真实录音和目标文字对照，不能只看本地日志。
- 60 秒远端停止、固件提前结束和无线链路丢失不属于主机侧释放时序能单独修复的范围。

拟定迁移规则仍待批准。

- 旧配置中的 `fn` 保留硬件映射默认路径。软件 Fn 按住作为显式启用、按来源和工具验证的候选能力。
- 启用前确认权限、目标设备中和读回和适用的工具验证结果。权限拒绝、映射失败或已知不支持时显示具体状态。
- 缺少目标接受证据时显示未知。回退由用户明确选择，先清理软件按键与本进程映射所有权，再恢复硬件路径。
- 原始录音、输出或目标文字任一项缺尾时，整体完整性验收记为失败。

## 验证状态与门槛

当前状态：

- [PR #1029](https://github.com/HD838A/remote-mic-app/pull/1029) 已合入，只覆盖蓝牙正常停止时软件语音键的尾音排空；Fn 硬件映射仍不在其范围内。
- 本方案尚未实现，不能用现有自动化或 #1029 的结果宣告 Fn 尾音问题已修复。
- [PR #936](https://github.com/HD838A/remote-mic-app/pull/936) 是系统听写的注入按键证据，不是豆包或微信输入法的验收结果。

待批准的首个真机 spike 范围为 RC003 与豆包。

1. 保存硬件 Fn 基线，冻结设备、固件、macOS、工具版本、输出设备与网络条件。
2. 在会话前中和目标遥控器 F5，使用真实物理按下驱动软件 Fn。
3. 分别记录物理边沿、按键提交、首个 PCM、首段输出及目标可见收音状态。目标状态不可观察时记为 unknown。
4. 覆盖已就绪输出、冷输出、极速按下释放和快速连续两句，并记录首字耗时。
5. 经来源完成屏障与输出自然排空后释放按键，分别核对原始录音、实际输出和目标文字的尾部。
6. 与硬件基线对照，首字回退或任一尾部缺失均记为失败。失败时保留对应计数和观测边界。

完整验收至少覆盖：

| 场景 | 通过标准 |
| --- | --- |
| 极速按下/释放 | 立即开始，不等待阈值；短句首字存在 |
| 正常短句 | 正常松键后自然排空，尾字完整，无正常路径 flush |
| 约 30 秒 | 首字和尾字完整，`interrupted_samples=0` |
| 约 60 秒 | 覆盖远端停止和固件边界，不能把 forced 结果当正常 |
| 连续快速会话 | 每次只有一组按下/抬起，第二段首字不丢，旧回调不释放新会话 |
| 停止时输出为空、上游仍有尾包 | 来源完成前继续保持本代次准入，待尾包入队并排空后才释放按键 |
| 断连、退出、权限撤回 | 按键不卡住，重连后第一次会话成功 |
| 全部语音键模式 | 行为一致，左右 Command/Option 侧别正确 |
| 多来源 | RC003、Apple Remote、Chromecast、iPhone、Watch、Web 分别回归，Mac 麦克风保留无额外注入契约 |
| 权限与迁移 | 旧配置、显式启用、权限拒绝、映射失败和用户选择回退都有可见结果 |
| 三段完整性 | 原始录音、实际输出和目标文字分别记录首尾结果 |
| 目标工具 | 豆包、微信输入法、Typeless 分别记录；不支持的组合明确标记 |

自动化只能证明状态机、顺序、清理和日志字段；真实 RC003、真实虚拟音频、系统权限和第三方文字上屏必须单独验收。未完成这些验收时，本功能只能称为候选。

## 范围与非目标

本次方案不包括：

- 双击、长按阈值、短按聚焦输入框等语音键附加动作。
- 修改 ATVV 协议、音频格式、虚拟音频设备或普通遥控器按键动作。
- 读取或依赖第三方 App 的私有数据。
- 在没有真实设备结果时宣称“首字和尾字 100% 不丢失”。
- 把 Fn 点按模式扩展成按住模式。

## 待批准
