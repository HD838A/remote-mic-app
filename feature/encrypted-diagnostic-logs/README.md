## 为什么开发

原有 `runtime.log` 是持续增长的本地明文文件，既不方便控制磁盘占用，也不适合让普通用户安全地提交现场诊断。新方案需要保留足够的最近故障上下文，同时确保日志不会在用户不知情时上传。

## 用户功能

- App 按本地自然日生成 `sayall.app-YYYY-MM-DD.rmlog`，每个文件最多 10MB，最多保留 5 天；保留期内旧 `runtime-*.rmlog` 会在升级后迁移到新前缀。
- 日志在落盘前逐条使用 AES-GCM 加密；Finder 中看到的 `.rmlog` 不能直接作为明文阅读。
- 每次 App 进程启动会记录系统版本、Mac 硬件型号、App 版本和 Build、系统与 App 语言、麦克风增益/脱敏输出类别，以及不包含用户内容的布尔或枚举设置。
- 设置页“权限与隐私”中的“发送诊断信息”由用户主动触发，只发送今天和昨天的日志。
- 发送前会替换常见的用户名、主目录、Mac 名称、邮箱、UUID、网络地址和凭据形式。
- 未点击发送按钮时，App 不会向 Sentry 上传运行日志。

## 范围与非目标

本功能只处理 App 自己的运行日志，不上传音频、语音识别文字、系统 Console、崩溃报告或其他应用文件。官方 Sentry SDK 只在用户点击发送后短暂启动，并关闭自动崩溃、会话、性能、App Hang、MetricKit、网络跟踪、自动面包屑和自动启动上报；发送完成后关闭 SDK 并删除其临时缓存，不提供后台定时发送。旧明文 `runtime.log` 在新日志器首次初始化时删除，避免升级后继续保留未加密副本。

## 隐私与安全边界

日志密钥优先存入 macOS Data Protection Keychain；当前运行环境不支持时，回退到仅限当前用户和创建 App 访问的 App 专用 Keychain 文件。日志目录权限为 `0700`，日志和 Keychain 文件权限为 `0600`。

这能防止日志以明文落盘和被普通文件查看，但不等同于 Secure Enclave，也不承诺抵御已经取得当前 macOS 用户权限的取证或恶意软件。发送时由 App 在内存中解密并脱敏，Sentry 最终收到的是可查询的脱敏文本，而不是无法读取的密文。

启动快照不记录用户名、完整姓名、Mac 自定义名称、序列号、设备 UID、蓝牙标识、IP、可信设备指纹、自定义快捷键内容、App 配置名称、输入文字、音频或使用统计明细。`hw.model` 仅用于区分 Mac 硬件型号。

Sentry DSN 是发布时注入的公开 ingest 地址，不是管理令牌；仓库和模板不保存真实 DSN。用户点击发送后，脱敏明文会短暂存在于权限受限的随机临时目录中供 SDK 传输，随后无论成功或失败都会删除；原始加密日志保留不变。

## 当前限制

自动化使用模拟发送器验证了上传内容和边界，并验证官方 SDK 配置关闭自动遥测；尚未使用真实 Sentry 项目确认服务端接收与查询。真实网络失败、服务拒绝、最小窗口和浅色/深色界面仍需按测试手册验收。
