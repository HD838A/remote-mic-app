## 为什么开发

用户首次安装后需要自行理解蓝牙、输入监控、辅助功能、遥控器连接、语音输出设备和第三方语音工具，任一环节失败时很难判断原因。设置向导把这些条件组织成一条现场验证的任务流，只有真实状态满足后才能继续。

## 用户功能

- 首次启动自动显示 Typeless 式双栏向导，顶部只显示“准备 › 设置 › 试一下”。
- Onboarding 加入前已经安装并启动过无线麦的用户升级后自动标记为已完成，不重复设置；只有真正全新安装需要完整流程。
- 依次完成语音工具选择、控制方式选择、对应系统权限、所选控制方式的真实连接与普通按键、音频回环设备选择、真实语音文字测试和三个普通按键体验。
- 先确认当前是否有实体遥控器：有则优先使用小米蓝牙遥控器；没有时下一页推荐 iPhone App；没有 iPhone 时使用手机浏览器扫码打开网页版。
- 选择豆包输入法或微信输入法时自动切换系统输入源，显示对应 Fn 设置截图，并检查系统与微信 App 是否仍占用 Fn。
- 选择 Typeless 时自动启用语音键模拟 Fn 点按；选择其他工具时关闭，且不受实体遥控器、iPhone 或网页版分支影响。
- 完成后记住所选语音工具；豆包/微信输入法在 Fn 按下时按需重新切换，Typeless 和其他工具保持原行为。
- Onboarding 全流程在默认 `1020 × 772` 窗口中完整展示当前页，不依赖页面内部滚动；语音工具设置充分使用右栏。
- 进入真实语音测试页、从其他 App 返回或点击重新测试后，输入框会重新成为文字写入目标，不要求用户再手动点击。
- 遥控器页直接展示首次激活与配对顺序，避免用户只按 Home + Menu 却没有先唤醒设备。
- 遥控器连接页接受语音 bridge Ready 或经过生产 HID 链路验证的普通实体按键作为“已识别”证据；仅系统蓝牙文字状态和普通键盘均不能通过，完整语音能力仍在后续页面验证，完成页继续要求当前语音连接可用。
- 音频页只展示并接受 MiRemoteV 2ch 与 BlackHole 2ch；扬声器、Beosound 和其他普通设备不能完成 Onboarding，主设置页的普通设备选择不受影响。
- 不提供跳过或稍后继续；关闭 App 后保存当前页，下次启动恢复。
- 完成前不能进入主面板；进入设置阶段后才启动所选连接服务和音频运行时，不会为了 iPhone 或网页版提前启动实体遥控器蓝牙发现。
- “关于”页可重新运行设置向导，并明确说明该操作只重新检查环境，不会清除现有连接、按键映射或其他设置。
- Onboarding 卡住时仍可通过“文件 → 打开日志所在文件夹”取得 `runtime.log`。
- 完成页会再次确认当前权限、所选控制方式连接和所选音频输出仍可用，避免前面通过后环境变化却仍进入主面板。
- 尚未绑定的实体遥控器会先进入安全的非独占 HID 探测，首个真实按键选择实际操作的设备，不会因等待首报告而永久卡在遥控器页。
- 权限页的蓝牙、输入监控和辅助功能卡在显示已授权后仍可点击，方便用户随时打开对应系统设置检查或重新配置；点击卡片不会替代实时权限门禁。
- 已完成用户在升级首次启动时若权限没有延续，会直接进入“权限与隐私”补授权，不清除现有配置，也不重跑完整 Onboarding。

## 范围与非目标

本功能复用现有权限、蓝牙、HID、Nearby、网页 WSS、音频设备和语音输出状态，不修改协议、PCM 格式、设备配对方式或按键默认含义。控制方式只决定 Onboarding 使用哪条现有生产链路；不在向导中新增高级映射编辑。

## 隐私与兼容边界

- 新增的样本计数和来源状态只记录当前语音会话来自实体遥控器、Nearby 或网页版以及收到多少 PCM 样本，不保存样本内容。
- 向导输入框中的测试文字只存在于当前视图状态，不写入设置或业务日志。
- 流程版本和当前位置保存在本机 `UserDefaults`。
- 旧安装迁移只读取既有 Build 记录和 Sparkle 的“曾启动”标记，并保存一次迁移版本；不上传安装历史。
- 隐藏截图入口使用随机独立 `UserDefaults` suite，不读取或修改用户正式向导进度。
- 隐藏截图入口不会切换用户当前输入法；生产流程只在用户选择豆包/微信输入法及进入真实语音测试时调用系统输入源 API。
- 支持 macOS 14 及以上；中文最终显示字号不低于 12pt。
- App 文件名和显示名改为 SayAll/无线麦时继续保留 `com.hd838a.RemoteMic` Bundle ID、`RemoteMic` 可执行文件和正式 Developer ID 代码身份，以延续既有 TCC 权限；ad-hoc 或第三方重签名包不保证继承。

## 本次方法总结

- 设计目标不是介绍功能，而是把“权限、硬件、音频和第三方语音工具是否真的可用”变成一条不可跳过、可恢复、可诊断的任务流。
- 页面节奏参考 Typeless 的连续截图和双栏信息层级，但不复制其视觉；顶部只保留“准备 › 设置 › 试一下”，不显示步骤数量、百分比或强制措辞。
- 开发时把流程状态、运行时启动门禁和生产能力检测分离，复用现有权限、蓝牙、HID 与音频状态，避免为向导建立第二套业务链路。
- 测试分为状态机自动化、真实生产视图截图、构建发布验证和真实环境人工验收；任何一层都不能替代下一层。
- 锁屏截图问题最终通过 App 内隐藏的离屏 AppKit 渲染入口解决；浅色和深色必须分别固定整个窗口外观，不能只给单侧视图设置颜色方案。
