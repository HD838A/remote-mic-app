# 功能测试说明

本功能的完整人工测试步骤统一维护在 [`Testing/FirstRunOnboarding.md`](../../Testing/FirstRunOnboarding.md)。

`v1.8.8 (100)` 公开 Pre-release 已通过原流程验证；2026-08-15 首次连接指引候选已通过 220 项 Swift 测试、42 项项目自检、Release App 构建，以及浅/深色各 8 张 Onboarding 生产视图截图检查。既有 16 项硬件模拟结论未受本轮静态页面改动影响；真实 TV 键激活、Home + Menu 配对、RC001 / RC003 新配对和实体按键仍需真机验收。

交付前至少确认：

- 首次启动无法进入主面板，也没有跳过或稍后继续入口；
- 从 Onboarding 加入前的已安装版本升级后直接进入主面板并保留原设置；全新安装、中途续接和主动重新运行仍显示向导；
- 退出并重启恢复到保存页；
- 每项实时条件缺失时“继续”不可用；
- 音频页同时显示 MiRemoteV 2ch、BlackHole 2ch 和其他已安装设备，任一所选设备存在且输出就绪时可进入真实语音测试；
- RC003 真实语音必须同时出现会话开始、PCM 样本、松开停止和文字上屏；
- 三个不同普通按键被真实检测后才能完成；
- 已安装用户通过 Sparkle 升级后首次启动，即使 HID 按键先到而 BLE 状态仍在查找，也能在不重启 App 的情况下只恢复一次连接；
- 从系统蓝牙设置返回后无需重启即可发现新配对遥控器；多个 HID service 部分映射失败时，安全设备普通按键仍可用且电源键不触发锁屏；
- 遥控器页完整显示首次连接顺序：TV 键长按约 2 秒至底部白灯闪烁，再按 Home + Menu 进入配对；中英文均不得裁切；
- 遥控器页从系统设置返回时同时刷新 BLE 和 HID，按键失败原因可见且“重新检测按键”可以恢复；音频页从外部设置返回时自动刷新设备；
- 完成页在权限、BLE 或音频失效时不能进入主面板，恢复实时条件后可继续；完成页重建不会因前序临时标志清零而永久卡死；
- 完成后进入现有设置页，“关于”页能够重新运行向导，并且语音输出设备、按键映射、Dock、启动和更新设置不被清除；
- `1020 × 772` 下中英文没有裁切，中文文字不小于 12pt。
- “文件 → 打开日志所在文件夹”在 Onboarding 未完成时也可用。
- 每个失败状态只显示一个主要修复动作；“复制设置诊断”不包含用户名、路径、设备名、UUID、蓝牙地址、文字、音频或密钥。
- 完成页环境回退可分别定向返回权限、遥控器或音频页，不重新开始完整流程。

单元测试和构建不能替代系统权限、蓝牙、真实音频设备、Sparkle 升级首次启动、豆包、Typeless 及其他第三方工具验收。

## 验证分层

1. 流程层：状态机、持久化、门禁、重新运行和旧设置保留。
2. 页面层：生产视图浅色/深色各 8 张截图、`1020 × 772`、中英文、字号、裁切和视觉一致性。
3. 产物层：Release 构建、签名、公证、安装包、锁屏启动、资产摘要和 Sparkle 更新发现。
4. 现场层：真实权限历史、RC003、MiRemoteV 2ch、BlackHole 2ch、其他回环设备、第三方语音工具、前后台与断连恢复。

只有现场层可以证明用户机器上的完整链路可用；前面三层用于尽早发现确定性回归。
