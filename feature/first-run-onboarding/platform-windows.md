# Onboarding Windows 平台适配规范

本文定义未来 Windows 版必须如何满足 [`PRODUCT_SPEC.md`](PRODUCT_SPEC.md)。它是产品适配契约，不代表当前 Windows Onboarding 已经实现，也不提前指定未经验证的驱动、系统 API 或第三方工具方案。

## 适配原则

- Windows 可以使用与 macOS 不同的权限、热键、蓝牙、HID、音频和输入目标实现。
- 平台差异只能替换实现方式，不能降低真实连接、真实音频、真实文字和失败恢复门槛。
- 开始开发前必须填写本文的具体支持矩阵，并把不能可靠实现的能力明确标记为不支持，不能以页面确认代替。

## 必须确定的平台映射

### 控制来源

Windows 实现前必须明确：

- 首批支持的实体遥控器型号和公开识别条件。
- 蓝牙语音与 HID 普通按键分别使用的系统公开 API。
- 是否支持 iPhone、网页版或其他移动控制来源，以及如何隔离不同来源事件。
- 如何证明“系统已连接”之外的真实普通按键和语音能力已经可用。

### 权限与系统限制

必须逐项列出实际需要的 Windows 权限或系统能力，例如蓝牙、麦克风、输入注入、辅助访问或防火墙授权，并为以下状态设计不同指引：

- 尚未授权或功能被系统关闭。
- 被组织策略限制。
- 安全软件拦截。
- 驱动缺失或设备不可用。
- 需要重新启动 App 或系统。

不得照搬 macOS 的权限名称，也不得显示并不存在的授权步骤。

### 语音触发

- Windows 不得默认假设 Fn/地球键具有与 macOS 相同的系统语义或可注入能力。
- 首次实现必须为每个受支持语音工具选择经过真实验证的触发方式。
- SayAll 发出的触发方式和第三方工具需要配置的触发方式必须在语音测试输入框页并列显示。
- 如果第三方工具不支持可靠且可配置的触发方式，该工具不能被列为已支持。
- 按下/释放、点按切换或按钮式开始/结束的生命周期必须明确，且不能丢失停止事件。

### 音频路线

Windows 实现必须定义一个经过验证的音频路线，使 SayAll 接收的无线麦音频能够成为第三方语音工具可选择的麦克风输入。

必须区分：

- SayAll 写入或播放到的音频端点。
- 第三方语音工具选择的麦克风捕获端点。
- 端点存在、已选择、实际绑定、正在接收、停止与排空状态。

具体使用虚拟音频驱动、系统回环或其他公开能力，必须在技术验证后写入本文；未经验证不得在 UI 中承诺支持。

### 输入目标与文字验证

- 必须使用 Windows 公开 UI Automation、原生控件焦点或等价公开能力确认当前测试输入框是文字目标。
- 不得读取其他 App 私有内容或依赖窗口标题、文档名等用户信息进行日志判断。
- 最终门禁必须观察到第三方语音工具向当前测试输入框写入文字。
- 手动键盘输入、粘贴、其他窗口文字或上一 attempt 的结果不得通过。

### 第三方工具

每个正式支持的 Windows 语音工具必须记录：

- 官方安装来源。
- 支持的版本范围。
- 语音触发方式。
- 麦克风选择位置和期望设备。
- 可以通过公开能力自动观察的状态。
- 只能由用户确认的状态。
- 真实端到端验收结果与已知限制。

不得读取第三方 App 私有文件、数据库、注册表内部配置或未公开协议来伪装自动检查。公开文档或公开 API 明确支持的系统集成需单独记录依据。

## 建议的 Windows 页面流程

在未发现 Windows 必须不同的依赖关系前，应该沿用跨平台标准流程：

1. 欢迎。
2. 选择语音工具。
3. 判断并选择控制来源。
4. Windows 权限与系统能力。
5. 真实连接和普通控制事件。
6. 选择并验证 Windows 音频路线。
7. 在输入框页集中核对触发方式、SayAll 音频端点、第三方触发方式和第三方麦克风。
8. 完成真实语音到文字测试。
9. 验证多个不同普通控制操作。
10. 重新检查运行条件后完成。

页面可以按 Windows 设计语言调整布局，但配置核对、失败原因和主要修复动作必须在当前页面直接可见。

## Windows 验收门槛

首个 Windows Onboarding PR 至少必须提供：

- 流程状态机和所有分支自动化。
- Windows 支持版本、架构与升级迁移测试。
- 每个受支持控制来源的真实连接、普通按键和语音测试。
- 每个受支持语音工具的触发、音频电平和文字上屏测试。
- 音频设备缺失、被占用、失效、切换和停止排空测试。
- 权限拒绝、组织策略或安全软件拦截的可恢复指引。
- 默认缩放、高 DPI、浅色、深色、高对比度、键盘和屏幕阅读器的完整流程截图或录屏证据。
- 诊断日志对控制、音频、焦点和第三方未提交边界的区分。
- 自动化、模拟设备和真实 Windows 机器验收边界说明。

在上述具体映射和真实验收完成前，Windows 文档只能标记为“设计中”或“验证中”，不能宣称与 macOS Onboarding 等价完成。
