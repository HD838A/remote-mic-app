# 遥控器系统睡眠隔离

状态：实验候选。本机已完成完整应用的睡眠隔离、后台维护唤醒观察、按键重连和第一次语音验证，并收到更新后使用一天正常的用户反馈；整夜、异常恢复及跨版本验收未完成。详细证据及其边界见[验收手册](../../Testing/RemoteSleepConnection.md)。

- 用户在当前 RC003 遥控器设置中明确启用，默认关闭。设备标识仅存本机，不随映射导出。
- 仅系统准备睡眠触发隔离；屏保、锁屏、显示器熄灭不单独触发。
- 保留配对，限定选定遥控器，不改变蓝牙电源、键鼠、屏保或电源超时设置。
- 应用先门控目标桥的重连，再请求取消目标连接及内置服务自动连接。睡眠确认最长等待两秒；失败或超时不阻止睡眠，明确显示未确认保护。
- 后台维护唤醒不应释放隔离；系统恢复、显示器点亮且当前会话在控制台时才允许请求恢复连接。这不识别具体输入设备，也不证明唤醒来自用户。
- 恢复沿用原蓝牙桥。可能需要按一下遥控器使其响应，不要求重新配对。
- 关闭功能、改变隔离目标、取消睡眠或正常退出时释放本次请求；异常退出后通过原桥的正常连接流程恢复。不得承诺进程崩溃时执行清理。
- 未公开的系统选项必须封装并运行时检查，缺失时禁止新启用，但必须允许关闭已有配置。不回退到遗忘设备或关闭整个蓝牙。
- 断连回调只确认当前 CoreBluetooth 会话断开，不足以证明系统物理链路已断或长期保护有效。界面与日志必须保留该边界。

- 解除隔离后，仅目标 UUID 的第一次恢复优先查询系统已连接候选及广播发现，最长 30 秒；窗口超时回到原连接路径。不把等待休眠遥控器广播视为已连接，不承诺按一次必连。重复睡眠或停止应用清理该临时恢复意图。

- 已开启目标在清醒、已就绪且没有主动断开请求时发生链路丢失，可在 100ms 后发起一次恢复；30 秒内不得重复快速重试。不得补发断连期间的输入或掩盖被中断语音，不宣称该机制阻止底层断连。
