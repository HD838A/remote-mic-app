# 修饰键双击录入

**状态：规范草案，等待产品确认；未开始开发。**
权威产品行为见 [`PRODUCT_SPEC.md`](PRODUCT_SPEC.md)。

## 为什么开发

快捷键录入器今天只能录「按一次」的修饰键，无法表达「同一个修饰键连按两次」。
而「双击修饰键」是 macOS 既有交互语言：系统听写的默认快捷键就是「按两下 Fn 键」，
右 Command / Control 按两下也是系统提供的听写快捷键选项，不少第三方语音与效率工具
同样用双击修饰键触发。用户想把这个组合绑到遥控器按键上、由 SayAll 代发，目前做不到。

**本功能与语音键无关**：不修改 `VoiceKeyMode`，不给遥控器语音键增加手势，
只作用于快捷键录入器、`CustomKeyboardShortcut` 数据模型和快捷键发送路径。

## 用户可以看到和操作什么

- 在按键映射页录入一条「双击右 Command」「双击 Fn」这样的快捷键。
- 按键映射页紧凑显示为 `⌘⌘` / `fn fn`，悬停与朗读给出完整名称。
- 绑定到遥控器按键后，触发时对目标 App 连发两次该修饰键的按下与释放。
- 单击修饰键的录入与显示保持现有行为不变。

## 本次做什么 / 不做什么

**做**：单一修饰键的双击录入、显示、发送、持久化与导入导出兼容。

**不做**：多修饰键双击、普通主键双击、三击；不改语音键；不改遥控器按键的
单击/双击/长按识别；不引入常驻键盘监听；不新增根目录文档或可执行辅助文件。

## 数据边界

全部配置只留在本机 `UserDefaults`（`buttonShortcuts`），随现有配置导出与完整备份。
不新增数据采集，不上传任何内容。日志只记录成功/失败与是否双击，不记录用户按了什么键。

## 涉及的共享链路

`CustomKeyboardShortcut`（持久化与导入导出的中心模型）、`ShortcutCaptureMonitor`
（录入器）、`KeyboardInjector` / `ShortcutEventSequence`（发送）、`AppSettings.validatedShortcut`
（导入白名单）、`KeyboardShortcutPicker`（选择器），以及独立仓库中的私有包
`macos-combination-actions` / `macos-button-profiles`。

其中最需要小心的一处：`validatedShortcut` 用「正常初始化器重建」做过滤，
**重建时不透传新增字段就会让导入的双击快捷键静默退化为单击**。

## 关键问题

1. 录入交互怎么设计才不会让现有的单击修饰键录入变慢（`PRODUCT_SPEC.md` D1）。
2. 双击判定窗口与发送间隔是否都用 300 ms（D2）。
3. 与 macOS 听写抢同一个键时如何提示（D6）。
4. 私有包与 Windows 仓是否同步（D7、D8）。

## 验证边界

自动化覆盖录入状态机、发送连发、以及旧配置解码和导出导入往返；
真机需要验证目标 App（至少 macOS 听写加一个第三方工具）是否真的响应双击修饰键。
单元测试和构建通过不能替代真机验收。

## 用户测试步骤

只按一次回落单击、组合键不误判、两个修饰键不误判、导入后不退化、显示正确。
