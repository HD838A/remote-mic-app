# 首选输入法自动准备

## 为什么开发

用户在 Onboarding 中已经选择准备使用的输入法，但日常工作中 macOS 会按 App 或用户操作切回 ABC 等其他输入源。按下 Fn 开始语音时如果输入法不对，遥控器音频虽然正常送出，目标输入法却不会处理语音。

## 用户功能

- 复用并记住 Onboarding 中选择的豆包输入法、微信输入法、Typeless 或其他语音工具。
- 豆包或微信分支在 Fn 从松开变为按下时检查当前系统输入源；不一致时自动切换到已选择输入法。
- 同一次按住 Fn 只检查一次；松开后下一次按下可以重新检查。
- Typeless 和其他独立语音工具不切换系统输入源。
- 语音结束后保持当前输入法，不自动恢复旧输入源。

## 范围与非目标

本功能只准备已经安装、已经启用且由用户在 Onboarding 明确选择的系统输入法。它不按显示名称猜测输入法，不安装或启用第三方输入法，不自动操作 Typeless 等独立 App，也不改变现有 BLE、HID 映射、虚拟音频或按键动作。

## 关键实现

- `AppSettings.onboardingVoiceTool` 继续作为版本化本机选择，不新增重复偏好。
- `OnboardingInputSourceSwitcher` 使用精确 Input Source ID 检查并按需选择输入源。
- `PreferredInputSourceMonitor` 在输入监控权限有效时监听全局 Fn 修饰键边沿；只处理按下边沿并在 App 停止时移除监听。
- `BridgeAppModel.applyHIDSettings()` 根据当前输入监控权限启动或停止监听，确保权限失效时不扩大行为范围。

## 隐私与兼容边界

当前输入源和 Onboarding 选择只在本机读取；不上传输入内容、按键内容或输入源列表。日志只记录语音工具枚举和切换结果，不记录用户文字、应用名称或完整输入源列表。支持豆包与微信的已确认精确 ID；第三方更新 ID 后需要重新验证。

## 验证

- 自动化覆盖 Fn 按下边沿、重复事件去重、松开后重新触发、非输入法工具旁路和监听清理。
- 230 项 Swift 测试、20 个 suite 和 42 项项目自检通过；本地预览 App 代码签名校验通过。
- 人工步骤见 [`Testing/FirstRunOnboarding.md`](../../Testing/FirstRunOnboarding.md) 的“用例 2A”。

当前自动化不能证明 macOS 全局 Fn 事件与豆包、微信真实输入法的启动时序，也不能替代遥控器 F5 映射为 Fn 后的真机验收。
