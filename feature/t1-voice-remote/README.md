# T1 蓝牙语音遥控器适配提案

状态：待评审。目标是在 macOS 的 SayAll 中选择已配对的艾拍宝 T1，并用它的麦克风驱动现有虚拟麦克风和语音输入工具。首轮范围是蓝牙语音。普通按键映射、2.4 GHz 接收器和 Windows 支持需要各自的设备证据。

## 真机记录

2026-11-25，一只艾拍宝 T1 蓝牙／2.4 GHz 双模样机通过蓝牙与 Mac 配对。系统显示已连接的遥控器，并注册了 BLE 键盘输入接口。与小米遥控器同时连接时，SayAll 的「连接与语音」只列出了小米。

| 观察项 | 样机结果 |
| --- | --- |
| 蓝牙发现提示 | 默认名称为 `T1-Remote` |
| GATT 设备信息 | Model Number 为 `hid_mouse`、Manufacturer 为 `shenzhen_xingwei`、Firmware Revision 为 `0.0.1` |
| PnP ID 和系统 HID | 厂商 ID `0x620A`、产品 ID `0x0407` |
| 蓝牙语音协商 | ATVV v1.0、16 kHz ADPCM、128 字节帧、交互值 `0x03` |
| 一次语音键测试 | 收到 `AUDIO_START` 和持续音频帧。操作者确认已松手，采集窗口内未收到 `AUDIO_STOP`，由宿主超时结束。 |
| 按住与松手 | 另一轮收到返回键的 HID 正对照和语音 `AUDIO_START`，但未收到语音 HID 释放或松手停止事件。设备在约 15.4 秒后以超时原因 `0x08` 停止。 |
| 两次点按 | 两个连续会话均收到 `AUDIO_START` → `START_SEARCH`。宿主在第二次点按后写入 `MIC_CLOSE`，设备分别在约 432 ms 和 433 ms 后确认停止，收到 158 和 84 帧音频。 |
| 重复消息 | 第一个点按会话在正常停止后额外收到一次 `AUDIO_STOP`。两次第二点按均出现 HID Consumer Search `0x0221` 报告。 |
| 交互能力字段 | `GET_CAPS` 分别请求 `0x03`、`0x01`、`0x00` 时，CAPS 响应返回对应值。请求后恢复 `0x03`。按键结论基于 `0x03`，其余值尚未验证按键行为。 |
| 真实语音输出 | 已生成解码后的 PCM。语句可辨识度、首尾字、虚拟麦克风到输入工具的文字上屏均待验证。 |

上述语音数据来自独立 CoreBluetooth 探针。表格仅保留共享型号信息、协议参数和事件结果。配对方法见 [T1 硬件说明书](https://device.report/manual/15400369)。[Remote Buddy 的 T1 说明](https://github.com/zfdang/remote-buddy/blob/main/README.en.md)记录其样机使用「点按开始，再按结束」。本样机的第二次点按与关麦确认已经复现。两只样机是否拥有相同的 HID 释放能力仍待确认。

## 现有实现与切入点

- [设备准入](../../Sources/RemoteMic/BluetoothLifecycle.swift)由已保存身份或目录中的已知名称进入。T1 的默认名称不在目录中，单独暴露 ATVV 服务也无法通过准入。
- [型号目录](../../Sources/RemoteMic/RemoteDeviceProfile.swift)按 Device Information 服务里的 Model Number 识别小米机型。`hid_mouse` 是通用值。建议在有新鲜设备信息时组合精确匹配 PnP 厂商／产品 ID、厂商字符串及语音能力。广播名只用于发现。样机证据只覆盖上述指纹。
- [蓝牙语音桥](../../Sources/RemoteMic/XiaomiBluetoothBridge.swift)已有可变帧长、ADPCM 解码和语音停止路径。先验证 T1 的帧和可辨识语音，再决定可复用的部分。常用键和 Fn 硬件映射独立于蓝牙语音，可单独验证。

## 需评审的语音键交互

[仓库语音键规范](../../AGENTS.md#语音键响应与手势边界)要求按下立即开始、释放后尽快结束。在当前样机与协商模式下，诊断只验证了两次点按。可先在其他协商模式下检查硬件是否提供可靠的松手边沿。

建议评审是否为已确认的 T1 提供「点按开始，再按结束」，与小米的按住说话并存。第一次 `AUDIO_START` 开始接收和输出，录音中的 `START_SEARCH` 请求关麦，收到有效停止确认后排空并结束。重复停止只处理一次。还要验证仅针对 T1 语音键抑制系统搜索，普通 HID 键继续走原生链路。

## 验收

1. 在已有小米档案的 Mac 上首次配对 T1、重连及切换设备。独立显示真实型号和系统名称，快捷键及语音会话归属正确。
2. 核对语音开始与结束事件、首段 PCM、首字延迟、尾帧完整，至少连续录两段，确认每段文字从现有虚拟麦克风进入目标输入工具。
3. 验证录音时断连、超时、取消和恢复。正常结束先排空音频，再释放输入工具的触发键。
4. 复测小米 RC001／RC003 的按下、松手、连续会话和重连。未知 ATVV 设备不能仅因名称近似或服务匹配而被标记为 T1。
5. 分别记录 macOS 和 Windows 的实现与实测状态。当前只有表中这一只样机的 macOS 蓝牙和音频传输证据。
