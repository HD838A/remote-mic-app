# 唤起目标后的首次语音就绪协调

## 为什么开发

用户通过遥控器打开或切换目标 App 后立即开始语音时，App 的启动、窗口激活和输入框聚焦可能需要数秒。旧实现只等待固定 150 ms 就发送 Fn，导致第一次甚至前两次语音无效。

## 用户功能

- 执行内置 App、自定义 App 或自定义快捷键后，第一次语音会等待目标输入位置真正可用。
- 等待期间的语音会短暂保存在内存中，目标就绪后完整回放。
- 用户提前松开语音键也能完成一次完整开始和结束。
- 目标退出、切换、超时或落在敏感字段时自动取消，避免发错窗口。
- 没有目标切换时，原有即时 Fn 行为不变。

## 范围与非目标

本功能只协调目标 App、Accessibility 最终焦点与现有 Fn 点按语音会话，不修改蓝牙协议、ATVV 命令、音频解码、虚拟麦克风、按键配置格式或第三方 App 的专用聚焦规则。

本功能不保证所有第三方 App 永久提供稳定 Accessibility 信息，也不尝试在密码或受保护字段中启动语音。

## 隐私与兼容

- 只在本机读取当前前台 App 标识、focused Accessibility 元素的角色和少量语义属性，不上传、不持久化输入内容。
- 语音等待缓存只存在于内存，最大约 80,000 个 Int16 sample，结束、取消或超时后释放。
- 现有设置键、导入导出格式、内置动作标识和自定义 App 配置不变。

## 当前状态

生产代码、复合旅程测试和 RC001/RC003 模拟硬件测试已完成。第三方 App、实体遥控器和最终文字上屏仍按 [`Testing/VoiceInputDestinationReadiness.md`](../../Testing/VoiceInputDestinationReadiness.md) 在预览版中验收。
