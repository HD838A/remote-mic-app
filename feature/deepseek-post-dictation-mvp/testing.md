# DeepSeek 语音结束后整理 MVP 测试手册

## 1. 测试目标

本手册验证三个层级：

1. 功能关闭时，现有语音输入行为完全不受影响；
2. 功能开启时，DeepSeek 只整理本次语音文字，并保持上下文、数字、否定和术语；
3. 焦点、文字、请求或写入出现异常时，豆包原文不会被错误覆盖。

任何“构建成功”或“API 调用成功”都不能代替本手册中的真实豆包输入法和目标输入框验收。

## 2. 测试准备

### 2.1 环境

- macOS 14 或更高版本；
- 本功能对应分支构建的 Remote Mic；
- 豆包输入法已经可以正常语音上屏；
- Remote Mic 已获得辅助功能权限；
- Remote Mic 虚拟音频设备可用；
- RC003、附近 iPhone 或网页遥控器至少有一个语音入口可用；
- 有效 DeepSeek API Key。

本地构建：

```bash
cd /path/to/remote-mic-app
CONFIGURATION=release ./scripts/build-app.sh
./scripts/verify-app.sh 'dist/Remote Mic.app'
open 'dist/Remote Mic.app'
```

### 2.2 配置 Key

打开设置，点击左侧独立的“AI 整理”入口：

1. 点击 Key 输入框，使用 `Command-V` 粘贴 DeepSeek API Key，确认保存按钮启用；
2. 点击“保存 Key”；
3. 确认输入框只显示 Key 前四位和后四位，中间为遮罩，完整 Key 不回显；
4. 点击“测试连接”；
5. 确认显示“DeepSeek 连接测试成功”；
6. 退出并重新打开 App，确认仍显示“Key 已配置”及相同遮罩预览。

不要在测试记录、截图、终端输出或问题报告中粘贴 API Key。

## 3. P0：功能关闭基线

### 用例 P0-01：设置缺失或默认关闭

步骤：

1. 使用新的 `UserDefaults` 环境，或者确认此前从未开启该功能；
2. 打开设置；
3. 检查“AI 整理（实验）”开关；
4. 完成一次普通语音输入。

预期：

- 开关默认关闭；
- 豆包文字正常上屏；
- 不出现 DeepSeek 请求状态；
- 文字不发生二次替换；
- 音频、Fn 和遥控器行为与正式基线一致。

### 用例 P0-02：明确关闭

步骤：先开启功能，再明确关闭，然后完成语音输入。

预期：与 P0-01 完全一致。

### 用例 P0-03：使用后再关闭

步骤：

1. 开启功能并成功完成一次整理；
2. 关闭开关；
3. 再完成一次语音输入。

预期：第二次只保留豆包结果，不再整理；第一次的旧请求不能延迟覆盖第二次内容。

## 4. P0：普通整理和语义保持

### 用例 P0-04：改口和口头禅

口述：

> 嗯我们今天那个把这个版本发一下，哦不对，明天发。

预期：

- 删除没有语义的口头禅；
- 只保留最终确认的“明天发”；
- 不添加原话没有的理由、步骤或方案。

### 用例 P0-05：否定和限制

口述：

> 不要关闭兼容模式，也不要删除旧配置，只有测试通过后才能发布。

预期：两个“不要”、“只有”和“才能”均保留，不能改变条件和立场。

### 用例 P0-06：数字、时间和版本号

口述：

> 版本是 1.7.3，明天下午 3 点 30 分发布，预算是 12,500 元，不是 15,200 元。

预期：所有数字、标点形式、时间、金额和否定均保持正确。

### 用例 P0-07：问句不被回答

口述：

> 这个功能为什么会失败？我想把这句话直接发给同事。

预期：输出仍然是用户准备发送的问句，DeepSeek 不回答问题。

## 5. P0：上下文和局部范围

### 用例 P0-08：句中插入

准备文字：

> 我们计划在之后开始内测。

把光标放在“在”和“之后”之间，口述：

> 下周三完成接口验证

预期结果类似：

> 我们计划在下周三完成接口验证之后开始内测。

必须确认：

- “我们计划在”逐字不变；
- “之后开始内测”逐字不变；
- 没有重复前后文；
- 只修改本次插入范围。

### 用例 P0-09：原选区替换

步骤：

1. 输入“请把旧内容替换掉”；
2. 选中“旧内容”；
3. 口述“新的实现方案”。

预期：只替换原选区，两侧文字不变；原选中文字不作为上下文重复出现在结果中。

### 用例 P0-10：emoji 和组合字符边界

在光标两侧放置 emoji、中英文及带组合音标的字符，再进行句中插入。

预期：不出现乱码、半个 emoji、字符丢失或替换范围偏移。

## 6. P0：编程术语

先在设置里添加：

| 准确写法 | 口述别名 | 类型 |
| --- | --- | --- |
| `open-voice-bridge` | `open voice bridge` | 项目名 |
| `feat/voice1-test` | `feat 斜杠 voice one 横杠 test` | 分支 |
| `ATVVProtocol` | `ATVV protocol`、`ATVV 协议` | 标识符 |
| `RC003` | `RC 零零三` | 系统名 |

### 用例 P0-11：完整分支名和标识符

口述：

> 先切到 feat 斜杠 voice one 横杠 test，然后修改 open voice bridge，但是不要改 ATVV protocol。

预期必须包含：

- `feat/voice1-test`；
- `open-voice-bridge`；
- `ATVVProtocol`；
- 原来的“不要”约束。

术语内部不能增加空格、改变大小写或修改符号。

### 用例 P0-12：自然语言符号防误判

口述：

> 这个横杠看起来太长，点的位置也不对。

预期：“横杠”和“点”保持自然语言，不能变成 `-` 和 `.`。

### 用例 P0-13：自动列表保持关闭

口述：

> 第一点检查延迟，第二点检查文字覆盖，第三点检查费用。

预期：可以补标点或分段，但不能变成 `1.`、`2.`、`3.` 的 Markdown 列表。

## 7. P0：并发和安全取消

### 用例 P0-14：切换 App

松开语音键后立即切换到另一个 App。

预期：本次跳过，豆包原文保留，新 App 内容不受影响。

### 用例 P0-15：改变焦点或选区

松开后立即点击同一输入框的其他位置或改变选区。

预期：本次跳过，不把结果写到新光标位置。

### 用例 P0-16：用户继续编辑

在显示“正在通过 DeepSeek 整理”时继续输入或删除文字。

预期：迟到结果不能覆盖用户编辑后的完整内容。

同时确认：DeepSeek 请求期间 Dock 上方中央出现“AI 正在整理”HUD；HUD 不抢焦点、不阻止点击或继续输入，请求结束后淡出。

### 用例 P0-17：连续两次语音

第一次语音结束后，在其结果返回前立即开始第二次语音。

预期：第一次等待或请求取消；只能处理第二次会话，不出现交叉覆盖。

### 用例 P0-18：请求中关闭功能

请求期间关闭实验开关。

预期：请求结果不能再自动写入；之后的语音保持普通路径。

## 8. P0：错误和回退

### 用例 P0-19：错误 Key

保存一个无效 Key，执行连接测试和语音输入。

预期：连接失败，豆包原文保留，不自动替换。

### 用例 P0-20：删除 Key

点击“删除”。

预期：

- 显示 Key 未配置；
- 实验功能自动关闭；
- 重新启动后仍未配置；
- 普通语音路径可继续使用。

### 用例 P0-21：网络中断或超时

在请求前断开网络，或让请求超过等待时间。

预期：显示请求失败或超时，豆包原文完整保留，不重复请求。

### 用例 P0-22：不支持的输入框

在密码框、安全输入框、终端或不支持精确 AX 写入的网页编辑器中尝试。

预期：

- 密码框绝不调用自动整理；
- 不支持的控件被安全跳过；
- 原文和剪贴板不被自动修改；
- 如果已经取得整理结果但最终写入失败，“复制整理结果”按钮可以由用户主动使用。

## 9. 入口和稳定基线回归

分别使用以下入口完成至少一次短语音和一次较长语音：

- RC003；
- 附近 iPhone；
- 网页遥控器；
- Fn 点按模式，如果日常使用该模式。

每条路径检查：

- `STREAM_START → AUDIO → STREAM_STOP` 完整；
- 豆包能收到开头和尾部音频；
- 没有尾音截断、重复输入或重复请求；
- 功能关闭时与上一正式版行为一致；
- 功能开启时每次成功捕获的语音最多一次请求。

自动化和模拟测试通过不能代替这一节的真实设备验收。

## 10. 设置页面检查

在 App 支持的最小窗口尺寸下：

1. 逐一点击连接、按键映射、使用统计、权限和关于；
2. 打开独立“AI 整理”页面；
3. 滚动检查运行状态、工作流程、DeepSeek API、编程术语、隐私和格式策略面板；
4. 测试 Key 输入、保存、删除、连接测试、术语类型选择、添加、启停和删除；
5. 切换中英文，确认文字完整且控件不被裁切。

预期：侧边栏、页头、主要控件和滚动正常，窗口几何不会因切换页面异常变化。

## 11. 全局 HUD 检查

分别在 TextEdit、Codex、浏览器和聊天工具中触发一次真实 DeepSeek 整理：

1. 请求前和等待豆包文字稳定时，HUD 不出现；
2. DeepSeek 请求真正开始后，HUD 显示在当前屏幕 Dock 上方中央；
3. HUD 使用暖橙、星光黄和深暖灰主题，不显示麦克风、波形、电平或按钮；
4. HUD 显示期间继续点击、选择和输入，确认鼠标事件穿透且目标 App 始终保持焦点；
5. 请求完成、失败、跳过、中途关闭功能或退出 App 后，HUD 消失；
6. 点击“测试连接”，确认设置页显示测试状态，但不会出现全局 HUD；
7. 在全屏 App、外接显示器以及 Dock 位于底部、左侧、右侧时重复检查位置。

预期：HUD 不激活 Remote Mic、不出现在窗口切换列表中、不被设置窗口可见性影响，并始终处于当前工作空间的可见区域内。

## 12. 隐私日志检查

测试后检查功能日志：

```bash
rg -n 'POST_DICTATION' ~/Library/Logs/RemoteMic/runtime.log
```

预期只包含 Prompt 版本、输入/输出字符数量、耗时和错误类型。

检查是否出现类似 API Key 的值：

```bash
rg -n 'sk-[A-Za-z0-9_-]{20,}' ~/Library/Logs/RemoteMic/runtime.log
```

预期没有输出。还应使用本轮测试中的独特口述短语搜索日志，确认 App 名称、上下文、术语、豆包原文和整理结果没有被记录。

## 13. 验收判定

以下任一情况出现即为 P0 失败，不能扩大试用：

- 功能关闭时改变现有语音路径；
- 修改本次范围以外的上下文；
- 用户编辑、切换焦点或新会话后仍被迟到结果覆盖；
- API、解析或写入失败时豆包原文丢失；
- 否定、数字、版本号或受保护术语被错误改变；
- 密码框或安全输入框触发云端整理；
- 日志、配置或仓库出现 API Key 或用户文字。
- DeepSeek 实际请求时 HUD 未显示，或等待/连接测试阶段错误显示 HUD；
- HUD 抢走焦点、拦截鼠标、遮挡 Dock，或在请求结束后残留。

以下属于可以记录后继续优化的问题：

- 整理风格不够自然；
- 等待时间偏长；
- 某些富文本、终端或网页编辑器被安全跳过；
- 自动列表尚未实现。
