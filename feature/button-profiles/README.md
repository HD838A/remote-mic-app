# 键位方案

## 为什么开发

用户需要为同一只遥控器保存“默认、Codex、Claude、网易云”等多套完整按键配置，而不是每次重新修改单击、双击和长按。用户还需要选择手动切换，或在明确开启后根据当前前台 App 自动切换。

## 用户功能介绍

私有组合动作页面新增并列的“键位方案 / Button Profiles”入口。用户可以创建、复制、重命名和删除方案，设为默认方案，点击“立即使用”切换为手动模式，并在遥控器图上为单击、双击和长按选择已经保存的组合动作。

自动模式只按前台 App 的精确 Bundle ID 选择方案。未匹配 App 时回默认方案；Remote Mic 自己前台、锁屏或无法取得 Bundle ID 时保持当前方案。

## 范围与非目标

- 本期包含组合动作基础能力、单设备多套键位方案、手动切换和前台 App 自动切换。
- 任一时刻每只遥控器只有一套方案生效，不叠加、不使用隐藏优先级。
- 本期不开发键位预设导入导出、官方预设、社区市场、跨设备场景或任意脚本。
- 功能继续通过可选私有模块接入；没有私有模块或功能访问关闭时，公开宿主保持原行为。

## 关键设计

- `button-bindings.json` 使用格式 2 保存方案、当前/默认选择和 App 规则。
- 格式 1 自动生成备份并迁移；遥控器精确绑定覆盖通用绑定，迁移后每只遥控器拥有独立默认方案。
- 自动模式使用 `NSWorkspace.didActivateApplicationNotification` 和约 150ms 防抖，不轮询、不新增系统权限。
- 公开宿主仍只查询“当前触发是否有私有绑定”和“执行当前私有绑定”；方案解析完全留在私有模块。
- 当前组合动作在按键触发时解析一次，执行过程中切换 App 只影响下一次触发。

## 隐私与兼容边界

- App 规则只保存用户选择的 Bundle ID，不上传前台 App 历史。
- 键位方案属于本机配置，不包含蓝牙地址、设备身份、输入文字或学习到的完整 Accessibility 树。
- 旧公开构建、未注入私有模块和功能访问关闭状态均保持安全 no-op。

## 当前状态
