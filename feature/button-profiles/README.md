# 键位方案

## 为什么开发

用户需要为同一只遥控器保存“默认、Codex、Claude、网易云”等多套完整按键配置，而不是每次重新修改单击、双击和长按。用户还需要选择自己切换，或在打开指定 App 时自动使用对应方案。

## 用户功能介绍

设置侧边栏新增独立的“键位方案 / Button Profiles”页面，不再与“组合动作”使用同页分段。已保存方案默认只显示简洁摘要；新建或编辑时，页面依次引导用户完成“基本设置（名称与使用方式）→ 设置按键 → 确认保存”，每一步都可按 Return 执行主操作。用户可以创建、复制、重命名和删除方案，设为默认方案，明确选择“改为手动使用”，并在遥控器图上为单击、双击和长按选择禁用、基础按键、系统与媒体、已保存快捷键、App 或组合动作。

自动方式下，用户打开已选择的 App 时会使用对应方案；打开其他 App 时使用默认方案。无线麦SayAll.app 自己正在使用、锁屏或暂时无法识别当前 App 时保持现有方案。若用户切到手动使用，已保存的 App 关联不会丢失，摘要会显示“自动切换已暂停”并提供恢复入口。

页面只显示 App 图标和名称，不显示内部 App 标识。没有任何方案时，内容区中央会直接提供大号“新建键位方案”按钮，不要求用户先理解侧栏结构。方案整行可点击；方案栏用“正在查看”“正在使用”“默认方案”直接说明查看、生效和兜底状态，不使用无说明的 Radio 或星标，窄空间仅把状态文字收成带辅助说明的图标。查看状态使用扁平摘要，编辑时隐藏方案栏。名称与输入框同排，不显示“格式”等装饰术语；第二步固定显示遥控器，并在图上标出已设置按键；最终确认页列出每个按键、按法和具体操作。

## 范围与非目标

- 本期包含组合动作基础能力、单设备多套键位方案、手动切换和前台 App 自动切换。
- 任一时刻每只遥控器只有一套方案生效，不叠加、不使用隐藏优先级。
- 本期不开发键位预设导入导出、官方预设、社区市场、跨设备场景或任意脚本。
- 功能继续通过可选私有模块接入；没有私有模块或功能访问关闭时，公开宿主保持原行为。

## 关键设计

- `button-profiles.json` 使用第一版公开格式 v1 保存方案、类型化动作绑定、当前/默认选择和 App 规则。
- 此功能尚未正式发布，不迁移开发过程中产生的 `button-bindings.json`；未来格式必须向后读取当前公开 v1，当前版本对未知未来格式安全拒绝。
- 新建和编辑使用本地草稿；步骤切换不会丢失草稿，取消不修改已保存方案，只有最后点击“保存方案”才一次性提交全部字段。
- 私有模块保存宿主动作的稳定 ID、显示快照和不透明 payload，执行时交回宿主现有 `ButtonAction` / `KeyboardInjector` 路径，不复制第二套宿主动作枚举。
- 只有第二步“设置按键”处于编辑状态时，真实遥控器按键只更新遥控器图片选择，不执行动作；摘要页、其他步骤和离开页面后均恢复执行。
- 第二步可以直接录入新的键盘快捷键，保存到本机私有快捷键库；键位方案和组合动作复用同一份快捷键记录。录入期间取消只停止当前录入，长快捷键允许换行完整显示。
- macOS 对方向键自动附带的系统 `Fn` 标记不会作为用户修饰键保存；升级前已保存的方向键记录在展示和执行时也会规范化，真实功能键仍保留 Fn。
- 页面内录入的单快捷键同步交给宿主现有键盘注入器执行，不再包装成无法回传投递结果的临时组合动作；方向键补齐扩展键标志。
- 未独占 HID 时，左右键只有在当前方案没有单击覆盖动作时才使用系统原生方向键透传；存在方案绑定时优先执行方案动作。
- 自动模式使用 `NSWorkspace.didActivateApplicationNotification` 和约 150ms 防抖，不轮询、不新增系统权限。
- 公开宿主仍只查询“当前触发是否有私有绑定”和“执行当前私有绑定”；方案解析完全留在私有模块。
- 当前组合动作在按键触发时解析一次，执行过程中切换 App 只影响下一次触发。

## 隐私与兼容边界

- App 规则只保存用户选择的 Bundle ID，不上传前台 App 历史。
- 键位方案属于本机配置，不包含蓝牙地址、设备身份、输入文字或学习到的完整 Accessibility 树。
- 旧公开构建、未注入私有模块和功能访问关闭状态均保持安全 no-op。键位方案自身此前没有正式用户数据兼容负担。
