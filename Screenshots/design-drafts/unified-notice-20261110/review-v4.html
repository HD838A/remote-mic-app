SayAll · 提示气泡 v4 · 未开发

气泡，而不是提示条

上一版是“系统提示条”的语言：中性底色、彩色徽章、紧凑排版。它正确，但确实像设置面板里的工具。 这一版换成产品引导的语言：饱和品牌色、18pt 大圆角、指向锚点的尾巴、去掉图标、标题 + 说明的双行节奏。 同时补上你要的第二件事：提示可以钉在某个元素上，而不是只能浮在页面正中。

新增：锚定元素 + 指向尾巴 版式：标题 + 说明 + 一个动作 品牌色替代中性反色 待确认后才开发
01

先定颜色：三种气质

气泡的“高级感”主要来自颜色和圆角，不是阴影。三种都算过对比度，白字必须 ≥ 4.5:1。 注意 SayAll 品牌原色 #D56059 只有 3.72:1，直接用会不达标，必须加深。

行为规则

场景关闭方式说明
引导气泡（锚定）点 X / Esc / 点气泡外只显示一次，按 seenKey 记忆；手动关掉也算看过
状态气泡（权限）条件恢复后自动消失不给 X；它描述的是仍然存在的状态，关掉会误导
字段错误点 X / Esc / 动作修好后自动消失；不自动超时，避免还没读完就没了

多个锚定同时命中—只显示优先级最高的一条；其余排队
和“位置统一”的关系。用户仍然只需要记两个位置：有具体元素 → 贴着那个元素；没有具体元素 → 页面正中。 两种都不会跑到顶部或角落，所以习惯不会被打散。锚定气泡的尾巴本身就是位置说明。
06

锚定怎么实现

业务侧只多传一个锚点标识，不写坐标、不写尾巴方向。方向由中心按可用空间算。

① 注册锚点：在目标元素上加一个修饰符

// 任何 View 都能被锚定
VoiceKeyCard()
    .noticeAnchor(.voiceKey)

// 用枚举而不是字符串，避免拼错
enum NoticeAnchorID: Hashable {
    case voiceKey, inputMonitoring, phraseField
}

② 业务侧：只声明锚在哪

NoticeCenter.shared.show(.init(
    kind: .tip,
    title: "按住它说话",
    text: "按住遥控器语音键，松开后文字会插到光标处。",
    action: .dismiss(title: "知道了"),
    anchor: .voiceKey,          // nil = 居中
    seenKey: "tip.voiceKey.v1"  // 只显示一次
))

// 状态类：不给 X，条件恢复后自己消失
NoticeCenter.shared.show(.init(
    kind: .status,
    title: "这一项还没开",
    text: "勾选后按键映射才会生效。",
    action: .openSystemSettings(.inputMonitoring),
    anchor: .inputMonitoring,
    dismissible: false
))

③ 中心侧：方向由几何决定，不靠调用方猜

func placement(for anchor: CGRect, in bounds: CGRect, size: CGSize) -> Edge {
    let gap: CGFloat = 18   // 8 间距 + 10 尾巴
    if bounds.maxX - anchor.maxX >= size.width + gap { return .trailing }
    if anchor.minX - bounds.minX >= size.width + gap { return .leading }
    if bounds.maxY - anchor.maxY >= size.height + gap { return .bottom }
    return .top
}

// 尾巴位置 = 锚点中心，收进 [22, 宽-22]
let tailX = min(max(anchor.midX - frame.minX, 22), frame.width - 22)
取值方式。用 anchorPreference 把子视图的 frame 提到父层，避免全局坐标系手算； 滚动容器里再叠一层 onScrollGeometryChange，锚点离开可视区就关闭气泡。

和上一版的差别

v3 · 系统提示条

  • 12pt 圆角矩形，中性黑 / 白底
  • 16pt 彩色圆徽章承载语义
  • 13pt 单行，11 × 13 内边距
  • 只能居中，会挡住正在看的内容
  • 动作是蓝色文字，像表单里的链接
  • 气质：系统通知

v4 · 产品气泡

  • 18pt 圆角 + 18 × 10 指向尾巴
  • 去掉徽章，语义靠标题措辞与深红
  • 14.5 标题 + 13.5 说明，16 × 18 内边距
  • 锚定元素，不挡操作；没有锚点才居中
  • 动作是半透明白胶囊，像气泡的一部分
  • 气质：产品引导

颜色：跟主题色，还是跟状态

我把八种系统强调色分别套进气泡算了一遍。结论不是“哪个好看”，而是其中一个方向在这个位置上根本不可读。

方向 1 实测：白字 + 系统强调色

同一句文案、同一个尺寸，只换底色。数字是白字的 WCAG 对比度，4.5 是正文合格线。

黑字全过，但代价是三条。第一，气泡不再有“深色实体”的重量，像贴纸。第二，用户选红强调色时，错误提示和普通提示同一个色，语义分级作废。 第三，SayAll 的品牌识别被系统设置覆盖——用户换一次主题，App 的说话就变了。 Apple 自己的边界也在这里：强调色用于控件高亮（按钮、焦点环、开关），不用于承载整块信息背景。

方向 2：按“需要的行动量”分三档，不按状态种类分

四种状态各给一个颜色会变成彩虹。真正该编码的不是“发生什么”，而是“用户要做什么”： 成功不需要行动，就不该抢颜色；错误必须处理，就该最重。

琥珀 #8A4B0F。和红色拉开色相，用户不用读字就知道“这不是失败，但要注意”。

L3 · 必须处理

错误

输入目标已改变，重新打开常用语。

深红 #5E120D（白字 13.4:1，比品牌红重一倍）+ 白色叉标记 + 不给自动消失。三处信号叠加，颜色只是其中一层。

我的建议是方向 2，方向 1 只保留一小块。 气泡底色跟状态三档；系统强调色用在动作按钮的焦点环和键盘选中态上——那里是控件层，正好符合 accent 的本职。 这样既尊重用户选了紫色或石墨，也不会让一条提示因为主题色变成读不出来的黄块。
09

需要你定的三件事

1. 颜色策略走哪个方向？

  • 按状态三档（红 / 琥珀 / 深红），accent 只做焦点环
  • 完全跟系统强调色，改用黑字
  • 只用品牌红一色，状态靠文案与结构区分

2. 错误也用品牌色吗？

  • 用深红区分 #5E120D + 叉标记
  • 完全同色，只靠标题区分

3. 引导气泡只显示一次？

  • 是，按 seenKey 记忆，关掉不再出现
  • 每次进页面都出，直到完成对应操作

确认后我再补

  • 出现动效（缩放 + 淡入 160ms）
  • 800×650 压力尺寸复验
  • 常用语面板接线（私有仓）
