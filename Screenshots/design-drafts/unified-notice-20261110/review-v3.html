通用提示样式：反色 · 居中

按你定的三条规则重做：浅色外观用黑条、深色外观用白条（与所在界面反色，形成“被强调”的直觉）； 位置只有一处——宿主内容区正中，让用户形成固定预期； 手动关闭按业务传，必须处理的错误可以不给自动消失。 另外把动作按钮拆成「语义动作 + 中心路由」，业务不写 UI、不写按钮文案。

已定：反色 已定：居中 已定：关闭策略按业务 待你确认后才开发
规则 01

反色，不跟随材质

浅色界面 → 近黑条白字；深色界面 → 近白条黑字。提示永远比所在界面更“重”，靠对比度而不是阴影被看见。

规则 02

只有一处位置

宿主内容区正中，水平与垂直都居中。侧边栏不计入；常用语面板居中于面板自身。不提供顶部/底部变体。

规则 03

关闭由业务决定

automatic(2.4s) / manual 两种。必须处理的错误传 manual，其余默认自动消失，Esc 始终可关。

两套外观，同一个组件

黑条里图标要提亮，白条里用标准语义色；两套对比度策略不能直接互换

02

位置：只有一处，居中

居中指“宿主内容区”的正中：设置页不把侧边栏算进去，常用语面板以面板自身为界。窗口大小变化时提示跟着中心走，不让用户重新找。

层级背景遮罩点击说明
信息 / 成功 无 穿透（allowsHitTesting(false)） 2.4s 自动消失；不打断正在进行的操作
警告 无 只拦截提示条本身 4s 自动；点条外可继续操作
错误 无（默认） 只拦截提示条本身 自动或手动取决于业务；Esc 可关
阻断 black 0.14 / dark 0.34 拦截全部，只响应提示条 必须确认；仅用于“当前步骤已失效，必须重做”
页内状态条 无 正常 权限缺失、兼容性降级这类持续状态；不参与浮层层级
为什么保留页内状态条，而不是一律居中浮层。 design-qa.md 第 205/208 行已经规定“自动连接失败只显示页面内错误文案，不连续弹窗”。 权限缺失这类状态会持续存在几十分钟，居中浮层既挡操作又会反复出现。它不是提示的一种位置，而是另一种东西：状态。

04

关闭策略：业务传，不写死

组件只提供两种策略，默认值按类型给，业务可覆盖。用户的手动关闭方式始终有效，不被“必须处理”剥夺。

类型默认策略用户可用的关闭方式业务可以怎么改
信息automatic(2.4)自动 / Esc / 点条外只在确有必要时改长，不建议改为 manual
成功automatic(2.4)自动 / Esc同上
警告automatic(4.0)自动 / Esc / 关闭按钮可改 manual，但要同时给动作，否则用户只能干等
错误automatic(6.0)自动 / Esc / 关闭按钮可传 .manual：必须处理的错误不给自动消失
阻断.manual确认 / Return / 遥控器 OK / Esc不可改为 automatic

✓manual 用在这些地方

  • 输入目标失效，必须重新打开面板
  • 写入失败且原数据未被修改
  • 权限被撤销，后续每一步都会失败

✕不要用在这些地方

  • “已复制”“已保存”——挡住用户几秒还不消失
  • 网络抖动这类会自动恢复的失败
  • 同一条错误重复出现：应合并计数，而不是堆三条 manual
05

动作按钮：会不会让文案变复杂

会——如果把动作当成“额外补充一句”。控制住的关键是：动作不是新增信息，而是把提示语里已经存在的“下一步”提出来做成按钮。

规则 A

一条最多一个动作

出现两个动作就说明用户在做一个决策，那不是提示，是 Sheet 或确认框。

规则 B

按钮必须是一个具体动词

「重新打开」「重试」「打开系统设置」「重新安装」。禁止「去处理」「查看」「确定」这类空词。

规则 C

找不到动词就不给动作

说明这条只是告知。给一个假动作比没有动作更糟——用户点了没反应，下次就不信提示了。

✕文案被动作拖长的写法

  • 主文案：无法写入虚拟麦克风，语音输入暂不可用，请重新安装应用后重试。
  • 按钮：去处理
  • 问题：一句话塞了原因、后果、两个动作，按钮还是空动词

✓把下一步提到按钮上

  • 主文案：语音输入暂时用不了。
  • 副文案：重新安装可以恢复，设置不会丢失。
  • 按钮：重新安装
  • 句子更短了，动作也更明确了

06

业务怎么把动作注入进来

业务只声明“要做什么”，不传 UI、不写按钮文案、不碰颜色。按钮文案、图标、样式由中心按动作类型统一给，这样各页不会长出「去处理 / 去设置 / 去修复」三种说法。

① 提示模型：动作是一个语义枚举，可空

// Sources/RemoteMic/NoticeCenter.swift
public struct Notice {
    public enum Kind { case info, success, warning, error, blocking }
    public enum Dismissal { case automatic(TimeInterval), manual }

    let kind: Kind
    let text: String
    let detail: String?
    let action: NoticeAction?      // nil = 只需知晓，条宽自动收窄
    let dismissal: Dismissal
}

// 动作是语义值，不是闭包；按钮文案由中心统一给
public enum NoticeAction {
    case reopenCommonPhrases
    case openSystemSettings(SystemSettingsPane)
    case retryLastOperation
    case reinstallAudioComponent
    case custom(id: String, title: String, perform: @MainActor () -> Void)
}

② 业务侧：一行声明，不带任何视图代码

// 常用语面板
NoticeCenter.shared.show(.init(
    kind: .error,
    text: "输入目标已改变，请重新打开常用语。",
    action: .reopenCommonPhrases,
    dismissal: .manual            // 这条必须手动关
))

// 语音设备页
NoticeCenter.shared.show(.init(
    kind: .error,
    text: "语音输入暂时用不了。",
    detail: "重新安装可以恢复，设置不会丢失。",
    action: .reinstallAudioComponent,
    dismissal: .manual
))

// 只需要告诉用户，不需要动作
NoticeCenter.shared.show(.init(
    kind: .info,
    text: "已切换到跟随系统外观。"
))

③ 中心侧：唯一的执行与文案来源

// 按钮文案只在这里定义，业务无法覆盖
extension NoticeAction {
    var title: String {
        switch self {
        case .reopenCommonPhrases:      return "重新打开"
        case .openSystemSettings:       return "打开系统设置"
        case .retryLastOperation:       return "重试"
        case .reinstallAudioComponent: return "重新安装"
        case .custom(_, let title, _):     return title
        }
    }
}

// 执行失败不静默：替换成一条新的 error 提示
func perform(_ action: NoticeAction) {
    switch action {
    case .reopenCommonPhrases:      membership.openCommonPhrases(source: "notice")
    case .openSystemSettings(let pane): SystemSettings.open(pane)
    case .retryLastOperation:       lastOperation.retry()
    case .reinstallAudioComponent:  audioInstaller.start()
    case .custom(_, _, let perform):   perform()
    }
}
键盘与遥控器。有动作时，Return 和遥控器 OK 触发动作；无动作时它们关闭提示。Esc 永远关闭（阻断类也一样，退出即放弃当前操作）。 动作执行期间按钮进入禁用态，不重复触发；执行失败由中心替换提示，不弹第二个浮层。

✕全玻璃的三个硬伤

  • 信噪比：13pt 正文压着透出来的 11.5pt 表单文字，对比度够也难读；这不是数值问题，是叠字
  • 跨版本：部署到 macOS 14，26 以下没有玻璃；同一个提示在旧系统变成另一种东西
  • 不可复现：isScreenshotHarness 会关掉 glass，设计验收和回归截图看到的不是真机效果

✓值得吸收的两点

  • 边缘高光：inset 0 0.5px white 20% + 外描边，让实心块有实体感，零成本、无版本依赖
  • 动作按钮用玻璃：macOS 26+ 把「重新打开」做成 .glassEffect(.clear.interactive(), in: Capsule())；按钮是交互元素，正合 HIG
  • 阻断场景可以真玻璃：背后已经压暗，透不出内容细节，此时玻璃不会伤可读性
结论。提示条本体不做全玻璃——它要和背景拉开距离，而玻璃的语义是融入背景，方向相反。改用 B： 实心反色 + 0.5pt 玻璃高光边；macOS 26+ 额外把动作按钮换成玻璃胶囊。这样既拿到 26 的质感，又保住 13/14/15 的一致性和截图可审计。
09

跨页面共用的约束

约束要求
唯一入口只有一个 NoticeCenter.show(_:in:)；页面不得自拼 Text + background
唯一位置宿主内容区正中；不提供顶部/底部/角落变体
单一实例同时只显示一条；新提示替换旧的，error 优先于 warning，warning 优先于 success
不抢焦点不是 Sheet，不改 first responder；常用语面板靠遥控器操作，抢焦点会让方向键失效
文字可独立读懂图标只承载语义；去掉图标仍能理解。VoiceOver 播报「错误：…」
尺寸固定字号 13 / 圆角 12 / 内边距 11×13；只有宽度跟随容器，中文不低于 12pt
不顶开布局overlay / ZStack；页内状态条除外（它本来就占位）
反色跟随外观按 colorScheme 取黑条或白条；自定义深色容器显式传 .dark，不靠局部背景猜
动作单一来源按钮文案由 NoticeAction.title 统一给，业务不能自定义（.custom 除外）
材质边界提示条本体不使用全玻璃；只允许 0.5pt 高光边。动作按钮可在 macOS 26+ 用玻璃胶囊，低版本自动回退实心
10

还剩四件事要你定

前三条影响实现细节，第四条决定要不要为 macOS 26 多做一层质感。

1. 阻断提示要不要压暗背景？

  • 要：浅色 0.14 / 深色 0.34，只用于“步骤已失效”
  • 不要：连阻断也不压暗，只靠白条本身

2. 错误的默认关闭策略？

  • 默认 6s 自动，必须处理的才传 manual
  • 默认 manual，所有错误都要用户关

3. 点提示条外部要不要关掉？

  • 要：info / success 点外部立即消失
  • 不要：只能 Esc 或等自动消失

4. 玻璃方案选哪个？

  • B：实心 + 0.5pt 玻璃高光边（推荐）
  • A：全玻璃，仅 macOS 26+ 使用
  • C：不加任何高光，保持纯实心
