# 统计周期分段控件尺寸偏小

## 复现

- 环境：macOS 26，中文浅色，设置窗口内容区 `800 × 650`，打开“统计”。
- 实际结果：“日 / 周 / 全部”虽位于 480pt 居中布局槽内，但真正的原生分段控件仍按文字固有宽度和 `.large` 高度绘制；与用户提供的系统四段参考相比，单段宽度、总高度和外轮廓都偏小。
- 预期结果：继续使用原生分段 Picker；在 macOS 26/27 使用系统 `extraLarge` 控件密度，使每段尺寸和胶囊轮廓与系统参考一致。三段控件应因选项少一项而自然更短，不能用自绘背景或非等比拉伸伪造四段宽度。

## 日志

检查同一时段的 `SayAll` / `RemoteMic` unified log，没有统计绑定、布局约束或运行时错误。截图中三个选项和选中态均完整可见，问题限定为控件尺寸提案没有作用到原生分段控件。

## 根因

`.frame(width: 480, height: 32)` 位于 SwiftUI `Picker(.segmented)` 外层，只扩大并限制了居中占位；底层系统分段控件仍使用 `.large` 的固有尺寸。因此源码里的 480pt 并不是屏幕上真实控件宽度，固定 32pt 高度还阻止系统采用新版更高的原生轮廓。

## 修复

- 保留 SwiftUI `Picker(.segmented)`，不引入 `NSViewRepresentable`、自绘胶囊、颜色或圆角。
- macOS 26/27 使用系统 `.controlSize(.extraLarge)`；macOS 14/15 保留 `.large` 回退，继续呈现各自系统版本的原生外观。
- 删除固定 32pt 高度。480pt 仅用于内容列中的居中布局，不再宣称为控件实际宽度。

## 验证

- 中文浅色 `800 × 650` 成品渲染确认：三段单段宽度约 62pt、高度约 36pt，与四段系统参考的约 60pt/段和 36pt 高度一致；控件外没有第二层背景。
- 回归门禁覆盖 `Picker(.segmented)`、macOS 26 `extraLarge`、旧系统 `large` 回退、无固定 32pt 高度，并继续禁止自定义分段控件桥接。
- 完整自动化、构建、成品校验和其他外观复核记录在 `Testing/NativeSettingsInterface.md`。
