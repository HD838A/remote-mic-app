## A 已确认的时序缺口

用户报告翻页时偶发系统音量变化。
用户还报告播放打开默认播放器，以及 Home 快捷键失效。
现场为小米遥控器和 Build 264。

日志显示，原生音量按下已被拦截。
原生松开却早于 HID 松开报告到达。
一例相差 13 毫秒；旧代码没有匹配项。
另有原生 Home 按下早于 HID 按下报告 79 毫秒。

这些通道没有统一的设备事件编号。
时间相邻只能支持时序关联，不能证明设备来源。
松开漏拦截也不能单独证明系统音量变化的全部原因。

## B 最小修复

只有已拦截的原生按下，才能拥有提前松开。
同码原生事件仍处于单一遥控器按住状态时，拦截对应松开。
HID 松开报告随后到达时，不再登记多余的松开。
未拦截过按下、重叠持有或存在旧松开时，不扩展匹配。

```sequence
遥控器 -> 宿主: HID 按下，登记预期原生按下
系统 -> 宿主: 原生按下，匹配并拦截
系统 -> 宿主: 原生松开，关闭已拦截的事件对
遥控器 -> 宿主: HID 松开，确认提前松开已消费
宿主 -> 宿主: 不留下多余松开记录
```

不增加等待、延时、轮询或按键节流。
保留原有 500 毫秒的迟到事件窗口。
停止监听时清除所有匹配和诊断状态。
新实体键盘按下会结束旧的键盘按住归属。

## C 尚未定位的部分与日志

| 场景 | 本轮处理 | 仍需确认 |
| --- | --- | --- |
| 原生按下早于 HID 报告 | 记录登记前已放行的同码按下及时间差 | 无法回收已经放行的事件 |
| Chrome Home 快捷键 | 记录配置事务的修饰键与会话层观察 | 目标 App 是否接受，以及真实 Fn 状态 |
| 全局播放键 | 记录提交和会话层观察 | macOS 最终选择哪个播放器 |

快捷键诊断只记录稳定类别和修饰键标志。
Command 组合统一标为 command_shortcut，不记录主键字母。
翻页统一标为 page_navigation；原有 Control 方向类别保留。
记录请求、硬件快照、规范化快照、逐事件标志和唯一终态。
零时间戳的诊断事件在提交前补单调时间戳。

播放按下和松开共用一次操作编号。
提交失败仍尝试松开；不声称播放器已经响应。
观察器只匹配宿主标记事件，最多保留 64 条、2 秒。
无时间戳、重复标识或观察超时都记为未知，不记为送达失败。

系统播放仍走全局媒体分发，不改为 Space。
不读取第三方 App 私有文件或接口。
这些明细留在本机运行日志，不扩大 Sentry 上传范围。
复现后需提供对应加密 rmlog，不能只依赖“发送诊断”。

## D 验证与边界

旧代码在提前松开的 4 类事件回放中产生 8 个断言失败。
候选修复通过同一回放。
覆盖音量加减、播放、Home、乱序、连续点击、到期和停止清理。
覆盖 Chrome 主页、书签、收藏及翻页配置的主键与修饰键。
配置数据格式和统一注入入口保持兼容。

自动化只证明匹配、事件构造和日志关联。
公开宿主 1046 项测试、4 项 XCTest 与 48 项自检通过。
私有组件接入公开宿主的 47 项定向测试通过。
Apple Silicon Release 构建和仓库边界检查通过。

一项发布脚本回归曾以 SIGPIPE 失败；单独及整套重跑通过。
本地测试包因缺少诊断服务配置未生成，未执行包校验。

没有在现场机器投递真实遥控器事件。
Chrome、网易云与 WorkBuddy 的最终结果仍待真实验收。

系统事件没有可靠设备来源时，仍存在同码时序匹配边界。
不通过扩大窗口或全局等待掩盖此限制。
