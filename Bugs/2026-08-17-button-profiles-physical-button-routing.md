# 键位方案实体按键未选中并触发错误音

## 复现条件

1. 打开“组合动作”中的“键位方案”页面。
2. 使用鼠标点击遥控器图片中的 TV 键。
3. 再按真实遥控器的 OK、方向键或其他已经配置普通映射的按键。

## 错误行为与正常边界

- 鼠标点击图片热点可以切换“当前按键”，说明遥控器图片热点本身正常。
- 实体按键不会更新键位方案页面当前按键，也不会在图片上显示对应选择。
- 实体按键仍执行普通按键映射；无线麦设置页前台时，部分无有效目标的键盘动作会产生系统错误提示音。
- 正常行为应为：只有四步向导的第三步“设置按键”会把实体按键作为选键输入；摘要页、其他步骤和离开页面后均正常执行当前方案。

## 日志证据

现场日志 `/Users/andy/Library/Logs/RemoteMic/runtime.log` 记录到：

```text
2026-08-16T18:40:07Z HID BUTTON button=ok trigger=singleClick action=returnKey
2026-08-16T18:40:13Z HID BUTTON button=up trigger=singleClick action=commandReturn
```

日志证明按键进入 HID 路由后仍执行了普通动作，而不是只作为编辑页选键输入。

## 根因

- `BridgeAppModel.makeHIDMonitor()` 的 `monitor.onButtonPressed` 只更新宿主的 `lastRemoteButtonPress`、遥控器 Profile 和统计，没有调用私有模块已经提供的 `noteButtonInteraction(button:)`。
- 宿主集成层没有暴露该转发入口，因此键位方案页面订阅的最近交互按键状态永远收不到真实遥控器事件。
- `onButtonPressed` 固定返回 `shouldPerformAction = true`，没有识别键位方案页面正在编辑，导致同一次实体按键继续进入原普通映射或方案动作执行路径。

## 修复范围

- 宿主转发实体按键交互给私有模块。
- 仅在第三步“设置按键”激活时，将 HID 按键路由切换为“只选择、不执行”；摘要页和其他步骤继续执行。
- 不改变普通按键页面、组合动作页面、移动端遥控或语音按键路径。

## 验证要求

- 自动化验证实体按键通知存在，第三步激活时 `shouldPerformAction` 为 `false`，摘要页及其他步骤为 `true`。
- 鼠标点击遥控器热点仍可选择按键。
- 真实遥控器在键位方案页逐一按下可见按键时，图片选择同步变化且没有错误音。
- 真实遥控器验收前，只能声明代码、模拟和构建验证通过，不能声明真机问题已验收。

## 2026-08-17 摘要页误拦截跟进

### 新复现

1. 创建自动键位方案并把网易云音乐设为目标 App。
2. 为左、菜单、OK、右等按键保存动作。
3. 保存后停留在键位方案摘要页，切换网易云音乐到前台并按遥控器。

错误行为：页面显示方案为“当前”，但动作不执行。正常边界：只有第三步需要选键，保存后的摘要页不应继续拦截。

### 日志与代码结论

现场日志没有出现对应的 `APP ACTION` 或媒体动作完成记录；代码核对确认 `SettingsView` 用整个 `.buttonProfiles` 页面激活状态设置 `isButtonProfilesPageActive`，`BridgeAppModel` 再把该状态直接传给 `shouldPerformAction`。因此摘要页和四步向导的全部步骤都被错误视为选键状态，事件在 `HIDRemoteMonitor` 执行动作前被消费。

### 根因与修复

- 根因：宿主只知道“键位方案页面是否打开”，不知道“第三步是否正在编辑按键”，拦截粒度过粗。
- 修复：私有页面只在 `draft != nil && editorStep == .buttons` 时向宿主发布编辑状态；宿主直接订阅该状态，摘要页和其他步骤不再拦截。
- 诊断：仅在第三步消费实体按键时记录 `BUTTON PROFILE input selected_only ... reason=binding_editor_active`，便于区分“已选键”和“已执行”。

### 验证边界

自动化已覆盖第三步为 `false`、摘要及其他步骤为 `true` 的路由策略；真实网易云音乐前台、真实遥控器和最终媒体结果仍需本地测试包验收。
