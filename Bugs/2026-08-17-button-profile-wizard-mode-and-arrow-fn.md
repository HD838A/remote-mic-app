# 键位方案回车、自动切换状态与方向键 Fn

## 复现

1. 编辑键位方案，在非空名称输入框按 Return，页面仍停留第一步。
2. 为 Chrome 保存自动使用规则后切到手动模式，摘要同时显示“手动”和 Chrome，但没有说明自动规则已暂停；自动模式下当前方案仍可点击“立即使用”，会无提示切成手动。
3. 录入 `Command + Option + ←/→`，摘要额外显示 `fn`，执行结果与原快捷键不一致。

## 日志与数据结论

- 运行日志没有动作执行失败；名称问题发生在页面提交事件之前。
- `button-profiles.json` 中 Chrome 规则仍启用，但遥控器选择状态为手动；现有自动模式测试确认 Chrome 精确命中和其他 App 默认回退正常，说明规则被模式门禁暂停。
- 本机私有快捷键记录中的左右方向键包含 `function`。Quartz 构造事件确认方向键会携带系统 `.function` 标记，旧转换代码无条件保存。

## 根因

- 名称 TextField 没有 `.onSubmit`。
- App 关联属于单个方案，手动/自动模式属于整只遥控器；页面没有解释两层状态，“立即使用”也没有说明会停止自动监听。
- macOS 方向键的 `.function` 是特殊键语义标记，不代表用户真实按下 Fn；录入和执行都未规范化。

## 修复

- 非空名称按 Return 复用下一步门禁；空名称保持当前步骤。
- 有 App 规则但处于手动模式时显示“自动切换已暂停”和恢复按钮；自动模式明确说明目标 App 使用专用方案、其他 App 使用默认方案。自动状态下当前方案不能重复“立即使用”，切换非当前方案明确标为“改为手动使用”。
- 新方向键录入忽略伪 Fn；旧记录在展示和执行时使用规范化修饰键，不改写用户配置文件；非方向功能键仍保留 Fn。

## 验证命令与边界

- 私有模块完整 `swift test` 通过 119 项，覆盖表单结构、模式恢复、Chrome 命中、默认回退、方向键新旧数据规范化和真实功能键保留；Release 构建通过。
- 宿主注入私有模块后完整 `swift test` 通过 228 项；自检通过 42 项协议/硬件模拟测试，仓库边界检查、Release App 构建、App 验证和 `git diff --check` 均通过。
- 代理 UI 复测确认 Return 从名称步骤进入使用方式步骤；手动状态显示暂停提示，恢复后明确显示“正在使用这些 App 时使用此方案，其他 App 使用默认方案”；旧方向键摘要不再显示 `Fn`。
- 真实 Chrome 前后台和实体遥控器最终按键结果仍需用户在本地测试包验收。
