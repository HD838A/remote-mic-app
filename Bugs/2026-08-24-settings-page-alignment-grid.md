# 设置页多套对齐基准导致元素悬浮

## 复现

- 环境：当前 macOS 深色外观，本地 `dist/SayAll.app`，设置窗口 `800 × 650`。
- 操作：以“连接”页为基准，依次打开按键、统计、回眸、权限和关于；继续把按键、统计、回眸和关于滚动到底部，核对每行标签、说明、状态、操作和分区 footer 的左右边线。
- 实际结果：
  1. 按键页顶部在普通 `GroupBox` 中使用 `LabeledContent`，开关标签被推到卡片中部；遥控器标签、状态和重连操作没有共用清晰的左右边线。
  2. 按键页底部把 HID 状态、两个开关和恢复按钮硬塞进一条横排；最小窗口下压缩明显，两个开关的说明缺少稳定归属。
  3. 统计页把页面标题“统计”重复用作周期控件的左标签，短标签和右侧分段控件之间形成大空洞。
  4. 回眸页把关闭状态做成高大的居中空状态，历史用途说明另起一条左边线；“本地 Agent 访问”又同时承担功能行标题，开关实际的“允许访问”层级没有显示出来。
- 预期结果：连接页的标签列、控件列和 section 边线是唯一基准。普通设置行必须明确左标签、右控件；整块数据和说明必须明确左对齐；只有需要强调的完整空状态才允许居中，且不能把后续说明悬在另一条边线上。

## 日志结论

复现后检查最近 20 分钟的 `RemoteMic` 统一日志。逐页切换和滚动期间没有 SwiftUI 布局约束、窗口几何、资源加载或崩溃错误；只出现正常更新检查网络事件及无关的 CoreSpotlight donation 警告。本问题是稳定可复现的静态布局错误，不是运行时状态异常。

## 代码结论与根因

1. `LabeledContent` 只有在 grouped `Form` / `Section` 的标签列环境中才会得到与连接页一致的列宽；按键页把它放进普通 `GroupBox` 后，系统按局部容器重新计算标签和值区域，形成页面中部的第三条边线。
2. 统计页第一分区已经由工具栏标题表达页面名称，却再次用同一文案作为行标签，让单一的周期筛选被拆成左右两块。
3. 回眸页的空状态使用整行居中和 116pt 最小高度，而相邻说明使用 section footer 左对齐；关闭时同一任务被视觉上拆成三块。
4. Agent 分区没有 section header，行标签使用“本地 Agent 访问”，隐藏的 Toggle 标签才是“允许访问”，所以视觉标题、功能名和说明的父子关系倒置。

## 修复

- 按键页顶部和底部的普通 `GroupBox` 行改为显式 `HStack`：标签与说明固定在左边线，开关、设备状态和操作固定在右边线；HID 状态独占左对齐信息行，恢复默认独占右对齐操作行。后续用户截图确认设备卡作为业务内容不应被压进右侧控件列，最终修复见 `2026-08-24-mapping-remote-card-width.md`。
- 统计周期选择移除重复页面标题标签，系统分段控件占满第一分区可用宽度；本机隐私说明继续作为该分区 footer。
- 回眸记录开关直接使用系统 `Toggle` 设置行；关闭/空状态改为左图标加左对齐说明的紧凑信息行，不再占用大块居中空白。
- Agent 分区把“本地 Agent 访问”提升为 section header；“允许访问”成为真实功能行标签，原说明紧跟该标签，开关保留在统一 trailing control 边线。
- 权限和关于页保留 grouped `Form` 的原生标签/控件列；权限页最大内容宽度统一为 700pt，与连接、统计、回眸和关于一致。
- 未修改任何现有用户文案或功能接线。
