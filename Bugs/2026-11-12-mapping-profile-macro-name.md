# 键位方案里的组合动作改名后仍显示旧名字

## 复现

1. 在组合动作页把已保存的动作改名（改名字会保存并生成新版本）。
2. 回到按键映射页，切到任意键位方案：该按键卡片仍显示改名前的名字；若动作是最近新建的，卡片显示「原操作已不可用，请重新配置。」，悬停提示同样如此。
3. 同一个动作在基础映射作用域显示正常，按下按键执行也正常。
4. 完全退出并重开 App 后，方案作用域的卡片恢复正确名字。

测试机为 2.0.0 (320) 本地包，遥控器为小米蓝牙遥控器 2，方案为自建方案。

## 日志与证据

- 只读检查本机数据副本：`<Macros>/library/library.json` 对同一个宏 ID 保留了 1.0.1 / 1.0.2 / 1.0.3 三条记录（每次保存 patch +1 追加，属于版本历史，`macros` 只保留最新一条）；`button-profiles.json` 里方案绑定是 `{macro: {macroID, version}}`，基础映射只存 `macroID`。
- 用 2.8.1 私有 xcframework 对同一份数据副本做离线解析：把宏库裁到只剩最早一条版本时，电源键得到 `source=unavailable`「原操作已不可用，请重新配置。」、主页键得到最早那条的名字，与截图逐字一致；换回当前宏库并 `reload()` 后分别恢复为「2」和「一键三连2」。证明绑定没坏，是读到的是旧快照。
- 私有包资源 `profile.binding.unavailable`（方案绑定文案）与运行期弹窗 `macro.action.unavailable` 共用同一句中文，所以"解析不到"看起来像"动作被删除"。
- 结构原因：键位方案组件（`RemoteMicButtonProfilesController`）自己持有 `MacroLibraryStore`，`reload()` 会重读，但 `SayAllButtonProfilesFeature` 没有对外暴露刷新入口；组合动作组件是另一个实例，改名只刷新自己那一份。宿主没有文件监听，也没有在进入按键页时重载。

## 根因

两处宏库快照互不通知。按键页在方案作用域优先使用方案组件的 `resolvedBindingText`，而它只在启动时读过一次宏库；组合动作改名或新建后它仍是旧内容，命中不到就退化成「原操作已不可用，请重新配置。」。

运行期不受影响：统一配置下宿主用宏 ID 调组合动作组件执行，用的是最新定义，只有显示文案来自旧快照。

## 最小修改

- 方案作用域的组合动作不再使用方案组件文案，改按宏 ID 从组合动作组件的 `libraryActions`（宏库当前内容）现取名字；取不到时用宿主既有文案「组合动作不可用，请重新选择」，与基础映射一致。
- 其余动作（快捷键、打开 App、内置动作）继续用方案组件文案，和键位方案页逐字一致。
- 不改私有组件、不改绑定文件格式、不改运行期执行路径；旧私有组件缺失相关 API 时行为不变。

## 验证

- 新增 `ProfileMacroTitleTests` 4 例：改名后取当前名字、动作缺失回落宿主文案、绑定缺宏 ID 回落、按稳定 ID 而非名字匹配。
- `swift build --disable-keychain` 通过；公开全量 `swift test --disable-keychain` 1347 项通过。
- 未验证：实体遥控器复测、"宏库被其他进程改写"后的自动恢复、正式 Developer ID 签名本地包。
- 真实运行验证（本机）：用私有仓 2.9.0 源码在本机重建 XCFramework（Xcode 26.5 / Swift 6.3.2），经 `scripts/build-app.sh` 出包并启动后实测——在组合动作页改名保存，不重启回到按键页的键位方案作用域，主页键单击格立即显示新名字，"退出重开"不再是恢复手段。
- 打包链路阻塞（与本修复无关，但会挡住所有人的本地包）：`scripts/prepare-private-artifact-package.sh` 未跟上私有平台 2.9.0 新增的 `SayAllHostBridge`——产物清单、provenance modules、解压循环和生成的 `Package.swift` 目标四处都缺，官方准备流程必然失败；本机验证包是在仓库外临时补齐后打出的，需要单独 PR 修。

## 遗留

跨进程场景仍会旧：另一份安装包、测试包或配置恢复流程写同一个宏库目录时，本进程两处快照都不会重读。彻底解决需要键位方案组件暴露「只重读宏库」的接口（`RemoteMicButtonProfilesController.reload()` 已存在，只差 feature 层转发），由宿主在进入按键页时调用；该项属于私有仓工作，不在本修复范围。

该接口与宿主接入已在 [`2026-11-12-profile-macro-library-refresh.md`](2026-11-12-profile-macro-library-refresh.md) 落地：组件侧广播宏库变化通知并提供 `reloadMacroLibrary()`，宿主在进入按键页和键位方案页时调用。
