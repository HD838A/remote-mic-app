# 1.9.0 内测版 OK 键偶发无响应且日志无法定位

- 时间：2026-08-19
- 状态：诊断增强完成，等待 RC003 真机复现并确认根因
- 影响范围：macOS 1.9.0 内测候选；实体小米遥控器 OK 键
- 功能点：IOHID 报告接收、设备路由、按键解析、手势识别与动作执行
- 简单描述：用户偶发按下 OK 键后没有任何动作；当时语音链路仍可使用，但旧日志只在动作执行后记录 `HID BUTTON`，无法判断事件丢在哪一层。
- 原始记录：用户提供的 1.9.0 内测日志与截图

## 复现与观察

- 现场尚未在开发机稳定复现；缺少同一只 RC003、同一系统权限历史和故障发生时的实时 IOHID 回放条件。
- 用户故障期间仍能使用遥控器语音，说明蓝牙 ATVV 语音链路可用，但不能据此证明 macOS HID 报告链路也正常。
- 对应时段没有 `HID BUTTON button=ok`。旧实现只有动作成功或进入动作执行时才写该日志，因此“没有记录”可能发生在系统回调、设备过滤、报告解析、按下边沿、手势状态机或动作前置检查中的任意一层。

## 代码检查

`Sources/RemoteMic/HIDRemoteMonitor.swift` 的生产路径依次为：

1. `hidInputReport` 收到 IOHID 回调；
2. `handleReport` 检查监听状态、映射开关、设备位置、指纹路由和运行时权限；
3. `RemoteHIDReportParser` 解析 report ID 与 payload；
4. `process` 计算按下/松开边沿；
5. 原始单击或 `RemoteButtonGestureRecognizer` 产生手势；
6. `performConfiguredAction` 执行动作并写入旧的 `HID BUTTON` 日志。

修复前第 1～5 层的大多数拒绝分支都静默返回，现有日志不足以确认具体失效层级。

## 根因判断

目前只能确认“现场没有走到既有 OK 动作日志”，不能确认是遥控器固件未发 HID 报告、IOHID 回调未到达、设备路由拒绝、解析失败、边沿状态卡住还是动作前置检查失败。没有真实 RC003 复现证据前，不把任何一种假设写成已确认根因，也不调整按键阈值、设备抢占或手势行为。

## 诊断增强

- 为 IOHID 回调失败记录 `callback_rejected` 与错误码/报告长度。
- 为监听状态、设备位置、指纹路由、设备激活和运行时权限的每个拒绝分支记录明确 `reason`。
- 报告解析成功时只记录来源、report ID、长度、usage 数量和标准化按键名；解析失败记录 `parse_failed`。
- 记录按下/松开边沿、手势产生路径和动作执行失败层。
- 不记录原始报告字节、蓝牙地址、设备指纹、唯一标识、按键映射参数或用户输入内容。
- 不改变 HID 报告解析、设备选择、按键阈值、手势时序、系统事件抑制或动作执行逻辑。

## 验证

- `swift test --filter RemoteButtonsTests`：84 项通过，包含所有指纹路由拒绝原因测试。
- 使用全新 SwiftPM 构建目录和私有硬件模拟依赖运行完整测试：322 项、30 个 Suite 通过；其中覆盖 OK press/release 的报告、边沿、手势和动作日志，并检查日志不含原始 payload 与模拟设备指纹。
- `git diff --check`：通过。

## 真机边界

自动化只证明每个软件层能够产出可区分且脱敏的诊断记录，不能证明 RC003 固件一定发送报告，也不能证明 macOS IOHID 在现场没有丢回调。下一次真实故障需保留完整 `runtime.log`，按 `Testing/HIDIntermittentButtonDiagnostics.md` 对照最后到达的层级后，再决定是否需要行为修复。
