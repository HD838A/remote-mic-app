# 语音键回归缺少映射、Fn 观察与构建来源证据

- 时间为 2026-11-10。
- 现场记录为 Intel、macOS 14、build 320。维护者报告重装 build 289 后恢复语音输入。
- 已提供的加密日志中，build 320 的 26 段宿主音频会话正常排空，解码、路由、调度与播放计数逐段一致。
- 两版记录均有 Fn 观察缺失，第三方采集和文字结果为 unknown。原日志无法据此定位版本回归。

## 已确认的诊断缺口

原始遥控器报告只显示未知普通键集合，无法区分文档已知的 F5 与 i 语音 usage。映射组件只记录写入返回值，未区分回读匹配。原生 Fn 观察依赖 AppKit 全局监听，SayAll 自身前台窗口存在观察边界。启动环境和复制诊断没有带出产物已有的源码 Commit 和私有依赖版本。

这些缺口不能证明某项映射必然失败，也不能把宿主播放成功解释为目标工具已生成文字。语音回归的根因保持待验证。

## 诊断补充

- 启动头和复制诊断从当前包读取源码 Commit、构建通道、dirty 标志和私有平台版本。缺少或无效字段写 unknown，运行时不读取 Git。
- 遥控器报告只分类已知 F5 和 i 的按下与松开边沿，重复报告去重。分类不改变映射、动作或语音生命周期，不输出原始报告与任意键内容。
- 映射写入后回读 F5 条目，单独输出匹配结果。回读结果只用于诊断，沿用既有成功、失败和回滚判据。
- 复用现有 session event tap 的 Fn 观察，只接受 Fn 的 flagsChanged，排除本 App 标记的合成事件和方向键 Fn 标志。时间戳通过既有锁读取，停止或 tap 失效时清空。
- 每段语音关联映射操作号、模式、触发路径、服务数量、回读结果和事件 tap 状态。终态保留 Fn 观察来源及最近按下年龄，防止下一会话的松开被归到上一会话。

观察到的 Fn 事件无法归属具体物理设备，也不证明目标工具收到。日志保留 session_tap_unattributed、target_response=unknown、transcript_commit=unknown 与 external_capture=unknown。

## 验证与边界

自动化覆盖元数据缺失和换行拒绝、写入成功但回读不一致、正常回读、无服务、语音 usage 边沿去重、排除导航及宿主合成 Fn、监听复位、快速会话隔离和单一终态。现有映射事务、输入源和语音完整性测试继续回归。

验收入口为 `Testing/RuntimeLogging.md` 的语音键诊断用例。工作站验证只承担编译、模拟事件和脱敏断言。Intel 真实 Fn、首尾字、连续会话和第三方文字上屏需现场记录。此次只补诊断，未将回归标记为修复。
