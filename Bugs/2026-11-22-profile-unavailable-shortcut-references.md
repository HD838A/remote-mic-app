# 键位方案引用失效时显示「配置不可用」且按键变成死键

- 时间：2026-11-22
- 影响范围：包含自动保存接口的键位方案组件；按键页、Siri Remote 画布和方案覆盖执行
- 简单描述：方案仍在，但它引用的本地快捷键/组合动作/宿主动作已不存在。按键页把每条失效引用都显示成笼统的「配置不可用」，执行路径同时把该按键置为不执行；用户既不知道缺了什么，也无法直接修复。

## 证据

- 另一台 Mac 的 2.0.9 build 424 日志显示设置加载正常，没有方案文档解码失败、导入或恢复事件；按键执行日志反复出现 `BUTTON PROFILE button=back ... binding=missing result=delegated_to_unified`。
- 同一台机器的生产界面截图显示：方案页每个单击格是「这个快捷键在本机不可用」；按键页把同一批绑定显示成「配置不可用」，并出现在多颗普通按键和按住摘要上。
- 隔离复现：加载旧版方案并移除其快捷键库后，所有引用该快捷键的格子立即变成「配置不可用」，按住摘要也一起变化；保留快捷键库时相同方案全部解析成功。
- 本机旧方案备份中的 31 个快捷键引用在当前快捷键库中全部存在，说明旧方案格式本身没有被废弃；失败来自引用目标缺失或解析失败。
- 代码路径：私有 `RemoteMicButtonProfilesFeature.displayBinding` 把 `bindingText.source == .unavailable` 压成 `.unavailable`，丢弃组件已有的具体文案；宿主 `mappingActionSummary` 和 `mappingActionDetail` 再统一显示 `button_mapping.save.unavailable`。
- 执行路径：`MacroFeatureIntegration.profileBinding` 对缺失快捷键返回 `.disabled`，覆盖基础映射；物理按键因此不会执行任何动作。
- 2026-11-22 现场补充：受影响 Mac 在 2.0.10 build 429 导出的完整配置包含 7 个方案、57 个可显示绑定和 7 个方案内的 25 条快捷键引用；引用的 7 个抖音快捷键和全部 25 个定义都在本机快捷库中。把导出文件按原目录结构加载后，走公开宿主同一条 `MacroFeatureIntegration.displayProfileBinding` 通路，57 个绑定全部解析、0 个失效。说明这份配置的数据本身完整，界面上的失效提示来自运行期快照不一致或修复前的旧状态，而不是导出文件缺少定义。

## 根因

1. 失效引用同时承担三种不同状态：方案文档读取失败、引用目标缺失、宿主 payload 无法解码。宿主只显示一个笼统文案，无法区分。
2. 失效引用被当成显式「不执行」，覆盖了仍然可用的基础映射，导致按键变死键。
3. 编辑区对 `.unavailable` 禁用写入，用户只能清除覆盖，不能直接重新选择动作。
4. `loadProfilesSynchronously()` 只读方案文档，却同时把 `hasSuccessfullyLoadedContent` 置为 true；快捷库快照仍为空时，所有 `.shortcut` 引用都会被判为失效，而 host 绑定正常。截图、测试和写失败后的 `reloadMappingProfiles()` 都会走到这条同步入口。

## 修复

- 执行与显示统一回退基础映射：`profileBinding` 对缺失快捷键、已删除组合动作、失效 focus 目标和无法执行/解码的宿主 payload 返回 `nil`，由基础映射继续执行；宏库初次加载完成前不把尚未读到的宏误判为已删除。
- 按键卡片显示实际执行的基础动作，并在动作前显示橙色警告图标；继承项继续使用链接图标。悬停和编辑区显示具体原因「本方案引用的快捷键或动作在本机不存在，已回退基础映射：<动作>」。
- 允许直接替换失效覆盖；保留单键「恢复继承默认」。
- 新导入方案时把快捷键定义内联为自包含 host 动作，导入完成后不再依赖本机快捷库里是否还留有同 ID 定义。
- 启动重载时按方案缺失的原始快捷键 ID，先从 transfer-history 恢复；历史没有时，再从 sayall-market 已发布快捷键目录恢复。无法识别的 ID 明确记录 `result=unavailable`，不静默失败。
- 同步加载方案时一并刷新快捷库；快捷库读取失败则整次加载失败，不留下“方案已加载、快捷库为空”的半状态。
- 方案作用域显示汇总提示：`本方案失效引用：N 个`，提供一次清除全部失效覆盖的入口；部分失败时显示剩余数量。
- Siri Remote 私有画布新增与共享画布相同的 `actionConfigured`/`actionSource` 语义，已配置动作使用主题色、继承项显示链接图标、失效项显示警告图标。
- 新增脱敏日志 `BUTTON PROFILE REPAIR ... action=clear_unavailable`，只记录数量、终态和原因码。

## 验证

- 公开模式 `swift build --disable-keychain` 通过。
- 私有源码 `SAYALL_ENABLE_PRIVATE_SWIFTPM=1` 构建通过，Siri Remote 画布新接口被宿主探测并编译。
- 新增回归：缺失快捷键、不可执行宿主 payload 和失效 focus 目标时 `profileBinding` 返回 `nil`；按键页包含具体回退文案、警告图标和批量清理入口；Siri 画布来源闭包与共享画布一致。
- UI 截图用生产 `SettingsView` 离屏入口渲染方案失效、部分可用和非会员状态；截图只证明静态界面，不证明真实快捷键恢复或目标 App 响应。

## 未覆盖边界

- 对既不在 transfer-history、也不在 sayall-market 已发布目录中的本地随机 `shortcut.*` ID，无法凭空重建定义；这类方案仍需重新录制、重新导入带依赖的方案，或清除覆盖回退基础映射。
- 现场导出配置已在宿主显示通路验证 57/57 解析，但 430 签名包的真实窗口截图、真实快捷键执行和第三方 App 响应仍需现场验收。
- 两台真实遥控器、第三方 App 目标响应和 Siri Remote 实体画布仍需签名包与真实设备验收。
- 组件的 focus 引用缺失仍依赖组件文案；公开宿主无法在旧构件上取得 focus 目标是否存在。
