# 键位方案的旧快捷键引用在换机或迁移后失效

- 时间：2026-11-22
- 影响范围：2.0.8 及更早版本创建的键位方案；旧版导入或手工迁移的方案
- 简单描述：方案绑定只保存本机快捷键 ID，快捷键的键码和修饰键另存在本机快捷键库。方案被复制到另一台 Mac、旧版导入未带快捷键定义，或本机快捷键库丢失时，引用无法解析，按键页显示「这个快捷键在本机不可用」。

## 证据

- 2.0.9 build 412 日志：设置和方案加载正常，但按键执行出现 `BUTTON PROFILE ... binding=missing result=delegated_to_unified`。
- 2.0.2 build 322 日志已有相同 `binding=missing`，说明不是 2.0.9 新引入；2.0.9 把原本静默失败的引用显示出来。
- 2.0.8 和 2.0.9 的 `MappingProfileBinding` 对用户新录制或重新选择的自定义快捷键都写入自包含 host payload，包含 `keyCode`、`modifierFlags` 和 `keyLabel`。
- 旧格式 `.shortcut(profileKey:)` 只保存本机快捷键 ID；键码定义在 `private/local-automation-profiles.json`，与方案文件 `button-profiles.json` 分离。
- 方案导出和完整备份路径会把引用到的快捷键定义放进包，导入缺依赖会拒绝；但旧方案、手工复制的方案文件和旧版导入仍可能留下悬空引用。

## 根因

旧方案绑定把「本机快捷键库 ID」当成动作本身。方案文件具有可迁移性，但快捷键 ID 没有跨机语义；本机快捷键库缺失或未一起迁移时，引用无法解析，执行和显示同时失效。

## 修复

- 控制器每次变化（含初次加载和导入完成）后，扫描可编辑方案里的 `.shortcut(profileKey:)` 绑定。
- 能解析的引用改写为自包含 host 动作，写入同一方案；显示的快捷键文本保留修饰键；以后换机、重装或复制方案文件不再依赖本机快捷键库。
- 不能解析的引用保持原样，继续显示警告，不静默删除用户意图。
- 只迁移可编辑方案；默认方案、非会员只读方案和预览状态不写入。
- 写入前重新读取磁盘方案，避免在导入提交后、控制器异步重载前用旧内存文档覆盖新方案；导入进行中或保存中不迁移。
- 每个会话对同一绑定最多迁移一次；写入失败不会被自身触发的变更事件无限重试，下次启动再试。
- 每个绑定通过私有组件的正常写入接口保存，保留 before-save 快照。多绑定迁移会生成多条快照，这是当前已知代价。
- 新增脱敏日志 `BUTTON PROFILE MIGRATION operation_id=... phase=completed result=passed|partial|failed`，只记录方案数、候选数、成功数、未解析数、失败数和原因码。

## 验证

- 公开完整测试 1637 项 / 114 suites 通过；公开模式构建通过。
- 私有源码构建通过；定向 37 项通过。
- 定向测试覆盖：可解析旧引用变为 host 动作且显示名保留修饰键；缺失引用保持不变；重复迁移不改变 payload；2.0.8 自包含自定义快捷键保持不变；方案导出包含快捷键定义，缺定义时拒绝导出。
- 真实快捷键库、真实遥控器和目标 App 仍需签名包与现场验收。

## 未覆盖边界

- 已删除的快捷键定义无法自动重建；用户必须重新录制或导入带快捷键定义的包。
- 只读、非会员和默认方案不写入，继续保持原有只读行为。
- 迁移不会改变方案名称、按住设置或其他动作字段。
