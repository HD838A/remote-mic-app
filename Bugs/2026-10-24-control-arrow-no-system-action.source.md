## 现象与证据

RC003 下键绑定 Control + Up 后，调度中心没有打开。
同一 Mac 的实体键盘组合可以打开调度中心。

2026-10-24 19:35 的现场版本为 2.0.0 build 251。
保存值为方向上键和 Control，未带 Fn。

5 次触发各提交 4 个事件；另 5 次被 600 ms 防抖拒绝。
日志未报告构造失败，但不能证明系统执行了动作。

## 根因与本次范围

首次无效的根因尚未确认。Fn 扩展属性只是待验证假设。
旧日志缺少逐事件属性，以及系统会话监听点的观察证据。
本次仅补诊断，不改变快捷键标志、顺序、时序或防抖。

无系统投递的最小实验显示：默认方向键事件带 Fn 属性。
现行序列覆盖该属性，只保留 Control 与 NumericPad。
此差异尚未通过现场对照证明为故障原因。

```flow
遥控器下键 -> HID路由: 已有按键与拒绝日志
HID路由 -> 合成事件: 请求及逐事件属性
合成事件 -> 会话监听点: 记录实际事件属性
会话监听点 --> 系统动作: 仍需人工观察
```

## 新日志与判断

只追踪已配置的 Control 方向键，不采集实体键盘内容。
请求记录方向分类、修饰标志和硬件快照的规范化结果。
投递记录事件类型、生成属性、最终属性和提交结果。

会话观察只记录本进程标记的 Control 方向键。
时间戳有效且唯一时，观察日志关联操作号。
时间戳缺失、变化或重复时，关联状态为 unavailable。
此时仍可判断事件到达，不把相邻操作强行配对。

观察记录实际属性、与预期是否一致及放行结果。
只有成功关联时，才比较预期属性。
登记最多保留 64 项，超过 2 秒不再匹配。

监听器记录启动失败、停用和恢复请求。
缺少观察日志不能单独证明 WindowServer 拒绝。
已观察也不代表调度中心打开，用户结果仍为 unknown。
