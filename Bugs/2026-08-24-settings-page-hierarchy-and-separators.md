# 设置页说明归属、分区边界与垂直顺序不一致

## 复现

- 环境：当前 macOS 深色外观，本地 `dist/SayAll.app`，设置窗口 `800 × 650`。
- 操作：以“连接”页为基准，依次打开按键、统计、回眸、权限和关于页，核对每段标题、功能行、状态、操作和说明文字所属的视觉分区。
- 实际结果：
  1. 按键页顶部把总开关和遥控器状态放进一个外层 `GroupBox`，设备状态内部又有自定义圆角描边，形成双重边界和不对等的视觉重量。
  2. 统计页把周期筛选、两张图、排行和分享分别包装为连续卡片，本机隐私状态表现为绿色功能状态，而不是筛选分区的说明。
  3. 回眸页把记录隐私、空状态说明、功能说明和 Agent 隐私分散在不同卡片内外，底部功能说明看起来不属于任何功能。
  4. 权限页把升级后的授权说明放进权限卡，视觉上成为第四个权限项目。
  5. 关于页把当前版本、检查动作、更新状态和版本历史拆成数条缺少标签列关系的行。
- 预期结果：不改现有文案；按连接页的原生设置层级，让功能使用系统行，说明使用对应 `Section` footer，业务内容只保留必要的一层容器，并让同一任务的状态和操作共享同一标签/操作关系。

## 日志结论

复现后检查最近 15 分钟的 `RemoteMic` 统一日志。五个页面均可切换，没有 SwiftUI 布局、资源加载或崩溃错误；日志只有正常的更新检查网络事件与无关的 CoreSpotlight donation 警告。本问题属于稳定可复现的静态信息层级偏差，不是运行时状态异常。

## 代码结论与根因

1. `statisticsPage` 和 `transcriptHistoryPage` 仍通过自定义滚动页加多层 `GroupBox` 组织内容，没有沿用连接页的 grouped `Form` 与 `Section` footer。
2. `UsageBarChart`、`voiceSessionRankingCard` 和 `TranscriptAgentAccessSection` 自带外层 `GroupBox`，父页面再给它们增加卡片，导致每个模块都争夺最高视觉层级。
3. `permissions.upgrade_identity_help` 与真实权限行处在同一个 `Section` 内容闭包中，所以系统自动把说明渲染成列表项目。
4. 关于页的更新按钮和状态是未标记的独立 `HStack` / `VStack`，没有与“当前版本”或“新版本内容”建立原生标签列关系。
5. 按键页设备空状态和设备卡自己绘制描边，再嵌入顶部 `GroupBox`，造成双重毛边。

## 修复

- 按键页顶部保留一个原生 `GroupBox`，内部固定为“启用自定义按键功能”和“遥控器”两条 `LabeledContent` 行；移除设备空状态和设备选择项的额外描边，遥控器关系图仍是页面唯一主要业务可视化。
- 统计页改为 grouped `Form`：周期选择是第一分区功能行，“数据仅存本机”作为 footer；两张图共享一个数据分区，排行与分享各自位于后续分区。图表和排行图标缩为 24pt 语义图标，不再各自包裹 `GroupBox`。
- 回眸页改为 grouped `Form`：记录开关、空状态/历史、本地 Agent 访问分别进入系统 `Section`；记录隐私、历史用途和 Agent 隐私分别贴在所属分区 footer，不再悬空；Agent 标题、说明、开关和授权列表共享同一分区。
- 权限页把升级后的授权说明移到“所需权限” footer，不再占用权限行。
- 关于页把版本号、检查更新和重新检查并入“当前版本”行；当时曾把更新状态归入“新版本内容”行，后续用户截图确认这仍然混淆了检查结果与更新日志。最终修复见 `2026-08-24-about-update-status-release-notes-hierarchy.md`；版本历史继续使用系统前进指示的导航行，常规检查更新不使用突出蓝色按钮。

## 后续视觉复核

后续真实截图检查确认：本轮虽然修正了说明归属和分区边界，但按键页普通 `GroupBox` 内的局部标签列、统计页重复标签以及回眸页居中空状态仍产生多套对齐基准。因此本文件中的“没有悬空说明”只代表分区归属通过，不能作为最终对齐验收。后续修复与新的视觉门禁见 `Bugs/2026-08-24-settings-page-alignment-grid.md`。
