# Cursor 切换后焦点回到代码编辑器

## 复现与原因

用户反馈 Agent 切换正常，但 Cursor 会进入文本编辑器。2026-09-10 本机原生 UI 复现：聊天输入框已经聚焦时再次发送保存的 ⌘L，聊天区隐藏、焦点回到编辑区；再发送一次又显示聊天框。原来的单次切入验证没有覆盖此切换行为。

此外，Cursor 的 Electron 输入框有时忽略 AXFocused / AXPress 请求。只找到输入元素或提交快捷键不能证明已经聚焦。

## 修复

仅对 Cursor 保存的 ⌘L 聚焦配置启用专门路径：先识别当前窗口的聊天输入框并直接聚焦。候选要求可见 AXTextArea，并具有聊天语义或邻近的占位提示、Agent 模式及模型选择控件；排除代码编辑器、搜索、终端和密码输入。不会因窗口标题包含这些词而误排除聊天框。

找到聊天框但未确认焦点、或暂时找不到聊天框时，都只重试辅助功能识别，绝不自动发送 ⌘L。用户再次复现了早期“一次快捷键兜底”会关闭已打开聊天框，因此该兜底已删除。Electron 忽略 AX 聚焦时，使用该聊天框当前坐标及系统命中测试确认点击目标，恢复鼠标位置，并在后续重试中验证真实焦点。请求已过期或前台已改变时不点击、不发送快捷键。只打开、自定义其他快捷键及记录输入框的方式保持原有配置语义。

只使用公开辅助功能与系统输入 API；不读取输入框 AXValue，不记录草稿或聊天内容。

## 验证

- 原生 ⌘L 连续切换复现失败行为；回归测试先红后绿，覆盖可见框重复聚焦、不确定焦点不切换、识别失败也绝不发送切换快捷键，以及编辑器/搜索/终端排除。
- `swift test --disable-keychain`：509 tests / 44 suites 通过。
- `SKIP_SWIFT_PACKAGE_BUILD=1 ./scripts/test.sh`：44 passed / 0 failed。
- `CONFIGURATION=debug ./scripts/build-app.sh`：本机构建通过。
- 08:16 UTC，同一运行实例的切换器预览两次连续选择 Cursor，聚焦操作 5、7 均记录 `method=cursor_composer` 成功，没有发送 ⌘L；可见辅助功能分别确认聊天输入框获得焦点。
- 已撤回的中间版本在 08:17 UTC 曾用一次 ⌘L 打开聊天区；用户随后确认仍会关闭已经打开的聊天区。此证据推翻“AX 找不到就代表隐藏”的假设，最终版本彻底移除自动 ⌘L，不再声称可以自动打开隐藏聊天区。
- 较早的一次运行遇到界面更新期间聚焦超时，保留失败日志；不将所有动态界面状态宣称通过。没有输入或提交测试消息。

仍需用户实际遥控器重复切换、第三方 App 冷启动、多窗口、多屏和非英文 Cursor 布局验收。当前识别依赖公开 AX 控件结构，未来 Cursor UI 变化可能需要更新匹配。

聊天区确实隐藏时，最终版本只激活 Cursor 并报告聚焦失败，保留界面状态；需先在 Cursor 显示聊天区或使用明确记录的输入框配置。此边界优先避免关闭用户当前聊天。

最终不发送 ⌘L 的版本于 08:22 UTC 重建并打开，遥控器保持连接；509 项测试及 44 项自检通过。本机最后一次预览中 Cursor 的活动内容发生变化、未确认聊天聚焦，保留为验证缺口；该版本的关键保证由生产分派回归测试验证：即使连续八次识别失败也不发送切换快捷键。
