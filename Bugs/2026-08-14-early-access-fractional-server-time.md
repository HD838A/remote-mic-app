# 内测邀请码兑换成功但客户端无反应

- 时间：2026-08-14
- 状态：已修复，本机源码包已验收，等待 Developer ID 预览包与用户验收
- 影响范围：包含旧版 `sayall-ai` 或 `sayall-macro-platform` 的 macOS 内测包
- 功能点：使用共享资格客户端的私有内测功能
- 简单描述：服务端已成功兑换邀请码，但客户端把带小数秒的 `server_time` 判为无效响应，既不保存资格也不展示错误。

## 复现

在 `Remote Mic 1.8.17 (109)` 的“关于 → 快捷指令内测”输入有效体验码并点击“验证并加入”。页面清空输入框，但没有成功状态，侧边栏也不出现“快捷指令”。重启 App 后仍无资格。

正常行为应为：服务端授权通过后，本机完成验签并保存 `grant-bundle`，页面显示资格有效，侧边栏立即出现入口；重启后从本机资格恢复。

## 日志与证据

- 线上 D1 记录同一 Mac 的 `grant.redeemed`，资格状态、批次和远程开关均有效。
- 应用专用 Keychain 只有兑换前创建的 `anonymous-device-id`，没有 `grant-bundle`。
- 生产响应的 `server_time` 格式为带小数秒的 ISO 8601，例如 `2026-08-13T17:34:56.359Z`。
- 客户端原实现只调用默认 `ISO8601DateFormatter().date(from:)`；当前 macOS 无法解析该格式，导致 `EarlyAccessClientError.invalidResponse`。
- 页面未展示 `lastErrorCode`，运行日志也没有资格失败记录，因此用户看到的是“没有反应”。

## 根因

客户端测试夹具使用不带小数秒的 `2026-08-12T00:00:00Z`，没有覆盖生产 Worker 返回的带小数秒格式。两个私有内测模块使用相同的响应解析逻辑，因此共享该缺陷。

## 修复

- 两个私有模块优先使用 `.withInternetDateTime + .withFractionalSeconds` 解析，保留无小数秒格式作为兼容回退。
- 快捷指令邀请码页面展示明确的失败状态，避免再次无反馈。
- 两个资格控制器记录脱敏的成功或失败日志，只包含错误码和请求编号，不记录邀请码、匿名设备 ID、刷新凭据或授权令牌。
- 两个模块增加生产格式回归测试；快捷指令同时验证旧格式兼容。

## 验证

- 修复前：真实生产响应在日期解析阶段失败，无法进入验签和保存。
- 修复后：同一生产响应完成日期解析、Ed25519 验签、应用专用 Keychain 保存及重新读取。
- 已执行最小相关测试：两个私有内测模块各 2 项客户端测试通过。
- 两个私有模块全量测试分别通过 34 项和 23 项；宿主 App 注入两个模块后的 222 项测试全部通过。
- 宿主 Release 构建、`verify-app.sh`、42 项项目自检、仓库边界检查和三个工作区的 `git diff --check` 全部通过。
- 已在当前 Mac 启动本地构建包验证生产服务：无效码立即显示明确错误；已兑换的有效资格立即显示“资格有效”并出现快捷指令侧边栏；完全退出重启后资格恢复；“重新检查资格”成功。
- 系统日志只出现资格错误码和请求编号，没有输出体验码、匿名设备 ID、刷新凭据或授权令牌。

## 验证边界

服务端真实响应、本机 Keychain 链路和快捷指令邀请码页面已经由代理在当前 Mac 验证。另一私有内测模块已通过相同生产响应格式的包内回归测试和宿主注入测试，但本轮没有独立有效邀请码可执行其完整页面兑换。当前本地 App 为 ad-hoc 签名，不能替代 Developer ID 签名、公证、覆盖安装和用户真实操作；预览版必须重新使用 Developer ID 构建并完成相同资格回归。
