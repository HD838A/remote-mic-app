## 现象与证据

Build 265 在另一台 Intel Mac 发生按键泄露。
音量减配置为逗号时，系统音量也减少。
快速按 TV 键时，输入框出现圆点。
现场日志记录 macOS 主版本 14、x86_64 和 Xiaomi 设备家族。

| 观察 | 原生按下 | HID 拦截登记 | 差值 |
| --- | --- | --- | --- |
| 音量减 sys1 | 01:11:52.762 | 01:11:52.964 | 约 200 ms |
| TV key50 | 01:14:17.828 | 01:14:18.075 | 约 246 ms |

日志来自用户提供的会话 40E9F781。
相关字段为 source_correlation=timing_only。
时间相关不能替代同次事件的跨接口唯一标识。
日志另有 result=already_passed_through。

独占打开返回 0xe00002c1，即 kIOReturnNotPrivileged。
随后 App 使用 monitored 模式。
输入监控和辅助功能启动记录均为 true。
此返回码不能直接解释为用户没有勾选权限。
过滤器停用记录集中在重建周围。
现有证据未证明它导致上述两次泄露。

## 根因与提交对照

系统原生事件可以先于主线程的 HID 报告到达。
现有过滤器只在 HID 登记后拦截。
因此，它不能追回已放行的按下。
TV 原先还晚于报告日志和配置回调才登记。

| 提交 | 改动与结论 |
| --- | --- |
| #731，8e035785，合并 8483c6ed | tap 改为专用线程，HID 仍在主线程；是主要回归候选 |
| #744，7a6fe541 | 处理原生事件晚到，未覆盖首次原生按下先到 |
| #760，78a51763 | 处理原生松开先到，未覆盖首次泄露 |
| #763，c1f6b1d2 | 放行已泄露按下的重复和松开，防止持续调音量 |
| #764，48b87198 | 固定私有组件版本，没有改变上述时序 |

七版原始过滤器共完成 56 个进程内观察。
v1.9.21 至最新主线均会放行登记前的原生按下。
这说明算法缺口早已存在。

受控实验将主线程处理延后 250 ms。
同线程安排先登记，分线程安排先放行。
TV 和音量的四项观察均符合该机制。
缺少现场前后版本 A/B，不能认定 #731 是唯一原因。
不可将 tap 移回主线程，避免恢复系统输入停摆风险。

## 候选修复

接受遥控器报告前，先设置设备级 UserKeyMapping。
映射只作用于精确 VID/PID 匹配的遥控器服务。
普通电脑键盘不在匹配范围内。
原始 HID 报告继续驱动用户配置的动作。

| 设备家族 | 接管范围 | 语音边界 |
| --- | --- | --- |
| Xiaomi | 会产生原生事件的全部普通键，包括 TV、音量、方向和电源 | 保留既有 Fn 映射 |
| Siri Remote | 已批准普通控件的标准别名和实际输入元素 | 排除 Siri、语音和触摸输入 |
| Chromecast | 普通键的标准别名和实际输入元素 | 排除独立语音入口 |

手机、手表、小程序和 Mac Remote 不通过此物理 HID 双路径。
它们保留现有网络协议与动作语义。
Windows 不使用本次 macOS 映射实现。

```flow
匹配设备 -> 保存恢复记录: 系统启动及服务
保存恢复记录 -> 写入普通键映射: 保存成功
写入普通键映射 -> 回读核对
回读核对 -> 接受设备: 一致
回读核对 -> 回滚并报告失败: 不一致
接受设备 -> 执行配置动作: 原始 HID 报告
```

每次激活都重新枚举并核对服务。
不复用其他设备的成功状态。
源头映射生效时，不再登记普通键的 tap 拦截次数。
否则，残留次数可能误吞普通键盘的同码输入。
默认左右动作由 App 执行，不能等待已被屏蔽的系统动作。
TV 在旧过滤路径仍提前登记。

## 恢复与失败边界

修改系统服务前，先保存普通键的原始映射。
三个设备家族使用独立的持久恢复记录。
记录使用系统 boot session 和服务 Registry ID。
不保存硬件地址、序列号或稳定硬件身份。
新系统启动不能使用旧服务的恢复记录。

退出 App、关闭自定义映射或撤销权限时恢复。
崩溃后，下次启动可恢复同次系统启动内的记录。
恢复只替换本功能仍持有的零映射。
外部新改的映射和 Fn 映射均保留。
电源普通键由本功能恢复，Fn 映射器不再覆盖它。

旧三键恢复记录不能误认新增按键的外部零映射。
恢复失败时保留记录，供后续重试。
服务已消失时保留记录，不套用到另一个服务。

写入失败或回读不一致时，回滚本次已尝试的服务。
记录不可用、保存失败或服务身份不明时，拒绝修改。
私有适配器的重新准备失败会取消已按住状态。
后续普通键报告不会继续执行配置动作。
恢复条件满足后，下次成功准备可以重新接管。

早期内存恢复和 locationID 恢复原型已撤回。
原型保存在仓库外，不进入产品。

## 文件与日志

| 文件 | 必要变化 |
| --- | --- |
| RemoteNativeKeyMapper.swift | 普通键源头映射、分家族恢复、回读及回滚 |
| RemoteVoiceFunctionMapper.swift | 精确服务枚举；保留独立电源映射所有权 |
| HIDRemoteMonitor.swift | 激活前核对；停止留下普通键拦截次数；执行默认左右动作 |
| BridgeAppModel.swift | 接入三类硬件的准备、退出、关闭和权限恢复 |
| 两份 FeatureIntegration.swift | 将源头映射准备和恢复回调传到私有组件 |
| Tests 下两份回归测试 | 快速按、默认动作、普通键盘、恢复和失败路径 |
| Testing/HIDIntermittentButtonDiagnostics.md | 补充全部硬件的源头映射及恢复验收 |

新增日志为 HID NATIVE MAPPING。
family 区分三个设备家族。
phase 区分 prepare 和 restore。
reason 区分记录、写入、回读及服务不可用。

只记录阶段、结果和服务计数，不记录映射正文或设备身份。
result=verified 只表示系统属性回读一致。
native_delivery=unobserved 明确标记原生投递尚未实测。
苹果普通键日志区分 source_mapped 和 armed，避免声称未执行的登记。

## 验证结果与限制

公开完整测试：1,069 项通过，覆盖 79 个测试套件。
私有集成测试：1,136 项通过，覆盖 87 个测试套件。
Siri Remote 组件：107 项通过。
Chromecast 组件：117 项通过。
集成测试中的发布脚本用例受父进程私有开关影响失败。
该用例在公开完整测试中已通过。

私有集成复跑只跳过此发布脚本用例，没有改动测试预期。
公开宿主双架构 Release 构建均通过。
私有集成双架构 Release 构建均通过。
Intel 另以 RELEASE_VARIANT=intel 验证 macOS 13 编译目标。
工程自检：48 项通过。治理检查通过。

所有本地 SwiftPM 命令均带 --disable-keychain。

回归实验暂时恢复旧拦截登记行为。
原三键的六组普通键盘保护用例失败，共 164 项断言失败。
恢复保护后，六组全部通过。
当前保护矩阵扩大到小米十二键和两种独占状态。

实验代码已恢复，没有改动系统设备映射。

Chromecast 另执行失败取消的反证实验。
撤回失败时的取消逻辑后，新回归用例出现两项断言失败。
恢复候选代码后，同一用例通过。

系统属性回读不能证明真实原生事件已经消失。
模拟测试也不能证明原始 HID 报告仍完整到达。
本次没有修改本机系统设备映射或已安装 App。

反馈设备仍须执行测试手册用例 5。
慢按、快按、长按和松开都须检查。
任何额外圆点、系统音量变化或持续连发均判失败。
普通键盘、默认音量、Fn 语音和多设备隔离也须通过。
因此，当前为候选修复，不能声明真机验收完成。

本次没有打包或替换 Draft 安装包。
Build 265 不含此候选改动。

## 组件交付顺序

本次宿主新增回调需要配套的新私有组件。
旧私有 Tag 2.3.5 不含此接口。
私有修复须先单独交付，再通过独立版本 PR 发布新 Tag。
宿主依赖升级使用独立 PR，不能覆盖旧 Tag。
未完成该顺序前，宿主候选不得作为正式发布源码。
