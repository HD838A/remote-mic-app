# v1.8.25 安装后 App bundle 仍显示 Remote Mic

- 日期：2026-08-17
- 状态：已修复，待真实中英文 Finder / Launchpad 安装验收
- 影响范围：macOS v1.8.25 的 ZIP、PKG 安装目标，以及同一构建链路生成的 DMG / Sparkle 更新 ZIP
- 功能点：无线麦SayAll.app 品牌名称与发布打包
- 简单描述：App 内部元数据已显示 SayAll / 无线麦，但正式 ZIP 和 PKG 的 bundle 文件名仍是 `Remote Mic.app`，Finder 因而可能继续显示旧名称。

## 复现

使用 GitHub Release `v1.8.25` 的正式 Apple Silicon 产物：

1. 查看 `Remote-Mic-1.8.25.zip` 顶层目录。
2. 读取顶层 App 的 `Contents/Info.plist` 和中英文本地化 `InfoPlist.strings`。
3. 使用 `pkgutil --payload-files Remote-Mic-1.8.25-Installer.pkg` 查看安装目标。

错误结果：

- ZIP 顶层是 `Remote Mic.app`。
- PKG BOM 安装到 `/Applications/Remote Mic.app`。
- 同一个 App 的基础 `CFBundleName` / `CFBundleDisplayName` 已是 `SayAll`，简体中文本地化已是“无线麦”。

正常边界：可执行文件仍应为 `RemoteMic`，Bundle ID 仍应为 `com.hd838a.RemoteMic`；这些历史技术标识不属于用户可见的 bundle 文件名，不应随品牌显示名修改。

## 日志

本问题发生在 App 启动前的归档和安装元数据层，不涉及运行时事件、设备会话或用户操作状态，因此没有可用于定位根因的 App 运行日志。复现证据由正式 ZIP 目录结构、Info.plist / InfoPlist.strings 和 PKG BOM 构成。

## 根因

品牌更新只修改了 Info.plist 和本地化显示名。以下发布链路仍分别硬编码 `Remote Mic.app`：

- App 组装和本地运行路径；
- 签名、公证、DMG 和 Sparkle ZIP 输入路径；
- PKG payload 和安装脚本目标路径；
- GitHub Release 本地产物验证和 ZIP 解包验证；
- 对应 shell / Swift 回归测试。

原有验证只断言 `CFBundleDisplayName == SayAll`，没有同时断言 App basename、`CFBundleName`、中英文本地化名称、ZIP 顶层和 PKG BOM 目标一致，所以冲突未被发布门禁拦截。

## 修复

- canonical App bundle 文件名、开发产物和安装目标统一为 `SayAll.app`。
- 英文 `CFBundleName` / `CFBundleDisplayName` 保持 `SayAll`，简体中文本地化保持“无线麦”。
- 可执行文件 `RemoteMic`、Bundle ID `com.hd838a.RemoteMic`、更新 Feed 和 `Remote-Mic-*` 发布资产文件名保持不变。
- PKG 在 preinstall 中只检查 canonical 和两个旧路径，不删除 App；只有新 `SayAll.app` 已安装并通过 Bundle ID、架构、版本和签名验证后，postinstall 才会把 Bundle ID 匹配的旧 `Remote Mic.app` / `无线麦.app` 移入目标卷对应的 macOS 废纸篓。目标名使用带时间和进程标识的防冲突名称；移动失败或 Trash 不可用时旧 App 保持原样，canonical `SayAll.app` 继续有效。不匹配的同名内容也保持原样。
- 发布验证新增 basename、CFBundleName、中英文本地化、ZIP 解包路径和 PKG BOM 路径门禁。

## Sparkle 升级边界

Sparkle 2.9.4 默认把普通 App 更新安装回当前 host bundle 路径（其构建配置 `SPARKLE_NORMALIZE_INSTALLED_APPLICATION_NAME` 为 `0`）。因此更新 ZIP 顶层改为 `SayAll.app` 可以保证新归档正确，但从旧 `/Applications/Remote Mic.app` 或 `/Applications/无线麦.app` 发起纯应用内更新时，Sparkle 仍可能保留旧文件系统路径。本次不修改或重编 Sparkle，也不增加运行中 App 自行改名逻辑；旧路径的安全迁移由新版 DMG 中的 PKG 完成。发布说明和用户指导不得宣称仅靠应用内更新就完成了路径迁移。
