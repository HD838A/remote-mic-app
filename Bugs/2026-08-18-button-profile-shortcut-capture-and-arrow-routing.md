# 键位方案快捷键录入与左右键路由

## 状态与影响范围

- 时间：2026-08-18
- 状态：修复完成；Chrome 方向快捷键已通过真实 Chrome 与实体遥控器验收
- 影响：键位方案创建流程、页面内快捷键录入、监听模式下遥控器 Left/Right 单击绑定

## 复现

1. 在键位方案“我的快捷键”中查看 `Command + Option + ←/→`，卡片以省略号隐藏末尾内容。
2. 开始录入快捷键后点击页面底部“取消”，整个键位方案草稿退出，而不是只停止录入。
3. 名称以外的步骤按 Return，没有统一执行“下一步”或“保存”。名称本身还单独占据一个步骤。
4. 普通按键页保持 Left/Right 方向键，在 Chrome 专用方案中把左右键单击绑定为 `Command + Option + ←/→`；Chrome 前台时遥控器仍不切换标签页。

正常边界：关键信息应完整显示；取消只作用于正在进行的录入；三步主操作均支持 Return；存在键位方案单击绑定时优先执行方案动作，没有覆盖时继续保留系统原生方向键长按连发。

## 日志、数据与实验

- 本机私有快捷键文件包含完整 key code 和 Command、Option 修饰键，截断只发生在单行卡片布局。
- System Events 的 `Command + Option + →` 能在真实 Chrome 窗口切换标签页。
- 使用与无线麦执行器相同的 Quartz key down/up、key code 和修饰键，也能在真实 Chrome 窗口切换标签页。
- 修复前新增硬件模拟：普通 Left/Right 仍为方向键，私有模块报告单击覆盖；Left、Right 两个参数的 `privateEvents.count` 均为 0，确认事件在私有执行器之前被截走。

## 根因

- 快捷键描述固定 `.lineLimit(1)`，长组合只能省略。
- 录入状态没有局部取消；唯一取消按钮始终调用整个向导的 `cancelEditor()`。
- 向导没有统一的默认 Return 主操作，且名称被错误拆成独立步骤。
- `HIDRemoteMonitor.shouldUseNativePassthrough` 只检查普通动作、双击和长按，没有检查键位方案单击覆盖；命中方向键透传后提前 `continue`，不会调用 `overrideActionPerformer`。

## 修复

- 快捷键卡片允许两行并增加最小高度，确保修饰键与方向键完整可见。
- 录入等待区增加“取消录入”；录入期间底部取消也只停止录入，保留方案草稿。
- 合并名称与使用方式为“基本设置”，向导缩减为三步；每步主按钮使用 Return 默认操作，录入期间禁止推进。
- 原生方向键透传新增键位方案单击覆盖门禁；存在覆盖时进入私有执行器，无覆盖时维持原生透传和长按连发。
