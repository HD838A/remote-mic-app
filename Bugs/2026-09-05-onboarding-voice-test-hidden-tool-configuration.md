# Onboarding 语音测试页隐藏第三方配置

- 时间：2026-09-05
- 状态：已修复（代码、自动化与生产截图已验证；真实第三方工具仍待现场验收）
- 影响范围：Onboarding 语音测试页，豆包、微信输入法、Typeless 及其他语音工具

## 观察

用户能够看到无线麦已经收到语音样本、会话也已结束，但第三方工具没有文字提交。1.9.19 (172) 日志中曾出现 `voice.external_tool_no_commit`、`voice.input_target_not_ready` 和 `voice.input_target_focus_lost`，仅凭原页面无法判断是语音识别键、全局唤起、麦克风设备还是 SayAll 自身焦点问题。

## 日志证据

用户现场确认豆包输入法的麦克风选择错误；将豆包麦克风手动改为 SayAll 音频页选择的 `MiRemoteV 2ch` 后立即恢复。SayAll 可以观察自己的音频输出、输入框焦点和语音会话，但不能通过公开 API 读取豆包/微信/Typeless 的内部快捷键、全局唤起或麦克风配置。

## 根因

原语音测试页只显示实时收音和文字结果，没有把“无线麦发送语音键”和第三方工具的识别键、SayAll 音频输出和第三方麦克风配置放在同一处。用户即使看到无线麦有电平，也不知道第三方工具是否监听了相同的按键或同一个虚拟音频设备。

## 修复

1. 在语音测试输入框页增加不可忽略的配置核对卡，显示无线麦发送语音键、SayAll 音频输出、第三方语音识别键与第三方麦克风。
2. 豆包额外显示并要求确认“全局唤起语音”；Typeless 显示 Fn 点按开始/结束；其他工具明确要求支持语音输入并自行配置麦克风。
3. 第三方状态以用户逐项确认表示，日志记录 `observable=false` 与 `user_confirmed`，不伪装成自动检测，也不读取第三方私有数据。
4. SayAll 自身音频输出未就绪显示红色；切换工具或音频设备后相关确认自动失效，未确认不得继续。
5. 保持 `diagnostic_schema=3`，新增字段均为向后兼容的可选字段，并增加期望按键、全局唤起适用性、用户确认和后续检查顺序。
