# 组合动作后立即说话导致回眸整段漏记

- 日期：2026-08-19
- 状态：候选修复完成，等待真实 Codex 与遥控器验收
- 影响范围：macOS 1.9.0 内测版“回眸”；打开或切换目标 App 后立即开始语音
- 功能点：本地语音转写记录、Accessibility 输入目标快照
- 简单描述：语音本身正常进入 Codex 等目标 App，但回眸没有保存刚才的内容。

## 复现与日志

1. 用组合动作打开 Codex并聚焦已学习的输入框。
2. 输入框刚出现时立即开始语音。
3. 语音文字正常写入并发送，但回眸没有新增记录。

1.9.0 现场进程共有 23 段语音，其中 13 段记录：

`TRANSCRIPT CAPTURE skipped reason=snapshot_unavailable`

同一时段语音流持续正常，且没有归档写入失败，说明丢失发生在捕获开始阶段，而不是 MCP 查询或文件缓存。

## 根因

`TranscriptCaptureCoordinator.startSession` 在语音开始时只获取一次 Accessibility 快照。组合动作刚完成时，目标 App虽然已到前台，但输入框尚未成为稳定的 `AXFocusedUIElement`，单次失败便永久放弃整段语音。

下一段语音开始时，旧实现还只提交已经被轮询观察到的候选；如果文字刚出现、轮询尚未来得及执行，也会直接取消上一段。

## 修复

- 初始快照不可用时，以 125ms 间隔在 1.25 秒窗口内异步重试，不阻塞音频或 Fn 流程。
- 敏感或不安全输入区域仍立即拒绝，不因重试扩大采集范围。
- 下一段语音开始前对上一目标做最后一次安全快照和连续差异检查。
- 所有取消路径记录稳定原因，包括初始焦点超时、结束后快照不可用、目标变化、目标变为敏感区域、文字非连续、功能关闭、超时和会话覆盖；日志不记录正文、输入框全文或设备标识。

## 验证

- `swift test --filter TranscriptCaptureCoordinatorTests`：10 项通过。
- 新增覆盖：初始焦点延迟后恢复、下一段开始前最终快照、初始焦点最终超时原因。
- 既有快速发送、连续语音、敏感目标、焦点变化、非空草稿恢复和开关关闭回归全部通过。
- `git diff --check`：通过。

## 验证边界

自动化使用可控 Accessibility 快照，不能证明 Codex真实输入框、组合动作前后台时序、输入法提交或真实遥控器。最终需要在签名候选中连续执行“打开 Codex → 聚焦已学习输入框 → 立即说话 → Return发送”，并同时核对目标文字、回眸记录和 `TRANSCRIPT CAPTURE` 日志。
