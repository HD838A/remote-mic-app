# 苹果遥控器序列号默认名称被当作自定义名

关联 [Issue #406](https://github.com/HD838A/remote-mic-app/issues/406) 和 [PR #451](https://github.com/HD838A/remote-mic-app/pull/451)。

## 复现证据与根因

2026-09-18，在 macOS 15.7.9 上以独立只读探针验证单只 A2854。用户确认此前未改名，系统显示名称与公开 API 返回的 HID 序列号完全相同。改名后 IOBluetooth 重新枚举能读到新名，HID 序列号保持不变。完整验证边界见[测试手册](../Testing/BluetoothDeviceNames.md)。没有运行候选 App，因此不把探针结果记为候选 UI 故障复现。

原名称策略只识别有限型号别名，不接收序列号元数据；使用合成名称 `TESTSERIAL001` 可确认原策略会把这种名称保留为自定义名，无法采用默认型号编号。



## 修复

- 从同一 HID 身份读取可唯一确定的序列号，仅传入本次名称判断；不新增配置字段或日志。
- 仅对苹果型号，在非空系统名称与本设备非空序列号完全相同时清空自定义名称缓存，复用既有型号编号。普通自定义名继续保留，序列号缺失或冲突时不猜测。
- 手动改名为序列号与默认名不可区分，采用相同展示；不声称检测到了系统别名的设置或清除。



## 验证

```sh
swift test --disable-keychain --disable-automatic-resolution --skip-update
SKIP_SWIFT_PACKAGE_BUILD=1 ./scripts/test.sh
```

结果：名称定向 29 项、完整测试集 612 项（47 个测试组）、独立自测 44 项通过。

新增回归覆盖精确匹配、缺失/空值、类似名称、非苹果隔离、多接口冲突、跨设备元数据隔离、旧缓存纠正与历史编号恢复。真实序列号不进入测试夹具。候选 App 的运行、外部适配器、界面与音频验收仍待完成；本次不构建或启动 App。
