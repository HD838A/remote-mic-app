# v1.9.0 内测包升级后系统权限失效

- 日期：2026-08-19
- 状态：权限 UI 与发布边界修复完成，等待真实签名包升级验收
- 影响范围：macOS 1.9.0 内测候选，尤其是从旧 `/Applications/Remote Mic.app` 升级到 `/Applications/SayAll.app` 的已有用户
- 功能点：输入监控、辅助功能、可分发预览包签名与 App 路径迁移
- 简单描述：旧版本已有权限，但 1.9.0 内测包启动后输入监控和辅助功能均显示未授权，用户必须清理旧条目再授权。

## 复现与日志

现场日志使用 UTC，需加 8 小时对应北京时间。相邻启动记录显示：

- `1.9.0`：`HID PERMISSIONS input=false accessibility=false`；2 秒恢复检查后仍为 false。
- 切回 `1.8.25`：同一台 Mac 立即显示 `input=true accessibility=true`。
- 用户清理旧权限条目后，后续 `1.9.0` 启动恢复为 true。

自动化无法直接修改或读取完整 TCC 数据库，因此系统权限历史仍属于真实 Mac 验收边界。

## 根因

1. 品牌迁移把安装目标从 `/Applications/Remote Mic.app` 改为 `/Applications/SayAll.app`。
2. 早期内测使用 ad-hoc 签名包直接安装；路径迁移后，ad-hoc 代码身份不能证明与正式版保持同一权限身份。
3. Bundle ID `com.hd838a.RemoteMic` 与可执行文件 `RemoteMic` 没有变化；单独修改 `CFBundleDisplayName` 不会造成此问题。真正破坏权限连续性的是路径迁移与不稳定 ad-hoc 代码身份叠加。

## 修复

- `macOS Preview Candidate` 继续只生成无签名凭据的 ad-hoc exact-SHA CI 证明，不作为可分发或权限连续性验收包。
- 私有 Draft 与公开 Pre-release 必须通过受保护的 `macOS Signed Release Packages` 工作流，使用正式 Developer ID Team 签名、公证并验证；两类可分发包都不得使用候选 CI 的 ad-hoc Artifact 代替。
- 保留 `SayAll.app` 用户品牌与安装路径，也保留历史 Bundle ID 和可执行文件名。
- 权限页仅在权限缺失时显示请求按钮；已完成首次设置的升级用户若权限未延续，会看到一次性兜底说明。

## 验证

- 候选 CI 负向门禁确认不读取 Match、Notary 或 Developer ID 签名凭据，并以 commit SHA 命名 Artifact。
- 正式签名工作流继续受 `mac-release` Environment 保护，并保留 590 秒签名阶段 wrapper。
- `swift test --filter BuildSigningTests`：通过。
- `swift test --filter SettingsPageRegressionTests`：21 项通过。
- `git diff --check`：通过。

## 验证边界

本地没有运行 GitHub 受保护环境，也没有安装新的 Developer ID 可分发包，因此尚不能宣称真实 TCC 权限已经自动延续。最终必须使用同一台已授权旧版 Mac，安装私有 Draft 或公开 Pre-release 的签名公证包，确认输入监控与辅助功能保持开启，并核对 `codesign -dr -` 的 designated requirement 和 Team ID 与正式版一致。候选 CI 的 ad-hoc Artifact 不能用于此验收。
