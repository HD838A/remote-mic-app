# 遥控器卡片状态文案偏离设计稿且文字区域点击失效

- 时间：2026-11-16
- 状态：候选修复，等待真实多设备与辅助功能验收
- 影响范围：统一遥控器卡片的状态详情文案、整卡点击入口
- 简单描述：实现时在“已连接”详情里加入了设计稿没有的第三方 App 诊断限定语，并改写了其他状态详情；卡片只有标题和背景空白可点击，系统名称、状态和电量文字仍是死区。

## 现象与证据

用户现场截图：卡片显示“已连接 96%”，点击状态文字没有响应。

设计稿 `feature/remote-connection-lifecycle/design/cards.html` 定义的健康状态详情为：

```text
设备已连接，当前应当可用的按键和语音功能均正常。
```

提交 `f56b9dc9` 中的实际文案为：

```text
当前应当可用的按键和语音链路均正常。第三方 App 最终结果不在本状态诊断范围内。
```

该提交同时缩短了“检查中”“状态确认中”“按键异常”“语音异常”“设备异常”的详情，均与设计稿不一致。文案改动没有对应的设计批准记录。

本机生产窗口点击验证（修复前）：

- 点击 RC001 卡片的“已连接”文字后，`selectedRemoteProfileID` 保持为另一台遥控器。
- 点击同一卡片的标题按钮后，选中项立即切换。

这证明状态文字和系统名称区域没有接入选择动作，只有标题按钮与背景空白可以点击。

## 根因

### 1. 文案改为实现者自拟

`Resources/zh-Hans.lproj/Localizable.strings` 与英文文件中的 `remote.card.detail.*` 没有按已确认的 `cards.html` 落地。健康状态额外加入了“第三方 App 最终结果不在本状态诊断范围内”，属于设计稿之外的诊断说明。

### 2. 点击手势只挂在背景

`RemoteDeviceCard` 的背景形状带有 `.onTapGesture(perform: onSelect)`，但卡片前景的系统名称、状态文字和电量是独立视图，位于背景之上，点击不会穿透到背景。标题是独立按钮，因此只有标题和空白区域可点击。

## 修复

- 按设计稿恢复六条状态详情的中英文文案；“已连接”不再包含第三方 App 限定语。
- 连接页当前设备下方恢复改造前的三行本地状态：设备连接、语音链路、语音键映射。状态详情只作为卡片辅助功能标签，不再替代这三行。
- 背景形状继续提供留白和边框内侧的 `onSelect`，但不再作为唯一入口。
- macOS 的文字视图会先消费点击，且 `.help` 悬停层会拦截点击；因此移除系统名称、状态和电量文字上的独立 `.help`，并让这些文字、电量图标和百分比各自绑定 `onSelect`。型号与系统名称合并到标题按钮的悬停提示，状态详情继续在连接页显示。
- 保留标题按钮，以及启用、会员、连接等次要按钮的独立动作；整卡点击不依赖覆盖按钮的父级手势。
- 新增本地化精确文案回归和卡片点击入口源码回归。

- 公开模式全量 `swift test --disable-keychain -j 4`：**1498 tests / 111 suites passed**。
- 待执行：公开构建、仓库治理检查和本机生产窗口点击复验。

## 边界与已知限制

- 本次不改变卡片布局、尺寸、状态判定或动作语义。
- 不恢复设计稿之外的说明文字；第三方结果边界继续由产品规范和日志说明，不塞进卡片详情。
- 源码回归只能证明点击入口存在，不能证明真实命中区域；生产窗口点击和辅助功能仍需执行。
