# 2026-11-15 方案来源前缀挤占按键卡片动作名

## 现象

PR #1063 合入后，非默认方案的按键卡片在 `1020 × 772` 窗口下把动作名截成「本方案 · 向上…」「本方案 · ⌘…」；英文界面更明显，多个格子只剩 `This Profile · ...`、`Default · No...`。编辑区仍能显示完整动作，但总览无法一眼看清每个手势实际执行什么。

## 证据

- 合并后 UI 矩阵：中文/英文、浅色/深色 `1020 × 772` 截图。
- 英文总览中显式动作格子被 `This Profile ·` 占满，动作名不可见。
- 中文总览中「本方案 · 向上翻页」「本方案 · 增大音量」等被尾部截断。
- `800 × 650` 只是离屏压力尺寸，生产最小窗口是 `1020 × 772`；该尺寸的右侧交叠不作为本次依据。

## 根因

`mappingActionSummary` 在方案编辑状态给显式和继承动作都拼接来源前缀。按键卡片每个手势只有约 70pt 宽，前缀占掉近一半宽度，长动作名只能截断。继承值需要来源标识，但显式值在已选方案的上下文里不需要在每个窄格子里重复「本方案」。

## 修复

- 卡片上的方案显式动作只显示动作名；编辑区头部继续显示「本方案 · <动作>」，悬停帮助也补充「本方案 · <动作>」及完整键名。
- 继承默认方案不再拼接「默认 ·」文字前缀，改为动作名前的链接图标；编辑区继续显示链接图标和「继承默认方案：<动作>」，悬停帮助也给出完整来源。这样英文 `Default · No action` 不再被挤成 `Default · No…`。
- 方案显式禁用继续显示「本方案禁用」（文案短，能放进格子）。
- 按住摘要复用同一动作摘要，因此显式动作的按住行也不再被来源前缀挤占。
- 不修改卡片宽高、窗口最小尺寸或动作网格布局。

## 验证

- 公开模式：`SAYALL_PRIVATE_PLATFORM_MODE=public swift test --disable-keychain`，1450 项测试、104 个套件通过。
- 私有 2.12.0 源码：跳过与本修复无关的发布控制面 fixture 后，1515 项测试、113 个套件通过。
- 全量套件曾暴露既有测试隔离问题：`RemoteNativeKeyMapperTests` 与其他套件并发时默认 `UserDefaults.synchronize()` 会返回 false，`mapper.prepare()` 失败；在 main `ccfd2bff` 的独立 worktree 用同一过滤条件可复现，native suite 单独运行通过。测试改用只覆写 `synchronize()` 的隔离 defaults（不改变生产持久化），公开和私有全量均恢复通过。
- 生产 `SettingsView` 截图：中文/英文、浅色/深色 `1020 × 772`，检查卡片动作名、继承链接、显式禁用和编辑区来源文案。
- `scripts/verify-localizations.sh`、`scripts/verify-repository-governance.sh`、`scripts/check-repository-boundaries.sh`、`git diff --check` 通过。
