# 第三方语音输入结果未进入回眸

## 现象

RC003 的音频流和实时音量均正常，目标语音工具也完成输入，但“回眸”没有新增记录。运行日志显示捕获目标已就绪，随后以 `discontinuous_text_change` 放弃会话；部分会话在组合动作切换目标时出现 `initial_focus_unavailable`。

## 原因

原实现只接受目标输入框在原选区发生一次严格连续替换。第三方输入法在提交最终文字前可能短暂接管或重组光标附近内容，这个中间状态被误判为无关编辑并立即取消，之后即使最终文字稳定也不会再读取。

## 修复

- 严格连续差异仍为首选；额外接受原选区附近有限范围内的输入法重组。
- 遇到一次不连续中间状态时继续轮询，不立即取消；仍限制目标 App、焦点、安全输入区域和最大文字长度。
- 每次语音使用唯一 session ID 汇合文字与可选音频；最终无法安全读取文字时保存“未能读取转写文字”状态，避免整个会话无痕消失。
- 本地 MCP 忽略无文字的回退记录，避免改变只读文字接口。

## 验证

- `swift build` 通过。
- 项目轻量自检 61 项通过，包含第三方文字不可读回退、`.m4a` 写入、精确 4 小时过期和边界清理。
- 完整 Swift Testing 套件因当前机器只有 Command Line Tools、缺少 `Testing` 模块而未运行；真实 RC003 与千问/闪电说时序需在本地开发版人工验收。
