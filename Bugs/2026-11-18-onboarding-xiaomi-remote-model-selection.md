# Onboarding 无法在 RC003 已连接时选择并连接 RC001

- 时间：2026-11-18
- 状态：候选实现，等待真实 RC001 / RC003 与日志验收
- 影响范围：Onboarding 控制设备页、BLE 连接目标、HID 普通按键、语音来源门禁
- 简单描述：控制设备页把小米遥控器 2 和 2 Pro 合并成一个入口。RC003 已连接时，页面直接显示“已连接”，无法明确选择 RC001；连接页和语音门禁也只判断“任意小米遥控器”，另一只已连接型号可以替代所选型号通过。

## 证据与缺口

- 用户提供的附件是 `2134 × 1544` PNG 界面截图，不是 App 运行日志。
- 当前没有 `runtime.log`、BLE `CONNECT/READY` 事件、HID 报告或诊断包，无法确认失败发生在：
  1. App 没有对 RC001 档案发起连接；
  2. App 发起了连接，但 CoreBluetooth 或固件拒绝第二只设备；
  3. RC001 没有唤醒或不在广播范围；
  4. 连接成功但 HID/语音事件被另一只遥控器覆盖。
- 现有代码事实：
  - `OnboardingControlSource` 只有 `.xiaomiRemote`，控制设备页标题为“小米蓝牙遥控器 2 / 2 Pro”。
  - `BridgeAppModel.isOnboardingControlSourceConnected(.xiaomiRemote)` 接受任意非私有适配器档案。
  - Onboarding 语音判断只看活跃来源是否为 `.xiaomiRemote`。
  - HID `onButtonPressed` 在收到任意小米遥控器按键时调用 `selectRemoteProfile`，会把选择切到实际按键的遥控器。

## 根因假设

控制设备页没有型号维度，后续门禁也只看来源家族。RC003 已连接时，页面和门禁把“存在任意小米连接”当成“所选小米型号已连接”，用户无法为 RC001 建立独立的连接目标；同时 HID/语音事件没有按档案型号归属，另一只遥控器可以切换选择或满足门禁。

## 修复方向

- 新增 `OnboardingXiaomiRemoteModel` 和持久化值，控制设备页拆成 RC003 / RC001 两张卡片。
- 选择型号时优先选中并定向重连对应档案；没有档案时启动 discovery。
- 连接、普通按键、语音和完成门禁都按所选型号档案校验。
- Onboarding 已选定小米型号时，另一只已识别小米遥控器的按键/语音不得切换选择、执行映射或满足门禁。
- 未识别档案的第一份普通按键可暂存，但 DIS 确认型号前不能通过。
- 右栏真机图和连接页状态文案跟随所选型号。

## 验证

- 自动化：卡片顺序、型号持久化、控制来源门禁、事件归属纯策略、右栏分组资源和放大层。
- 离屏截图：控制设备页 4 卡顺序与高度、RC001/RC003 两个选中态、连接页状态文案和右栏真机图。
- 真机：RC003 已连接时选择并连接 RC001；反向场景；两只同时连接时切换；按错遥控器的普通键/语音；RC001/RC003 各自的真实语音文字上屏、极速按放、连续会话和断连恢复。

## 边界

- 不在没有日志的情况下自动断开另一只已连接遥控器。
- 不修改 BLE/ATVV/HID/音频协议、语音键生命周期、首字/尾字处理。
- 不读取或修改第三方 App 私有配置。
- 自动化、构建和离屏截图不能证明真实 CoreBluetooth 连接、HID 报告或第三方文字上屏。
