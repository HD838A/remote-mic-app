# 组合动作输入框学习容易与回眸 MCP 配置混淆

- 时间：2026-08-19
- 状态：说明已优化，等待最终签名包页面人工验收
- 影响范围：macOS 1.9.0 内测候选；组合动作与回眸本地 Agent 访问
- 功能点：组合动作页面说明、输入框学习、Codex MCP / TOML 配置
- 简单描述：页面没有直接说明两套配置的职责边界，用户可能误以为配置 Codex MCP / TOML 后就能自动聚焦输入框，或学习输入框后就已授权 Codex 读取回眸。

## 代码检查

- 组合动作输入框学习由私有 `sayall-macro-platform` 通过 macOS Accessibility 保存目标输入区域特征，用于运行动作时恢复光标位置。
- 回眸中的 Codex MCP / TOML 由公开宿主的 `SayAllMCPKit` 和客户端集成服务管理，只授权本地 Agent 读取已保存历史。
- 两条路径没有共享配置、令牌或运行状态；现有实现逻辑正确，问题是用户说明缺少直接边界。

## 优化

在公开宿主的组合动作页底部增加固定中英文说明：输入框学习只负责聚焦目标 App；回眸中的 Codex MCP / TOML 只负责授权读取本地历史，两者互不替代。

本次不修改私有宏引擎、Accessibility 学习数据、MCP 配置、授权令牌、回眸记录或按键绑定行为。

## 验证边界

- 自动化检查中英文 key、12pt 字号及宿主页面接线。
- 仍需使用包含私有模块的最终签名 App，在中英文和最小窗口下确认说明完整可见、不遮挡编辑器、底部状态和操作入口；组合动作不要求邀请码。
