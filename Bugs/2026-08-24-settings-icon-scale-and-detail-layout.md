# 设置页分类图标过大与右侧页面布局不一致

> 11:39 的同屏系统设置对照图进一步证明 16pt 后续版本反而偏小；当前图标与行内网格以 `2026-08-24-settings-sidebar-icon-size-and-row-spacing.md` 为准。

## 复现

- 环境：当前 macOS 深色外观，本地 `dist/SayAll.app`，设置窗口 `800 × 650`。
- 操作：依次打开按键、统计、回眸、连接、权限和关于，并与当前“系统设置 → 触控板”的侧栏图标、搜索框、分区宽度、文字基线和右侧控件位置对照。
- 实际结果：20pt 彩色图标底板带描边和投影，在源列表行中显得过大、过圆；按键页的启用/设备状态悬在业务画布上方，统计页先展示分享卡再展示数据，回眸页的隐私说明与开关悬在内容卡外，关于页使用 72pt App 图标、28pt 版本号、34pt 装饰图标和多套自定义卡片行。不同页面像由数套界面语言拼合。
- 预期结果：侧栏图标接近系统设置的紧凑彩色分类图标；搜索继续使用系统高度；右侧的设置、状态和动作使用一致的系统分区、内容宽度、标签列和操作列，只有遥控器关系图、统计图、二维码和历史等业务可视化保留自定义绘制。

## 日志结论

复现后检查最近 10 分钟的 `RemoteMic` 统一日志。页面均可正常切换，没有 SwiftUI 布局、资源加载或崩溃错误；仅有与本问题无关的 CoreSpotlight donation 警告和正常的更新检查网络事件。该问题属于稳定可复现的静态布局偏差，不是运行时状态错误。

## 代码结论与根因

1. `SettingsSidebarIcon` 把 11pt Symbol 放入 20pt 圆角底板，并叠加浅色描边与阴影，视觉重量高于系统源列表中的分类图标。
2. `mappingPage`、`statisticsPage` 和 `transcriptHistoryPage` 各自维护独立的页头布局，设置开关、隐私信息和设备状态没有进入统一分区。
3. `statisticsPage` 把分享卡放在数据内容之前，破坏了页面的任务优先级。
4. `aboutPage` 用多组手写 `HStack` / `GroupBox` 模拟表单行，并硬编码 72pt、28pt 和 34pt 尺寸，没有复用 grouped `Form` 的标签列与 trailing controls 对齐。

## 修复

- 分类图标改为 16pt 平面系统色底板与 9pt 单色 SF Symbol，删除额外描边和投影；原生 `.sidebar` 选择态、`.large` 行/搜索密度和 232pt 理想侧栏宽度不变。
- 按键页把启用开关与遥控器设备状态纳入同一个 `GroupBox`，遥控器连线画布继续作为必要业务可视化。
- 统计页把周期分段控件与本机隐私状态纳入同一分区，图表与排行优先，分享入口移到数据之后。
- 回眸页用 `LabeledContent` 对齐记录开关和隐私说明，历史与本地 Agent 区继续使用相同最大内容宽度。
- 关于页改用 grouped `Form` / `Section` / `LabeledContent`；App 图标缩为 48pt，版本号回到 `.body`，移除 34pt 偏好装饰图标，同时保留更新、反馈、分享、导入导出、语言和启动偏好的原有动作。
