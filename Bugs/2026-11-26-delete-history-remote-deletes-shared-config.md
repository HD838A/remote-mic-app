# 删除历史设备会删除共享键位方案

## 状态与范围

时间：2026-11-26。状态：已修复，等待真实双设备与私有方案现场验收。

范围：连接页“连接过的设备”卡片的删除流程、`unifiedBaseBindings` 清理、私有键位方案、BLE/HID 运行时资源。不涉及卡片布局或语音链路。

## 证据

- 功能提交 `abaf94c1` 在删除历史档案时调用私有键位方案的设备级删除入口，意图清理“只属于该设备”的方案。
- 固定私有依赖 `2.15.3` 的 Button Profiles 已启用全局作用域；其查询接口忽略设备参数，删除入口固定使用全局作用域。
- 因此删除历史设备 B 会遍历并删除所有非默认全局方案，已连接设备 A 正在使用的方案和自动应用规则一起消失。
- 在私有构件测试中添加双设备用例后，修复前用例在“删除 B 后共享方案仍存在”的断言处失败，复现了上述行为。
- 公开构建不编译私有模块，原有用例只检查源码中存在删除调用，不能发现该问题。

## 根因

实现把方法名当成了作用域契约，没有先确认固定私有版本的实际语义。私有 Button Profiles 当前是跨设备共享配置，`profiles(for:)` 的设备参数在全局作用域下不表示“只属于该设备”。对该集合调用删除，必然影响其他设备。

另外，运行时按 BLE identifier 和 HID fingerprint 清理 bridge/monitor，没有检查同一标识是否仍被其他档案使用。冲突重复档案可能共享这些标识，删除历史项也可能停掉已连接项的运行时链路。

## 修复

- 删除历史设备时不再删除私有键位方案；共享方案是全局配置，不由单个设备拥有。
- 保留 `unifiedBaseBindings` 中目标档案的清理，以及选中回退和默认映射恢复。
- 删除目标档案的 base bindings 时不再通知当前选中的其他设备，避免中断已连接设备正在进行的按键交互。
- 删除是一次显式事务：清理 base bindings、移除档案、切换或清空选中、恢复默认映射的整个过程都不广播交互模式变化，由模型按被删设备的真实身份取消通道，避免用已删除或暂为空的选中项误伤其它设备。
- 仅在没有任何其他档案使用同一 BLE identifier 或 HID fingerprint 时，才停止对应 bridge/monitor 并清理按标识共享的运行时缓存。
- 共享指纹保留监视器时，如果监视器仍绑定被删档案，把它重绑到存活的同指纹档案；否则按键和状态会回退到当前选中设备的映射。
- 删除确认文案明确“基础按键映射”和“共享键位方案不会删除”。
- 增加私有构件双设备回归、共享身份所有权回归、非选中删除交互回归和选中删除不广播交互变化回归。
- 删除日志使用单一终态和 `operation_id`；模型与设置组件共享同一个编号。
- 删除按钮的辅助功能标签带上型号，避免多张历史卡片的按钮都只读作“删除”。

## 验证

- 修复前，私有构件 `2.15.3` 新增双设备用例在“删除 B 后共享方案仍存在”的断言处失败；修复后该用例通过。
- 私有 `2.15.3` 定向下 4 项通过：共享方案保留、非选中删除不取消当前交互、选中删除不广播交互变化、共享运行时标识所有权。
- 私有 `2.15.3` 的 `RemoteProfilePersistenceTests` 与定向 `SettingsPageRegressionTests` 共 146 项通过，包含既有去重、选中回退和互补档案合并回归。
- 公开模式的 `RemoteProfilePersistenceTests` 与 `SettingsPageRegressionTests` 共 145 项通过；公开 Release App 构建通过。
- `scripts/test.sh`：50 项自测通过，随后公开 Swift Package 构建通过。
- `scripts/check-repository-boundaries.sh`、`scripts/verify-repository-governance.sh`、`git diff --check` 通过。
- 本机公开全量 Swift Testing 运行器两次以 signal 11 结束，未产生断言失败；受影响套件、私有套件和构建均单独通过，最终以 CI 全量结果为准。
- 生产 `SettingsView` 重新截图：中文浅色/深色、英文、删除确认和删除后状态均使用更新后的“基础按键映射 / 共享键位方案不会删除”文案。
- 私有方案测试只在 `canImport(SayAllButtonProfiles)` 且设置 `SAYALL_MACRO_STORAGE_ROOT` 时执行，并删除自己创建的方案，避免写入开发者真实配置。

## 边界

- 共享键位方案目前没有设备归属，无法按设备安全删除；如果产品要求按设备删除，必须先改私有组件的数据模型和 API。
- 删除后迟到的蓝牙 `.ready` 回调仍可能重新登记档案；需要私有 bridge 时序或真机日志确认，未在本次修复中加入 tombstone。
- 多个档案共享同一 HID fingerprint 时，发现链路可能创建多个同指纹监视器，而字典只保留最后一个；这是既有问题，需真机确认是否产生重复按键。
- 删除选中且没有替代档案时不再广播 `nil` 交互通知；映射页 discovery 监视器的进行中手势不会被这次删除取消，但删除入口位于连接页，影响有限。
- Chromecast/Apple 语音短语状态、`shortcutRecoveryEvaluatedKey` 和 `lastRemoteButtonPressProfileID` 仍可能保留被删档案的 UUID，属低影响内存或偏好残留。
- 单元测试不能替代真实蓝牙、HID、苹果遥控器和 Chromecast 的现场验收。
