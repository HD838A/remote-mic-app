# 历史遥控器卡片缺失名称、苹果条目及功能状态

## 证据与边界

用户在 #1072 合入后提供现场截图：离线小米档案显示通用名称与“系统名称未知”，曾连接的苹果遥控器不在历史列表。本轮用户确认了统一三行卡片、苹果安装/会员入口及整体状态语义，HTML 原型位于 `feature/remote-connection-lifecycle/design/cards.html`。现场原件按外部证据规则保存，图片字节不入本仓库。

没有与该现场截图同次操作的蓝牙/HID/音频流水，不能据此判定真实连接或语音故障；本次不推断具体设备身份、固件或系统原因。

## 已确认原因

- 历史筛选只允许带蓝牙 UUID 的非私有适配器档案，苹果 HID 档案被排除。
- 名称仅在内存或去除出厂名的 `customName` 字段中保存，出厂蓝牙名重启后丢失。名称缓存回归覆盖出厂名、缺失观察、重启和序列号排除；旧实现不保留独立上次名称。
- 卡片按 transport 是否连接显示“已连接”，没有合并设备级 HID 失败、权限或已授权语音不可用。
- 按键顶部/当前连接与历史列表分别拼接 UI，尺寸与动作不能保持一致。

## 修复与验证

复用同一生产 `RemoteDeviceCard`；历史列表包含苹果/Chromecast，保留有效的非序列号蓝牙名称缓存。共享纯状态策略只在所有适用本地功能 Ready 时显示“已连接”，优先呈现已确认故障；未知和准备中不伪报正常。苹果语音权益不影响普通按键与组件启用。

本地命令：`SAYALL_PRIVATE_PLATFORM_MODE=public swift test --disable-keychain -j 4`；`swift build --disable-keychain` 同样使用公开模式。状态测试覆盖组合、故障优先级、非会员排除、HID 权限/读取失败、名称保留与旧档案解码。生产设置页截图使用隔离演示档案，不能替代真机和第三方工具验收。结果与 PR 附件索引以当前提交证据为准。

日志新增 `REMOTE CARD_STATUS` 状态转换，重复状态不写；无设备身份、名称或映射。已有 BLE/HID/音频日志继续提供故障来源，卡片明确 `scope=local_readiness external_result=unknown`。测试手册见 `Testing/ConnectedRemoteCards.md`。

真实苹果组件安装/权限恢复、小米/苹果/Chromecast 按键和语音、首字/尾字、多设备隔离、睡眠与重连仍须现场验证，本轮只交付候选，不宣称硬件兼容或发布通过。
