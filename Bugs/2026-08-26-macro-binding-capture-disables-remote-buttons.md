# 组合动作页面捕获按键导致遥控器动作失效

## 复现条件

- 适用范围：宿主 App 注入 `sayall-macro-platform` 私有模块时。
- 打开“组合动作”页面，选择或创建一个已配置动作。
- 在页面内测试该动作，测试可以成功完成。
- 不离开页面，或将无线麦 App 隐藏后，按下实体遥控器按键；手机 Nearby / Web Remote 也可复现同一路由问题。

## 错误行为

页面测试执行器报告成功，但实体遥控器、手机或网页按键不再执行原来的按键动作或已绑定的组合动作。隐藏窗口后按键仍可能保持无效。

## 日志与代码证据

2026-08-25 的运行日志能看到 HID 报告已接收、按键边沿已识别，但问题场景没有后续动作执行记录。代码检查确认：组合动作页面出现时宿主把 `isEditorActive` 设为 `true`，HID 回调随后返回 `shouldPerformAction = false`；手机 / Web 路径也在该状态下直接返回，导致动作路由被消费。

## 根因

页面可见状态被错误当作“正在选择遥控器按键”的编辑状态。用户只是浏览或测试组合动作时，系统仍进入按键捕获模式；窗口隐藏、页面切换或关闭窗口也没有统一清除该状态。

## 修复

- 私有模块新增“选择遥控器按键”显式模式，默认关闭；只有该开关打开时才把遥控器按键写入当前绑定选择。
- 组合动作页面打开、测试或浏览时不再自动拦截按键；关闭显式模式后恢复原有动作 / 组合动作执行。
- 页面离开、视图销毁、设置窗口关闭或 App 隐藏时统一退出捕获模式。
- HID 与手机 / Web 捕获路径增加不含输入正文的诊断日志，便于区分“按键被编辑器捕获”和“正常动作执行”。

## 验证

- 私有包：`swift test`、`swift build -c release` 均通过。
- 宿主（注入修复后的私有包）：`swift test` 通过，403 个测试 / 36 个 suite；`swift build -c release` 通过。
- 自动化覆盖页面回调、显式模式保护和原有 Remote Buttons 回归。

## 验证边界

自动化和编译验证不能替代最终签名包上的真实实体遥控器、Nearby、Web Remote、App 前台 / 后台 / 隐藏、页面切换和“按键确定位置”人工验收；这些用例需按测试手册完成后再宣称真机通过。
