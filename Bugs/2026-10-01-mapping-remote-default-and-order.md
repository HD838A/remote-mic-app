# 按键映射页默认型号与设备卡顺序错误

- 时间：2026-10-01
- 状态：候选修复完成，自动化验证通过；待真实多遥控器窗口验收
- 影响范围：macOS 设置 → 按键映射
- 功能点：按键页默认硬件画布、顶部已连接遥控器卡片顺序

## 复现证据

同时连接小米遥控器、苹果遥控器和 Chromecast 遥控器，并在其他页面先选中苹果或 Chromecast。进入“按键映射”后，页面沿用此前选择，不默认显示小米画布；顶部卡片按本地化名称排序为 `Chromecast、苹果、小米`。

正常行为是：存在已连接小米遥控器时，进入按键页默认显示排序最前的小米型号；顶部卡片固定按“小米、苹果、Chromecast”排列。同一家族内仍保持稳定的型号名、系统名和 profile ID 排序。用户进入页面后手动切换型号时，不应因页面重绘自动跳回小米。

## 日志结论

原实现没有“进入按键页时选择默认型号”的事件，也没有对应日志。设备卡顺序稳定但与产品指定的硬件家族顺序不符；未观察到连接、断连或 profile 重建，因此不是蓝牙状态抖动。

## 根因

`RemoteDeviceNamePolicy.sortedForCards` 只按本地化型号名的拉丁化/拼音排序，没有硬件家族优先级；`SettingsView` 直接使用全局 `selectedRemoteProfileID` 渲染硬件画布，也没有在进入按键页时应用默认小米规则。

## 修复

- 卡片排序先按硬件家族固定为“小米、苹果、Chromecast、未知”，同一家族内继续使用原稳定排序。
- 仅在设置窗口首次显示按键页或侧边栏切入按键页时，从已连接设备中选择排序最前的小米遥控器。
- 页面画布重绘不执行默认选择，保留用户在当前页面手动切换苹果或 Chromecast 的结果。
- 没有已连接小米遥控器时保留当前选择，不伪造设备；日志记录 `selected`、`xiaomi_already_selected` 或 `xiaomi_unavailable`，不包含设备身份。
