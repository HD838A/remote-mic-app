# 800 × 650 按键映射页页头被压成竖排

- 时间：2026-08-18
- 状态：已修复，自动化与四态结构截图通过，等待最终打包 App 可见页面复验
- 影响范围：macOS 设置窗口为 `800 × 650` 时的按键映射页页头
- 功能点：页面标题、自定义按键开关与遥控器设备选择卡布局
- 简单描述：最小窗口下，页头横向空间不足，中文标题和“启用自定义按键功能”被逐字压成多行竖排。
- 原始记录：基线 `1390a7c2` 的中英文、浅色与深色四态截图均可复现。

## 复现与日志

1. 基于 `1390a7c2` 构建 App，使用设置页截图渲染器打开 `800 × 650` 的按键映射页。
2. 分别渲染简体中文、英文及浅色、深色外观。
3. 四种状态下，页头标题、开关和固定 `400pt` 的设备卡被放在同一个横向容器中；中文开关标签被压成逐字换行，标题也只剩极窄空间。

这是纯布局压缩，没有崩溃、系统错误或业务事件，因此运行日志没有对应错误。复现证据是修复前四态截图，位于本地忽略目录 `.codex-screenshots/mapping-header-bug/before/`，不纳入仓库。

## 根因

`mappingPage` 页头始终使用单行 `HStack`，同时保留 `400pt` 设备选择卡；标题和开关没有禁止横向压缩。在 `800pt` 窗口扣除侧栏、页边距、间距和设备卡后，剩余宽度不足，SwiftUI 只能压缩文本并逐字换行。

## 修复

- 使用 `ViewThatFits(in: .horizontal)` 保留宽窗口原有单行布局。
- 空间不足时回退为标题与开关上下排列，设备选择卡缩为 `320pt`。
- 标题和开关使用横向 `fixedSize`，避免再次被压成逐字竖排。
- 开关仍调用原有 `setCustomMappingEnabled`；没有修改按键动作、映射绑定、权限门禁、持久化格式或遥控器选择行为。

## 验证

- `swift test --filter SettingsPageRegressionTests`：17 项通过。
- `git diff --check`：通过。
- 使用最新 Debug 可执行文件重新生成 `800 × 650` 中英文、浅色与深色四态结构截图：页头标题和开关均不再逐字竖排，设备卡完整显示在右侧。
- 独立 Debug 可执行文件不带最终 App 的本地化与图片资源，因此本次截图只证明修复后的布局结构；最终打包 App 的真实中英文资源、遥控器图片和完整页面仍需在候选包中复验。
