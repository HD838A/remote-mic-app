# 延迟 HID 服务导致语音键失效和普通按键双重触发

- 时间：2026-08-25
- 状态：本地候选修复完成，等待 RC003 全按键真机验收
- 影响范围：启用自定义映射后启动 App、遥控器重连、Mac 睡眠唤醒、权限变化或切换语音快捷键

## 复现与现场证据

当前语音键配置为用户自定义的 Tab 上方符号键：`keyCode=50`、无修饰键。Mac 实体键盘按该键可以触发第三方语音工具，因此目标工具配置正常。

2026-08-25 11:33 的真实运行日志中，BLE 与语音音频链路均已工作；随后多次按语音键均出现 `ATVV STREAM START/AUDIO/STOP`，页面音量条也有变化，但没有 `HID EDGE` 或 `VOICE SHORTCUT`。同一启动时段的关键日志是：

```text
VOICE FN MAPPING applied=false mode=neutralized ... matched=0
VOICE FN MAPPING applied=false mode=function ... matched=0
HID START rejected native_buttons_suppressed=false
```

错误发生时普通按键仍可能走系统原生事件，造成“配置动作 + 原始键”双重触发；语音收音正常不能证明 HID 按键触发正常。

## 根因

RC003 的 BLE 音频服务与键盘 HID 服务不是同时枚举。App 第一次应用 `UserKeyMapping` 时可能匹配到 0 个 HID 服务，或只匹配到稍早出现的一部分服务。

旧恢复策略只在语音快捷键是单独修饰键时重试。普通单键、组合键、默认 Fn，以及 12 个普通按键的原生事件中和失败后均不会重试；一次启动时序竞争会永久保留到下一次设置变化或重启。这也解释了同一问题在左 Control 修复后，切换为普通符号键又复发。

## 修复

- 把语音专用重试改为统一 HID 映射恢复：就绪条件同时要求当前语音模式完整应用，以及 12 个普通按键的原生事件全部被中和。
- 覆盖默认 Fn、左右八个独立修饰键、普通单键和组合快捷键；语音目标始终来自当前 `voiceTriggerShortcut`，不写死左 Control。
- 启动失败后按 `0.5 / 1 / 2 / 4 / 8` 秒有界重试。
- 首次成功后在 `0.75 / 2 / 5 / 10` 秒做只读注册表复核；若发现晚到的 HID 服务或任一受管映射缺失，重新进入完整应用流程。
- 瞬时映射失败只停用当前运行会话，不清除用户已保存的 Fn 点按偏好或自定义快捷键。
- 保留事务回滚与 fail-closed：映射不完整时不启动可能产生双重触发的 HID 监听。
