# Dock 偏好、系统媒体动作、音量摘要与窗口菜单回归

- 时间：2026-09-13
- 状态：候选修复与自动化通过，等待真实 macOS 验收
- 影响范围：macOS 主设置窗口、按键映射与系统媒体动作
- 功能点：Dock 图标偏好、系统媒体、动作摘要、应用菜单
- 对应问题：#386、#407、#412、#413

## 复现

在当前主线执行以下检查可稳定观察旧行为：

1. 关闭 Dock 图标开关但保持设置窗口打开，激活策略仍返回 regular，Dock 图标不会立即隐藏。
2. 按键映射摘要把系统音量显示为单独的 + 或 −，与普通键盘字符混淆。
3. “上一首 / 下一首”发送 Command+左/右方向键，只由前台应用解释，后台播放器不会收到系统媒体事件。
4. 应用菜单缺少隐藏、隐藏其他、全部显示和最小化等标准 macOS 动作。

## 日志结论

这些问题发生在本地显示、AppKit 菜单和系统事件选择层，没有异步会话或外部服务日志。现有运行日志不能证明 Dock、播放器曲目或菜单最终可见结果；判断必须以界面、系统媒体会话和窗口行为为准。

## 代码与根因

- Dock 激活策略把“设置窗口已打开”误作强制显示 Dock 图标的条件。
- 映射摘要使用过短的 + / − 字符，没有复用可区分系统音量的文案。
- 上一首和下一首仍沿用历史 Command+方向键实现，没有发送 system-defined media key。
- 自建主菜单只注册退出、关闭和编辑动作，遗漏标准 AppKit responder action。

## 最小修复

- Dock 激活策略只遵循已持久化的 showDockIcon 偏好。
- 仅将映射摘要改为 Vol+ / Vol-，不改变音量事件路径。
- 播放/暂停、上一首和下一首统一通过可测试的系统媒体事件出口发送。
- 在应用菜单补充隐藏相关动作，并增加只包含最小化的标准窗口菜单。

未修改按键 raw value、持久化格式、蓝牙、音频、语音键或第三方 App 数据访问。
